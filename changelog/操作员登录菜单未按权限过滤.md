# 操作员登录菜单未按权限过滤

> 用户报：「我登录的是操作员，怎么没有按权限过滤呢？」（以操作员账号登录，侧边栏菜单却全量显示）

**范围（用户拍板）**：本轮只修**菜单/路由层**。按钮权限（`v-auth`）、子模块 tab 权限另开一轮。

---

## 一、定位

权限过滤链路本身是通的（上一轮「菜单与按钮权限控制」已交付）：

- `build/plugins/router.ts` 的 `onRouteMetaGen` 已把 `meta.permission` 注入 `router/elegant/routes.ts`；
- `store/modules/route/shared.ts` 的 `filterAuthRoutesByPermission()` 按 `meta.permission` 过滤，父目录子级被裁光后一并隐藏；
- `store/modules/route/index.ts` 的 `initStaticAuthRoute()`：`isSuperAdmin ? 全量 : filterAuthRoutesByPermission(...)`；
- `router/guard/route.ts`：`!routeStore.isInitAuthRoute` 时调用 `initAuthRoute()`。

**结论：过滤器没问题，问题在于「换账号后根本没重新过滤」。**

### 根因 1：`$reset()` 在 setup store 上是死的（致命）

`routeStore.resetStore()` 第一句是 `routeStore.$reset()`（store/modules/route/index.ts:137）。
Pinia 的 `$reset()` **只对 options store 有效**；本项目的 route/auth store 都是 setup store（`defineStore(id, () => {...})`），
结果：

- 开发环境：`🍍 "xxx" store does not implement $reset()` 抛错 → `resetVueRoutes()`、`initConstantRoute()` 全部不执行；
- 生产环境：静默 no-op。

⇒ 登出时动态路由没卸载、菜单没清空、`isInitAuthRoute` 还是 `true`。

`authStore.resetStore()` 第 44 行的 `authStore.$reset()` 同病：token/userInfo 不会被清，dev 下还会中断后续 `toLogin()`。
⇒ **登出流程在 dev 下基本是坏的。**

### 根因 2：登录成功不重建路由

`authStore.login()` 成功后只做了 `applyUser → checkTabClear → redirectFromLogin`。
若上一次会话的路由已初始化（`isInitAuthRoute === true`，登出失败/未登出/直接访问 `/login` 都可能出现），
guard 里 `!routeStore.isInitAuthRoute` 为 false ⇒ `initAuthRoute()` 不跑 ⇒ **菜单原样沿用上一个账号的权限**。

`checkTabClear()`（用 `lastLoginUserId` 比对）已经识别了「账号切换」，但它只清 tab，没碰路由。

### 根因 3：`Object.assign` 残留上一个账号的字段（放大器）

`applyUser()` 与 `initUserInfo()` 都用 `Object.assign(userInfo, user/cached)`,
后端 `UserDetail` 字段不固定：切换账号后若新响应不含 `roleType`/`accountType`/`authMap`，**旧值残留**。
而 `isSuperAdmin = roleType === 100 || accountType === 1` ⇒ 残留一个 `roleType: 100` 就判定为超管
⇒ `initStaticAuthRoute()` 走全量分支 ⇒ 菜单全在。这是「操作员登录却全量菜单」最可能的直接触发点。

## 二、设计（方案 A，已批准）

三个候选方案的取舍：

| 方案          | 做法                                                                                            | 评价                                                                     |
| ------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **A（采纳）** | setup store 内**手写重置**，弃用 `$reset`；登录时按 userId 判断是否重建；`applyUser` 前先清干净 | 改 2 个文件约 40 行，逻辑显式可读，顺带修掉登出流程                      |
| B             | 在 setup store 返回值里自定义 `$reset` 覆盖内置                                                 | 依赖 Pinia 内部 assign 顺序，`$reset` 不是可覆盖的公开类型，隐晦易踩坑   |
| C             | 只在登录时强制重建，不动 `resetStore`                                                           | 登出后旧路由仍挂在 router 上（地址栏直接输路径仍可进），dev 登出抛错依旧 |

### 实施点

**1. `src/store/modules/route/index.ts`**

- 新增 `authRouteUserId = ref('')`：记录「当前这批 auth 路由是为哪个用户初始化的」。
  `initStaticAuthRoute()` / `initDynamicAuthRoute()` 成功后写入 `authStore.userInfo.userId`。
- 重写 `resetStore()`，不再调用 `$reset()`：

  ```txt
  resetVueRoutes()              // 先卸载动态路由，保住 removeRouteFns
  → constantRoutes/shallowRef = []
  → authRoutes/shallowRef = []
  → menus = []  → cacheRoutes = []  → excludeCacheRoutes = []
  → authRouteUserId = ''
  → setIsInitConstantRoute(false) → setIsInitAuthRoute(false)
  → await initConstantRoute()   // 重新注册常量路由
  ```

  置 `isInitAuthRoute = false` 是让 guard 重建菜单的关键；置 `isInitConstantRoute = false` 后
  `initConstantRoute()` 会重新跑一次（内部 `handleConstantAndAuthRoutes` 再次 `resetVueRoutes()` 时
  `removeRouteFns` 已空，无副作用）。

- 导出 `authRouteUserId` 供 auth store 读取。

**2. `src/store/modules/auth/index.ts`**

- 新增 `createEmptyUserInfo()` + `resetUserInfo()`：先 `delete` 掉所有已有 key，再赋空值
  （只 `Object.assign` 空壳会漏掉 `roleType`/`accountType` 这类后端动态字段）。
- `applyUser()` 开头调 `resetUserInfo()`；`initUserInfo()` 恢复 localStorage 缓存前也先重置。
- `resetStore()`：`recordUserId()` → `clearAuthStorage()` → `resetUserInfo()` + `token.value = ''`（取代 `authStore.$reset()`）
  → `tabStore.cacheTabs()` → `await routeStore.resetStore()` → `toLogin()`。顺序不变。
- `login()` 中在 `applyUser()` 之后、`redirectFromLogin()` 之前：

  ```ts
  if (routeStore.isInitAuthRoute && routeStore.authRouteUserId !== userInfo.userId) {
    await routeStore.resetStore();
  }
  ```

  之后 `redirectFromLogin` 触发 guard，guard 发现 `isInitAuthRoute === false`
  ⇒ `initAuthRoute()` 用新账号的 `permissions` 重跑 `filterAuthRoutesByPermission` ⇒ 菜单按权限重建。

**3. 明确不动**

`filterAuthRoutesByPermission`、`v-auth` 指令、`useAuth().hasAuth`、子模块 tab、后端 —— 本轮一律不动。

## 三、验证

手动冒烟（超管 ⇄ 操作员双向）：

1. 超管登录 → 菜单全量；
2. 退出登录 → 跳登录页、token 清空、dev 控制台无 `$reset` 报错；
3. 操作员登录 → 侧栏只剩操作员角色被勾选的菜单项，且父目录无空目录残留；
4. F5 刷新 → 菜单一致（走 `initUserInfo` + 本地缓存路径）；
5. 再换回超管 → 菜单恢复全量（验证反向不残留）。
