# 阿里巴巴普惠体字体子集化（自动提取项目文字生成 woff2）

## 背景与诉求

- 项目要求全站使用**阿里巴巴普惠体**（免费商用）。
- 用户反馈：普惠体全字库太大、**系统加载很慢**。

## 问题定位

- 中文字体**不引入就不会加载**；一旦把全量字库挂到全局 `html/body`，任何页面首次渲染文字都会强制下载完整字体（普惠体单字重 9~16MB），这就是"加载慢"的根因。
- 中文字体 Web 化只有两条路，本项目语境下的取舍：

| 方案                                         | 体积                                       | 覆盖                             | 结论                         |
| -------------------------------------------- | ------------------------------------------ | -------------------------------- | ---------------------------- |
| unicode-range 全量分包（cn-font-split 默认） | 产物=全字库 8~16MB，但浏览器按分片按需下载 | 全覆盖，含动态数据               | 产物体积过大，用户明确不接受 |
| **真子集（只保留会用到的字）**               | **几百 KB**                                | 只覆盖收录字符，缺字回退系统字体 | **采用**                     |

## 方案：自动提取项目文字 + 真子集化

### 1. 字符提取脚本

`scripts/font/extract-i18n-charset.mjs`（零依赖 Node ESM，改文案后重跑即可）

- 扫描范围：`views` / `components` / `layouts` / `locales/langs` / `constants` / `typings` / `router` / `store` 下的 `.ts`、`.vue`；**跳过 `src/service`**（内含 DEV mock 假数据，避免污染字符表）。
- 提取规则：CJK 汉字 + CJK/全角标点 + 中文常用符号，叠加 ASCII 可打印字符（0x20~0x7E）保证英数/半角标点同字体显示。
- 输出：单行无分隔字符表，可直接喂给子集化工具。

### 2. 两个提取范围的实测对比

| 范围                           | 唯一汉字 | 字符表总数（含 ASCII） | 产物                                   |
| ------------------------------ | -------- | ---------------------- | -------------------------------------- |
| 仅 i18n（`src/locales/langs`） | 478      | 582                    | `src/assets/fonts/zh-i18n-charset.txt` |
| **整站静态文字（采用）**       | **765**  | **875**                | `src/assets/fonts/zh-web-charset.txt`  |

结论：多出来的 287 字正是 `views`/`components`/`layouts` 里**未走 i18n 的硬编码中文**。只用 i18n 子集会导致"菜单是普惠体、某几个按钮却是雅黑"的割裂；而体积代价仅几十 KB，因此采用整站静态字集。

### 3. 子集化生成

- 源文件：`src/assets/fonts/source/Alibaba-PuHuiTi.otf`（6.53MB，从兄弟项目 `user-web/src/assets/fonts/AlibabaPuHuiTi/` 复制而来）。
- 工具：**Python fonttools 的 `pyftsubset`**（业界标准真子集化，支持 otf→woff2）。
  - 曾安装 `cn-font-split@7.4.3`，但其 `subsets` 参数是"手动分包范围"而非"丢弃其余字符"，不做真子集，故**未采用**（可考虑移除该依赖）。

生成命令：

```bash
python -m fontTools.subset src/assets/fonts/source/Alibaba-PuHuiTi.otf \
  --text-file=src/assets/fonts/zh-web-charset.txt \
  --flavor=woff2 \
  --output-file=src/assets/fonts/AlibabaPuHuiTi-subset.woff2
```

### 4. 结果

| 项          | 值                                                             |
| ----------- | -------------------------------------------------------------- |
| 输出文件    | `src/assets/fonts/AlibabaPuHuiTi-subset.woff2`                 |
| 体积        | **119,372 字节（约 116.6 KB）**，源文件 6.53MB，**缩减约 98%** |
| font-family | `Alibaba PuHuiTi`                                              |
| subfamily   | `Regular`                                                      |
| glyph 数    | 917                                                            |

## 产物清单

- `scripts/font/extract-i18n-charset.mjs`：字符提取脚本
- `src/assets/fonts/zh-i18n-charset.txt`：仅 i18n 字符集（478 汉字，备用）
- `src/assets/fonts/zh-web-charset.txt`：整站静态字符集（765 汉字，**当前采用**）
- `src/assets/fonts/source/Alibaba-PuHuiTi.otf`：源字体（6.53MB，是否入库待定）
- `src/assets/fonts/AlibabaPuHuiTi-subset.woff2`：字体子集产物（116.6KB）

## 接入实施（2026-09-07 已完成）

- 设计：`docs/superpowers/specs/2026-09-07-alibaba-puhuiti-font-design.md`；实施计划：`docs/superpowers/plans/2026-09-07-alibaba-puhuiti-font.md`。
- 改动：
  1. 新增 `src/styles/css/font.css`：`@font-face`（`font-display: swap`）+ `--app-font-family` + `html:root` 覆盖 vxe 的 `--vxe-ui-font-family`。
  2. `src/styles/css/global.css`：顶部加 `@import './font.css';`。
  3. `src/styles/css/reset.css`：`html` 的 `font-family` 改为 `var(--app-font-family)`。
  4. `src/store/modules/theme/shared.ts`：`getNaiveTheme()` 的 `common` 加 `fontFamily: APP_FONT_FAMILY`（常量定义在同文件）。
  5. `.gitignore` 排除 `src/assets/fonts/source/`；移除未使用的依赖 `cn-font-split`。
- **关键坑**：只改 `reset.css` 不够。Naive UI 用自带默认字体栈（须改 `NConfigProvider` 的 `common.fontFamily`），vxe-table 自带 `:root { --vxe-ui-font-family }`（须在 `html:root` 覆盖），否则只有菜单变、表格和按钮不变。
- 验证结论：`pnpm typecheck` 通过；`pnpm lint` 0 error（仅 `link.vue` 2 个既有 warning）；`pnpm build:test` 成功，产物 `dist/assets/AlibabaPuHuiTi-subset-*.woff2` = 119,372 字节（带 hash，说明 Vite 正确解析字体资源）。
- 待用户执行：`pnpm dev` 后目视核对表格 / Naive 组件 / 菜单三处文字是否为普惠体，以及 Network 中 woff2 仅 116KB。

## 维护脚本（2026-09-07 新增）

改文案后**不会自动更新字体**，用下面的命令手动更新：

```bash
pnpm font:charset   # 只重新提取字符表 → src/assets/fonts/zh-web-charset.txt
pnpm font:build     # 一条龙：重新提取字符表 + 重新生成 woff2
```

- 脚本：`scripts/font/extract-i18n-charset.mjs`（提取）、`scripts/font/build-subset.mjs`（生成；自动探测 `python`/`python3` 调用 fontTools，缺少源字体或 python 时给出明确提示）。
- 前置：本机装了 Python 与 `fonttools`/`brotli`；源字体在 `src/assets/fonts/source/Alibaba-PuHuiTi.otf`。
- 不更新的后果：新增的字回退系统字体（不报错，仅个别字观感不一致）。
- 实测：`pnpm font:build` → 765 汉字、875 字符 → woff2 119,372 字节（116.6KB），与首次生成一致（幂等）。
