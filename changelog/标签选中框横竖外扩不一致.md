# 标签设计器选中/hover 框横竖外扩不一致

> 日期：2026-09-12　模块：`src/views/system-manage/label-designer`

## 现象

hover（1px dashed）/选中（2px solid，用户已自行改过样式）的 outline 框与元素边框之间的空隙，横向与竖向观感不一样。

## 根因

`outline-offset` 的外扩距离横竖本身完全一致（offset + 线宽），观感差来自两点叠加：

1. **扁宽元素**：同样 3px 外扩在高 8mm（约 30px）上占比 10%、在宽 40mm（约 150px）上仅 2%，视觉上「上下近、左右远」；
2. **画布 `scale(zoom)` 非整数缩放**：outline 亚像素渲染横竖独立舍入，可再差约 1px。

## 修复

hover 与选中框 `outline-offset` 2px → 0（贴元素边界）：没有外扩空隙，横竖观感完全一致，也顺便避免框线与元素边界之间出现「缝隙感」。缩放手柄位置不变。

`design-canvas.vue` 样式单点改动。

## 追加：描边横竖粗细不一致（scale 合成层栅格化）→ 改 CSS zoom 布局缩放

贴边后用户仍见「横向虚线比竖向粗」。根因升级：`transform: scale()` 是**合成层缩放**，非整数倍率下描边横向/纵向独立栅格化舍入，CSS 调 offset/线宽治不了本。修复两步：

1. **纸张缩放 `transform: scale(zoom)` → CSS `zoom` 属性**（布局级缩放，描边由布局引擎统一栅格化，横竖粗细一致，顺带缩放下文字/线条渲染更清晰）。兼容性确认：`onDrop` 坐标换算与 `mmPerPx`（`w / rect.width`）都基于 `getBoundingClientRect` 实际尺寸，zoom 下依然正确；pan 的 translate 在父级 transform 上不受影响；网格背景/手柄/文字随布局缩放行为不变。
2. **描边线宽按 zoom 补偿**：viewport 绑定 `--canvas-zoom` 变量，hover/选中 outline 线宽 `calc(1px / var(--canvas-zoom))` / `calc(2px / var(--canvas-zoom))` → 任意缩放下描边恒为 1/2 设备像素。

`pnpm typecheck` 通过。手测点：拖拽/缩放元素落点、滚轮缩放、平移、右键菜单位置。
