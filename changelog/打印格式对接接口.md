# 打印格式对接后端接口

> 2026-09-17。用户贴出 wms-user `PrintTemplateSchema`（`lib/common/models/print-template.js`）：「这是打印格式字段，帮我对接接口」。
> 目标：把「系统设置 → 打印格式」模块从**前端内存 mock** 换成 wms-user **真实接口**，涉及 3 个使用点：打印格式列表页、自研标签设计器（label-designer）、hiprint 打印设计（print-design，后两者读写同一份模板数据）。

## 一、后端接口事实（读 wms-user 源码核对）

路由前缀 `/tms/api/v1/web`（与前端 `.env.test` 的 `VITE_SERVICE_BASE_URL` 一致），实现文件 `lib/api-v1-web/print-template/index.js` + `lib/services/print-template.js`。

| 接口                               | 必填（validate）                                                 | 服务端行为                                                                                                                                                                                       |
| ---------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /print-template/query`       | 无                                                               | `where.templateType` 过滤、`keyword` 按 name 模糊（keywordFields:['name']）、`page/size` 分页；返回 `ret:{list,total}`；列表默认 **omit** `design/infoList/fieldList/barcodeList/subBarcodeList` |
| `POST /print-template/get`         | 无                                                               | `{_id}` 取单条完整文档（含 design）；未找到抛「打印格式不存在」                                                                                                                                  |
| `POST /print-template/create`      | `name`、`templateType`、`templateMode`、`sizeType`               | `setSize`（sizeType≠5 时按固定尺寸回填 width/height）；`setDefault`（isDefault=1 时同 templateType 其他记录清 0）；name **全局唯一**（重名报「打印格式已存在」）                                 |
| `POST /print-template/copy/create` | `copyId`、`pdfTemplate{name,templateType,templateMode,sizeType}` | 从 copyId 原模板复制 `design` 给新模板，再 setGenerate/setSize/setDefault/create                                                                                                                 |
| `POST /print-template/update`      | `_id`、`templateType`、`templateMode`、`sizeType`                | `setSize` → `setGenerate`（design 非空时 `generate=1` 且 `width=design.width, height=design.height`）→ `setDefault` → 更新；name 变化时才做唯一校验（自身不误报）                                |
| `POST /print-template/delete`      | `_id`                                                            | **仅单条删除**（无批量接口）                                                                                                                                                                     |

其它事实：

- `_id` 为 36 位字符串（`validate._id` minLength=maxLength=36）；`createDate/updateDate` 为毫秒时间戳。
- 固定尺寸表（后端 `sizeMap`）：`0=50×30`、`1=100×100`、`2=100×150`、`3=100×200`、`4=210×297(A4)`、`5=自定义（用 width/height）`。
- `templateType`：`0-收货标签 1-发货标签 2-派送标签 3-发货发票 4-派送发票 5-提单标签`（`define/1023-print-template.js`）。
- `templateMode`：`0-pdf 1-excel`。
- 设计器旧版式字段（`infoList/fieldList/barcodeList/subBarcodeList`）为本项目暂不用的旧版遗存，本次不涉及。

## 三、已确认的设计决策（四轮问答）

1. **分类口径**：改用后端 6 类（分类列、筛选、表单全部对齐 `templateType`）。
2. **表格列**：沿用现有 8 列结构（模板名称/分类/标签尺寸/是否默认/已生成标签/备注/最后编辑/编辑时间），只换数据源与字段映射。
3. **删除**：去掉勾选列与「批量删除」按钮，操作列新增单条「删除」（二次确认，调单条删除接口）。
4. **表单**：名称 + 分类（6 类）+ 模板格式（pdf/excel）+ 标签尺寸（选「自定义」时出现宽高输入，mm）+ 是否默认 + 备注。

## 四、实施设计（按文件）

### 1. `src/typings/api/print-format.d.ts` 重写

```ts
declare namespace Api {
  namespace PrintFormat {
    type TemplateType = 0 | 1 | 2 | 3 | 4 | 5; // 收货/发货/派送标签、发货/派送发票、提单标签
    type TemplateMode = 0 | 1;                  // pdf / excel
    type SizeType = 0 | 1 | 2 | 3 | 4 | 5;      // 50×30 … A4 / 自定义

    interface Template {
      _id: string;
      name: string;
      templateType: TemplateType;
      templateMode: TemplateMode;
      sizeType: SizeType;
      width?: number;
      height?: number;
      file?: string;
      fileUrl?: string;
      isDefault: Api.Common.EnableStatus;
      generate?: 0 | 1;
      design?: Record<string, unknown> | string | null;
      note?: string;
      creatorId?: string; creator?: string;
      updateId?: string; updateBy?: string;
      createDate?: number; updateDate?: number;
    }

    type List = { list: Template[]; total: number };
    type SearchParams = { page: number; size: number; keyword?: string; where?: { templateType?: TemplateType } };
    type CreateParams = { name; templateType; templateMode; sizeType; width?; height?; isDefault; note? };
    type UpdateParams = CreateParams & { _id: string };
    type CopyParams = { copyId: string; pdfTemplate: Omit<CreateParams, 'isDefault' | 'note'> & {...} };
    type SaveDesignParams = { _id; templateType; templateMode; sizeType; design: Record<string, unknown>; width: number; height: number };
  }
}
```

## 五、风险与注意

- **DEV 直连真实后端**：删 mock 后本地开发需 wms-user 在线（同站点/日志），无降级 mock。
- **name 全局唯一**：重名由后端报错，request 拦截器统一弹「打印格式已存在」。
- **同一个 design 字段承载两种设计器 JSON**（自研格式 / hiprint 格式）：同一模板只用一种设计器打开，读取侧做兼容即可；自研设计器只认 `paper/elements` 结构，顶层多余键无影响。
- **设计器换纸张后保存会同步 sizeType**（尺寸反查：命中固定表 → 0-4，否则 5 + 宽高），与后端 setSize 行为一致。
- **`updateDate` 毫秒** 需 dayjs 格式化，列表别直接渲染数字。
- 本次不动 elegant 路由、不动菜单、不动 `components.d.ts`；i18n 无新增键。
