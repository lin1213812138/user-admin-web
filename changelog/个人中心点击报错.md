# 个人中心点击报错（No match for {"name":"personal-center"}）

## 现象

侧栏头像下拉菜单点击「个人中心」报错：

```
Uncaught (in promise) Error: No match for
 {"name":"personal-center","params":{}}
    at createRouterError (vue-router.js)
    at ...routerPushByKey (router.ts)
    at handleDropdown (user-avatar.vue:71)
```

仅**非超管且无 `system:personalCenter:list` 权限**的用户复现；超管正常。

## 定位（纯定位即结论）

根因 = 个人中心路由被错误地挂了权限码 `system:personalCenter:list`。

链路：

1. `build/plugins/router.ts` 的 `routePermissions` 把 `personal-center` 映射成 `system:personalCenter:list`，经 elegant-router 生成进 `src/router/elegant/routes.ts` 的 `meta.permission`。
2. 静态路由模式下，`store/modules/route/index.ts` 的 `initStaticAuthRoute()` 对非超管用户调用 `filterAuthRoutesByPermission(routes, permissions)`（`shared.ts`）：**有 `meta.permission` 且不在用户权限集的路由被整体剔除，根本不 `addRoute` 进 vue-router**。
3. `user-avatar.vue` 的下拉菜单「个人中心」对所有登录用户都渲染（`DropdownKey` 写死），点击走 `routerPushByKey('personal-center')` → 路由表里根本没有这条命名路由 → vue-router 抛 `No match`。

个人中心是用户自助页，本应任何登录用户都能进（页面内部用 `editInfoCtrl` 控制可编辑字段、修改密码整块灰显「后端未开放」），路由层不该按 `system:personalCenter:list` 过滤。

## 方案（已实施）

- `build/plugins/router.ts`：从 `routePermissions` 删除 `'personal-center': 'system:personalCenter:list'`（源文件，注释说明个人中心故意不设权限门禁）。
- `src/router/elegant/routes.ts`：同步删除已生成路由 `personal-center` 的 `permission: 'system:personalCenter:list'`（否则重新 `pnpm dev`/`gen-route` 前线上仍是带权限的旧生成物）。

两点都改是因为 `routes.ts` 是工具自动生成、下次 `pnpm gen-route` 会以 `build/plugins/router.ts` 为源重生成，只改一处会被覆盖还原。

## 边界

- `menu-permissions.ts` 的 `MENU_PERMISSION_TREE` 仍保留 `system:personalCenter:list` 码，仅是无路由引用的孤立权限码，**不影响功能**（角色权限树里勾了也不会被任何路由消费）；为降低改动面未删除。
- 非超管用户现在能进入个人中心，但页面本身对不可编辑字段（无 `editInfoCtrl`）仍是只读/灰显，符合既有设计。
- DEV 下 `filterAuthRoutesByPermission` 会对「无 meta.permission 的叶子路由」打 `[permission] route "personal-center" has no meta.permission, allowed by default.` 的 console.warn，属预期提示（个人中心是故意公开），非错误。

## 验证

- `read_lints` 两个改动文件 0 报错。
- 后续建议：`pnpm typecheck && pnpm lint && pnpm build`；用无 `system:personalCenter:list` 权限的非超管账号登录，点击头像下拉「个人中心」应正常跳转、console 不再抛 No match。
