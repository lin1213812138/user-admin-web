# 标签预览弹窗不限制宽度

- 日期：2026-09-09
- 关联：[标签打印模板设计器实现](../changelog/%E6%A0%87%E7%AD%BE%E6%89%93%E5%8D%B0%E6%A8%A1%E6%9D%BF%E8%AE%BE%E8%AE%A1%E5%99%A8%E5%AE%9E%E7%8E%B0.md)

## 背景

设计器「预览」弹窗（`src/views/system-manage/print-design/modules/preview-modal.vue`）的 `NModal` 写死了 `class="w-800px"`，导致预览的标签被强制限制在 800px 宽内，较宽标签会被挤压/缩放。用户要求标签预览也不限制宽度，按实际尺寸完整显示。

## 修改

- 移除 `NModal` 的 `class="w-800px"` 固定宽度。
- 改为 `:style="{ width: 'auto', maxWidth: '95vw' }"`，让弹窗按预览内容自适应宽度，同时用 `maxWidth: 95vw` 防止超出视口。
- **关键修复（尺寸）**：原 `fitFrameHeight` 只测高度、iframe 仍用 `w-full` 填满父级，不会反向撑开弹窗。改为 `fitFrameSize`，加载后读取 iframe 内部 `.hiprint-printPaper` 元素的实际 `getBoundingClientRect()` 尺寸，同时设置 iframe 的 `width` 和 `height`，让外层容器自然撑开弹窗到标签真实大小。无 `.hiprint-printPaper` 时兜底取 body 尺寸。
- iframe 移除 `w-full` class（宽度由 JS 动态控制）。
- 预览容器保留 `min-w-400px` 保底，避免弹窗过窄。

## 修复：预览内容与画布不一致

- **根因**：`handlePreview()` 创建预览用的 `PrintTemplate` 时未传 `dataMode: 1`，而设计器实例创建时带了该参数（`use-hiprint.ts` 第 154 行）。`dataMode` 控制 hiprint 如何渲染字段数据，两实例模式不同导致同一份 JSON 渲染结果不一致（如显示字段名而非示例值、或丢失绑定数据）。
- **修复**：预览模板创建时补上 `dataMode: 1`，与设计器保持一致。

## 修复：预览元素位置偏移（最终方案）

- **尝试 1（失败）**：补 `dataMode: 1` → 内容一致但位置仍偏移。
- **尝试 2（失败）**：补 `setPaper()` → 位置仍偏移。
- **根因分析**：`getJson()` → 新建 `PrintTemplate` → `getHtml()` 这个 round-trip 路径本身就会导致状态丢失或坐标变换。hiprint 的 JSON 序列化/反序列化可能不完整保留设计器实例的内部状态（如元素实际像素位置、缩放后的坐标等），新模板反序列化后重新布局，导致位置与画布不一致。
- **最终修复**：**彻底放弃新建模板**，直接用设计器实例 `templateRef.value.getHtml()` 生成预览 HTML。完全绕开 `getJson()` round-trip，预览内容与画布 100% 一致。设计态多余 UI（拖拽手柄、选中框、resize 控件等）通过在预览文档内注入 CSS 隐藏。

## 修复：预览未显示最新编辑的数据

- **现象**：用设计器实例直接 `getHtml()` 后，预览仍不显示刚在属性面板里改的内容（文字/字体/绑定字段等）。
- **根因**：在属性面板改完直接点预览按钮时，当前聚焦的输入框未失焦，hiprint 的 `change` 提交未触发，内部模型仍是旧值；且点击按钮存在 DOM/模型同步时序差，`getHtml()` 读到的是旧状态。
- **修复**：`handlePreview` 改为 `async`，生成预览前先 `(document.activeElement)?.blur()` 强制提交，再 `await nextTick()` + `setTimeout(0)` 等一拍，确保模型与画布同步后再 `getHtml()`。
