# 承运网络选择计泡规则自动带出材积除/计泡比率

> 日期：2026-09-19 ｜ 状态：已实施 ｜ 模块：`data-manage/ship/modules/carrier`

## 背景

用户（附后端 `CarrierSchema`）：新增承运网络时，「材积除」（`cubicNum`）与「计泡比率」（`weightOff`）应从所选「关联计泡规则」（`weightRuleId`）带出来，而非手工输入。

计泡规则（`WeightRule`）与承运网络（`Carrier`）两模型均有 `cubicNum` / `weightOff` 字段，取规则值回填即可。

## 实施

- `carrier/Carrier.vue`：`loadWeightRuleOptions` 构建下拉时附带 `cubicNum` / `weightOff`（options 类型扩为 `{ label, value, cubicNum?, weightOff? }[]`）。
- `carrier/CarrierOperateDrawer.vue`：
  - prop `weightRuleOptions` 类型同步扩展；
  - `weightRuleId` select 挂 `onUpdate: handleWeightRuleChange`——按 value 反查选项，把 `cubicNum` / `weightOff` 写入 `formModel`（字段仍可手动修改）。

## 行为约定

- 每次选中计泡规则即以该规则值**全量同步** `cubicNum` / `weightOff`：规则已配置则带出，**未配置则清空**（避免残留上一规则带出的值，用户反馈修复）。
- 清空选择（value=null）不动已填值（用户可能已手改，不覆盖）。
- 编辑态回填走 `openEdit(row)` 原值，不触发重算。
- 回填后用户可再手动覆盖，以用户改后值为准提交。

## 关键修复（NInputNumber 清空失效）

- 根因：`NInputNumber` 的空值语义是 `null`；原实现未配置时把 `cubicNum/weightOff` 写成 `undefined`，naive-ui 在「有值 → undefined」时不刷新显示，导致切换规则后残留上一规则的值。
- 修复：`handleWeightRuleChange` 未配置项写 `null`（`rule.cubicNum ?? null`）；`formModel` 局部类型放宽到 `number | null`；提交前 `payload` 将 `null` 归一为 `undefined` 以保住既有字段契约（后端口径 `number | undefined`）。
