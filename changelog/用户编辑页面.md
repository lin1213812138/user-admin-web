# 用户编辑页面

> 2026-09-17 · 用户贴参考系统截图「用户编辑新加个文件，按照这个」：参考图 = 顶部「基本信息」卡片（账号/角色/创建人时间/名称/站点/更新人时间/状态/组别）+ 顶部横向 tabs（个人档案/配置权限/关联客户/账号配置），个人档案 tab 为字段详情展示。

## 需求澄清（用户逐项确认）

| 决策点       | 用户拍板                                                                                                                                                                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入口方式     | **仅编辑跳页面**：列表点「编辑」跳新页面，新增仍用现有 `user-operate-drawer.vue` 抽屉，详情列点击维持抽屉详情                                                                                                                         |

| 账号配置 tab | **留空占位**——参考截图的「登录控制/通知配置」字段（登录电脑控制/设备授权/微信通知/通知模块/微信UnionID/微信服务号Openid）在 tms-user `UserSchema` 里**均不存在**（仅 `openId`），mongoose strict 模式下提交会被丢弃，等后端支持后再做 |
| 关联客户 tab | **去掉**（后端 `/customer/query` 支持 `userId` 按 salesmanId/serviceId/cashierId 过滤，能力在但本期不要）                                                                                                                             |

## 后端事实（tms-user，零改动）

- `UserSchema`（`lib/common/models/user.js`）：account/name/siteId/roleIds/groupIds/fullName/sex/birthday/idCard/address/phone/email/wx/contact/job/entryDate/qrCodeUrl/file/fileUrl/openId/note/status/accountType/creator(creatorId)/updateBy(updateId)/createDate/updateDate。
- `/user/get` 返回全字段并 fillName 回填 site/group/role 名称；`/user/update` 仅 `_id` 必填，assign(body) 后 strict 丢弃未声明字段。
- User schema **没有** 截图「登录控制/通知配置」相关字段（全局搜 `登录电脑|设备授权|通知模块|微信通知|notify|device|unionId` 零命中）。

## 设计（方案 A，用户确认「可以」）

- **路由**：`views/system-manage/user-edit/index.vue` → RouteKey `system-manage_user-edit`，**query 传 id**（`routerPushByKey('system-manage_user-edit', { query: { id } })`）。弃 params 动态路由 `[id].vue`：elegant-router params 路由项目无先例、生成规则未验证，query 有系统设置 `?tab=` 先例。
- **页面结构**（对齐截图）：`NCard` 基本信息只读区（`NDescriptions` 3 列：账号/角色/创建、名称/站点/最后更新、状态 NTag/组别）+ 顶部横向 `NTabs`（个人档案/配置权限/账号配置）+ `defineAsyncComponent` + `:key` 重建（系统设置页范式，无 KeepAlive）。
- **个人档案**（`modules/profile/Profile.vue`）：FormWrap 3 列 12 字段 = 姓名/电话/职位、性别/微信/入职时间、出生日期/邮箱/附件、地址/其它联系方式/备注（全部复用 `page.manage.user.*` 现有 i18n key；**不含**身份证/微信二维码——截图没有）。props 收 `user`，watch 回填（日期转 `YYYY-MM-DD`），提交 `fetchUpdateUser({ _id, ...12 档案字段 })`（不动 account/siteId/roleIds/groupIds/status），成功 `emit('saved')` → 壳重新 `fetchGetUser` 刷新卡片「最后更新」。
- **空占位**（`modules/perm|account`）：`NEmpty` + `common.lookForward`。
- **路由插件**：`build/plugins/router.ts` 的 `hideInMenuRoutes` 加 `system-manage_user-edit`、`menuActiveKeys` 加 `'system-manage_user-edit': 'system-manage_user'`（编辑页点亮「用户管理」菜单）。
- **i18n 三处**：`route.system-manage_user-edit`（用户编辑/User Edit）+ `page.manage.user.editPage.{tabPerm,tabAccount,back,save}`（配置权限/账号配置/返回/保存）+ `typings/app.d.ts` I18n Schema 同步。
- **返回**：壳顶部「返回」按钮 → `routerPushByKey('system-manage_user')`；id 缺失或 `/user/get` 失败 → NEmpty + 返回按钮。

## 同日调整：独立路由页 → 侧滑抽屉（用户纠正「不是单独的界面是侧滑弹窗」）

- **撤销路由页方案**：删除 `views/system-manage/user-edit/` 整目录（4 文件）；还原 `build/plugins/router.ts`（hideInMenuRoutes/menuActiveKeys 移除 user-edit）；i18n 删 `route.system-manage_user-edit` 与 `editPage.back`；`pnpm dev` 重新生成后 `routes.ts`/`elegant-router.d.ts` 已无 user-edit 条目。
- **抽屉实现**：新增 `views/system-manage/user/modules/user-edit-drawer.vue`（挂既有 `UserDrawer` 公共组件，width 70%、`footer=false`——保存按钮在档案 tab 内部）+ `modules/edit/{Profile,Perm,Account}.vue`（内容自路由页版本平移，`edit` 子目录无 index.vue 不会被 elegant 扫描）。
- **交互**：列表「编辑」→ `handleEdit` 打开抽屉（独立 `editVisible/editRow`，与 `UserOperateDrawer` 的 create/detail 分离）；抽屉内打开即 `/user/get` 拉全量、重置到个人档案 tab；Profile 保存成功 → 抽屉刷新用户（更新卡片「最后更新」）+ `emit('submitted')` → 列表 `getData()`。
- **验证**：typecheck 0 / lint 0 error（link.vue 2 条既有 warning）/ fmt / read_lints 0；未跑 playwright。

## 同日调整 2：基本信息卡片改可编辑（用户贴实拍「做成这样是不想让我修改吗？」）

- **问题**：第一版抽屉把基本信息做成只读 `NDescriptions`（账号/名称/角色/站点/状态/组别都不能改），用户期望这些字段可直接编辑。
- **调整**：新增 `modules/edit/BasicInfo.vue` —— FormWrap 3 列可编辑表单（account 必填 / roleIds 多选 custom / name 必填 / siteId 必填 / status / groupIds 多选 custom），「创建」「最后更新」两格保持只读 custom 纯文本（formatOperator）；布局对齐参考稿（账号/角色/创建、名称/站点/最后更新、状态/组别）。
- **提交统一**：Profile 去掉内部保存按钮改为 `defineExpose({ validate, collect })`，抽屉底部 footer 统一「确认」→ `handleSubmit` 先取 `basic/profile` 的 collect 判空、再 `Promise.all` 校验两表单，一次 `fetchUpdateUser({ _id, ...basic, ...profile })`（全量覆盖语义），成功关抽屉 + `emit('submitted')` 刷列表；`editPage.save` key 删除。
- **坑**：① `profileRef` 原在 `v-for` NTabPane 内会被收集成数组 → 改显式三个 NTabPane ② 档案 tab 需 `display-directive="show"`（切走保留实例，否则在其它 tab 点保存校验拿不到组件静默失败）③ `...ref.value?.collect()` 展开后字段全变可选（TS2332）→ 先取值判空再展开。
