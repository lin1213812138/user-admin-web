# 收货渠道抽屉「渠道备注」并入基本信息

> 日期：2026-09-20 ｜ 状态：已实施（待手动冒烟）
> 页面：渠道报价 / 收货渠道（`src/views/channel-quote/receive/modules/channel-operate-drawer.vue`）
> spec：`docs/superpowers/specs/2026-09-20-收货渠道抽屉渠道备注并入基本信息-design.md`（✅ 已确认，方案 A）

## 1. 需求（用户截图 + 原话）

截图 = 抽屉底部：`▎渠道备注`（分区标题）紧接着又是「渠道备注」（`NFormItem` label）+ textarea。用户原话：**「这个也合并进去」**（与上一轮把「承运物品类别」塞进「基本信息」末行同口径）。

## 2. 现状

`formItems` 顺序为 `section-basic` → …（3 列 × 8 栅格字段 + `productGroupIds` 整行）→ `section-note` → `note`。
重复来源：分区标题 `section-note` 的文案与字段 `note` 的 label 同取 `page.channelQuote.receive.note`，渲染成上下两行同名标题。

## 3. 决策（用户确认：回复「可以」）

| #          | 结论                                                                          |
| ---------- | ----------------------------------------------------------------------------- |
| Q1         | 采用**方案 A**：删除 `section-note` 分区标题，`note` 字段并入「基本信息」区块 |
| Q2         | `note` 保持 `span: 24` + `rows: 3`，不改尺寸                                  |
| 备选 B / C | B = 保留分区标题 + `showLabel: false`；C = 不动 —— 均未采用                   |

## 4. 实施

- 删除 `formItems` 中的 `{ key: 'section-note', label: $t('page.channelQuote.receive.note'), type: 'section', span: 24 }` 一项；
- `note` 项本体不动（label「渠道备注」/ textarea / span 24 / rows 3），位置紧随 `productGroupIds` 之后；
- 同步修正上方区块注释为「单区块『基本信息』：3 列 × 8 栅格 + 整行的承运物品类别 / 渠道备注」。

结果：抽屉只剩一个「基本信息」区块 —— 字段顺序 `… 渠道标签 / 承运物品类别 / 渠道备注`，「渠道备注」只以 textarea 的 label 出现一次。

## 5. 边界

- 不改字段顺序（除删掉分区标题）、不改校验 / 提交 / `payload`；
- 不动「基本信息」其它项与上一轮的「承运物品类别」；
- 不改 `FormWrap` 本体、不改 i18n key（`page.channelQuote.receive.note` 继续被 `note` 复用，未成孤儿）。

## 6. 验证

- `pnpm typecheck` ✅ 0 error；`pnpm lint` ✅ 0 error（`components/common/link.vue` 2 条历史 warning 无关）；`oxfmt` ✅。
- 冒烟（待用户）：新增 / 编辑 / 详情三种模式打开抽屉 → 「渠道备注」只出现一次 → 文案与回填内容不变 → 提交后备注仍正确保存。
