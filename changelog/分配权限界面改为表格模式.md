# 分配权限界面改为表格模式

日期：2026-09-05
范围：`角色管理 → 分配权限` 抽屉（`views/system-manage/role/modules/role-permission-drawer.vue`）
状态：**已实现，待浏览器手测**

## 1. 背景与目标

现状：分配权限是一个 480px 宽的 `NDrawer`，内部用 `NTree`（`checkable cascade check-strategy="all"`）勾选菜单，只能看到菜单名称，无法看到菜单类型、路由地址、权限标识，也无法搜索。

目标：把 `NTree` 换成**抽屉内嵌的 vxe 树形表格**，保留父子层级与展开/折叠，行首 checkbox 勾选，顶部提供全选与关键字搜索，抽屉加宽到约 900–960px。

用户需求确认（两轮澄清）：

1. 形态 = **抽屉内嵌树形表格**（不做独立路由页，不做摊平表格）。
2. 列数据 = **双接口拼接**（不改后端接口）。

## 2. 方案对比

| 方案                           | 做法                                                                                                                                        | 代价                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **A（选定）复用通用 `Table`**  | 抽屉里用 `Table` + `treeConfig`；给 `Table` 增加可选 `checkboxConfig` prop，并 `defineExpose` 出 `getCheckboxRecords` / `setAllCheckboxRow` | 通用组件多 2 个向后兼容的 API                                                 |
| B 抽屉内裸写 `vxe-table`       | 完全不动通用组件                                                                                                                            | 重复列渲染、溢出 tooltip、loading 样式；类型 Tag / 图标插槽要在抽屉里复制一份 |
| C 抽通用 `TreeCheckTable` 组件 | 通用化「可勾选树表」                                                                                                                        | 当前只有一个使用方，过度设计                                                  |

选 A：抽屉内的 loading（vxe 原生）、`show-overflow="tooltip"`、列插槽与菜单管理页保持同一套实现。

## 3. 详细设计

### 3.1 布局

- `CommonDrawer` 宽度由 `480` 改为 `min(72vw, 960px)`（`CommonDrawer` 的 `width` 已支持 string）。
- 抽屉内容区需要确定高度，vxe-table 的 `height="100%"` 才生效：内容根容器 `class="h-[calc(100vh-160px)] flex-col"`（160px 约等于抽屉标题 + footer + padding）。
- 表格配置：`:pagination="null"`（菜单数量有限，不分页）、`show-seq=false`、`show-action=false`、`show-checkbox=true`、不传 `cacheKey`（抽屉内不做列持久化，也不显示列设置按钮）。
- `operation-left` 插槽放：**全选 / 取消全选**按钮 + 关键字搜索框（常驻 `NInput`，`clearable`，`placeholder` 新增 i18n key）。不使用 `SearchBar` 折叠搜索栏——抽屉空间宝贵，搜索常驻更好用。

### 3.2 取数（不走 `useVxeTable`）

`useVxeTable` 强绑定「单个 api + 分页」，本场景是两个接口 + 无分页，因此在抽屉内自行取数，只复用 `Table` 的渲染能力。

抽屉打开时（`watch props.show`）并发请求：

```
fetchGetRoleMenuTree(roleId)  ->  { menus, checkedMenuIds }   // 树结构与可分配范围的权威来源
fetchGetMenuList({})          ->  Menu[]                       // 仅用于补齐展示字段
```

合并规则：

1. `/system/menu/list` 生产环境返回**嵌套 children**（DEV mock 返回扁平 + parentId）→ 先递归拍平成 `Map<id, Menu>`，再按 id 补齐。
2. 递归遍历 `menus`，产出 `RoleMenuRow`：
   - `id` / `children` 来自 `RoleMenuNode`；
   - `title` 作为菜单名称的回退值；
   - `menuType` / `routePath` / `permission` / `icon` 从 Map 取，取不到则为 `undefined`，表格渲染 `-`。
3. **只展示 `role/menuTree` 里有的菜单**：若某菜单只存在于 `/system/menu/list` 而不在权限树中，忽略它（避免给角色分配权限树之外的菜单）。
4. 类型定义放抽屉组件内部：`interface RoleMenuRow extends Api.SystemManage.RoleMenuNode { ... }`，不污染全局 `typings/api`。

### 3.3 列定义

| 列       | 说明                                                                                       |
| -------- | ------------------------------------------------------------------------------------------ |
| 菜单名称 | `treeNode: true`（渲染缩进 + 展开箭头），`minWidth: 220`，自定义插槽渲染图标 + 名称        |
| 类型     | 目录 / 菜单 `NTag`，`width: 90`，居中；复用菜单页 `menuTypeTag` / `menuTypeLabel` 映射写法 |
| 路由地址 | `minWidth: 180`，溢出走表格默认 tooltip                                                    |
| 权限标识 | `minWidth: 180`                                                                            |

列数组类型直接手写 `VxeColumnRenderColumn[]`（从 `@/components/Table` 导入），不需要 `useVxeTable` 生成。

### 3.4 勾选与提交

- `Table` 新增 prop `checkboxConfig`，透传 `:checkbox-config`。抽屉传 `{ checkStrictly: false, checkField: 'checked' }`：
  - `checkStrictly: false` → 父子联动（勾父→子全选；子部分选→父半选），与原来 `NTree cascade` 语义一致；
  - `checkField: 'checked'` → 合并数据时按 `checkedMenuIds` 给行打 `checked: true` 完成回填。
- 全选按钮：`tableRef.value?.setAllCheckboxRow(true / false)`。
- 提交：`tableRef.value?.getCheckboxRecords().map(r => r.id)`，**含父节点 id**，与现有 `fetchAssignRoleMenu({ roleId, menuIds })` 入参语义一致，后端无需改动。
- `Table` 侧改动：`VxeExportableTable`（本地最小接口）补 `getCheckboxRecords` / `setAllCheckboxRow` 两个可选方法签名，并 `defineExpose` 出去；不影响既有导出能力。

### 3.5 搜索过滤

- `keyword` ref，命中字段：菜单名称 / 路由地址 / 权限标识，忽略大小写。
- 过滤结果保留：**命中节点的祖先链** + **命中节点自身及其完整子树**。
- 过滤**只筛引用、不重建行对象**，因此行上的 `checked` 字段天然保留，勾选态不受搜索影响。
- 树默认 `expandAll: true`（对齐原 `default-expand-all`）。

### 3.6 加载态与错误处理

- `loading` 传给 `Table`（vxe 原生 `:loading`，按项目约定**不包 `NSpin`**）。
- 两个接口用 `Promise.all` 并发；`role/menuTree` 失败 → `window.$message?.error` 并关闭抽屉。
- `/system/menu/list` 失败 → **不阻断**，仅三列显示 `-`（降级为「只显示菜单名称」的展示效果）。

### 3.7 国际化

- 复用菜单管理页已有文案：`page.manage.menu.menuName` / `type` / `catalog` / `menu` / `routePath` / `permission`。
- 复用通用文案：`common.selectAll` / `common.unselectAll`。
- **仅新增两个 key**：`page.manage.role.searchMenuPlaceholder`（`搜索菜单名称 / 路由地址 / 权限标识`）、`page.manage.role.loadMenuFailed`（权限树加载失败提示）。
- 按项目约定三处同步：`locales/langs/zh-cn.ts`、`locales/langs/en-us.ts`、`typings/app.d.ts` 的 `App.I18n.Schema`。

## 5. 风险与回退

- **风险**：`checkField` 与 `checkStrictly: false` 同时生效时的联动行为需实机验证（vxe-table 4.5 树表 checkbox）。
  **回退方案**：若联动不生效，改为抽屉内自维护 `Set<number>`：`@checkbox-change` 里手动同步父子节点，调用 `setCheckboxRow` 刷新，父节点半选态由自算结果写入行字段（`indeterminateField`）。
- **风险**：生产环境 `role/menuTree` 与 `menu/list` 的 id 是否同一空间未验证。
  **缓解**：以 `role/menuTree` 为权威，缺失字段显示 `-`，功能不受影响。
- **注意**：抽屉内不使用列设置 / 列缓存，避免在弹层里出现第二个弹窗层级。

## 7. 实现记录（2026-09-05）

按设计落地，实现过程中补充/调整的点：

1. **勾选权威集合 `checkedIds`**：勾选态不只依赖 vxe 内部状态。`@selection-change` 里做**增量同步**——只更新当前**可见行**的勾选，被关键字过滤掉的行原样保留。原因：搜索时表格数据被替换，vxe 内部勾选集只剩可见行，若整集覆盖会导致「搜索后提交丢权限」。
2. **视图重建时机**：`applyView()` 只在「加载完成」与「关键字变化」时调用，勾选时不重建，避免每次勾选都重置 vxe 展开态/滚动位置。行对象每次重建都是浅拷贝（`withChecked` 递归），不污染 `allRows`。
3. **菜单名称取值**：优先 `/system/menu/list` 的 `menuName`，取不到回退权限树的 `title`（写明在设计里的回退策略）。
4. **空 children → `undefined`**：mock 里存在 `children: []`，合并时转 `undefined`，否则 vxe 会给叶子渲染多余的展开箭头。
5. **加载失败处理**：`Promise.allSettled` 并发；权限树 rejected → 提示 `loadMenuFailed` 并关闭抽屉；菜单详情 rejected → 静默降级（Map 为空，三列显示 `-`）。
6. **UnoCSS arbitrary value**：`h-[calc(100vh_-_160px)]`，calc 的减号两侧空格在 Uno 里必须写成 `_`，否则 CSS 非法、高度失效。
7. **插槽参数改名**：单元格插槽统一写 `{ row: menuRow }`，避免 `vue/no-template-shadow` warning（同一 `<Table>` 上多个插槽都解构 `row` 会被判定遮蔽）。
8. 提交仍为 `fetchAssignRoleMenu({ roleId, menuIds: checkedIds })`，语义与原来完全一致（含父节点 id），后端无需改动。

校验结果：`pnpm typecheck` ✅、`pnpm lint` ✅（仅剩既有 `link.vue` 的 2 个 `vue/no-undef-properties` warning）、`pnpm fmt` ✅、`pnpm build` ✅（先 `Remove-Item -Recurse -Force dist` 绕开已知 shim 拦截）。
