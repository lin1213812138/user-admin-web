# 承运网络 · 同步渠道（侧滑抽屉）

> 日期：2026-09-20 ｜ 状态：已实施，待手动冒烟 ｜ spec：`docs/superpowers/specs/2026-09-20-承运网络同步渠道-design.md`

## 背景

用户给两张老系统截图 + 两条要求：

1. **承运网络加一列「同步渠道」，点击打开弹窗**（截图中该列位于「备注」之后、编辑/删除之前，列内是一个按钮）；
2. **弹窗原型「同步到物流渠道」**：顶部渠道类型单选（发货渠道 / 物流渠道）、中部渠道对照表格（渠道名称 + 原/新 五项对照，新值列带勾选框）、行内「移除」、底部取消 / 保存；
3. 追加口径「**物流渠道改成收货渠道**」——本仓库统一叫法为「收货渠道」，新代码不再出现「物流渠道」；
4. 第一版按 `NModal + NDataTable` 实现后被否，追加要求「**要使用表格组件不要乱写，统一布局，弹窗使用侧滑弹窗**」⇒ 改为 `CommonDrawer` 侧滑抽屉 + 项目通用 `Table` 组件，布局对齐 `RolePermissionDrawer`。

## 后端契约（tms-user 已就绪，零改动）

- 路由：`lib/api-v1-web/carrier/index.js` 的 `POST /carrier/sync`，validate = `_id` + `list`（对象数组）+ `channelType`（数字）。
- 服务：`lib/services/carrier.js#syncChannel`

```js
const { _id, list, channelType } = body;
const carrier = await this.findCheckById(_id);
const service = channelType ? channelOutService : channelService; // 1 → 发货渠道；0 → 收货渠道
const syncList = map(list, item => assign({ _id: item._id }, pick(carrier, item.fields)));
await service.updateMany(syncList);
```

要点：`list[i].fields` 是**字段名数组**，值由后端从该承运网络文档 `pick` 出来后批量更新到渠道 ⇒ 前端只需给出「同步哪些字段」。

- 可同步字段（已核 `lib/common/models/channel.js` 与 `channel-out.js`，两个模型**共有**）：
  `oilRate` 燃油费、`feeCustom` 报关费、`weightRuleId` 计泡规则、`remoteGroupId` 偏远。
- **计泡比 `weightOff` 渠道模型没有该字段**：渠道列表展示的「计泡比」来自其关联计泡规则的 `weightRule.weightOff`（后端 `fillName → weightContent` 回填为 `weightRuleName` / `weightRuleWeightOff`）。
  ⇒ 因此「新计泡比」列**不提供勾选框**（与截图一致），仅对照展示（取承运网络的 `weightOff`）；勾选「新计泡规则」后渠道计泡比会随新规则联动变化。

## 实施

### 1. 类型与接口

`src/typings/api/data-manage/ship.d.ts`（`DataManageShip` 命名空间）

- `CarrierSyncField`：`'oilRate' | 'feeCustom' | 'weightRuleId' | 'remoteGroupId'`
- `CarrierSyncParams`：`{ _id, channelType: 0 | 1, list: { _id, fields: CarrierSyncField[] }[] }`
- `CarrierSyncChannel`：同步抽屉渠道行（`name` + 四个可同步字段 + `weightRuleName / weightRuleWeightOff / remoteGroup` 等 fillName 回填字段）

`src/service/api/data-manage-ship/index.ts`

- 新增 `fetchSyncCarrierChannel(params)` → `POST /carrier/sync`

`src/service/api/channel-out/index.ts`

- `fetchGetChannelOutList` 增加可选 `scene` 入参（`scene=1` 触发后端 fillName 回填名称）；返回行类型由精简的 `ChannelOutOption` 扩展出 `ChannelOutRow`（补齐 `oilRate / feeCustom / weightRuleId / weightRuleName / weightRuleWeightOff / remoteGroupId / remoteGroup`）。
  扩展为超集，既有下拉调用（收货渠道抽屉的「绑定发货渠道」）零改动。

### 2. 抽屉组件（新增 `CarrierSyncDrawer.vue`）

- 形态：`CommonDrawer`（`width="min(94vw, 1280px)"`，内置 footer 取消 / 保存，`:confirm-text="$t('common.save')"`，`@submit="handleSave"`）。
- 布局：`<div class="h-[calc(100vh_-_160px)] flex-col">` 包 `Table`，与 `RolePermissionDrawer` 完全一致；
  - `#operation-left` 放渠道类型 `NRadioGroup`：发货渠道（`channelType=1`）/ 收货渠道（`channelType=0`，**默认**）；
  - `Table` 用 `:pagination="null"`（抽屉内全量）、`show-action` + `:action-width="80"` + `action-align="center"`；
  - 11 个数据列：渠道名称 + 原/新 五项对照（原值直接渲染预处理文本；新值四列用插槽渲染「`NCheckbox` + 值」，「新计泡比」为纯文本）；
  - `#action` 插槽 = 行内「移除」（`LButton type="error" text`）——仅从本次待同步列表剔除，**不删除渠道**，也不影响渠道原数据。
- 数据：打开时 `watch(() => props.show)` 重置为收货渠道并并行拉「渠道列表 + 偏远映射（缓存一次）」；
  - 收货渠道走 `fetchGetChannelList({ page: 1, size: 500 })`（service 已固定 `scene: 1`）；
  - 发货渠道走 `fetchGetChannelOutList({ page: 1, size: 500, scene: 1 })`；
  - 切换类型即重载列表并重建行（勾选与移除状态随之重置）。
- 展示口径：**原值空 → `--`，新值空 → `无`**（`common.none`）；数字 `0` 正常显示。
- 保存：`rows` → 过滤「未被移除且至少勾选一个字段」的行 → `{ _id, channelType, list }`；有效行数为 0 时警示「请先勾选需要同步的字段」并不发请求；请求失败保持抽屉打开，成功提示 `common.saveSuccess` 并关闭。

### 3. 列表入口（`Carrier.vue`）

- 模板新增 `#syncChannel` 插槽：`LButton type="primary" text` 文案「同步渠道」→ `handleSyncChannel(row)` 记录行 + 打开抽屉。

## 追加修正 2（表头列全选 ↔ 单元格勾选联动）

> 用户原话：「表头怎么漏了多选框而且没有进行联动，表格的多选框也要和内容的多选框进行联动的」（附图：红框圈出「新燃油费 / 新报关费 / 新计泡规则」三个列表头）

- 4 个可勾选字段列（新燃油费 / 新报关费 / 新计泡规则 / 新偏远）的表头改用 `headerSlot` 渲染「`NCheckbox` + 列标题」，与单元格内的字段勾选框双向联动：
  - 该列全部行勾选 → 表头勾选；部分勾选 → 表头半选（`indeterminate`）；全不勾 → 表头未勾；
  - 点表头 → 该字段在本抽屉所有渠道上全选 / 全不选（`toggleFieldAll`）；
- 汇总态用**单个 computed**（`fieldCheckState`）一次算完 4 个字段的 `checked / indeterminate`，避免在表头插槽里逐行 O(n) 遍历（500 行 × 4 列表头场景）；
- 「新计泡比」列单元格无勾选框，故表头也不加全选框（口径一致）；
- 复用 `Table` 组件既有的 `col.headerSlot` 机制（底层即 `vxe-column` 的 `#header` 插槽），未改表格组件与 vxe 配置。

## 追加修正 3（行勾选框 ↔ 行内字段勾选联动）

> 用户原话：「这里还没有联动」（附图：箭头从左侧行勾选框指向「新燃油费」等单元格勾选框）

- 左侧行勾选列由 vxe 内置的 `type="checkbox"` 列（`show-checkbox`）改为**自定义列** `rowCheck`：vxe 的行框只支持「勾 / 不勾」，无法表达「部分字段勾选」的行级半选；自定义列用 `NCheckbox`（`checked` + `indeterminate`）完全受控，与「表头列全选框」同一套机制。
- 双向口径：
  - 行内 4 个字段全勾 → 行框勾选；部分勾选 → 行框**半选**；全不勾 → 行框未勾（`rowCheckState`）；
  - 点行框 → 该行 4 个字段全选 / 全不选（`toggleRowAll`）。
- 表头行框 = 全表汇总（`rowAllState`：全表行均全勾 → 勾选，部分 → 半选），点击即全表全选 / 全不选（`toggleAllRows`）。
- 行勾选列 `fixed: 'left'`（对齐原 vxe 行选择列的固定行为）、宽度 50。
- 影响提示：抽屉工具栏的「批量删除」按钮（用户在 IDE 中所加的 UI，尚未接逻辑）原先若依赖 vxe 选中集合，其数据源应改为 `rows` 中「4 字段全勾」的行；如需把该按钮接成「批量移除选中行」，另行确认。

## 追加修正 4（新值与渠道原值不一致时标特别色）

> 用户原话：「如果这些新的和原来的不一样要标特别色」（附图：红框圈出「新燃油费 / 新报关费 / 新计泡规则 / 新计泡比 / 新偏远」五列）

- 逐行逐字段比较「承运网络新值 vs 渠道原值」，不一致时该「新」值文字标 **主色 + 中等字重**（`text-primary font-500`）；一致时维持默认色。只标新值单元格，不标原值列与表头。
- 比较口径：`normValue()` 先做空值归一（`null` / `undefined` / `''` 等价），再按字符串比较（数字与同值字符串等价）。
- 五列对照基准：
  - 新燃油费 ← `carrier.oilRate` vs 渠道 `oilRate`
  - 新报关费 ← `carrier.feeCustom` vs 渠道 `feeCustom`
  - 新计泡规则 ← `carrier.weightRuleId` vs 渠道 `weightRuleId`
  - 新计泡比 ← `carrier.weightOff` vs 渠道 `weightRuleWeightOff`（计泡比不可独立同步，仍对照提示）
  - 新偏远 ← `carrier.remoteGroupId` vs 渠道 `remoteGroupId`
- 差异标记在 `toRow()` 一次性算好（`SyncRow.changed`），模板只读布尔值，不做渲染期比较；`carrier` 为空时全部标记为 false，不会整表飘色。
