# 录单格式（系统设置 › 录单格式）接入真实接口

> 日期：2026-09-17
> 触发语：「先把录单格式的查询接口接上 … 其他的先不管」（附 tms-user OrderTemplate Schema）

## 1. 背景与现状

`views/system-manage/setting/modules/input-format/` 目前是**纯前端假数据**：`service/api/input-format/index.ts` 在 DEV 下返回内存 mockDb（10 条显式 + 30 条铺量），非 DEV 走自拟 URL `/input/format/*`（后端不存在）；类型 `Api.InputFormat.Format` 的字段（`scope` 适用范围 / `remark` / 数字 `id`）与后端 Schema 完全不匹配。

## 2. 后端事实核对（读源码 + 登录 192.168.2.105:15001 实测）

| 项              | 事实                                                                                                                                                                                                                                                                                   |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 接口            | `POST /order-template/{query,get,create,update,delete}`（前端 baseURL 已含 `/tms/api/v1/web`）                                                                                                                                                                                         |
| query           | body `{scene,page,size,where?,keyword?,keywordFields?}` → `ret:{list,total}`；`sort` 固定 `{order:1}`；模型 `omitFields:['fieldList']` ⇒ **列表不含 fieldList**；**不传 `scene` 时后端强制 `status=1` 且按角色 `user.orderTemplateIds` 过滤** ⇒ 管理端必须传 `scene` 才能看到停用/全部 |
| get             | `{_id}` → 完整文档（含 fieldList）；`check=1` 不存在直接报错                                                                                                                                                                                                                           |
| create / update | 路由 validate：create `name` 必填；update/delete `_id` 必须 36 位 uuid；服务端 `uniqField:'name'`（重名报错）；`isDefault=1` 时后端自动把其它记录 `isDefault` 清 0；创建人/修改人由 `processData` 中间件自动补（前端不用传，update 时还会剔除 creator/createDate）                     |
| delete          | 仅 `{_id}` 单条，**无批量删除接口**                                                                                                                                                                                                                                                    |
| fieldList 项    | 真实结构 `{label,key,fieldType,required,type?,keyMap?,options?,disabled?,renderName?,formatKey?,width?,precision?}`；**「显示」= 该项是否存在于 fieldList**（无 show 字段），`required` 0/1                                                                                            |
| fieldType 语义  | 0 运单信息 / 1 收件人信息 / 2 发件人信息 / 3 物品信息 / 4 子件信息（对齐 OJT `const.js` 的 `orderTypeFieldType`）                                                                                                                                                                      |
| 本地字段清单    | `modules/input-format/fields-config.ts`（116 项：order 52 / shipTo 16 / shipper 15 / product 20 / item 13）与真实字段**完全对齐无缺失**（order→0、shipTo→1、shipper→2、product→3、item→4）                                                                                             |
| 库内数据        | 仅 1 条：`系统默认`（`isDefault=1`、`status=1`、`fieldList` 53 项，其中 件数/实重/计费重 带 `disabled:true`）                                                                                                                                                                          |
| 搜索结果        | query **未配 `keywordFields`** ⇒ 直接传 `keyword` 搜不出东西；用户选择「先不做搜索」                                                                                                                                                                                                   |

## 3. 方案决策（三轮问答，用户逐项确认）

| #   | 决策点                | 结论                                                                                                                                                                        |
| --- | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 列表列映射            | 改为后端真实字段：格式名称(name) / 客户可用(customerEnable) / 是否默认(isDefault) / 排序(order) / 备注(note) / 状态(status)；**删掉「适用范围」列**                         |
| 2   | 名称搜索              | **先不做**，顶部搜索栏整块去掉（等后端补 keywordFields）                                                                                                                    |
| 3   | 写操作                | **也接真实接口**（create/update/delete + 编辑前 get 详情）                                                                                                                  |
| 4   | 字段映射（fieldList） | **接上**：保留 `FieldMapping` UI，字段清单换成 `fields-config.ts`（116 项/5 组）；保存时写真实 fieldList，原有项**保留 keyMap/options/disabled 等附加属性**，只改显示与必填 |
| 5   | 新建底稿              | 新建时以「是否默认」模板的 fieldList 为底稿拷贝（含原勾选状态），保证字段属性完整；库里无默认模板时降级为按 config 生成最小项                                               |
| 6   | 批量删除              | 去掉「批量删除」按钮（后端只有单条 delete）；勾选列保留                                                                                                                     |
| 7   | 内置保护              | `buildIn=1` 的行隐藏「删除」按钮                                                                                                                                            |
