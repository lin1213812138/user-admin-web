# 标签设计：点击元素后自动移到左上角

> 日期：2026-09-12
> 关联：[标签设计器拖动卡顿优化](./标签设计器拖动卡顿优化.md)（本次 bug 为该优化的回归）

## 现象

标签设计器中，元素已被选中后再次点击（或轻微挪动 ≤0.2mm），元素立刻飞到纸张左上角；点击画布空白处取消选中后，元素又回到原位。截图表现为：编辑时左上角出现一个带虚线选中框的元素副本，取消聚焦后原位元素恢复。

## 根因

「拖动卡顿优化方案 A」引入的 `onPointerUp`（`src/views/system-manage/label-designer/modules/use-canvas-interaction.ts`）在松手时**无条件清空**高频帧直写的内联样式键（`transform` / `width` / `height` / `left` / `top`），原注释假设「随后由 Vue patch 写回最终值」——该假设对纯点击不成立：

1. **纯点击**（位移 ≤0.2mm）时直接 `return`，不写 store → `elementStyle(el)` 输出不变 → Vue **不触发重渲染** → `patchStyle` 不会执行 → 被清空的 `left/top/width/height` 无人恢复。
2. absolute 元素失去 `left/top` 后停在静态占位点，即纸张左上角。
3. 点空白取消选中 → `selectElement(null)` → 画布重渲染 → `patchStyle` 重写全部样式键 → 元素回原位。
4. 真实拖动没事（`updateElement` 写 store 触发重渲染恢复样式），因此 bug 只在「已选中后再次点击/微动」时复现。

本质：Vue 3 的 `patchStyle` 只在组件重渲染且 style 对象引用变化时执行，**手动清空响应式管理的内联样式后，数据未变就不会有「随后」**。

## 修复（方案 A，用户确认）

仅改 `use-canvas-interaction.ts` 的 `onPointerUp`：

- 「真实拖动才写 store」由提前 `return` 改为 `if` 包裹（恢复样式对点击/拖动都要执行）；
- 清空合成类键（`transform` / `willChange`）后，**立即按 store 权威值恢复** `left/top/width/height`，且放在 `store.updateElement` 之后执行：
  - 纯点击：store 仍是原值 → 恢复原坐标，元素纹丝不动；
  - 真实拖动：store 已是最终值 → 恢复最终坐标，与后续 Vue patch 要写入的值完全一致，无冲突；
- 恢复值公式与 `design-canvas.vue` 的 `elementStyle` 保持一致（`mm × PX_PER_MM`）。

改动约 10 行，单文件，不触碰任何交互行为与性能优化路径。
