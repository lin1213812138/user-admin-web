# 标签设计面板拖拽未落纸回到原位动画

> 自研标签设计器（`label-designer`，非 hiprint 的 `print-design`）。
> 设计阶段遵循 AGENTS.md 规则 2（本机无 `brainstorming` skill，以等价的结构化设计 + 用户确认替代）：设计稿见下文「需求澄清」～「待确认」，**用户已确认方案 A、动画参数 260ms ease-in-out**；Q2 的回答是「画布内元素需要设置边界、不允许拖出标签」，故本次同时把画布 move 恢复为纸界钳制（见文末「实施结果」）。

## 需求澄清（用户截图）

用户截图为「从**左侧面板**（基础元素 / 业务字段）拖一项到灰色画布区域」，红色箭头终点在**纸张（标签）之外**。原话：

> 我说的是刚从这边拖出来的时候，没有拖到标签里面需要重新回到原来的位置的动画效果。

即需求是：

- 从左侧面板拖拽一项 → **落点在纸张内**：创建元素（现状不变）。
- 从左侧面板拖拽一项 → **落点在纸张外**（含灰底画布、右侧属性面板、工具栏、甚至拖回左侧面板）：**不创建元素**（现状已正确），但**被拖的那一项要以动画从松手位置平滑回到它在面板中的原始位置**。
- 现状：松手瞬间影子直接消失，没有任何回落过程。

## 与上一份文档的关系（认错记录）

[标签设计元素拖拽越界回到原位动画](./标签设计元素拖拽越界回到原位动画.md) 里实现的 `replayBack()` 是**画布内已有元素**拖出纸张后的回弹。用户本次澄清说明：那句「需要重新回到原来的位置的动画」原本指的就是**面板被拖项**，`replayBack` 属于认错需求后的产物。该行为是否保留见文末待确认第 2 项。

## 根因

1. **原生 HTML5 拖拽的「影子」（drag image）由浏览器绘制与销毁，JS 既拿不到也没法给它做动画。**
2. `design-canvas.vue` 的 `@drop="onDrop"` 落在整个灰色视口上，且 `onDrop()` 第一件事就是 `e.preventDefault()`（= 接受拖放），**即使落点在纸张外、后面直接 `return` 不创建元素，浏览器也认为「拖放已被接受」** → 松手时不是「拖拽被取消」，于是它**不会**播放任何回位动画，直接把影子抹掉 → 用户看到「松手直接消失」。
3. 顺带说明：这正是为什么在此之前无论怎么改画布元素的 CSS transition / rAF 补间都「没有任何区别」——那段代码与这条链路无关。

## 方案

### 方案 A（推荐）：松手瞬间接管成自定义幻影，再 FLIP 动画送回原位

- **拖拽过程完全不动浏览器原生影子**（跟手、半透明、尺寸零风险），只在 `dragover` 里记录指针位置。
- `dragstart`（`field-panel.vue`）：记录源项 DOM 与 `getBoundingClientRect()`、指针相对源项的抓取偏移。
- `dragend`：判定「本次没有创建元素」（共享标志位，画布 `onDrop` 成功创建时置位；`drop` 一定先于 `dragend` 触发）→
  - `sourceEl.cloneNode(true)` 造一份 `position: fixed; pointer-events: none; z-index` 极高的幻影，放到松手位置（尺寸/样式与源项一致，与原生影子交接在同一帧完成，无闪跳）；
  - 下一帧改成源项 rect 的位移（FLIP），用 **rAF 补间**逐帧插值 `transform: translate(±) scale(±)` 回到原位，随后移除。
- **动画实现方式用 rAF 补间而非 CSS transition**：本项目在画布回弹上已实测「内联 transition + 强制 reflow」不出动画（同目录文档记载），rAF 补间是已验证可行的路径，且与现有 `replayBack` 共用同一套时长/曲线常量，观感统一。
- **避免双重动画**：拖拽期间临时在 `document` 上挂 `dragover` / `drop` 监听，仅当 `dataTransfer.types` 含 `application/x-label` 时 `preventDefault()`（并保持 `dropEffect = 'copy'` 与 `effectAllowed` 一致）。这样**任何落点都被视为「拖放已接受」**，浏览器自己不会播放回位动画，回位动画的唯一来源是我们的幻影；同时也能覆盖「拖回左侧面板 / 落到工具栏」这类落点。
  - 监听只在本次拖拽期间存在，不影响应用内其它拖放（表格列拖拽等）。
- 落点在纸张内（创建成功）时，幻影做一次快速淡出（~120ms）后移除，避免与新建元素「双影」。
- ESC 取消拖拽同样走 `dragend` → 复用同一回落动画（附带收益）。
- 成本/风险：新增一个约 100 行的共享模块；需要保证幻影插入与原生影子销毁同帧。

### 方案 B：全程自绘拖拽影子（`setDragImage` 屏蔽原生影子）

用 1px 透明图把原生影子顶掉，自己用 `fixed` 元素跟手。优点是可做缩放/吸附高亮等增强；缺点是跟手精度、`zoom` 缩放层偏移、与 naive-ui hover 态交互都要自己兜，视觉回归风险明显高于 A。**本次不建议。**

### 方案 C：最小改动——只让面板里的源项自己抖动/回收一下

实现最省，但用户看到的是「面板里那格动了一下」，而不是「我拖的那张跟着手回到原位」，与诉求不符。仅作兜底。

## 涉及文件（按方案 A）

- 新增 `src/views/system-manage/label-designer/modules/drag-ghost.ts`：`startDragGhost(e, sourceEl)` / `markDragCreated()` / `endDragGhost()`。
- `modules/field-panel.vue`：`@dragstart` / `@dragend` 接上上述三个入口（现有 `onDragStart` 只写 payload，保留）。
- `modules/design-canvas.vue`：`onDrop()` 里 `store.addElement(...)` 两个成功分支调用 `markDragCreated()`。
- 无新增 i18n 文案（纯交互）。
- 回位动画参数建议与画布回弹统一：`260ms` + cubic ease-in-out（复用 `use-canvas-interaction.ts` 里已调好的常量，必要时抽到 `constant.ts`）。

## 验证方式

沿用本机已验证可行的帧级采样手段（`scripts/drag-probe.cjs` 同款 rAF 采样，系统 Chrome + 本机后端 `LINFLY/123` 登录），对三条路径分别采样幻影的 `transform` / `getBoundingClientRect()`，确认逐帧插值且终点与源项 rect 重合：

1. 落点在纸张内 → 创建元素 + 幻影快速淡出、无残留 DOM；
2. 落点在纸张外（灰底画布）→ 幻影逐帧回落且终点 == 源项 rect；
3. 拖回左侧面板 / 落到工具栏 → 同上；
4. 回归：连续两次拖拽、拖拽中 ESC、拖拽时源面板折叠态变化，均无幻影残留（验证 `dragend` 清理）。

## 待确认（用户已答复）

1. 方案 → **方案 A**。
2. 画布内已有元素拖出纸张 → **「画布内的需要设置边界，不允许拖出标签」** = 恢复纸界钳制（不是回弹，而是根本拖不出去）。
3. 动画参数 → **260ms cubic ease-in-out**。

## 实施结果

### 1. 面板拖拽未落纸回落动画（新增）

`modules/drag-ghost.ts`（新增，模块级单例，同一时刻只可能有一次拖拽）：

- `startDragGhost(e, sourceEl)`：`dragstart` 时记录源项元素、指针相对源项左上角的抓取偏移与指针位置；在 `document` 上以 **capture** 阶段临时挂 `dragover` / `drop`，并在 `window` 上以 capture 挂 `dragend`。选 capture 是因为拖放事件可能被内部 `stopPropagation` 截断，capture 阶段一定先收到。
- `onDocDragOver`：仅当 `dataTransfer.types` 含 `application/x-label` 时 `preventDefault()`（并保持 `dropEffect='copy'` 与 `effectAllowed` 一致）。**preventDefault 即「接受拖放」**，于是任何落点都不会触发浏览器自己的回位动画，回位动画的唯一来源是我们的幻影（避免双重动画）；顺带也让指针随时更新。
- `endDragGhost()`（`dragend` 触发）：摘掉所有临时监听 → `createGhost()` 用 `cloneNode(true)` 造同尺寸幻影、以 `position: fixed` 摆到「指针位置 − 抓取偏移」（与原生影子同帧交接，不闪）→
  - `created === true`（画布已创建元素）：幻影 ~120ms 淡出，避免与新建元素双影；
  - `created === false`（未落纸）：`flyBack()` 用 rAF 补间把幻影平移回源项原位后移除。
- `markDragCreated()`：画布 `onDrop()` 两个 `addElement` 成功分支调用（`drop` 一定早于 `dragend`）。
- 动画实现刻意用 **rAF 补间而非 CSS transition**：本项目在画布回弹上已实测「内联 transition + 强制 reflow」不出动画，rAF 是已验证路径；时间轴 0 点取**首个 rAF 帧的时间戳**（`performance.now()` 在 `dragend` 之后可能已跨过大半进度）。
- 曲线/时长抽到 `constant.ts`：`BACK_MS = 260` + `backRemain(t)`（cubic ease-in-out，返回**剩余比例** k∈[0,1]）。

`modules/field-panel.vue`：`onDragStart` 末尾接 `startDragGhost(e, e.currentTarget)`（基础元素与业务字段共用，两处都能回落）。

**踩坑（探针抓出来的）**：`backRemain` 返回的是「剩余比例」（1=起点），而幻影需要的是「已走完的比例」，第一版直接用了 `backRemain`，结果幻影在第二帧瞬间跳到面板原位、再**倒着**飘回落点后消失。改成 `1 - backRemain(t)` 后方向正确。这类反向错误肉眼容易误判成「动画在动」，必须靠逐帧采样定位。

### 2. 画布 move 恢复纸界钳制（推翻上一份文档的实现）

按用户 Q2 的答复，画布内元素**不允许被拖出纸张**：

- 恢复 `clampInPaper(geo, paperW, paperH)`：只动位置不改尺寸，`x ∈ [0, max(0, 纸界 - 元素尺寸)]`，元素本身比纸张大时上限退化为 0（贴左/上边）；与 resize 侧「上限取 max(原尺寸, 纸界余量)、不强制缩小」的约定一致。
- `applyFrame()` 的 move 分支走 `clampInPaper`（**预览与落库同源**，松手不跳变）；`resizeGeometry` 的纸界约束保持不变。
- **删除**上一份文档引入的整套越界回弹机制：`outAmount()`、`replayBack()`、`stopBack()`、`backRaf`/`backDom`、`BACK_MS`（迁到 `constant.ts` 供幻影回落使用）；`onPointerUp()` 回到「按 `lastGeo` 结算 + `movedEnough` 才快照/写库 + `settleDom()`」。
- 保留 `DragState.lastGeo`（松手结算取「最后一帧真正写进 DOM 的几何」，比用 `pointerup` 坐标重算更贴近用户所见，且 resize 的边手柄只改宽高时 `movedEnough` 也能正确判定）。
- 移除临时屏显徽标（`debugInfo`）与 `design-canvas.vue` 里对应的右下角小字。

## 遗留

- 幻影看起来与原生影子一致（克隆自源项），但原生影子在半透明/描边细节上由浏览器决定，交接瞬间可能有极轻微「实心化」；如需完全一致需走「方案 B 全程自绘」，本次不做。
- 拖拽期间不再有任何视觉越界提示（与本次需求无关）。
