# 资料管理新增「发货资料」

## 需求来源

用户贴思维导图截图："资料管理新增发货资料，有些可能是其他界面的可以直接移过来"。

导图结构：发货资料

- 服务商：发货服务商 / 派送服务商 / 提单服务商
- 渠道类别
- 计泡规则：按公斤 / 按方
- 承运网络

## 调研结论（前端无现成实现，后端接口全齐）

- 前端 `src/` 全文检索：服务商 / 渠道类别 / 计泡规则 / 承运网络的页面、service、类型**均不存在**；渠道报价（receive/ship）也未引用它们 ⇒ "从其他界面直接移过来"无可移代码，4 块全新建。
- 后端 tms-user 四组 CRUD 端点现成（`lib/api-v1-web/`）：
  - `/provider/*`：`providerType` 0-发货 1-派送 2-提单 **3-杂支**；name/code 唯一（`uniqField`）；query `keywordFields:['name']`、`sort:{code:1}`；delete 仅单 `_id`（连带删 apiConfig/channelOut）。
  - `/channel-group/*`：name / nameEn / order / note，**无 status 字段**。
  - `/weight-rule/*`：name / order / mode（0-件实重之和 1-件体积重之和 2-票总重和票总体积重取大值 3-件计费重之和）/ carryList 嵌套进位规则 / cubicNum 材积除 / weightOff 计泡比率 / note。
  - `/carrier/*`：name / weightRuleId / trackConfigId / remoteGroupId / order / oilRate / feeCustom / cubicNum / weightOff / note；另有 `/carrier/sync`（本页不做）。
  - 通用分页契约（`common.js queryCommon`）：`{ page, size, keyword, where }` → `{ list, total }`。
- 资料管理现有 18 张档案走通用网关 `/data-manage/:archive/*`（tms-user 无此端点、DEV 全 mock），与本次真实接口接入方式不同。

## 决策（用户逐项确认）

1. **挂载**：资料管理第 5 页，新建 `data-manage/ship` 路由页，左侧竖向 tab = 服务商 / 渠道类别 / 计泡规则 / 承运网络。
2. **服务商呈现**：1 个 tab，页内顶部 NRadioGroup（发货/派送/提单）切换 `where.providerType` 重查；杂支服务商(type 3)不在此页管理。
3. **计泡规则「按公斤 / 按方」**：不是分组维度，是新建/编辑表单内的**计算方式字段**；后端 weight-rule 模型目前无此字段，需新增（后端唯一改动）。
4. **字段范围**：四块按后端模型全量字段；承运网络的「关联追踪 trackConfigId」「关联偏远 remoteGroupId」因数据源页面不存在暂不提供下拉（字段保留在类型中不展示）；「关联计泡规则」下拉取本页计泡规则全量数据。
5. **实现路径**：用户拍板"**每个界面按照系统设置那样写**"——`index.vue` 壳（VerticalTabLayout + defineAsyncComponent + `:key` 重建，无 KeepAlive）+ `modules/<tab>/<Tab>.vue` 各自独立完整实现（useVxeTable + Drawer + NFormWrap），不搞 config 驱动通用组件（ShipArchive 方案与改造 MasterDataArchive 方案均未采纳）。不跟随系统设置的 `?tab=` query 同步（资料管理现有 4 页均无，保持组内一致）。
