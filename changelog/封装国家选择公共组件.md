# 封装国家选择公共组件（useCountrySelect）

- 日期：2026-09-18
- 触发：用户贴 FBA 仓库抽屉截图，要求封装国家选择公共组件，下拉项同时显示二字码（ISO alpha-2）。

## 现状与问题

- 项目中至少两处各自重复实现「调用 `/country/query` → 映射成 select 选项」：
  1. `views/data-manage/basic/modules/fba-warehouse/FbaWarehouseOperateDrawer.vue`：本地 `countryOptions`/`countryNameMap`/`loadCountryOptions`，`label` 仅用 `nameCn`，并额外维护 `_id → nameCn` 映射用于提交回填 `country`。
  2. `views/customer-manage/customer/modules/customer-detail/address-operate-drawer.vue`：同样本地加载，`label` 取 `name||nameCn||nameEn||code||_id`，`watch(countryId)` 反查回填 `model.country`。
- 下拉只显示名称，无法满足「同时展示二字码」诉求；逻辑重复、取值口径不一致。

## 澄清（brainstorming 4 问，全部采纳推荐）

1. 形态：组合式函数 Hook（`useCountrySelect`），适配 FormWrap 的 select 配置与裸 NSelect。
2. 选项显示：名称左对齐、二字码右对齐（naive `renderLabel`）。
3. 改造范围：一并替换上述两处，消除重复。
4. 取数：模块级单例缓存，整个会话只请求一次 `/country/query`。

## 设计要点

- 新增 `src/hooks/business/use-country-select.ts`：导出 `useCountrySelect()`，返回 `options` / `loading` / `load()` / `getName(id)`。
- 模块作用域 `cachePromise` 缓存数据；接口统一用 `data-manage-basic` 的 `fetchGetCountryList({page:1,size:1000})`（两处原本即同源真实接口，无 DEV mock）。
- 每个选项：`label = \`${nameCn} (${code2})\``（过滤与兜底文本，支持搜中文名/二字码）、`value = \_id`、`name`/`code2` 自定义字段、`renderLabel`返回`flex justify-between width:100%` 节点（左 name、右 code2 灰色）。
- naive 默认过滤大小写不敏感比较 `option.label`，故输入 `ae`/`阿联` 均可命中；`renderLabel` 同时作用于下拉项与选中态，无需改 FormWrap。
- 名称优先级：`nameCn ?? name ?? nameEn ?? code ?? _id`。

## 实施（已交付 2026-09-18）

- 新增 `src/hooks/business/use-country-select.ts`：`useCountrySelect()` 返回 `options`/`loading`/`load()`/`getName(id)`/`renderLabel`；模块级 `cachePromise` 单例缓存 `/country/query`（size:1000）；每项 `label = \`${nameCn} (${code2})\``（兼过滤与兜底）、`value=\_id`、`name`/`code2` 自定义字段、`renderLabel`用`flex justify-between w-full` 实现左名称右二字码（灰色），下拉与选中态共用；`getName`由`\_id` 反查纯中文名。
- **坑（用户截图复验发现）**：naive 的「自定义 option label」是 **select 级 prop `render-label`**，挂在每个 option 上的 `renderLabel` 字段 NSelect 并不识别，首轮下拉回退成纯文本「阿联酋 (AE)」。修复：`FormWrap` 的 select 增加 `:render-label="item.renderLabel ?? fallbackOptionLabel"` 透传（`FormItemConfig` 新增 `renderLabel` 配置项；`fallbackOptionLabel` 兜底识别 option 自带 `renderLabel`，否则纯文本 label），喂带 `renderLabel` options 给 FormWrap 的调用方零改动生效。
- **坑2（用户截图二轮复验发现）**：`render-label` 生效后仍非左右布局——naive 把自定义节点包在 `.n-base-select-option__content` 里，该内容容器默认不撑满整行（flex 子项无 `flex:1`），`justify-between` 没有可分配空间，二字码紧贴名称。修复：`src/styles/css/global.css` 全局兜底 `.n-base-select-option__content { flex: 1 1 auto; width: 100%; min-width: 0; }`（对纯文本选项视觉无差异），使 render-label 内容可占满行宽实现左名称右二字码。
- **坑3（用户截图三轮复验发现，浏览器实测定位）**：左右布局后二字码与滚动条间距和左侧留白不对称。盲补 5px 无效，用 playwright 实测 dev server 下的真实几何发现真正原因：①单选下拉全部选项的 li padding 实为 `0 32px 0 12px`（naive 为选中行 ✓ 勾选图标预留 20px 右内边距，经 `--show-checkmark` 动态注入样式覆盖静态表）；②滚动条 rail 宽 5px 且距菜单右缘还有 4px 内缩。修复：行加 `country-option-row` class，global.css 用 `:has(.country-option-row)` 把该类选项右内边距统一回 12px（需 `!important` 压过动态注入）并隐藏 ✓（与二字码语义重复），render-label 行补 `pr-9px`（=5px rail 宽+4px 内缩）。实测：名称距左缘 12px、二字码距滚动条 12px，完全对称；各行二字码同列对齐。
- `FbaWarehouseOperateDrawer.vue`：删本地 `countryOptions`/`countryNameMap`/`loadCountryOptions` 及 `SelectOption` import；改 `useCountrySelect`（`onMounted(load)`）；`countryId` 项 `options` 用 `options.value`；提交 `country: getName(countryId)` 回填。
- `address-operate-drawer.vue`：删本地 `countryOptions`/`loadCountryOptions` 改用 Hook（统一到 `data-manage-basic` 同源，移除 `ship-address/fetchGetCountryList` 死函数）；`watch(countryId)` 回填 `model.country` 改用 `getName(id)`，避免存带 `(AE)` 整串。
- 验证：`pnpm typecheck` 0 / `pnpm lint` 0 error（link.vue 2 既有 warning 无关）/ `pnpm build` 成功 / `pnpm fmt` 通过。dev 手动冒烟待用户。

## 不在范围

- 不改 `FormWrap` 源码；不新增独立 `<CountrySelect>` 组件；不做英文过滤（仅兜底显示）。

## 验证

- `pnpm typecheck` / `pnpm lint` / `pnpm build` 必跑；`pnpm dev` 手动确认下拉显示二字码、可搜索、提交回填纯中文名。
