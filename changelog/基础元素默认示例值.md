# 标签设计器：基础元素补默认示例值（文本 / 长文本 / 图片）

> 用户反馈（截图圈出基础元素的「文本 / 长文本 / 图片」）：「这三个能不能加个示例，拖出来都是空的，或者如果是空内容，能不能按之前那样显示呢？」

## 现状

`core/basic-elements.ts` 中只有条码 / 二维码带示例（`sample: '123456'` / `'https://example.com'`），文本 / 长文本 / 图片的 `sample` 为空字符串 → `defaultOptionsFor` 生成的 `options.text` / `options.src` 为空 → 拖到画布上是空白。

「空内容按之前那样显示」的另一路径（`placeholder` 占位）经评估**不采用**：占位文本与真实内容在渲染上无视觉区分（要改还得同时处理画布 + 打印 HTML 两端并隔离打印场景，避免占位被打印出来），且 `placeholder` 在导出格式里已有独立语义（承载 text / value 的内容值），容易混淆。

## 改动

与条码 / 二维码的口径对齐，给三个基础元素补默认示例：

| 元素   | 示例值                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------ |
| 文本   | `文本示例`                                                                                                   |
| 长文本 | `长文本示例，可输入多行内容`                                                                                 |
| 图片   | 内嵌 SVG 占位图（虚线框 + 山形 / 圆点；`data:image/svg+xml,...` 纯 ASCII 无需 URL 编码，`#` 已编码为 `%23`） |

- 图片占位图定义在模块级常量 `IMAGE_PLACEHOLDER_SRC`（带注释），拖出即有可见内容、可随时在属性面板替换为真实图片地址；
- 零渲染改动、零导出格式改动（示例值走既有 `sample → options` 通道，与业务字段拖入一致）。

## 验证

- `npx oxfmt` / `npx oxlint --fix` / `npx eslint --fix` 单文件：0 error；`pnpm typecheck`：0 error。
- `tsx` 实测（临时脚本已删）：五个数据类基础元素拖出后 `resolveDisplayText` 均非空 —— text「文本示例」/ longText「长文本示例，可输入多行内容」/ image SVG data URI / barcode「123456」/ qrcode「https://example.com」。
