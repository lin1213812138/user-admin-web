## 背景

用户截图圈出「录单格式 → 字段映射」里每个字段的「复选框 + ★ 星标」组合，反馈「不太好看，能不能换成其他的」。
该面板承载 5 组 116 个字段、每字段两个维度（显示 / 必填），此前已迭代过 5 轮（两复选框并排 → 复选框+星标 → 星标放大 → 加 tooltip → 组全选联动必填），仍被判定不好看。

本轮先做**浏览器可视化对比**（`.superpowers/brainstorm/field-mapping-ui/content/`，Node 伴随服务器 + IDE 预览），共 3 轮：

| 轮次 | 方案                                                        | 结果                       |
| ---- | ----------------------------------------------------------- | -------------------------- |
| 1    | A 文字标签 / B 静默必填（反标选填）/ C 胶囊循环             | 全部否决（「都不太行」）   |
| 2    | 版本 1 前缀红点 / 版本 2 柔和「必填」标签（含面板整体重构） | 未采纳（用户要求更多版本） |
| 3    | **版本 3 行式双开关** / 版本 4 瓦片墙 / 版本 5 色阶         | **用户选定版本 3**         |

选定的根因判断：网格布局把两个状态挤在 24px 行高里，只能用图标表达状态；**行式布局把「字段名」与两个可点状态拆成三个独立区域**，每个状态都是带字的胶囊 —— 不用猜、不用悬停、不需要学习。

## 设计决策（已与用户确认）

| 决策点       | 结论                                                                                                              |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| 行结构       | 字段名（`flex-1` 省略号）+ 「显示」胶囊 + 「必填」胶囊                                                            |
| 行栅格       | `repeat(auto-fill, minmax(280px, 1fr))`，不再用 24 栅格 span                                                      |
| 胶囊样式     | 未选中＝灰底灰字；选中＝主题色浅底深字（显示 `primary-50/600`、必填 `error-50/600`）；禁用＝`opacity-45`          |
| 置灰规则     | 未显示时「必填」置灰不可点（延续「不允许新配出『必填但不显示』」）；锁定字段的「显示」不可点+`title` 说明         |
| 分组一键操作 | 移入**组头**：「全选」=本组显示+默认必填；「清空」=只清显示、锁定字段保留                                         |
| 卡片头部     | 撤掉 5 个分组按钮，改放汇总「已显示 X/Y · 必填 Z」+ 搜索框 + 「仅看已选」                                         |
| 汇总口径     | 「必填」只统计**已显示且 required** 的字段，避免历史数据里「必填但不显示」把数字抬高                              |

| 数据结构     | `FieldMappingValue { show[], required[] }` 不变，`field-list-mapper.ts` 一行不动                                  |
| 组件契约     | props / emits 与旧版完全一致                                                                                      |
| 落地方式     | **新实现写进新文件** `FieldMappingRow.vue`；旧 `FieldMapping.vue` 原样保留 ⇒ 抽屉只改 1 行 import，回退改回来即可 |
| 顺带清理     | 消除 `fill` 分支两份重复模板（`NScrollbar` 常驻，`fill` 只控制外层 flex 与高度）                                  |

## 实施后修正：头部被压成竖排 + 列密度回归设计稿（用户截图反馈）

用户上手后反馈两处：①卡片头部那块和设计稿不一样、「仅看已选」被压成一字一行竖排，很难看；②整体比设计稿密。

**根因（头部）**：naive 的 `.n-card-header__main` 是 `flex: 1; min-width: 0`，`__header-extra` 默认 `flex: 0 1 auto`（可压缩）。上一版把三个控件塞进一个 `flex-nowrap + min-w-0` 的容器：

- 标题侧被 `min-width: max-content` 保住 → 空间压力全落在右侧；
- `NCheckbox` 内部是 inline-flex，CJK 文案可逐字换行，作为可压缩 flex 项的 min-content 只有「图标 + 一个字」→ 被一路压到约 20px，于是竖排。

**修法**：

1. 右侧容器改 `flex-wrap` + 三个子项 `shrink-0`（空间不足就折行，绝不压字）；`NCheckbox` 换成设计稿的 **`NSwitch` + 独立 `whitespace-nowrap` 文案**（去掉可断字的 checkbox label）；搜索框补 `shrink-0`；
2. 顺带修掉一处自引 bug：外层 div 的 `@click` 与 NSwitch 自身切换叠加会互相抵消（点开关看似无效），已去掉外层点击、只留开关；
3. **列密度回设计稿**：`repeat(auto-fill, minmax(280px,1fr))`（宽屏跑成 4 列）→ 新增 `.mapping-grid` scoped 样式 `repeat(auto-fill, minmax(min(420px,100%),1fr))`，抽屉宽度下稳定**两列宽行**（与设计稿一致），更宽屏 3-4 列，极窄回退单列且用 `min(…,100%)` 防横向溢出。

**验证**：`npx oxfmt` / `npx oxlint --fix` 该文件 0 error；`pnpm typecheck` exit 0。视觉效果待用户二次确认。

## 九次修正：组头动作按钮放大 + 修复汇总 `{total}` 不插值

### 2. 修复卡片汇总里 `{total}` 渲染为空（真 bug，用户截图中「已显示 116/ · 必填 116」）

**根因**：vue-i18n 的 `<I18nT>`（`TranslationImpl`）**只把具名插槽当作插值值** —— 源码 `renderChildren` 里 `const keys = Object.keys(slots)` + `getInterpolateArg(context, keys)` 的 `keys.reduce` 只从 `slots[key]()`取值，`:total="…"` 这类非声明 prop 落进 `attrs`，**不参与插值** ⇒ `{total}` 取到 undefined，渲染成空字符串（表现为斜杠后面空着）。

**修法**：把 `:total="stats.total"` 换成 `<template #total>{{ stats.total }}</template>`；`#shown` / `#required` 本来就是插槽，不变（数字加粗仍在）。

**验证**：`oxfmt` / `oxlint` / `eslint` / `pnpm typecheck` 全 0 error；`pnpm build` Build successful。
