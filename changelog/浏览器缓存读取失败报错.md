# 大量 `net::ERR_CACHE_READ_FAILURE 304` 报错定位（与新增菜单无关）

> 日期：2026-09-21
> 用户原话：贴出一组控制台报错（`base-layout/index.vue`、`store/modules/tab/shared.ts`、`store/modules/route/shared.ts`、`packages/color/src/constant/name.ts`、`packages/color/src/constant/palette.ts` 均 `net::ERR_CACHE_READ_FAILURE 304 (Not Modified)`）+「新增了菜单怎么又报错了」

## 1. 结论

**不是代码 / 菜单 / 本次改动的问题，是浏览器（Chromium 内核）的 HTTP 磁盘缓存读取失败。**

- `304 (Not Modified)` = **服务端正常**：告诉浏览器「资源没变，用你本地缓存」；
- `net::ERR_CACHE_READ_FAILURE` = **浏览器读自己的缓存条目失败**（Chromium 客户端错误码，请求根本没发出）。
- Vite dev 下模块是原生 ESM `import`，一个模块加载失败就会连带整页白屏/报错，因此看起来像「代码坏了」。

## 2. 实测证据（服务端健康）

`pnpm dev` 的端口 9111、base `/tms/`（见 `vite.config.ts:36` 与 `.env.test` 的 `VITE_BASE_URL=/tms/`）。

```
200  /tms/                                                        （HEAD 探活）
200  /tms/src/layouts/base-layout/index.vue            len=22512   （报错清单里的文件）
200  /tms/packages/color/src/constant/name.ts          len=147778  （报错清单里的文件）
200  /tms/src/views/data-manage/basic/modules/remote/index.vue             len=33301   （本次新增页）
200  /tms/src/views/data-manage/basic/modules/remote/RemoteImportDrawer.vue len=28330   （本次新增页）
```

⇒ 报错清单里的所有模块与本次新增页面模块**全部正常 200**，与「新增菜单」无因果关系。

## 3. 常见成因

1. 浏览器磁盘缓存目录损坏 / 被占用：Chrome 写入缓存时崩溃、或用清理工具删了缓存文件；
2. 杀软实时扫描（Windows Defender / 360 等）锁住 Cache 文件；
3. 磁盘空间不足；
4. 用户数据目录落在 OneDrive / 网络盘上；
5. 同时并发读取大量缓存条目（首屏 dev 模块很多）时偶发。

## 4. 处理步骤（按序）

1. **F12 打开 DevTools → Network → 勾选 `Disable cache`**（保持 DevTools 打开）→ `Ctrl+Shift+R` 硬刷新；
2. 仍不行：`Ctrl+Shift+Delete` 只勾「缓存的图片和文件」，时间范围选「过去 1 小时」→ 关闭标签页重开；
3. **完全退出浏览器**（含托盘/后台进程）后重开；必要时删除缓存目录：
   - Chrome：`%LOCALAPPDATA%\Google\Chrome\User Data\Default\Cache` 与 `...\Code Cache`
   - Edge：`%LOCALAPPDATA%\Microsoft\Edge\User Data\Default\Cache`
4. 检查 C 盘剩余空间；把项目目录与浏览器缓存目录加入杀软排除项；
5. 以上都无效时，换一个浏览器或换一个用户配置文件（`--user-data-dir`）验证，可快速判定是否为缓存目录损坏。

## 5. 本次变更的边界

- 本轮**未改动任何代码**（仅探活与只读请求）；
- 本次功能（通用资料 → 偏远数据）的验证不受影响：dev server 正常返回新页模块，硬刷新后即可继续冒烟。
