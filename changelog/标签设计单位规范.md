# 标签设计单位规范：纸张用 mm，位置与尺寸用 pt

## 背景

用户提出单位规则：「纸张尺寸必须用 mm，其他要用 pt」，并附「位置与尺寸」面板截图（X (pt) / Y (pt) / 宽 (pt) / 高 (pt)）补充口径——**这些（元素几何）先用 pt，其他项暂时不动**。

即本次「其他」的范围仅指元素的 x / y / width / height，「其他暂时不动」= 字号、线宽、圆角、间距等一律维持现状。

## 结论

**无需改动代码**：当前实现已完全符合该规则。

## 核对明细

### 纸张尺寸 = mm（已合规）

- `modules/constant.ts`：`PAPER_SIZES`（`100×150mm` / `A4(210×297mm)` 等）、`parsePaper()` 返回 mm、`PX_PER_MM = 96 / 25.4`
- `tool-bar.vue`：纸张下拉选项文案为 mm
- `design-canvas.vue`：纸张容器尺寸 `* PX_PER_MM`；网格仍 1mm 间距
- `preview-modal.vue`：预览 iframe 尺寸 `* PX_PER_MM`
- `render-element-html.ts`：纸张容器 `${w}mm`
- `export-format.ts`：导出 `paper: { width, height, unit: 'mm' }`
- 画布渲染、打印导出、存储三处纸张单位一致

### 位置与尺寸 = pt（已合规，即截图四项）

- 存储：`LabelElement.x/y/width/height` 自 `标签设计元素几何单位mm改pt` 起即为 pt；旧 mm 数据由 `export-format.ts` 的 `migrateGeometryToPt()`（×`PT_PER_MM ≈ 2.8346`）自动迁移，`unit` 缺省视为 mm
- 画布：`design-canvas.vue` 的 `elementStyle()` 用 `PX_PER_PT` 换算
- 交互：`use-canvas-interaction.ts` 的 `ptPerPx` / `MIN_SIDE` / 点击阈值均以 pt 表达
- 属性面板：`property-panel.vue` 的 `geoItems` 直读元素 pt 值，标签 `propX/propY/propW/propH` 已带 `(pt)` 后缀
- 打印/导出：`render-element-html.ts` 输出 `${x}pt`，`export-format.ts` 几何 pt 直传
- 拖放落点、快捷键步长、复制/粘贴偏移均经 `mmToPt()` 由纸张 mm 换算，无 mm/pt 混减

### 其他（本次不动）

- 字号 `fontSize` / 标题字号 `titleFontSize`：渲染已是 pt，属性面板标签不加单位后缀
- 线宽 `borderWidth`、圆角 `radius`、编码值间距 `textGap`、标题与内容间隔：维持 px
- 行高 `lineHeight`：维持无单位比值

## 追记：`DragState.paperW/paperH` 注释易误读

用户看到 `use-canvas-interaction.ts` 的 `paperW/paperH` 注释写着「纸张尺寸（pt…）」，质疑为何纸张变成 pt。

实际是**换算值而非原单位**：`store.template.paperSize` 恒为 mm 字符串，`paperPt(paperSize)` 经 `parsePaper()` → `mmToPt()` 得到 pt 数值，`begin()` 缓存进 `DragState`，仅供 `resizeGeometry()` / `outAmount()` 与元素几何（pt）**同单位比较、钳制纸界**使用（拖拽期间纸张不变，故只算一次）。纸张的权威单位仍是 mm（存储 / 下拉 / 画布 / 预览 / 导出 paper 全链路），`mmToPt` 只是此处的局部换算。

已将注释改为「纸张尺寸的 **pt 换算值**（paperSize 本身是 mm，这里仅为与元素几何 pt 同单位比较）」，消除误读。仅注释变更，无逻辑改动。

## 验证

`mmToPt` / `PX_PER_MM` / `PX_PER_PT` / `PT_PER_MM` 全局引用仅存在于标签设计器 7 个文件，且 `PX_PER_MM` 仅用于纸张侧、`PX_PER_PT` 仅用于元素几何侧；本次除一处注释外无代码逻辑变更、无需重新 typecheck。
