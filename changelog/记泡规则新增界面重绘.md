# 计泡规则新增/编辑抽屉界面重绘

> 日期：2026-09-19 ｜ 状态：已实施，待手动冒烟 ｜ spec：`docs/superpowers/specs/SPEC-weight-rule-drawer.md`

## 背景

用户反馈「记泡规则新增界面没有画好」。本机模型不支持查看用户附带的截图，故基于源码审查定位问题（详见 spec 的 Open Questions / Assumptions）。

## 定位到的问题

`src/views/data-manage/ship/modules/weight-rule/WeightRuleOperateDrawer.vue` 原实现：

1. 抽屉用 `Drawer` 默认 `width=420`，太窄——进位规则组一行要放「开始/结束重量 + 计重单位 + 删除」三列输入，必然拥挤/换行。
2. 基础字段走 `NFormWrap`（有 label、24 栅格对齐），但「进位规则」动态嵌套区块是手写裸 `NSelect`/`NInputNumber`/`LButton`——**无表单项 label、间距随意、按钮风格突兀**，与上半部分视觉语言割裂。
3. 计泡类型（mode）选项文案很长（如「票总重和票总体积重取大值」），在窄抽屉里被挤压/折叠。
4. 进位规则组只是一圈粗糙边框 + 裸粗体标题，无区块分隔、无空状态。

## 决策（设计闸门）

按 AGENTS.md 走 agent-skills 工作流：`using-agent-skills` → `spec-driven-development`（产出 spec，用户于对话中以「继续」确认）→ `frontend-ui-engineering`（实现）。

重绘方案：

- 抽屉 `width` 由 420 → **700px**，容纳三列输入 + 删除按钮无换行。
- 用 `NFormWrap` 的 `type:'section'` 把表单分为**「基础信息」**与**「进位规则」**两个区块，统一设计语言。
- 进位规则组改为**卡片**：组内顶部为带 label 的「进位类型」`NSelect` + 右侧删除组按钮；下方规则行采用带列标题（开始重量/结束重量/计重单位）的 `grid-cols-[1fr_1fr_1fr_auto]` 栅格，每行 3 个 `NInputNumber`(`:min="0"`) + 删除行按钮；底部「加区间」虚线按钮。
- 整段进位规则为空时显示 `NEmpty` 空状态 + 「加进位规则组」按钮。
- 控件尺寸/间距跟随项目 `FormWrap` 与 naive-ui token（`var(--n-border-color)` / `var(--n-text-color-3)` / `var(--n-fill-color)`），避免 AI 风格与自定义像素值。

## 实施

  - 进位规则区改为手写模板（嵌套数组 `FormWrap` 不支持），但带 label、列标题、空状态，与 `FormWrap` 风格一致。

## 追加（按真实后端 Schema 对齐字段，已实施）

用户提供 tms-user `WeightRuleSchema`，发现前端字段与后端**不一致**，界面需按真实 Schema 重写：

- **`calcMode` 实为 `unit`**：后端字段名是 `unit`（计费单位 0-公斤 1-方），前端曾错用 `calcMode`。这意味着此前新增提交里 `calcMode` 后端不存储、列表「计算方式」列实际取不到值 → 全部改为后端真实字段名 `unit`。
  - 冲突坑：i18n 的 `weightRule.unit` 原本就存在（进位规则每行「计重单位」的 label），故顶层「计费单位」字段的 label 改用新 key `weightRule.billUnit`，避免同一对象出现两个 `unit` 键（TS1117）。模型字段名仍为 `unit`（对应后端），仅文案 key 分离。
- **补 `weightToVolume`（折方系数）**：后端有、前端缺失；规则为「计费单位=方（unit=1）且计泡类型 mode∈{0,1,2} 时必填」。
  - 实现：`WeightRuleOperateDrawer.vue` 的 `formItems` 中 `weightToVolume` 项 `required` 设为 `formModel.unit === 1 && [0,1,2].includes(formModel.mode ?? 0)`（依赖 `formItems` computed 的响应式，切换 unit/mode 即时联动必填态）。

### 影响文件

- `typings/api/data-manage/ship.d.ts`：`WeightRule` 去 `calcMode`、加 `unit`、加 `weightToVolume`，注释对齐后端。
- `typings/app.d.ts`：`weightRule` i18n 类型 `calcMode→billUnit`、加 `weightToVolume`（保留原 `unit` 给每行计重单位）。
- `locales` zh-cn / en-us：`calcMode→billUnit`（计费单位），加 `weightToVolume`（折方系数）。
- `WeightRuleOperateDrawer.vue`：`unitOptions`（原 calcModeOptions）、`emptyForm`/`openEdit` 用 `unit`、表单加 `weightToVolume` 条件必填项。
- `WeightRule.vue`：列表列 `calcMode→unit`（标题用 billUnit），新增 `weightToVolume` 列；`calcModeLabel→unitLabel`、`calcModeOptions→unitOptions`。

### 边界（未动）

- 接口 `service/api/data-manage-ship` 仅透传 `formModel`，字段名纠正后即与后端契约一致；无需改接口路径。
- `carryList` 结构（carry/ruleList:{start,end,unit}）与后端一致，未改。
- 列表页/抽屉布局（700px、section 分区、进位卡片）保持上一轮重绘结果。

### 验证（追加后）

- `pnpm typecheck` 0 / `pnpm lint` 0 error（link.vue 既有 2 warning 无关）。
