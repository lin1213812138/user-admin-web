# 报关类型 / 出口原因 / 清关方式 / 销售条款 接口对齐

日期：2026-09-19

## 背景

用户给出 4 个 Schema，字段均极简（name 必填 + status + note(备注)，仅报关类型多 `inner` 仅内部可用）：

- `CustomsTypeSchema`：name / inner(0-否1-是) / status / note / 审计字段
- `ExportReasonSchema`：name / status / note / 审计字段
- `CustomsClearSchema`（清关方式）：name / status / note / 审计字段
- `SalesTermsSchema`（销售条款）：name / status / note / 审计字段

## 定位（后端）

`lib/api-v1-web` 下 4 个路由**均已存在**，service 全部 `commonService` + `queryCommon({ keywordFields: ['name'] })`、`create/update` 校验 `name`(`uniqField`)、`delete` → `batchDeleteCommon(ids)`：

- 报关类型 → `/customs-type/*`
- 出口原因 → `/export-reason/*`（额外 batch/create）
- 清关方式 → `/customs-clear/*`（注意前端 archive 键是 `clearanceMethod`）
- 销售条款 → `/sales-terms/*`（额外 batch/create）

## 问题

4 个前端页面原本配置带 `code` 列 + code 输入框（`page.dataManage.business.code`），但 4 个 Schema **都没有 code**，且表单用 `remark` 而后端字段是 `note` → 备注写不进库。清关方式页面此前走 MasterDataArchive mock（`clearanceMethod` 在 mock 兜底列表）。

## 改动（沿用 problem/goods-category 同款范式）

1. `data-manage-archive`：
   - 清关方式：新增 `fetchGetCustomsClearList / fetchCreateCustomsClear / fetchUpdateCustomsClear / fetchDeleteCustomsClear`（`/customs-clear/*`），`archiveApiMap['clearanceMethod']` 切真实，删 mock 工厂 → 真实档案 6→7、mock 6→5。
   - 修正既有分页 bug：原 `fetchGetSalesTermsList / fetchGetExportReasonList / fetchGetCustomsTypeList` 直接 `data: params`（含 `current`），但 `queryCommon` 读 `page`（common.js:112），导致 `page` 为 undefined、每页都从第 1 条按 `size` 截取、翻页无效。统一改为 `page: params.current` + `status` 拼 `where`（与 goods-category 一致）。
2. 类型 `BusinessCustomsType / BusinessExportReason / BusinessClearanceMethod / BusinessSalesTerms`：去 `code`，加 `name` + `note?`；报关类型加 `inner?: 0|1`。
3. 4 个页面：去 code 列/code 表单；列 = 类别名称(detail) + 备注；报关类型额外「仅内部可用」列（slot 渲染 是/否，用 `common.yesOrNo`）；表单 = 名称(必填) + 备注(textarea)，报关类型加 仅内部可用 switch；`createDefault` 含 `name/note/status`（报关类型含 `inner:0`）。备注列/表单标签复用 `common.remark`（备注）。
4. i18n：zh/en 的 `business.customsType` 补 `inner`（仅内部可用 / Internal Only），`App.I18n` 类型同步。

## 结果与备注

- typecheck 0 / lint 0 error（link.vue 2 既有 warning）/ fmt / build:test 通过。
- 备注字段用后端 `note` 名（页面标签显示「备注」= common.remark），与 4 个 Schema 的 note 字段对齐，解决了原 `remark` 不落库问题。
- 修正的 3 个既有档案分页错位属既有 bug 收口（此前 currency 等也如此，未改），现 4 个一致正确。
