# 收货渠道「报价设置」界面（内嵌路由页）

> 落点目录（用户指定）：`src/views/channel-quote/receive/modules/quote-setting/`
> 路由：`channel-quote_receive_quote-setting` → `/channel-quote/receive/quote-setting`

## 背景

用户贴老系统渠道详情页「渠道备注」tab 区的 5 张分页截图（**地址分区 / 渠道报价 / 渠道加收 / 客户报价 / 销售成本价**），要求新增「报价设置界面」：

- 代码放在 `src/views/channel-quote/receive/modules/quote-setting/`；
- **「要当做路由跳转不是弹窗」**；
- **「菜单栏不显示菜单高亮还是收货渠道」**。

   - 新增 `customRoutes: { map: { 'channel-quote_receive_quote-setting': '/channel-quote/receive/quote-setting' } }`（C4）。
2. **`src/router/routes/index.ts`**

   - 新增 `embeddedViews`（内嵌页视图）并在 `getAuthVueRoutes` 内与自动生成的 views 合并后交给 `transformElegantRoutesToVueRoutes`。
3. **新增页面** `src/views/channel-quote/receive/modules/quote-setting/`
   - `index.vue`：页面壳 —— 无 `channelId` 时给引导空态；否则渲染「渠道信息条 + `NTabs`（5 个页签）+ 当前面板」，页签与 `?tab=` 双向同步（复刻资料管理/系统设置的 tab 记忆语义，`replace` 不新增历史 + 同步页签 `fullPath`）；
   - `modules/zone-panel.vue`（地址分区：编辑分区/导入分区 + 国家或二字编码检索 + 表头 分区/目的地/时效(天)/特别提示）；

   - `modules/fee-ext-panel.vue`（渠道加收：新增加收 + 加收名称检索 + 表头 加收名称/加收国家或地区/加收类型/加收条件/加收费用/备注/状态/操作）；
   - `modules/customer-price-panel.vue`（客户报价：新增报价/删除报价 + 勾选列 + 表头 客户/报价类型/其他费用/报价备注/最新编辑/编辑时间/创建时间/状态/操作 + 分页）；

   - **本轮所有工具条按钮仅渲染 UI，点击无行为**（各 tab 的编辑/导入/新增功能为后续独立迭代）。
4. **`src/views/channel-quote/receive/index.vue`**：操作列「编辑」后新增「报价设置」→ `routerPushByKey('channel-quote_receive_quote-setting', { query: { channelId: row._id, name: row.name } })`；`action-width` 230 → 300。
5. **i18n 三处同步**：`route.channel-quote_receive_quote-setting`（报价设置 / Quote Setting）+ `page.channelQuote.quoteSetting.*`（tabs / actions / search / empty / 各表头）→ `zh-cn.ts`、`en-us.ts`、`typings/app.d.ts`。

## 踩坑与处置（重要）

1. **生成文件被「旧配置 watcher」覆盖** ⚠️
   - 现象：重新生成后 `imports.ts` 又多出 `channel-quote_receive_modules_quote-setting`、`transform.ts` 反而丢了自定义 key，typecheck 报「不存在 `channel-quote_receive_quote-setting`，你是不是要 `layout.base$view.channel-quote_receive_modules_quote-setting`」。
   - 根因：工作区里**已有一个 dev server**（PID 6664，`vite --mode test`，11:54 启动，早于本次配置修改）。Vite 因配置依赖（`build/plugins/router.ts`）变化重启时会重建插件实例，但**旧实例的 chokidar watcher 未被销毁**，于是在新增页面文件时仍用**旧 options**（无 `pageExcludePatterns`、无 `customRoutes`）重新生成并覆盖。
   - 处置：用 vite programmatic `createServer(...)` 以**当前配置**跑一次生成，产物恢复正确；**并需用户重启 dev server**（见「待办」）。
   - 附带证据：`pnpm gen-route` 实为 `sa gen-route`，只创建空页面文件，**不含任何生成逻辑**（`packages/scripts/src/commands/router.ts`），排查时勿把它当生成入口。
2. **`routes.ts` 残留子树**：生成器合并函数 `N()` 以**旧文件为基准**（`K = {...旧节点, path}`），新扫描结果没有的 children **不会被删除** ⇒ 被污染过的 `channel-quote_receive.children`（modules 分支）会一直留着（进而在菜单里多出一层）。处置：按项手工清掉该残留子树（`transform.ts`/`imports.ts`/`elegant-router.d.ts` 是纯生成、无此问题）。
3. **循环依赖 TDZ**：最初把 `const views = {...elegantViews, ...embeddedViews}` 写在模块顶层，运行时报 `Cannot access 'elegantViews' before initialization` —— `routes/index.ts` → `elegant/imports.ts` → `layouts/base-layout` → … → 回到路由模块构成环。处置：合并挪进 `getAuthVueRoutes` **调用时**求值（原代码 `transformElegantRoutesToVueRoutes(routes, layouts, views)` 也是函数内传参，天然规避）。
4. **类型模板局限**：`CustomSingleLevelRoute.component` 被官方限定为 `layout.${RouteLayout}$view.${LastLevelRouteKey}`，而内嵌页属于 `CustomLastLevelRouteKey` ⇒ 该组合覆盖不到。处置：**仅对 `component` 一个字段** `as unknown as CustomRoute['component']`（项目内 `as unknown as` 已有 21 处先例），其余字段仍受类型检查。
5. **面板 `channelId` prop 未使用**：触发 `vue/no-unused-properties`。本轮面板无任何数据逻辑，按 YAGNI **移除该 prop**（页面 URL 仍带 `channelId`，后续接接口时再加）。

## 实现修正（同日，冒烟反馈后）

### 1. `layout.base$view.xxx` 只对「一级单级路由」生效 → 改为注入子路由

- **现象**：控制台 `Error transforming route "channel-quote_receive_quote-setting": Error: Layout component "base$view.channel-quote_receive_quote-setting" not found`，随后点入口报 `No match for {"name":"channel-quote_receive_quote-setting",…}`（该路由整体注册失败）。
- **根因**：`transform.ts` 的 `isSingleLevelRoute = isFirstLevelRoute && !children`，而 `isFirstLevelRoute = !name.includes('_')`。我们的 name 是三段式（含 `_`）⇒ 不走 `getSingleLevelRouteComponent`（按 `$` 拆分），直接进 `isLayout` 分支，把 `base$view.channel-quote_receive_quote-setting` 当成 layout 名去找 → 抛错。
- **修正**：把该路由**注入 `channel-quote` 的 children**（`injectQuoteSettingRoute`，幂等），`component` 用纯 `view.channel-quote_receive_quote-setting`（非一级路由允许 `view.x`/`layout.x` 之一）。这样它既有 base layout 包裹，又保住父子层级（面包屑两级、`getCacheRouteNames` 命中 keepAlive、菜单不受影响）。`customRoutes` 数组保持为空，`build/plugins/router.ts` 的 `customRoutes.map` 仍只负责生成 `RouteKey`/`routeMap`。

### 2. 表格搜索栏改用组件自带的 `search-action` 插槽

- **反馈**（用户贴「地址分区」tab 截图）：「这个界面用 card 包起来，并且里面没有正确使用表格组件的东西」。
- **根因**：原实现把搜索框/按钮放在 `Table` 的 `operation-right` 工具条里 —— 既没有卡片外观，也不符合仓库既有用法（**仓库内 32+ 处页面的搜索栏都走 `search-action`**，该插槽会自动渲染成 `NCard` 卡片，组件注释亦写明"内容由业务页面自定义（输入框/下拉/按钮）"）。
- **修正**（`zone-panel.vue`、`fee-ext-panel.vue`）：`NInput` + 「搜索」（`zone` 另有「重置」）整体放进 `#search-action`（`flex flex-wrap items-center gap-12px`，输入框 `w-240px!`），业务按钮（编辑分区/导入分区/新增加收）留在 `#operation-left`；清掉 `operation-right` 里的残留（含用户手工注释掉的搜索按钮）。
- **说明**：无搜索栏的 tab（渠道报价 / 客户报价 / 销售成本价）保持"工具条 + 表格（或空态）"，与老系统截图形态一致，因此没有 `search-action` 卡片。

### 3. 面板文件按子模块隔离

- **反馈**（用户贴目录截图）：「用文件夹隔离，不然文件太多很乱」。
- **调整**：`quote-setting/modules/` 下 5 个平铺面板文件改为各自一个文件夹，文件名统一 `index.vue`（对齐仓库 `modules/<子模块>/<组件>.vue` 惯例）：
  `zone/index.vue`、`price/index.vue`、`fee-ext/index.vue`、`customer-price/index.vue`、`cost-price/index.vue`；页面壳的 import 路径同步改为 `./modules/<tab>/index.vue`。文件夹隔离也为后续每个 tab 各自拆出编辑抽屉/子组件留出位置。

### 4. 组件 name 修正（keep-alive 匹配）

- 页面壳的 `defineOptions({ name })` 曾被改成 PascalCase `ChannelQuoteReceiveQuoteSetting`，与路由 name 不一致 ⇒ 顶部页签的 keep-alive（`routeStore.cacheRoutes` 存的是路由 name，`<KeepAlive :include>` 匹配的是组件 name）**不会命中**，切走再切回会重新挂载。已改回 `channel-quote_receive_quote-setting` 并在注释里写明原因（内嵌页不参与扫描，插件不会自动注入组件 name，必须手写且与路由 name 保持一致）。

### 5. 补 `LCard` 包裹（spec 4.2 的既定设计）

- **反馈**（用户贴页面截图）：「我不是说要用 LCard 包起来吗？怎么不做？」
- **事实**：spec 4.2 的页面结构里写的就是 `LCard「报价设置」`，但实施时 `src/components/basic/LCard.vue` **不存在**（同期 `AGENTS_CHANGELOG` 有"封装 LCard"的记录，代码里却没有该文件），当时擅自降级为裸布局且未告知用户 —— 属实施与 spec 不一致、且未暴露假设。
- **修正**：按记录重建 `src/components/basic/LCard.vue`（位置与 `LButton` 同目录同风格：基于 `NCard` 封装，标题前为主题色竖条 `useThemeVars().primaryColor`，`header-padding` 默认收紧、`content-padding` 支持 `string|number|false`（`false` 去内边距）、`#title`/`#header-extra` 插槽、无标题且无 `header-extra` 时不渲染 header；样式上把卡片设为纵向 flex 并让内容区 `flex:1 / min-height:0`，便于内部放「页签 + 整高表格」）。`src/typings/components.d.ts` 中本就残留 `LCard` 声明（路径 `./../components/basic/LCard.vue`，说明组件曾存在后被删），与重建位置一致，无需改动。
- **页面**：`quote-setting/index.vue` 模板改为 `<LCard class="min-h-0 flex-1" :title="报价设置" content-padding="0">` 包住「NTabs（`px-16px`）+ 当前面板（`px-16px pb-16px pt-12px`）」，页签与表格贴卡片内边距。
- **补充（同日）**：按用户要求给 `LCard` 增加显式的 `showHeader`（`show-header`）开关 —— 不传时仍按「有 title / #title / #header-extra」自动判断，显式传值以此为准（`show-header={false}` 强制隐藏头部）。
- **修正（同日，用户反馈「表格高度问题」）**：现象为表格被压成**只有一个表头**高、空态不可见（卡片本身是撑满的，说明卡片有高度、内容区没拿到）。根因是卡片内容区高度链依赖作用域样式命中 NCard 内部结构（`.l-card` 的 `display:flex` 与 `:deep(.n-card__content)` 的 `flex:1`），一旦未命中则 `content` 高度退回 auto，内部的表格 `height:100%` 随之塌陷。修法：把 flex 链改为**内联样式**保证生效 —— `cardStyle`（`n-card`：`display:flex; flex-direction:column`）与 `contentStyle`（`n-card__content`：`flex:1 1 0%; display:flex; flex-direction:column; min-height:0`，并合并 `contentPadding` 生成的 padding），同时移除对应的 scoped 规则。**同时**给 `zone` / `fee-ext` 面板的 `Table` 加 `:search-action-flush="false"` —— 搜索卡片现在位于 `LCard` 内部，默认 `searchActionFlush: true` 的 `-mx-10px -mt-10px`（为抵消页面 `p-10px` 而设）会溢出卡片内边距。
