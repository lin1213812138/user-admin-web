## 1. 背景与需求

1. 用户管理、角色管理从「权限管理」迁回「系统管理」（2026-09-14 曾反向迁移，本次迁回）。
2. 系统管理二级菜单顺序：用户 1 / 角色 2 / 分组 3 / 站点 4 / 系统设置 5 / 系统日志 6（新增页面）。
3. 客户管理独立成一级菜单「客户管理」，现有页面降为其子项「客户列表」。
4. 权限管理保留一级菜单，仅剩「菜单管理」。
5. 系统日志操作日志与登录日志合并为一个列表，数据源为真实接口 `POST /op-log/query`（tms-user 后端），不走 mock。

澄清确认：客户管理 = 独立一级菜单；权限管理 = 保留只留菜单管理；日志查询 = 时间范围 + 操作类型 + 操作端 + 关键字（关联实体名称）共 4 项。

## 2. 后端接口事实（已核实 tms-user 源码）

`POST /op-log/query`（`lib/api-v1-web/op-log/op-log.js` → `queryCommon`）：

- 入参：`{ page, size, startDate, endDate, keyword, where }`；`keyword` 只模糊匹配 `refNames`（keywordFields 固定）；时间按 `createDate`（毫秒时间戳）过滤；不传 startDate/endDate 时后端默认近 12 个月。
- 返回：`ret: { list: OpLog[], total: number }`，与 `/site/query` 同构。
- OpLog 字段（Mongo Schema）：`_id`、`name`（操作名，服务端已拼好「登录/修改/删除/退出 + 模块名」）、`refIds[]`、`refNames[]`（关联实体）、`client`（0-TMS 1-PC 2-PDA 3-OMS）、`opType`（0-登录 1-修改 2-删除 3-退出）、`logs[]`（`{ name, oldValue, newValue, oldId, newId, desc }` 变更明细）、`ip`、`desc`（摘要）、`creatorId`、`creator`（操作人）、`createDate`（毫秒时间戳）。
- 只读页面：无 create/update/delete 接口参与。

## 6. 系统日志页面（真实接口，无 mock 分支）

### 6.1 文件

- `src/views/system-manage/log/index.vue`：独立列表页范式（自包含，不套 MasterDataArchive）
- `src/views/system-manage/log/modules/op-log-detail-drawer.vue`：明细抽屉（只读）
- service：`src/service/api/system-manage.ts` 新增 `fetchGetOpLogList`（直接 `request` POST `/op-log/query`，与 fetchGetSiteList 同款，**不加 DEV mock 分支**）
- 类型：`src/typings/api/system-manage.d.ts` 新增 `OpLogClient`、`OpLogType`、`OpLogDetail`、`OpLog`、`OpLogSearchParams`、`OpLogList`（`Api.SystemManage` 命名空间）

### 6.2 列表（useVxeTable + Table）

- 列：序号（show-seq）/ 操作名称 `name`（detail）/ 操作人 `creator` / 操作端 `client`（NTag 枚举）/ 操作类型 `opType`（NTag 枚举）/ 关联实体 `refNames`（数组 join「、」）/ IP `ip` / 摘要 `desc`（ellipsis+tooltip）/ 操作时间 `createDate`（dayjs `YYYY-MM-DD HH:mm:ss`）/ 操作列（详情）
- api 闭包：`current → page`，解包 `{ data, error }`，`error || !data` 返回空列表；`transform: r => ({ records: r.list, total: r.total })`
- cacheKey：`system-manage-log`
- 只读：无 show-checkbox、无批量操作

### 6.3 查询区（4 项，FormWrap）

- 时间范围：NDatePicker daterange（毫秒时间戳 → startDate/endDate，不填走后端默认近 12 个月）
- 操作类型 opType：select（0-登录/1-修改/2-删除/3-退出，空=全部）
- 操作端 client：select（0-TMS/1-PC/2-PDA/3-OMS，空=全部）
- 关键字 keyword：input（placeholder「关联实体名称」）
- opType/client 非空时放入 `where: { opType?, client? }`，空值不传 key

### 6.4 明细抽屉

- NDescriptions 头部：操作名称/操作人/操作端/操作类型/IP/操作时间/关联实体
- 明细表渲染 `logs[]`：字段名 `name`、旧值 `oldValue` → 新值 `newValue`（oldId/newId 存在时值即关联实体名）、说明 `desc`；`logs` 为空显示 `desc` 摘要兜底
- 无提交按钮（只读），关闭即弃

### 6.5 i18n（三处：zh-cn.ts / en-us.ts / app.d.ts）

- `route` 段：删 `permission-manage_user`/`permission-manage_role`；增 `system-manage_user`（用户管理/User Management）、`system-manage_role`（角色管理/Role Management）、`system-manage_log`（系统日志/System Logs）、`customer-manage`（客户管理/Customer Management）、`customer-manage_customer`（客户列表/Customer List）
- `page.manage.opLog.*`：col（opName/creator/client/opType/refNames/ip/desc/createDate）、form（dateRange/opType/client/keyword + placeholder）、clientOption（tms/pc/pda/oms）、typeOption（login/update/delete/logout）、detail 文案
- `app.d.ts` 补 `page.manage.opLog` 段类型声明；`route` 段类型由 `I18nRouteKey` 自动派生无需手改
