# 渠道加收 · 新增加收（表单实现 + 界面优化）

> 日期：2026-09-20 ｜ 状态：已实施，待手动冒烟 ｜ spec：`docs/superpowers/specs/2026-09-20-渠道加收新增加收-design.md`

## 背景

> 用户原话：「这是之前的新增渠道加收界面，按照这个字段帮我实现，并且优化一下界面」（附图：老系统「新增加收」弹窗）

老系统字段：加收名称\*、加收类型\*（+ⓘ）、加收目的地\*、加收费用\*、加收条件\*（文本域 + 清空公式 +［无条件加收/重量/长度/体积］［大于/大于等于/小于/小于等于］按钮组 + 数值 + 填充）、状态、备注、取消/保存。

## 后端契约（已核实 tms-user，后端零改动）

- 路由 `/channel-fee-ext/{create, batch/create, update, delete, query, get}`；`create` 校验 `refId`（36 位）+ `name`。
- 模型 `lib/common/models/channel-fee-ext.js`：`refId / name / strategy(0按重量 1按票 2按件 3按重量超出部分) / price / countryIds[] / varType(0重量 1长度 2体积) / start{value,op} / end{value,op} / expr / unit / status / note`。
- `uniqField:'name'` + `uniqFilter:{ refId }` ⇒ **同一渠道内加收名称唯一**（重名 103401）。
- 计费口径（`common/services/channel-fee-ext.js`）：只读 `varType` + `start`/`end`（区间判断）+ `strategy`；`expr` 仅作展示与「无条件加收」标记（`!expr || expr === '无条件加收'` 视为恒真）。
- `query` 走 queryCommon（`{ page,size,keyword,where }`），返回后**无条件 fillName** 回填 `country`（国家 `nameCn` 以「，」拼接），无需 scene。

2. **接口** `src/service/api/channel-fee-ext/index.ts`：`fetchGetChannelFeeExtList`（`/query`）、`fetchCreateChannelFeeExt`（`/create`）。
3. **表单** 新增 `.../quote-setting/modules/fee-ext/FeeExtOperateDrawer.vue`（`Drawer` + `FormWrap`，宽 720）：
   - 加收名称：`NSelect filterable + tag`，选项取**费用类型**（启用中）名称，同时允许直接输入（后端 `name` 本就是字符串，无外键）；

   - **加收条件（交互优化）**：变量下拉（无条件加收/重量/长度/体积）+ 区间组（`[>|≥] 值 ～ [<|≤] 值`，两端可只填一端）+ **实时生成表达式**（只读 `NInput` 展示，写回 `form.expr` 作为校验与提交字段）+「清空」按钮；替代老系统的「按钮拼接→填充→清空公式」；

5. **父页** `quote-setting/index.vue`：`<FeeExtPanel :channel-id="channelId" />`（渠道上下文来自 sessionStorage）。
6. **i18n** zh-cn / en-us / `typings/app.d.ts` 三处同步：`feeExt.addTitle` + `feeExt.form.*`（占位、清空、条件提示、策略/后缀/变量/运算符文案、`strategyTip`）。

## 追加修正 10（双端区间左侧运算符反向 —— 表达式语义翻反）

> 用户附图（变量 `重量` + 开始 `大于 0.5` + 结束 `小于等于 20`）：回显 `0.5KG>重量≤20KG`，原话「这个表达式不对，怎么都是小于？」

- **根因**：双端区间把**开始值放在表达式左侧**（`开始值 <label> 结束值`），但左侧运算符仍直接用 `startOp` 原符号 ⇒ 语义翻反：`0.5>重量` 读作「重量小于 0.5」，与所选「大于」完全相反。
- **性质（重要）**：这是**既有缺陷**，自「追加修正 2」把表达式改成区间式（`10≤重量<20`）起就存在（旧代码同样是 `${startValue}${OP_SYMBOL[startOp]}${label}…`），**不是**「追加修正 9」引入的；本轮用户实测双端条件才暴露。
- **修正**：`FeeExtOperateDrawer.vue` 新增 `LEFT_OP_MIRROR: Record<0 | 1, 2 | 3> = { 0: 2, 1: 3 }`（`>` → `<`、`≥` → `≤`），双端分支左侧改用镜像运算符：
  - `重量` + `> 0.5` + `≤ 20` → **`0.5KG<重量≤20KG`**（修正前 `0.5KG>重量≤20KG`）；
  - `长度` + `≥ 10` + `< 20` → **`10CM≤长度<20CM`**。
- **口径不变**：单端分支（label 在左）仍用原符号 —— 「只填开始」`重量>4KG`、「只填结束」`体积≤3CBM`；`无条件加收` 分支原样返回。
- **边界**：仍不改后端、i18n、类型文件、条件区布局；`expr` 格式再次变化，历史记录同样需重新保存才会是新格式。
