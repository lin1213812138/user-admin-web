# 通用公共上传组件（Upload）

日期：2026-09-17

## 背景

用户："按照组件库能不能给我封装一个通用的公共上传组件呢？"

调研现状——项目内上传共 3 处、能力参差不齐：

| 位置                             | 现状                                                 | 真实上传               |
| -------------------------------- | ---------------------------------------------------- | ---------------------- |
| FormWrap `type:'file' / 'image'` | `default-upload=false`，只回填文件名 / blob 本地预览 | 否                     |
| BasicConfig 公司 LOGO            | 内联 `NUpload` + `custom-request`                    | 是（`/upload?dest=2`） |
| ExportFormat 抽屉                | `default-upload=false`，只取文件名                   | 否                     |

后端契约（tms-user 源码核实）：`POST /upload?dest=<1..10>`（form-data 字段名 `file`）→ `{name,size,url}`；
dest 1-用户 / 2-公司 / 3-打印格式 / 4-导出格式 / 5-服务商 / 6-工单 / 7-运单 / 8-交易 / 9-问题件 / 10-临时；
单文件 dest 必填（否则 100030）；拒绝 php/js/html/exe 等扩展；另有 `/files` 支持多文件。

## 需求确认（两问）

1. **范围** = 只做独立通用组件：新建 `src/components/Upload/` 供页面按需引入，首个落地场景替换
   BasicConfig 的内联 LOGO 上传；FormWrap 与 ExportFormat 本次不动。
2. **形态** = 单组件覆盖图片 + 文件：`listType`（'image-card' | 'file'）+ `max`（1=单值，>1=数组）+
   `dest`（1..10）；v-model 输出 URL 字符串或 URL[]；带进度与失败状态。

## 设计

### 产物

- `src/components/Upload/index.vue` 组件本体（自动注册名 `Upload`）

### 组件 API

| props           | 类型                     | 默认           | 说明                                   |
| --------------- | ------------------------ | -------------- | -------------------------------------- |
| `v-model:value` | `string \| string[]`     | `''`           | URL（max=1）/ URL 数组（max>1）        |
| `dest`          | `1..10`                  | 必填           | 后端上传目录                           |
| `list-type`     | `'image-card' \| 'file'` | `'image-card'` | 图片卡片 / 文件列表                    |
| `max`           | `number`                 | `1`            | 最大数量；>1 时 value 为数组           |
| `accept`        | `string`                 | 按 list-type   | image-card 默认 `image/*`              |
| `max-size`      | `number`                 | —              | 单文件上限 MB（可选，超出拒绝 + 提示） |
| `disabled`      | `boolean`                | `false`        | 禁用                                   |

| events         | 载荷                  | 说明               |
| -------------- | --------------------- | ------------------ |
| `update:value` | `string \| string[]`  | 仅写入已完成项     |
| `success`      | `{ name, size, url }` | 单个文件上传成功   |
| `remove`       | `url: string`         | 移除（仅前端解绑） |

### 内部行为（关键坑沿用 LOGO 上传经验）

- 上传：`custom-request` 调 `fetchUpload`；`onUploadProgress` → `onProgress({percent})` 驱动进度条；
  成功 `file.url = url` 再 `onFinish()`（本仓 naive `onFinish` 无参）；失败 `onError()` + message 提示。
- 受控同步：以组件内 `fileList` 为准，外部 value 变更时重建（`{id: url, name: 末段, status:'finished', url}`）；
  **pending / failed 项不写入 v-model**（上传中提交不丢旧值，沿用 LOGO 现有语义）。
- 替换与删除：max=1 时 naive 自动隐藏「+」（替换 = 先删后传）；删除同步剔除 v-model 对应 URL。
- image-card 缩略图内置 `object-fit: contain`（非正方形 LOGO 不裁切，吸收自 BasicConfig 现有样式）。
- 不做（YAGNI）：拖拽上传、远端文件删除（后端无删除接口）、裁剪压缩。

## 实测过程中的一个伪缺陷（记录备查）

验证中期曾出现「删除 LOGO 后提交仍保存成功」，一度怀疑 v-model 失效；后经组件实例级排查确认：
两次操作之间发生过页面重载（`goto`），`loadCompany` 重新回填了 `logoUrl` → 提交的是回填值
（业务字段均未变化，仅 updateDate 被刷新一次，数据无实质污染）。隔离状态下重测，校验拦截正常。
经验：**验证「删除 → 提交」类链路时不要在中间重新导航**，或用组件实例（`__vueParentComponent`）直接读值断言。

## 同日追加：补齐拖拽形态（dragger）

用户贴 naive-ui 文档「拖拽上传」截图（NUploadDragger + `directory-dnd` 提示）："拖拽上传类型有没有封装"。
确认 = 加进通用组件。

### API（在原有基础上新增/扩展）

- `listType` 扩展第三个值 **`'dragger'`**（文件列表 + 拖拽虚线框触发区）；内部 naive `list-type` 映射为 `text`
- 新增 **`directoryDnd?: boolean`**（透传 naive `directory-dnd`，允许拖入文件夹；naive 类型声明即 boolean）
- 其余 props / 事件不变，拖入文件与点击选择走**完全相同**链路（accept 过滤 → maxSize 校验 → `/upload` → 进度 → 失败重试 → v-model 只写 finished）

### 关键实现（naive 源码核实）

- `NUploadDragger` 必须是 `NUpload` 默认插槽的**第一个子节点**（`$slots.default()[0].type[uploadDraggerKey]` 判定 → `draggerInsideRef`），否则 drop 事件被忽略（`handleTriggerDrop` 直接 return）；组件内部已满足该约束
- 拖拽源的 accept 过滤只对 `source === 'dnd'` 生效（input 源靠原生 accept）；drop 读取走 `webkitGetAsEntry` → `getFilesFromEntries`
- **naive 不提供默认触发内容**（locale 里无 Upload 段、`NUploadTrigger` 直接渲染 default 插槽）：`file` 形态此前无触发按钮 → 本次**一并修复**，`file` 形态默认渲染「选择文件」按钮（`common.chooseFile` + 上传图标）
- 为不影响 image-card 形态（naive 的「+」块经 `resolveSlot(slots.default, fallback)` 取插槽内容，**任何非空插槽都会替换掉原生「+」图标**），组件采用分支渲染：`v-if="isImageCard"` 不传插槽、`v-else` 传触发区；两边共用 `v-bind="uploadProps"`（computed 集中绑定，避免重复）
- 踩坑：`naiveListType` 的三元字面量在 computed 返回位被拓宽为 `string` → 用 `computed<'image-card' | 'text'>` 显式标注；`directoryDnd` 的对象形态（`{ maxDepth }`）不在 naive 类型声明内，收敛为 `boolean`
