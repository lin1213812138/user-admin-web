# 标签设计元素拖拽越界回到原位动画

> **本文方向已被更正（认错记录）**：用户后续用截图澄清，「需要重新回到原来位置的动画」指的是**从左侧面板拖出来、没落进纸张的那一项要回到它在面板里的原位**，不是画布内已有元素出界回弹。本文实现的 `replayBack` / `outAmount` 那条链路属于认错需求后的产物，**已整段删除**，画布 move 恢复为纸界钳制；面板项的回落动画见 [标签设计面板拖拽未落纸回到原位动画](./标签设计面板拖拽未落纸回到原位动画.md)。本文保留作为定位过程与「CSS transition 无效 / rAF 补间时间轴基线」两个结论的记录。

自研标签设计器（`label-designer`，非 hiprint 的 `print-design`）。

## 问题

上一步（[标签设计元素拖拽越出右下边界](./标签设计元素拖拽越出右下边界.md)）用「每帧硬钳制」解决元素拖出纸张：拖动中元素贴在纸边停住。用户反馈这不是想要的手感——**他要的是拖动时元素可以自由跟着鼠标出界，松手若越出纸张，元素用动画平滑回到拖动前的位置（本次移动作废）**。

## 设计（用户确认）

- 移动（`move`）**去掉拖动中的实时钳制**，元素自由跟随指针，允许暂时越出纸张。
- 松手判定：越出纸张 → **不落库、不记撤销、不选中态变化**，元素动画回到本次拖动开始前的位置；未越界才写回 store。
- 缩放（`resize`）**不在本次范围**：`resizeGeometry` 的纸界钳制保留，缩放根本不会越界，也就无需回弹。

## 实现

`use-canvas-interaction.ts`：

- 删除 `clampInPaper()`（move 不再钳制，已无调用方），改为纯函数 `outAmount(geo, paperW, paperH)` 计算**越界量**：
  - 某方向元素本身比纸张还大（宽/高 > 纸张）时该方向不计——它无法完全落纸，判定无意义；
  - 回弹判定用「目标越界量 > 拖动前越界量」而不是「越界量 > 0」：这样拖动前就已溢出的元素（旧模板 / 属性面板手输 / paste 偏移）仍能往纸张内拖（越界量减小即放行），不会被永久锁死。
- `applyFrame()` move 分支：直接写 `orig + delta`，不再钳制。
- `onPointerUp()`：算出未钳制的目标 `geo`；`movedEnough && move && outAmount(geo) > outAmount(orig)` 时走 `replayBack()` 并 `return`（跳过撤销快照与 `updateElement`），否则原逻辑写回 + `settleDom()`。
- 新增 `replayBack(d, geo)`：先把内联 `transform` 钉到松手时的实际位移 → `void dom.offsetWidth` 强制 reflow（否则「设 transition + 清空 transform」可能被合并进同一帧直接跳回，不出动画）→ 设 `transition: transform 180ms ease-out` 并清空 `transform`。store 全程未写入，动画终点天然就是原位；`transitionend`（且 `propertyName === 'transform'`）后清掉 transition。
- 抽出 `settleDom(d)` 复用「按 store 权威值恢复 left/top/width/height + 清 transform」的收尾逻辑（纯点击不写 store、Vue 不重渲染，必须手动恢复）。
- `begin()`：拖动前清掉元素上可能残留的 `transition`，否则上一次回弹的 transition 会让本次拖动每帧写 `transform` 都被过渡拖慢。

## 追代：回弹改成 rAF 手动补间（用户手测反馈「松手瞬间跳回、看不到动画」）

### 现象与定位

用户整页刷新后手测：元素**可以**自由拖出纸张（说明 `move` 去钳制的改动已生效、运行时是新代码），但松手时元素**瞬间跳回原位**，看不到任何过渡。

即 `replayBack()` 被正确调用了（元素回到原位的前提是 store 未被写入 + `transform` 被清空，只有这条分支），只是 `transition` 没有产生动画。内联 `transition` + `void dom.offsetWidth` 强制 reflow 这套写法在本项目里不生效，具体被谁中断未能定性（`design-canvas.vue` 的 `elementStyle()` 只写 `left/top/width/height` 不含 `transform`，Vue 的 style patch 不会碰 `transform`；全局样式也无 `transition: none !important`），因此不再追这条链路。

### 决策（用户选择）

按用户给的方案「改用 rAF 补间」重写，**彻底不依赖 CSS transition 生命周期**：回弹与拖拽高频帧走同一条「rAF 直写 `transform`」路径，天然不存在被中断 / 需要强制 reflow 的问题。

### 实现

`use-canvas-interaction.ts`：

- 删掉 `replayBack()` 里整套 transition 逻辑（内联 `transition` 写入、`void dom.offsetWidth` 强制 reflow、`transitionend` 清 transition、`begin()` 里清残留 transition）。
- `replayBack()` 改为 rAF 插值：同步先钉到松手时的实际位移（最后一帧 rAF 可能已被 `cancelAnimationFrame` 取消，不钉会先闪回原位）→ 每帧 `translate(dx * k, dy * k)`，`k = (1 - t) ** 3`（ease-out，起步快、贴近原位收慢）→ `t >= 1` 时清空 `transform` 收尾。终点仍是 store 权威值（= 拖动前位置），store 全程不写入。
- 时长 `BACK_MS` 180 → **220**：原时长在长距离回弹时太短，容易被当成瞬移（用户诉求就是「要看得到这个动画」）。
- 新增补间生命周期 `backRaf` / `backDom` + `stopBack()`：取消未完成补间并把元素归位。调用点两处——`replayBack()` 开头（防抖，避免两次补间抢写同一个 `transform`）、`begin()`（取代原来「清残留 transition」那行，避免补间与本次拖动抢写）。
- 补间帧内的 `backDom !== dom` 兜底：被新的拖动 / 新的回弹接管时立即退出。

### 验证

- `vue-tsc --noEmit --skipLibCheck`：仅剩 `packages/scripts` 的 rimraf 既有错误。
- `oxlint` 针对本次文件：0 warnings / 0 errors。

## 追代 2：回弹时间轴基线改成「首个 rAF 帧时间戳」（改为 rAF 补间后仍报「松手直接消失、没有回位动画」）

### 现象

上一追代的 rAF 补间落地后，用户手测仍反馈：**松手瞬间元素就回到原位（从落点「直接消失」），看不到回位过程**。即：终态正确（元素回到了拖动前位置），但过程不可见 —— 和之前的现象一致，说明**动画确实被跳过了，而不是 DOM 写不进去**。

### 定位（关键点：动画时钟的 0 点取错了）

`BACK_MS` 的进度是用 `performance.now()` 记的基线算的：

```ts
const start = performance.now();          // 在 pointerup 任务里取的「墙钟」
const step = (now: number) => {           // now 是 rAF 首帧的时间戳
  const t = (now - start) / BACK_MS;      // ← 两个时钟不是一回事
```

而 `pointerup` 任务里紧跟着就有一堆同步 + 微任务工作（`store.dragPreview = null` 会触发属性面板的 rAF 重渲染、Vue 的 patch、naive-ui 表单组件更新），**回弹的第一帧必须等这些结束后才被调度**。把「松手那一刻的墙钟」和「第一帧的 rAF 时间戳」一相减，差值直接就跨过了 BACK_MS 的一截：

- 一般情况（一帧 ≈ 16~33ms）：首帧 `t` 就有 0.07~0.15，`k = (1-t)^3` 直接掉到 0.8~0.6，**元素在第一次绘制时就跳掉了 20%~40% 的距离**；
- 主线程被占用更久（低帧率 / 慢机器 / 属性面板重渲染重）：首帧 `t >= 1`，**当场清空 transform，动画 0 帧结束** —— 这就是「松手直接消失」；
- 反向也有坑：rAF 时间戳取的是 vsync 时刻，可能**小于** `performance.now()`，此时 `t < 0`、`k = (1-t)^3 > 1`，位移被**反向放大**，元素会先弹到落点之外（可能弹出视口被 `overflow-hidden` 裁掉）。

上一次用内联 CSS transition 失败也是同一个原因：transition 的计时 0 点是「样式变更事件」（`void dom.offsetWidth` 在 pointerup 任务里就把它提交了），等第一帧真正绘制时，180ms 早跑完了。

### 修法

`replayBack()`：

- 基线改为**首个 rAF 帧的时间戳**：`if (t0 < 0) t0 = now;`，`t = (now - t0) / BACK_MS`。动画 0 点天然对齐「第一帧渲染」，中间被打断多久都不影响，**一定播满 BACK_MS**（也顺带解决了一帧内 `performance.now() > rAF 时间戳` 导致的 t<0 放大）。
- `t` 夹到 `[0, 1]`，`k = Math.min(1, (1 - t) ** 3)`：位移只允许向原位单调收缩，**永不超过松手位置**，从机制上消灭「弹到视口外被裁掉」。
- 保留同步钉住松手位移的那次写入（第一帧到达前元素停在落点，不闪）。
- 顺带：页面长时间不可见（rAF 暂停）后恢复时，`now - t0` 会很大 → `t >= 1` → 直接收尾归位，不会卡在纸外。

### 临时排查日志（确认后删除）

`replayBack()` / `onPointerUp()` 里加了 `[back] release` / `[back] first-frame` / `[back] done` 三条 `console.log`，用来看：走了哪个分支、首帧离松手多久（`delay`）、补间实际跑了多少帧（`frames`）、元素 DOM 是否还在文档里（`connected`）。确认动画正常后删除。

- `vue-tsc --noEmit --skipLibCheck`：仅剩 `packages/scripts` 的 rimraf 既有错误。
- `oxlint` 针对本次文件：0 warnings / 0 errors。

## 追代 3：帧级实测定位——回弹本身没坏，是「跑的不是这份代码」+ 动画曲线观感偏瞬移

### 现象

「追代 2」交付后用户仍反馈「松手直接消失、没有回位动画」，且明确说「**还是一样没区别**」。注意这句话本身是强线索：本追代之前的三次改动**全部落在 `replayBack()` 内部**，如果 `replayBack()` 根本没被调用，用户看到的行为必然「每次都没区别」。

### 定位（先证伪「判定分支没进」，再证伪「代码没生效」）

1. **判定分支**：`outAmount()` 依赖 `d.paperW/d.paperH`（`paperPt()` → `parsePaper()`，任何非法输入都回落 100×150，不会 NaN），且 `outAmount` 用「目标越界量 > 拖动前越界量」判定，正常「拖出纸张」必然命中 `revert`。逐条排除后，判定链路不存在恒假的路径。
2. **不再靠嘴说，改成自己跑**：本机后端起在 `10010`，登录页预填 `LINFLY/123`，于是用 Playwright（系统 Chrome，`channel: 'chrome'`，无需下载浏览器）写了一个临时探针 `scripts/drag-probe.cjs`：登录 → 进标签设计器 → 从左侧面板拖一个元素进纸张 → 把元素拖出纸张右边缘 → 松手，同时用 rAF **逐帧采样 `.element-item` 的 `style.transform` 与 `getBoundingClientRect()`**。
3. **实测结果（决定性）**：徽标 `v4 revert … tween:78f/260ms dom:ok`，采样显示 `left` 从 `968 → 910` 连续变化约 96ms、`transform` 逐帧插值 `57.8px → 0.002px`，且曲线与 ease-in-out 的收尾段完全吻合。
   → **回弹补间确实每帧都在写 DOM，动画真的在跑，代码本身没有坏。**
4. **那就是「跑的不是这份代码」**：`netstat` 发现机器上同时有 **4 个 dev server**（9111/9112/9113 是历史会话遗留的僵尸实例，9114 是本次新起的）。历史日志里还出现过 `FSWatcher` 崩溃（`Error: UNKNOWN: unknown error, stat 'E:\LINFLY\TMS\user-admin-web\.junction-test'`）。Vite 的模块转换缓存只靠 watcher 失效，**watcher 一旦死掉，即使整页刷新，dev server 也会一直吐旧模块**；用户浏览器里的那个 SPA 只要没被真正重新加载（模块图不换），后面几次改动全都进不去。
   → 已 kill 掉 `29592/25616/27816/13636` 四个 PID，只重新拉起**一个**干净实例（`9111`，PID 24380），并再次用探针确认这份实例发的是新代码（拿到 `v4` 徽标）。

### 顺带修掉的两个真问题

- **结算/回弹起点改为「最后一帧真正写进 DOM 的几何」**：`DragState` 增 `lastGeo`，`applyFrame()` 每帧记录；`onPointerUp()` 的 `geo` 取 `d.lastGeo ?? (pointerup 重算)`，`movedEnough` 也改为按几何差值判定（含宽高，让 resize 的 e/s/w/n 边手柄只改尺寸时也能正确计入）。
  原实现拿 `pointerup` 的 `clientX/clientY` 重新算一遍：最后一帧的 rAF 常被 `cancelAnimationFrame` 取消（松手比帧快），天然差一帧；更糟的是 `pointerup` 坐标在部分环境不可靠，差值会被「钉住松手位移」那一次写入放大成**起点跑到屏幕外**——元素一闪就没，且回弹过程基本都在视口外，看不见。现在起点的唯一权威是「用户眼睛最后看到的位置」。
- **回弹曲线 `(1-t)^3`（ease-out）→ cubic ease-in-out，时长 220 → 260ms**：ease-out 起手就打满速度，60Hz 下 **61% 的距离在前 3 帧走完**，短距离拖拽会被当成瞬移（这正是「看不到动画」的观感来源之一）。ease-in-out 两端收速，`k = t<0.5 ? 1-4t³ : (2-2t)³/2`，`k ∈ [0,1]` 恒成立，仍然只向原位单调收缩、不会弹过松手位置。

## 遗留（未纳入本次范围）

- 缩放（`resize`）仍是纸界钳制（贴边停住），与 move 的自由出界 + 回弹手感不一致；如需统一可另开。
- 拖动中越界没有任何视觉提示（如变红/半透明），越界与否只在松手瞬间体现。
- 属性面板手输 X/Y/宽/高、复制/粘贴偏移、`addElement` 落点仍无钳制（沿用上次遗留）。
