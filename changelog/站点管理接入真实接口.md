# 站点管理接入真实接口

> 用户："站点管理开始改，去掉mock数据改成调用真实接口/site/query"；后续补充：范围=全部 CRUD 都切（列表 + 新增 + 编辑 + 删除，另加 /site/get）；"先都不要（状态/站点类型筛选），帮我把接口先接好"。

## 后端接口合约（用户提供）

- 实体 Schema（MongoDB）：`code`(编号，必填) / `name`(名称，必填) / `concat`(联系人) / `phone`(电话) / `workTime`(工作时间) / `note`(备注) / `startPlace`(默认出发地) / `address`(仓库地址) / `siteType`(0-分公司 1-总公司，default 0) / `creatorId` / `creator` / `updateId` / `updateBy` / `createDate`(毫秒时间戳) / `updateDate`(毫秒时间戳)；主键为 `_id`（字符串 uuid）。
- `POST /site/query` 请求 `{ page, size, keyword /* 按 code、name 查 */, fields? }`，其他条件放 `where` 对象；返回 `{ errcode, errmsg, ret: { list: [...], total } }`，实测列表项仅含 `siteType/_id/code/name/createDate/updateDate`（联系人类字段可能缺省 → 类型定义为可选）。
- `POST /site/create`、`POST /site/update`（含 `_id`）、`POST /site/delete`、`POST /site/get`。
- **无独立 `status` 字段**；用户确认状态/站点类型筛选本轮都不做。

## 关键定位：flat 请求此前从未跑通

`request` 来自 `@sa/axios` 的 `createFlatRequest`（`packages/axios/src/index.ts:142-175`），返回扁平结构 `{ data, error, response }` 而**不是裸数据**。旧 `system-manage.ts` 的 PROD 分支直接 `return request(...)`，而各页面 `useVxeTable.transform` 直接读 `r.records` —— 读到的是包裹层的字段，恒为 undefined。DEV 走 mock（裸数据）才正常，**说明真实接口路径此前从未真正验证过**。本次站点切换按正确姿势解包：页面 api 闭包内 `const { data, error } = await fetchGetSiteList(...)`，`error || !data` 时返回空列表（错误提示已由 request 的 onError 统一弹出），成功返回 `data`（即 `ret:{list,total}`），`transform` 改读 `r.list`。
