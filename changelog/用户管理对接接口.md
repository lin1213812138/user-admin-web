## 一、后端接口调研（tms-user `/tms/api/v1/web/user/*`）

| 接口                      | 说明                                                                                                                                                                                                       |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /user/query`        | `queryCommon` 分页查询：`page/size/keyword/keywordFields(固定 name、fullName、account)/where`，返回 `ret:{ list, total }`；service 未限制 fields（全字段）+ `fillName` 回填 `group/role/site` 三个名称字段 |
| `POST /user/get`          | `{ _id }` → 单个完整用户（含回填名）                                                                                                                                                                       |
| `POST /user/create`       | 必填 `account`、`password`、`siteId`（validate）；`account` + `name` 唯一（uniqField）；后端自动写 `upperAccount`、密码走 model virtual 加密                                                               |
| `POST /user/update`       | `{ _id, ... }`；**改自己的密码后端会强制重新登录（logout）**；account/name 变更做唯一校验                                                                                                                  |
| `POST /user/delete`       | `{ _id }` **单条删除**；管理员账号(accountType)/本人/绑定了客户的业务员会被后端拒绝                                                                                                                        |
| `POST /user/manage/query` | 按站点分组的管理视图（site.userList），本轮**不用**，列表页走 `/user/query` 平铺                                                                                                                           |

另有 `/role/query`（queryAllCommon 全量 `{list}`，角色字段为 `name`）可给抽屉角色下拉用。

## 四、风险 / 待确认点

1. **idCard 精度**：后端 `Number`，18 位身份证超 `Number.MAX_SAFE_INTEGER` 丢精度。本轮方案：前端按字符串输入、提交时转 Number（提示风险）；根治需后端改 String（另行安排）。
2. `/user/query` 返回全字段（model `omitFields` 已排除 hashedPassword/salt），列表不额外做字段裁剪。
3. 批量删除为前端逐条调单条接口（后端仅单条）。
4. 编辑直接用行数据 or 先 `/user/get`：按 site 页惯例**先 get 再回填**。
