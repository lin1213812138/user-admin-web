# 问题类别接口对接

日期：2026-09-19

## 背景

用户提供 `ProblemGroupSchema`（name 类别名称必填且唯一 / desc 详细描述 / note 处理办法 / status 0-1）与老系统截图（列：类别名称/详细描述/处理办法/状态/操作，仅「输入类别名称搜索」一个关键字框），要求接入真实接口。

## 定位

- 后端 `tms-user/lib/api-v1-web/problem-group` 已有 `/problem-group/query|get|create|update|delete` 路由：
  - `query` → `queryCommon`，service 内固定 `keywordFields: ['name']`；**读 `page`（非 current）**；status 过滤需放进 `where`
  - `delete` → `batchDeleteCommon`，校验 `ids: string[]`
  - `create/update` 校验 `name` 必填；service 层 `uniqField: 'name'`（重名报 EXISTS）
- 前端 `ProblemCategory.vue` 原走 `MasterDataArchive` + 本地 mock（`data-manage-archive` 把 problem-category 列在「后端未实现」），且配置含 `code`/`remark`，与 Schema 不符。

## 方案（沿用 currency / sales-terms 等真实档案范式）

1. `service/api/data-manage-archive/index.ts`：新增 `fetchGetProblemGroupList / fetchCreateProblemGroup / fetchUpdateProblemGroup / fetchDeleteProblemGroup`；`archiveApiMap['problemCategory']` 由 mock 切换为真实函数；移除 problemCategory mock 工厂；注释 8→7 个未实现档案。
2. **分页映射**：后端 `queryCommon` 只读 `page`，无 `current→page` 转换，故 list 函数显式发 `{ page: current, size, keyword, where }`（status 非空时拼 `where.status`）；与 `data-manage-bl` 传参习惯一致。
3. `ProblemCategory.vue` 配置对齐 Schema：去掉 `code`/`remark`；列 = 类别名称(detail) + 详细描述 + 处理办法（status/createTime 由 MasterDataArchive 自动追加）；搜索仅关键字（对齐截图，去掉状态下拉）；表单 name(必填)/desc(textarea)/note(textarea)；`createDefault` `{ name:'', desc:'', note:'', status:1 }`（status 不进表单，与 goods-category 一致）。
4. 类型 `BusinessProblemCategory` 改为 `{ name; desc?; note? }`（移除 code）；i18n `business.problemCategory` 补 `name/desc/note/namePlaceholder`，`typings/app.d.ts` 的 `App.I18n` 同步。

## 结果

typecheck 0 / lint 0 error（link.vue 2 既有 warning）/ fmt / build:test 通过。

## 备注

- currency 等真实档案直接透传 `current`，后端同样读 `page`，分页实际可能未生效（返回全量）——既有问题，本次未改动；问题类别按正确方式映射。
- 老系统状态列是「启用/禁用」开关样式，本页沿用 MasterDataArchive 的 status NTag 展示。
