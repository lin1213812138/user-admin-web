# 设置模块按文件夹归类

## 用户诉求

用户贴 `src/views/system-manage/setting/modules/trace-capture` 目录截图（9 个文件平铺）：「怎么不按文件夹区分，这样太乱了，只要文件夹里面不出现 index.vue 就行了」。

两问确认：

1. 范围：先只改 `setting`（全项目盘点结果里暂不动 print-design / home / login 等）。
2. 命名：按子 tab key 命名（目录 `track-network` 等）并同步把 `TraceConfig*` 改名为 `TrackNetwork*`。

## 定位：elegant-router 的页面扫描规则（源码核实）

`@elegant-router/core@0.3.8` 的默认配置（`node_modules/.pnpm/@elegant-router+core@0.3.8/.../dist/index.mjs`）：

```
pageDir = 'src/views'
pagePatterns = ['**/index.vue', '**/[*].vue']
pageExcludePatterns = ['**/components/**']
```

结论：

- 只有 `index.vue`（以及 `[id].vue` 这类动态参数文件）会被当成页面生成路由；
- 任意深度的**纯分组文件夹**，只要不含 `index.vue` 就不会被扫到 —— 私有子组件可以安全留在 `views` 内按文件夹分组，**不需要**挪去 `src/components`（与「MasterData 移回 views 的 modules 目录」的结论一致）；
- 反之，分组目录里若出现 `index.vue` 会凭空生成路由（进路由表、可能进菜单）。

## 实施

最终结构：

```
setting/modules/trace-capture/
├── TraceCapture.vue                 # 入口，留在原位（setting/index.vue 引用不变）
├── track-network/    TrackNetworkTable.vue / TrackNetworkDrawer.vue
├── track-transform/  TraceTransformTable.vue / TraceTransformDrawer.vue
├── track-keyword/    TraceKeywordTable.vue / TraceKeywordDrawer.vue
└── capture-time/     CaptureTimeTable.vue / CaptureTimeModal.vue
```

- 移动：PowerShell `Move-Item`（本机 `git mv` 报 ENOENT），8 个文件按上表落位并新建 4 个子目录；
- 重命名：`TraceConfigTable.vue` / `TraceConfigDrawer.vue` → `track-network/TrackNetworkTable.vue` / `TrackNetworkDrawer.vue`；其余文件仅移动、文件名不变（`Table → Drawer` 是同目录相对引用，整体移动后路径天然有效）；
- 代码改动仅 8 行：`TraceCapture.vue`（4 行 import + 1 行注释 + 1 行模板标签）、`track-network/TrackNetworkTable.vue`（import 标识符 + 模板标签）；
- 边界：`service/api/trace-config`、`typings` 里的 `TraceConfigItem` 等属于后端域命名，与目录归类无关，不动。

## 坑

同一文件的多处 `replace_in_file` 在同一批次并行下发会互相覆盖（各自基于同一份原文写回，后写的覆盖先写的）：本次 `TraceCapture.vue` 的 import 块被同批次的注释/模板两次编辑挤掉、`TrackNetworkTable.vue` 的 import 行被模板编辑挤掉，靠 typecheck 报 TS2307 才发现。**同一文件的多处改动必须串行执行。**
