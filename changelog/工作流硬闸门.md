# 工作流硬闸门（违规回滚 + 三层强制机制）

> 日期：2026-09-20 ｜ 状态：已实施（hooks 层待 IDE/CLI 侧生效条件确认）

## 1. 事件与用户诉求

- 用户指令：收货渠道「操作栏（新建渠道 / 编辑 / 停用 / 删除 / 绑定录单格式）+ 绑定录单格式弹窗」。
- **Agent 违规**：未做 `using-agent-skills` 判定、未等用户确认 spec，直接把 spec 当实施记录，边写边改代码。
- 用户指出两点：**「你完全没按我定的步骤，为什么直接改代码？」**、**「你不能让我每次都提醒，能不能强制规定」**。

## 2. 违规根因（对照 AGENTS.md 规则 2）

| 规定步骤                                                  | 实际行为                                          |
| --------------------------------------------------------- | ------------------------------------------------- |
| ① `using-agent-skills` 判定技能链                         | 跳过                                              |
| ② `spec-driven-development` 产出 spec → **用户确认 spec** | 把 `ask_followup_question` 的选择当成「设计确认」 |
| ③ 确认后才 PLAN → IMPLEMENT                               | 边写 spec 边实现，spec 沦为事后文档               |

本质：把规则当「提示词」而非「闸门」——没有把「用户确认 spec」做成必须停下等待的检查点。

## 3. 决策（用户确认）

| 问题         | 结论                                                                                                                       |
| ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 强制机制     | **三层硬约束**：`.codebuddy/rules` 规则 + `AGENTS.md` 硬闸门段 + spec 状态位；并探测 IDE hooks，支持则加 `PreToolUse` 拦截 |
| 违规代码处理 | **全量回滚**到 spec 待确认（禁 `git checkout`，逐项反向编辑，避免抹掉用户未提交的改动）                                    |

## 5. 三层硬约束（已落地）

1. **规则层**：`.codebuddy/rules/workflow-gate/RULE.mdc`（`alwaysApply: true`）——G0…G6 闸门表 + 5 条禁令 + 例外 + 自动口令。
2. **项目层**：`AGENTS.md` 顶部新增「⛔ 硬闸门（Hard Gate）— 违反即回滚」段（闸门表 + 禁令 + 回滚纪律 + 口令 + hooks 说明）。
3. **产物层**：spec 状态位强约定 —— 新建 spec 一律写 `> 🔴 状态：待确认（禁止实现）`；仅在用户明确确认后才可改成 `> ✅ 状态：已确认（用户确认：<原话摘要>）`，这是写生产代码的唯一前置条件。

## 6. 第四层：hooks 强制（脚本已验证，运行时待激活）

- `.codebuddy/hooks/gate-pre-write.mjs`（`PreToolUse`）：拦截对 `src/**`、`packages/**`、`build/**` 的写入，退出码 2 + 回传修复步骤；放行条件是 `.codebuddy/gate/approved.json` 存在且 mtime ≥ `docs/superpowers/specs` 下最新 spec —— **新写一份 spec 会自动关门**，因此每个任务都必须重新等确认。
- `.codebuddy/hooks/gate-user-prompt.mjs`（`UserPromptSubmit`）：每次用户消息自动注入闸门提醒（**用户不必再重复叮嘱**）；命中口令（`确认 spec` / `spec 已确认` / `设计通过` / `按这个实现` / `开始实现`）时写审批文件开闸。
- `.codebuddy/settings.json`：注册上述两个 hook；`.codebuddy/.gitignore` 增加 `gate/`、`tmp/`（审批文件与日志不入库）。
- **自测证据**（临时 Node 测试脚本，无 shell 引号干扰，测完已删）：
  | 场景 | 结果 |
  | ---- | ---- |
  | src 写入（未确认） | `exit=2` → 拦截并回传步骤 ✅ |
  | changelog 写入（非受保护路径） | `exit=0` 放行 ✅ |
  | UserPromptSubmit「确认 spec」 | `exit=0` + 输出提醒（注入上下文）✅ |
  | src 写入（已开闸） | `exit=0` 放行 ✅ |
  | 清理审批文件后 src 写入 | 重新 `exit=2` ✅ |
- **运行时探测结论**：写入探针后 `.codebuddy/tmp/hooks.log` **未生成** ⇒ 本 IDE 会话未调用 hooks。官方文档中 hooks 属 CodeBuddy **Code（CLI）** 能力且为 Beta：配置在会话启动时拍快照、外部改动需在 `/hooks` 面板审核后才生效、Windows 下强制走 Git Bash。
  **激活方式（待用户决定）**：在 CodeBuddy CLI 中打开本项目 → `/hooks` 审核启用 → 新会话生效。
  未激活期间，第 1–3 层（规则 + AGENTS.md + spec 状态位）仍会生效。

## 7. 后续使用方式

- 我（Agent）开工即读硬闸门；开发类任务先出 spec 并停下等你确认。
- 你只需在确认设计时回一句口令（如「确认 spec」），无需再复述流程。
- 需要我破例走快速通道时，明说「直接改，不用流程」即可（属规则例外）。
