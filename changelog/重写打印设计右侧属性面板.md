# 重写打印设计右侧属性面板

> 日期：2026-09-11
> 设计文档：[docs/superpowers/specs/2026-09-11-print-design-property-panel-design.md](../docs/superpowers/specs/2026-09-11-print-design-property-panel-design.md)

## 根因（推翻初版方案 A 与方案 B）

1. **选中事件名用错（即用户报告的 bug）**：初版监听 `BuildCustomOptionSettingEventKey_<id>`。经 `vue-plugin-hiprint` 源码确认，元素选中实际触发 `getPrintElementSelectEventKey()`（内部 `PrintElementOptionSettingPanel` 构造时监听它 → `buildSetting`）；`BuildCustomOptionSettingEventKey` 仅用于纸张/页码等**全局设置**，元素选中不会触发它 → 监听收不到 → 选中后右侧无反应。
2. **字段元数据混淆两个 API**：初版以为 `getPrintElementOptionTabs()` 的 item 含 `type/title/options` 可重建。实际该 API 只按 `name` 从 `OptionItemManager` 取共享 item 单例，**只有 `name`**，没有 type/options。但 `getConfigOptions()` 返回**原始字段配置**（含 `type/title/options`），简单字段的 type 与下拉项完全可得。

## 结论

采用 **方案 D：简单字段 Naive 控件 + 复杂字段 hiprint 原生控件兜底**。

- **数据源**：`element.getConfigOptions()`（原始字段配置，含 `type/title/options`）+ `getPrintElementOptionTabs()`（复杂字段拿 manager item 单例）。
- **简单字段**（text/textarea/number/select/checkbox/color/image）→ Naive 控件（统一风格 + 暗黑 + i18n 标题）。
- **复杂字段**（coordinate 坐标 / widthHeight 尺寸 / border 边框 / table 列配置 / 未知 type）→ `item.createTarget()` 原生控件兜底。
- **机制**：监听 `getPrintElementSelectEventKey_<id>`（选中）+ `clearSettingContainer`（清空）；写回用 `element.updateOption(name, value)`（重绘 + 广播 `hiprintTemplateDataChanged`）。**不调 `element.submitOption()`**（源码显示它会批量改同类型其它选中元素，有副作用）。
- **写回时机**：`change` 实时写回，去掉「确定」按钮。
- **tab 标题**：本地映射（basic/style…→`$t`）+ fallback 原中文。

## 关键决策

1. `onElementSelect` 改监听 `getPrintElementSelectEventKey`（修正根因①）。
2. 简单字段按 `type` 映射 Naive 控件，`v-model` 绑 `element.options[name]`，`change` → `updateOption`。
3. 复杂字段用 `item.createTarget()` 生成 hiprint 原生控件，外观用 CSS 接近 Naive；`change`/`input` → `updateOption(name, item.getValue())`。
4. 多选本期只驱动「最后选中的单个元素」；table 等复杂字段由 hiprint 原生控件自带交互处理，无需降级占位。
5. item 是全局单例，`createTarget` 覆盖 `item.target`；切换元素时清空宿主 div 的 `innerHTML` 即可安全清理旧 DOM 与事件。
