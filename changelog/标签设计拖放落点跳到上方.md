# 标签设计拖放落点跳到上方

## 现象

用户把元素放到画布纸张下方，松手后元素跳到纸张上方约 1/3 处。

## 根因

几何单位 mm→pt 迁移的漏改点。`design-canvas.vue` 的 `onDrop` 落点换算：

```ts
x = ((e.clientX - rect.left) / rect.width) * size.w; // size.w 来自 parsePaper，单位 mm
```

算出的落点是 **mm 坐标**，直接 `store.addElement` 写入后按 **pt** 语义解释 → 坐标整体缩小 72/25.4 ≈ 2.83 倍。放到 y≈140mm 处被存成 140pt ≈ 49mm，元素显示在上方，与截图吻合。

排查遗漏原因：全局按 `mm`/`PX_PER_MM` 字面量搜索时，该处通过 `parsePaper` 返回值间接引用 mm、不含字面量，被漏掉。

## 同类漏改点（一并修复）

1. `index.vue` `moveSelected`：方向键钳制上限 `paper.w - el.width` 把 mm 纸张尺寸与 pt 元素宽混减，上限偏小 2.83 倍 → 元素无法用方向键移到纸张下部。改为 `mmToPt(paper.w) - el.width`。
2. `store` `duplicateElement` / `pasteElement`：复制错开偏移 `+= 4` 本意 4mm，pt 语义下变 4pt（≈1.4mm）。改 `mmToPt(4)` 保持手感。

## 验证

`pnpm typecheck` 通过、lint 无错误。

## 经验

单位迁移类改动不能只按单位字面量搜索：凡 `parsePaper()` 返回值流入元素几何的调用点都要逐个核对（本次按数据流排查又发现 2 处）。
