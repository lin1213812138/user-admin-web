# 提单资料-航线表单：去掉状态、补排序、全量国际化

> 日期：2026-09-19
> 范围：仅「提单资料 → 航线（bl-route）」模块；其余 5 个子档案（港口/航名航次/地址簿/柜型/轨迹配置）不动。

## 需求背景

用户贴「新增航线」抽屉截图，要求：

1. 表单里**去掉「状态」**字段（直接走后端默认值 `1` 启用即可）。
2. 表单**补上「排序」**字段（原遗漏）。
3. 截图里表单 `label` 大量硬编码中文（`航线类型`/`中文名`/`英文名`/`空运`/`海运`），要求**全部走 `$t` 国际化**。
4. 列表 `BlRoute.vue` 的列标题（`中文名`/`英文名`/`航线类型`）与单元格标签（`海运`/`空运`）同样硬编码，一并进行国际化。

> 用户明确：只从「表单」去掉状态；列表的「状态」列与搜索栏「状态」筛选**保留不动**（旧记录 status=0 仍显示禁用，新记录默认启用）。

## 方案决策

- 后端零改动：`createCommon`（`model.create(body)`）不传 `status` 时取默认 `1`；`updateCommon`（`updateOne`）不传 `status`/`order` 时保留原值、缺失落默认 `0`。因此去掉表单状态字段后记录默认启用，排序落库为用户值或默认 `0`。
- 国际化键命名沿用仓库约定：本仓库 `排序` 通用键名是 `order`（参考 `page.manage.role.order`），新增键挂在 `page.dataManage.bl.blRoute` 下。

## 实施

### 1. i18n（`src/locales/langs/zh-cn.ts` + `en-us.ts`）

`page.dataManage.bl.blRoute` 新增：

```
nameCn: '中文名' / 'Chinese Name'
nameEn: '英文名' / 'English Name'
routeType: '航线类型' / 'Route Type'
order: '排序' / 'Sort'
routeTypeOption: { air: '空运' / 'Air Freight', sea: '海运' / 'Sea Freight' }
```

### 2. 类型约束（`src/typings/app.d.ts`）

`App.I18n.Schema.page.dataManage.bl.blRoute` 补充上述新键的类型声明（`$t` 键受 `I18nKey` 强约束，缺声明会报 TS 错）。

### 3. 抽屉表单（`src/views/data-manage/bl/modules/bl-route/BlRouteOperateDrawer.vue`）

- 删除 `status` 的 `switch` 表单项（及其 `common.status`/`common.enable`/`common.disable` 文案）。
- 新增 `order` 数字项：`{ key: 'order', label: $t('...blRoute.order'), type: 'number', span: 24 }`，位置在「英文名」之后、「备注」之前。
- `routeTypeOptions` 的 `空运`/`海运` 改为 `$t('...routeTypeOption.air' / '.sea')`。
- `formItems` 的 `航线类型`/`中文名`/`英文名` 改为对应 `$t` 键。
- `emptyForm()`：`{ ..., routeType: 1, order: 0, note: '' }`（去掉 `status`，补 `order`）。
- `openEdit(row)`：去掉 `status: row.status ?? 1`，改为 `order: row.order ?? 0`。

### 4. 列表（`src/views/data-manage/bl/modules/bl-route/BlRoute.vue`）

- 列标题 `中文名`/`英文名`/`航线类型` → `$t('...blRoute.nameCn' / '.nameEn' / '.routeType')`。
- 单元格 `routeType` 标签 `{{ '海运' : '空运' }}` → `$t('...routeTypeOption.sea') : $t('...routeTypeOption.air')`。
- 列表「状态」列与搜索栏状态筛选**保持不变**。

## 验证

- `pnpm typecheck`：0 错误。
- `pnpm lint`：0 错误（仅 `link.vue` 2 个历史 warning，与本次无关）。
- 列表状态列、搜索栏状态筛选仍正常显示。

## 追加（2026-09-19）：状态改回下拉选择

用户后续要求：「状态还是加上吧，改下下拉选择」——即把之前去掉的状态字段恢复，但由 `switch` 改为 `select` 下拉。

### 实施（`BlRouteOperateDrawer.vue`）

- 新增 `statusOptions`：`[{ label: $t('common.enable'), value: 1 }, { label: $t('common.disable'), value: 0 }]`。
- `formItems` 在「排序」之后、「备注」之前补回 `status` 项：`{ key: 'status', label: $t('common.status'), type: 'select', required: true, span: 24, options: statusOptions.value }`。
- `emptyForm()` 恢复 `status: 1`；`openEdit(row)` 恢复 `status: row.status ?? 1`。
- 列表/搜索栏状态字段不变。

### 验证

- `pnpm typecheck` 0 错误；`pnpm lint` 0 错误（link.vue 2 既有 warning）。
