# 录单格式新增：字段映射不默认全选

> 状态：已实施（2026-09-19）

## 用户诉求

「打开新增界面，字段映射不要默认全选。」

## 定位

- `input-format-drawer.vue` 的 `loadDrawer()` 新增分支：`applyBaseFieldList(await fetchDefaultTemplateFieldList())`。
- `applyBaseFieldList` 内部把底稿整体交给 `fieldListToMapping()`，而该方法遵循「项存在 = 显示」语义 ⇒ 底稿里有多少项就勾多少项，于是新增界面一进来就是全选。
- 底稿（拉取「是否默认」模板的 `fieldList`，无默认模板时为空数组）本身有存在价值：`mappingToFieldList()` 会按底稿项原样透传 `keyMap` / `options` / `width` / `renderName` 等附加属性，丢掉底稿会让用户后勾的字段变成 `fields-config` 的最小项。

## 决策

用户在三个选项中选定：**保留底稿里的必填字段**（默认勾选默认模板中 ★ 标记为必填的字段，其余不勾）。

技术补全：`disabled === true` 的**锁定字段一并保持勾选**。这类字段在编辑器里是 disabled 复选框（`buildNavGroups` 锁定勾选、`mappingToFieldList` 对锁定项强制保留），若初始不勾会形成「界面看着没选、保存却被强制带上」的错位。

## 实施

| 文件                      | 改动                                                                                                                                                                                                                   |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `field-list-mapper.ts`    | 新增导出 `initialMappingOf(fieldList)`：先 `fieldListToMapping()` 得到全量勾选态，再按 `required === 1 \|\| disabled === true` 过滤每个分组的 `show`/`required`，空分组不落键（`FieldMapping` 对缺省分组本就视为全空） |
| `input-format-drawer.vue` | 新增分支不再调 `applyBaseFieldList`，改为 `baseFieldList = draft` + `fieldMapping = initialMappingOf(draft)`；`fetchDefaultTemplateFieldList` 的注释去掉「含勾选状态」表述                                             |

编辑态不受影响：仍走 `fieldListToMapping(data.fieldList)` 全量回显（已保存的 fieldList 就是该格式的勾选结果）。

## 验证

- `pnpm typecheck`：0 错误。
- `pnpm lint`：0 error（仅 `components/common/link.vue` 2 个既有 warning）。
- `pnpm fmt`：通过。
- 预期效果：打开新增抽屉时，只有默认模板里 ★ 的字段（以及客户端固定字段）是勾选态，其余全部为空，需手动勾选。
- 边界：无默认模板 ⇒ 底稿为空 ⇒ 映射全空；用户手动勾选某字段时 `FieldMapping.toggleField` 仍会按既有行为同时把它置为必填（未改动）。
