## 定位

- 「新增加收」弹窗是**渠道加收**（渠道报价 → 报价设置）与**承运网络附加费**（发货资料 → 承运网络 → 附加费）**共用**的 `FeeExtOperateDrawer.vue`（承运网络侧 `CarrierFeeExtDrawer.vue` 以 `:channel-id` 传承运网络 \_id 作 `refId` 复用它）；
- 文案全部来自 i18n `page.channelQuote.quoteSetting.feeExt.*`（zh-cn），改文案即可，零业务逻辑改动；
- 附加费列表无操作栏，但编辑/删除能力全部现成（共用抽屉已实现 `openEdit`；`fetchDeleteChannelFeeExt` 已有；后端 `/channel-fee-ext/update|delete` 已核）。

### 2. 关键技术点：`expr` 魔法值解耦（`FeeExtOperateDrawer.vue`）

- 后端 `tms-user/lib/common/services/channel-fee-ext.js:47`：`if (!expr || expr == '无条件加收') return true;` —— `expr === '无条件加收'` 是**计费恒生效的契约魔法值**；
- 现状 `emptyForm()` 与 `conditionExpr` 直接把 i18n 文案当 `expr` 提交；若只改 i18n，提交值会变「无条件」→ 后端判非无条件 → **无条件费用永不生效（隐性 bug）**；
- 改法：新增常量 `EXPR_UNCONDITIONAL = '无条件加收'`，两处改用常量；下拉 label（i18n「无条件」）与提交值解耦。后端与存量数据零影响。

### 3. 操作栏（`CarrierFeeExtDrawer.vue`）

- `<Table>` 加 `show-action :action-width="140"` + `#action` 插槽：
  - **编辑**：`LButton primary text` → `feeExtDrawerRef?.openEdit(row)`（复用共用抽屉，提交走 `/channel-fee-ext/update`，带 `_id` + `refId` + `name`）；
  - **删除**：`LButton error text` + `popconfirm` 二次确认 → `fetchDeleteChannelFeeExt(row._id)` → `common.deleteSuccess` → `reload()`；
- 与渠道加收面板（`fee-ext/index.vue`）交互完全同款，复用 `common.edit` / `common.delete`，零新增 i18n 键；组件头注释补操作栏说明。
