# 操作轨迹配置单独提为一个模块

日期：2026-09-17
设计文档：[docs/superpowers/specs/2026-09-17-operation-trace-tab-design.md](../docs/superpowers/specs/2026-09-17-operation-trace-tab-design.md)

## 需求与确认

用户：「操作轨迹配置单独提为一个模块」。

- 现状：「系统设置」页左侧竖 tab 共 6 项，其中「轨迹抓取配置」内部有 4 个子 tab：追踪网络 / 轨迹改造 / 轨迹关键词 / **操作轨迹**。操作轨迹的表格与抽屉（`OperationTraceTable.vue` / `OperationTraceDrawer.vue`）物理上在 `modules/trace-capture/` 目录里，但 service 已独立（`service/api/operation-trace`）。
- 澄清提问（层级）：三选一（A 系统设置内的顶级 tab / B 系统管理下的独立菜单页 / C 仅代码层面独立目录），用户选 **A**。
- 澄清提问（i18n）：两选一（甲 复用现有 key / 乙 新建独立命名空间），用户选 **甲** —— 只新增 title，列/表单/抽屉文案继续引用 `traceCapture.*`（这些 key 是整个轨迹域共用：`createTitle` 一个 key 四个抽屉在用、`col.timeFormat` 被轨迹改造与操作轨迹共用）。

## 方案与实施

1. **组件挪位 + 重命名**（`Move-Item`，Windows 不用 `git mv`）：
   - `modules/trace-capture/OperationTraceTable.vue` → `modules/operation-trace/OperationTrace.vue`（主组件对齐模块命名习惯）
   - `modules/trace-capture/OperationTraceDrawer.vue` → `modules/operation-trace/OperationTraceDrawer.vue`
   - 组件内部零逻辑改动；`cacheKey: 'operation-trace'` 保持不变 → 已有列配置缓存继续生效；目录下**不能用 `index.vue`**（会被 elegant-router 当页面生成路由）。
2. **`trace-capture/TraceCapture.vue`**：删 `OperationTraceTable` import、`SubTabKey` 联合类型（`active` 直接用 `Api.SystemManage.TraceCaptureCategory`）、`operationTabLabel` 与最后一个 `<NTabPane name="operation-trace">`，头注释同步更新（仅剩 3 个子页）。
3. **`setting/index.vue`**：`tabs` 末尾追加 `{ value: 'operation-trace', label: $t('page.manage.setting.operationTrace.title') }`；`componentMap` 追加 `'operation-trace': OperationTrace`。`?tab=operation-trace` 由 `syncTabFromQuery` 的 `tabs.some` 校验自动支持。
4. **i18n 三处同步**（zh-cn.ts / en-us.ts / typings/app.d.ts 的 I18n Schema）：新增 `page.manage.setting.operationTrace.title`（操作轨迹配置 / Operation Trace Config）；删除已无引用的 `traceCapture.subTab.operationTrace`。

不改动：service / mock / 类型声明 / 表格列 / 抽屉字段 / 路由 / 菜单 / `contentShowPadding` 排除数组。
