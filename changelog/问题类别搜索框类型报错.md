# 问题类别搜索框 `v-model:value` 类型报错

## 现象

`src/views/data-manage/business/modules/problem-category/ProblemCategory.vue` 的搜索区 `NInput` 报类型错误：

```
不能将类型 "unknown" 分配给类型 "string"
```

代码位置：

```vue
<template #search-action>
  <NInput v-model:value="searchParams.keyword" class="w-260px" />
  <LButton type="primary" @click="handleSearch">{{ $t('common.search') }}</LButton>
</template>
```

## 根因

`searchParams` 被声明为：

```ts
const searchParams = reactive<Record<string, unknown>>({
  keyword: ''
});
```

因此 `searchParams.keyword` 的类型是 `unknown`。`NInput` 的 `value` prop 期望 `string | null`，读取时把 `unknown` 传给 `string` 即触发 TS 报错。

## 修复

单字段内联类型 `reactive<{ keyword: string }>` 可用，但字段一多就难维护。按仓库约定把搜索状态抽成命名类型，放在 `src/typings/api/data-manage.d.ts` 的 `Api.DataManage` 命名空间下：

```ts
// typings/api/data-manage.d.ts
type ProblemGroupSearchParams = {
  /** 关键字（后端 keywordFields 固定 ['name']） */
  keyword: string;
};
```

页面引用：

```ts
const searchParams = reactive<Api.DataManage.ProblemGroupSearchParams>({
  keyword: ''
});
```

要点：

- 用 `type`（而非 `interface`）定义，可隐式满足 `Table` 的 `search-model: Record<string, unknown>`，无需额外索引签名。
- 后续新增筛选字段（如 `status`）直接在 `ProblemGroupSearchParams` 内追加，取数 `Object.entries(searchParams)` 与重置 `searchParams.keyword = ''` 逻辑无需改动。

## 验证

- `read_lints` 针对本文件：0 error / 0 warning。
- 全仓 `pnpm typecheck` 目前被 `src/typings/components.d.ts(160)` 的既有语法错误阻塞（`const 'LButton.bak': ...` 非法标识符），与该文件无关，暂无法跑通全量类型检查。
