# 菜单「状态」（select + number 值）选了仍报必填校验失败

> 日期：2026-09-04
> 模块：`src/components/Form/index.vue`（FormWrap 的 `mergedRules`）+ 菜单编辑抽屉 `status` 字段

## 现象

编辑菜单抽屉里，`状态` 下拉框已选中「禁用」（值为数字 `0`），点击「确认」提交时
`NForm.validate()` 仍报「状态必填」，校验不通过。

## 定位过程

1. 阅读 `menu-operate-drawer.vue`：`status` 为 `type: 'select'`，`required: true`，
   `statusOptions` 值为数字 `1`（启用）/`0`（禁用），默认 `model.status = 1`。
2. 阅读 `Form/index.vue` 的 `mergedRules`：`item.required` 为真时自动生成的必填规则为
   `{ required: true, message, trigger: ['change', 'blur'] }`；
   仅当 `item.type === 'number'` 时才补 `type: 'number'`。`status` 是 `select`，故未补 `type`。
3. 纯推理一度走入误区：单独测试 async-validator 对数字 `0` 的 `{ required: true }`（无 `trigger`）
   是**通过**的，与报错矛盾。

## 根因（实证确认）

用真实规则隔离复现（Node + `async-validator@4.2.5`）：同样的 `{ required: true, message }`，
**是否带 `trigger` 数组导致结果完全不同**：

| 规则                                               | 值 `0`(number) | 值 `1`(number) | 值 `'0'`(string) | 值 `null` |
| -------------------------------------------------- | -------------- | -------------- | ---------------- | --------- |
| `{ required, message }`（无 trigger）              | PASS           | PASS           | PASS             | FAIL      |
| `{ required, message, trigger:['change','blur'] }` | **FAIL**       | **FAIL**       | PASS             | FAIL      |

原因在 `async-validator` 的 `getValidationMethod`（`dist-node/index.js`）：

```js
var keys = Object.keys(rule);
// 移除 message 后：
if (keys.length === 1 && keys[0] === 'required') {
  return validators.required; // 纯 required → 基于 typeof value 判空（数字 0 正确）
}
return validators[this.getType(rule)] || undefined; // 否则按 type 分发，默认 'string'
```

- **不带 `trigger`**：移除 `message` 后 keys 仅剩 `['required']`，命中纯 `required` 分支，
  按 `typeof value`（`'number'`）判空，数字 `0` 正确。
- **带 `trigger`**：keys 含 `['required', 'trigger']`（2 项），不再命中纯 required 分支，
  落入 `getType()` → 默认 `string` 校验器 → **string 校验器把数字值 `0`/`1` 判定为空** → 报「必填」。

> 注：此前 `菜单排序必填校验不通过.md`（2026-09-01）的 `sort` 已通过补 `type:'number'` 解决——
> 带 `type:'number'` 后落入 `number` 校验器，数字正常。但该修复只覆盖 `item.type === 'number'`，
> `select` + 数字值（如 `status`）依旧按默认 `string` 误判为空。

## 设计（已确认：方案 A — 通用修复 `mergedRules`）

采用通用修复，让 `FormWrap` 自动生成的 required 规则**不再依赖 async-validator 的 `type` 分发**：

- 保留 `required: true`：**仅用于让 naive-ui 显示必填星号**（`mergedRequired = rules.some(r => r.required)`，见 naive-ui `es/form/src/utils.mjs:167`）。
- 新增自定义 `validator` 判空：`null / undefined / ''` 视为空（FAIL），其余（数字 `0`/`1`、字符串 `'0'`/`'1'` 等）视为有值（PASS）。
- 删除原 `if (item.type === 'number') rule.type = 'number'` 分支：自定义 validator 已彻底规避 type 分发，无需再为 number 字段补 `type`。

```ts
const message = item.requiredMsg || `${item.label}必填`;
const rule: FormItemRule = {
  required: true,
  message,
  trigger: ['change', 'blur'],
  validator: (value, callback) => {
    const empty = value === null || value === undefined || value === '';
    if (empty) callback(new Error(message));
    else callback();
  }
};
```

实证（Node + `async-validator@4.2.5`）：`{ required: true, message, trigger, validator }` 对
`0/1/'0'/'1'` 均 PASS；`null/undefined/''` 均 FAIL 且 message 正确显示 `状态必填`。
naive-ui 星号逻辑（`formItemRule` → `hasRequiredRuleRef`）确认保留 `required: true` 即可显示星号，
不会因删掉 `type: 'number'` 而丢失必填标记。

## 实现

- `src/components/Form/index.vue` 的 `mergedRules`：自动必填规则改为 `required: true` + 自定义 `validator` 判空，移除 `type: 'number'` 补充分支。（2026-09-04）
- 空判断覆盖 `null / undefined / '' / 空数组 []`：`checkbox` / 多选必填若初始 `[]` 也判空 FAIL（code review 指出的潜在 gap，仓库当前无 required checkbox 用法，补上防未来误判）。

## 影响面

- 通用组件 `src/components/Form/index.vue` 的 `mergedRules` 自动必填规则生成逻辑。
- 用 `FormWrap` + `required` + **数字值字段**（当前为 `select` 的 `status`、`number` 的 `sort` 等）均受益。
- 需回归：`sort`、`status`、以及其它 `FormWrap` 必填字段（字符串值）不回归。

## 验证手段

- `pnpm typecheck` + `pnpm lint` + `pnpm build`（仓库无单测）。
- 手动：菜单编辑抽屉选「状态=禁用」点确认不再报必填；清空状态报必填。
