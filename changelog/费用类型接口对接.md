# 费用类型接口对接（真实 /fee-type/\* + 收发地址同款布局）

> 状态：**已实施（2026-09-19），待手动冒烟**；设计见 `docs/superpowers/specs/2026-09-19-fee-type-design.md`

## 用户输入

- 提供 tms-user 后端 `FeeType` Schema：`name`（费用名称，必填）/ `order`（排序）/ `scope[]`（使用范围 0-运单应收 1-运单应付 2-提单应付 3-杂支应付 4-杂支应收）/ `status`(0-未启用 1-使用中) / `buildIn`(0-否 1-是) / `sysType`(1-基础运费 … 11-清关费) / `note` / `creatorId` / `creator` / `createDate` / `updateDate`。
- 要求：「费用类型接口对接 …… 做成跟收发地址一样布局就行」。

## 现状定位

- 前端 `views/data-manage/finance/modules/expense-type/ExpenseType.vue` 走 `MasterDataArchive` 通用档案 + `service/api/data-manage-archive` 的**本地 mock**（字段 `code/name/scope/remark`），与真实 Schema 不符：后端**没有 code**、备注字段是 **note**。
- 后端 `tms-user/lib/api-v1-web/fee-type` 已有真实路由 `/fee-type/query|get|create|update|disable`，**没有 delete**；`/fee-type/disable` 是批量置 `status=0`。契约三要点：
  1. `services/fee-type.js` 的 `query` 里 `if (!scene) where.status = 1` —— **不传 `scene` 只能查到「使用中」的记录**，管理页看不到停用项；
  2. `update` 走 `updateCommon({ uniqField: 'name' })`，对内置项（`buildIn=1`）只 `pick(['_id','scope','order','note'])`，其余字段静默丢弃；局部更新（如只切 status）**缺失 name 会进入唯一性判断并写入 `nameUpdate` 脏字段**（同录单格式踩过的坑）；
  3. `disable`（`{ ids }`）→ `batchUpdateCommon`，是软停用而非物理删除。
- 「收发地址」布局 = 独立页面：`useVxeTable` + `<Table>`（`#search-action` 搜索卡片 + `#operation-left/right`）+ `TableColumnConfig` + 命令式 `OperateDrawer`（参考 `business/modules/address/ship-to/ShipTo.vue`）。

## 用户决策（ask_followup 4 问）

1. **操作能力**：操作列 = 编辑 + 停用/启用（走 `/fee-type/update`），工具栏另加「批量停用」（`/fee-type/disable`），**不提供删除**；
2. **内置项**：不允许删除 → 落地为「内置行停用按钮禁用 + tooltip」「批量停用自动跳过内置行并 warning」，且编辑抽屉内**名称/状态只读**（对齐后端白名单，避免界面看着改了实际被丢弃）；
3. **字段范围**：列表 = 费用名称（+「内置」NTag，写法对齐角色管理）/ 使用范围 / 排序 / 状态 / 备注 / 创建人 / 创建时间；抽屉 = 费用名称\* / 使用范围（多选 0-4）/ 排序 / 状态 / 备注；**不展示系统类型（sysType）**，「是否内置」不单独成列而挂在名称后；
4. **搜索条件**：关键字（费用名称）+ 状态 + 使用范围，同一搜索卡片内。

实施补充约定：名称列不做可复制 `detail` 交互；抽屉宽度 520。

## 实施

- **类型** `typings/api/data-manage/finance.d.ts`：`FinanceExpenseType` 换成后端真实字段（含前端 transform 生成的 `createTime`），新增 `FinanceExpenseTypeSearchParams / SaveParams / List`，删掉错误的 `code`。
- **接口** 新建 `service/api/fee-type/index.ts`（真实接口、flat request、调用方解包 `{ data, error }`）：
  - `fetchGetFeeTypeList`：`current → page` 显式映射，`keywordFields:['name']`，恒定传 `scene: 1`，`where.status` / `where.scope` 承载筛选（scope 走 Mongo 数组精确匹配）；
  - `fetchCreateFeeType` / `fetchUpdateFeeType` / `fetchDisableFeeType(ids)`。
- **常量** 新建 `modules/expense-type/constants.ts`：`buildExpenseScopeOptions()`（0-4，builder 内调 `$t`）+ `formatExpenseScope()`（列渲染，空值 '-'）。
- **抽屉** 新建 `modules/expense-type/ExpenseTypeOperateDrawer.vue`：`open(row?)` 命令式 + `@submitted`；表单 费用名称\*(内置只读) / 使用范围(多选,必填) / 排序(number,默认 0) / 状态(下拉,内置只读) / 备注(textarea)；**内置项提交只发 `{ _id, scope, order, note }`**，自定义项发全量。
- **列表页** 重写 `ExpenseType.vue`（收发地址同款布局，仍挂财务资料 tab、权限码与 cacheKey 不变）：
  - 搜索卡片：费用名称输入框（回车即查）+ 状态下拉 + 使用范围下拉 + 搜索/重置按钮；
  - 工具栏：新增、批量停用（未勾选禁用、popconfirm `common.confirmDisable`、自动跳过内置行并 warning）、列设置、刷新；
  - 操作列：编辑、停用/启用（`:type` warning/success，popconfirm `common.confirmDisable/confirmEnable`，内置行 disabled + `NTooltip`）；
  - 停用/启用走 `fetchUpdateFeeType({ _id, name, status })` —— **name 随行回传**规避 uniqField 坑。
- **i18n**：`page.dataManage.finance.expenseType` 重写（name 改「费用名称」，新增 scope/order/builtIn/creator/createTime/builtInDisableTip/scopeOptions/form.\*），`common.batchDisable` 新增；`zh-cn.ts` / `en-us.ts` / `typings/app.d.ts` Schema 三处同步（删掉 code/codePlaceholder）。
- **清理**：`data-manage-archive/index.ts` 删 `expense-type` mock 工厂与 `archiveApiMap` 条目（注释同步：mock 5→3），`DataManageArchiveKey` 移除 `'expense-type'`（全仓已无引用）。
- **生成物**：`typings/components.d.ts` 自动新增 `IconMdiBlockHelper`（批量停用按钮图标 `icon-mdi-block-helper`，unplugin-icons 构建期解析）。
- **不动**：菜单 / 路由 / 权限码（`system:dataFinance:expenseType`）、MasterDataArchive 公共组件与其它档案（account / settlement / declared-goods 仍走原 mock）、后端零改动。
