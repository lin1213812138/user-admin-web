# 轨迹改造：字段改造（异常状态定义表）

日期：2026-09-15
设计文档：[docs/superpowers/specs/2026-09-15-trace-transform-fields-design.md](../docs/superpowers/specs/2026-09-15-trace-transform-fields-design.md)

## 问题定位

用户附原型截图（"这是轨迹改造的字段"）：「系统设置 → 轨迹抓取配置 → 轨迹改造」的字段应为
**排序 / 状态名称 / 时间格式 / 服务地点 / 详细描述 / 抓取轨迹关键词判断定义**，
示例 8 条异常状态（航班延误、船期延误、清关延误、扣关、派送失败、快件丢失、快件破损、其它异常），
带「添加一行」与行内「编辑 / 删除」；第二张截图补充「时间格式」为下拉三选一
（年月日 / 年-月-日 时分 / 年-月-日 时分:秒）。

现状：「轨迹改造」与追踪网络 / 轨迹关键词 / 抓取时间同构，共用 `TraceConfigTable` + `TraceConfigDrawer`
（名称 / 服务器地址 / 系统类型 / 最后编辑 / 编辑时间），与截图不符。

## 方案（已确认）

澄清 4 问的结论：① 只改「轨迹改造」，其余 4 个 tab 保持现状；② 交互沿用抽屉表单范式
（工具栏「添加一行」→ 抽屉新增；行内「编辑 / 删除」+ `NPopconfirm` 二次确认）；
③ 「抓取轨迹关键词判断定义」为自由文本、多个关键词用中文逗号分隔；
④ 「排序」= 表格自动序号（`show-seq`），不落库、不可编辑。

- **类型**：`typings/api/system-manage.d.ts` 新增 `TraceTransformTimeFormat`（`'ymd' | 'ymd-hm' | 'ymd-hms'`）
  与 `TraceTransformItem / List / SearchParams / CreateParams / UpdateParams`（不动 `TraceConfig*`）；
  时间格式存枚举 key、展示走 i18n。
- **组件**：新增 `trace-capture/TraceTransformTable.vue`（`useVxeTable` + `Table`，cacheKey `trace-transform`）与
  `TraceTransformDrawer.vue`（`NFormWrap`：状态名称必填 / 时间格式 select 默认「年-月-日 时分」/ 服务地点 /
  详细描述 / 关键词判断定义）；`TraceCapture.vue` 的 `configTabs` 循环内加一个分支渲染（tab 顺序、其余 tab 不变）。
- **数据**：`mock.ts` 增 `traceTransformItems` 8 条（截图数据，服务地点留空显示 `--`）+
  `mockGet / Create / Update / DeleteTraceTransform`；`system-manage.ts` 增 4 个 `fetch*TraceTransform`
  （DEV mock `as unknown as`，PROD `/system/trace-transform/...`，删除为 `ids: number[]`）。
- **i18n**：`traceCapture` 段增 `col.statusName / col.keywordDefinition`、`form.statusName(+Placeholder) /
form.keywordDefinition(+Placeholder)`、`addRow`、`timeFormatOption.{ymd,ymdHm,ymdHms}`，zh-cn / en-us /
  `typings/app.d.ts` 三处同步。

不做：勾选列 / 批量删除（截图左侧勾选列视为原型示意）、审计字段（最后编辑 / 编辑时间）、
其余 4 个 tab 的任何改动。
