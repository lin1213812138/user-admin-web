# 结算货币接口对接

> 日期：2026-09-19 ｜ 状态：已实施（typecheck/lint 通过，待用户手动冒烟）

## 背景

用户贴出 `tms-user` 的 `CurrencySchema`（code/name/countryId/local/rate/status…）与一张结算货币列表截图，要求把 `finance/modules/currency/Currency.vue` 对接真实 `/currency/*` 接口。

当前 `Currency.vue` 走通用 `MasterDataArchive`，列只有 `code/name/rate/symbol`（旧 `FinanceCurrency` 类型），与真实 Schema 不符（无 countryId / local / status，且有截图不需要的 symbol）。

## 已确认

- 接口路径：`/currency/query`（用户明确回复）。

## 设计要点（详见 `docs/superpowers/specs/2026-09-19-结算货币接口对接.md`）

- 改造成独立页，复用 `ExpenseType` / `Account` 范式（`useVxeTable` + `NFormWrap` + `useCountrySelect`）。
- 列表列：排序 / 编码 / 中文名称 / 国家 / 是否本币 / 汇率 / 状态 / 操作。
- 国家：用 `useCountrySelect`（已封装 `/country/query` 缓存）存 `countryId`、列表 `getName()` 反查中文名，对齐 Shipper/ShipTo 写法。
- 是否本币：`local` 0/1 → NTag「外币/本币」；表单 switch。
- 状态：`status` 0/1 → NTag（type:'status'）；表单 select。
- 工具栏：名称搜索 + 新增 + 批量停用；操作列：编辑 + 更多。

## 待用户确认（3 点，阻塞实现）

1. query 是否需要 `scene:1`（同 fee-type/trade-account 的 `if (!scene) where.status = 1` 坑）。

3. `code` 是否唯一（uniqField:'code'）→ 局部更新需随行回传 code。
