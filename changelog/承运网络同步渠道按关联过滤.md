# 承运网络同步渠道按关联过滤

## 2026-09-20 已实施（待手动冒烟）

### 用户需求

> 「同步渠道这里要查询关联这个承运网络的渠道」——附图「同步到收货渠道 - EMS」抽屉截图。

### 背景与定位

- 承运网络「同步渠道」抽屉（`CarrierSyncDrawer.vue`，见 [2026-09-20-承运网络同步渠道.md](./承运网络同步渠道.md)）初版按原 spec 待确认项 3 的口径实现为「列出该类型**全部**渠道」；
- 本次用户要求改为只列 **`carrierId` 关联当前承运网络**的渠道，与同页面「附加费同步到渠道」抽屉（`CarrierFeeExtSyncDrawer.vue`）口径对齐。

### 契约核实（tms-user 零改动）

- `/channel/query`、`/channel-out/query` 控制器直接 `getCtxQueryParams(ctx)` → `queryCommon`，`where` 直通 Mongo 查询；
- `Channel` / `ChannelOut` 模型均有 `carrierId` 字段；
- 前端 service 能力已具备：`fetchGetChannelList` 入参含 `where`；`fetchGetChannelOutList` 已有可选 `carrierId` 入参（内部拼进 `where`），**无需新增类型与接口参数**。

### 实施

仅改 `src/views/data-manage/ship/modules/carrier/CarrierSyncDrawer.vue`：

1. `loadChannels()` 收货渠道查询加 `where: { carrierId: carrier._id }`；
2. 发货渠道查询加 `carrierId: carrier._id`（保留 `scene: 1` 以回填 `weightRuleName` / `remoteGroup` 名称）；
3. 补 `carrier` 空值守卫（无承运网络清空列表直接返回，不发请求）；
4. 文件头注释补充「渠道范围：仅取 carrierId 关联当前承运网络的渠道」。

### 边界

- 不动后端、`fetchGetChannelList` / `fetchGetChannelOutList` 签名、抽屉其余勾选/保存逻辑、附加费同步抽屉；
- 行为变化：未绑定该承运网络的渠道不再出现在同步列表（需先在渠道表单绑定承运网络）。

### 验证

- `pnpm typecheck` 0 错误；
- `pnpm lint` 0 error（`link.vue` 2 条既有 warning，与本次无关）。

### 待办

- 用户冒烟：承运网络「EMS」→ 同步渠道 → 收货/发货 tab 均只显示承运网络=EMS 的渠道；切到未关联任何渠道的承运网络 → 列表为空；保存同步行为不变。
