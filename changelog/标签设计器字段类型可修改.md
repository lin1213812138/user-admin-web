# 标签设计器：字段类型可修改

> 用户需求（截图圈出属性面板「字段类型」下拉）：「这个类型需要能修改」。此前该项是 `disabled` 的只读展示项，store 也没有切换类型的能力。

## 设计确认（3 个决策点）

| 决策点             | 用户选择                                                                                |
| ------------------ | --------------------------------------------------------------------------------------- |
| 切换类型时原有配置 | 保留共有 + 内容互迁（共有配置保留；内容 text ↔ value 自动互迁；新类型独有键补默认）     |
| 尺寸处理           | **重置为新类型默认尺寸**（位置 x/y 不变）                                               |
| 可选范围           | 5 种数据类（文本 / 长文本 / 图片 / 条形码 / 二维码）；矩形 / 线条无数据语义，不参与互转 |

## 数据迁移规则（store.updateElementType）

- 入撤销栈（`commit()`），可 undo / redo；
- **内容互迁**：`text | longText` 的 `text` ↔ `barcode | qrcode` 的 `value`（仅当新旧内容键不同且旧值非空）；图片 `src` 是资源地址，不参与互迁；
- **保留共有键**：键存在于「新类型默认 options」中（如 `field` / `testData` / `title` / `showTitle` / 标题样式 / 边框 / `fontSize`），或属于该类型支持但默认未写出的可选键（`placeholder`，见 `EXTRA_OPTION_KEYS`）；
- **丢弃新类型不支持的键**：文本的 `color` / `fontWeight` / `align` / `lineHeight` 转条码时不保留；`symbology` / `displayValue` / `textGap` 转文本时不保留；
- 合并顺序 `{ ...defaults, ...kept, ...migrated }`：迁移值 > 保留值 > 默认值；
- **尺寸**重置为 `defaultSize(type)`，位置不变。

> 关键约束：迁移后 options 里**只能有一个内容键**——`resolveDisplayText` 按 `text → value → src` 顺序取第一个「键存在且有值」的，残留旧内容键（如空 `text`）会遮蔽新键导致画布永远渲染空（历史踩坑，见 `buildModel` 同段注释）。

## 实现

### store（`store/modules/label-design/index.ts`）

- 模块级新增 `SWITCH_CONTENT_KEY`（内容键互迁表）与 `EXTRA_OPTION_KEYS`（各类型支持但默认未写出的可选键）；
- 新增 `updateElementType(id, type)`：按上表迁移 options、重置尺寸、切换 `el.type`，并导出。

### 属性面板（`panels/property-panel.vue`）

- `fieldTypeDisplay`（UI-only，存展示文案 `label`）→ `fieldTypeSelect`（UI-only，存 `ElementType` 值），`UI_ONLY_KEYS` 同步替换；
- `fieldTypeItem` 去掉 `disabled`，`options` 改为 5 种数据类（`SWITCHABLE_TYPES`，label 复用既有 `TYPE_LABEL_KEYS` i18n 键，**无需新增文案**）；
- `watch(model)` 开头拦截类型变化：`syncing = true` → `store.updateElementType` → `buildModel()` 重建受控值（新 options 全键写入 model，保证新面板项都是受控的）→ `nextTick` 解除；不落入下方几何 + options 的常规写回（结构变更不走 options 合并）。

## 追加修正：切到文本类型高度自适应（用户截图反馈）

用户反馈（截图：条码元素切到文本后内容溢出元素框，高度 22.68pt = 8mm）：「切换到文本类型这个高度还是有问题」——首次实现把尺寸统一重置为 `defaultSize(type)`，文本（50×8mm 兜底）用了固定默认高度，与项目既有的「文本类型宽度 50mm + 高度按内容自适应」机制不一致。

### 修法：新增同源离屏实测工具

- 新增 `modules/canvas/measure-element.ts` 的 `measureElementHeight(el)`：临时 `createApp` 挂载与画布同源的 `ElementRenderer`（`position:fixed;left:-9999px` 离屏宿主，宽度 = 元素宽、`height:auto` + 单行高度下限），`nextTick` 后实测 `offsetHeight / PX_PER_PT` 返回 pt，随后卸载并移除宿主；未测到返回 `null`。
  - 与 `drag-preview` 的口径完全一致（宽度换算、`height:auto`、`minHeight = fontSize × lineHeight`），保证「拖入落纸」与「切换类型」两条路径的高度自适应结果一致；
  - 宿主只用 `left:-9999px` 移出视口，**不用** `display:none`（会塌成 0 测不到高度）。
- `property-panel.vue` 类型切换分支：`nextType === 'text'` 时克隆切换后的元素快照 → `measureElementHeight` 异步实测 → 校验（元素仍在且仍为 text）后 `store.updateElement` 只写回 `height`。
  - **不额外入撤销栈**：高度写回属于同一次切换操作（`updateElement` 本就不 commit），undo 一步即恢复切换前状态；
  - 写回后 `geo watch` 的 rAF 会把新高度同步到面板「高」输入框，无需手动同步；
  - `longText` 不做实测（与拖入行为保持一致：拖入时 `textDropSize` 也只处理 `text`，longText 用默认 16mm）。

- `pnpm typecheck`：0 error。
- `npx oxfmt` / `npx oxlint --fix` / `npx eslint --fix` 单文件：0 error（`measure-element.ts` 提示 eslint 无匹配配置，属既有配置范围现象，非错误）。
- `pnpm build`：BUILD SUCCESS。
- **迁移逻辑 tsx 实测**（临时脚本 `tsx tmp-migrate-check.ts`，跑完已删除）：
  - 文本 → 条码：`text:"ABC123"` → `value:"ABC123"`；`field`/`title`/`showTitle`/`fontSize:10` 保留；`color`/`align`/`text` 丢弃；尺寸 50×15mm、位置不变；
  - 条码 → 文本：`value` → `text` 回迁；`symbology`/`displayValue`/`textGap` 丢弃、文本默认值补齐；
  - 文本 → 图片：`src` 空默认（不迁移）、`title`/`showTitle` 不保留；尺寸 20×20mm；
  - undo：类型与配置整体恢复；长文本 → 文本：内容与全部样式保留。
- 建议手动冒烟：条码元素切「文本」→ 高度应自动收缩为内容高度（约单行 fontSize×lineHeight ≈ 3.4mm），「高」输入框同步刷新；undo 一步回到条码。
