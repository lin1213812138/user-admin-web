# 新增按钮被权限隐藏后左侧残留间隔

> 日期：2026-09-19
> 现象：用户贴「用户管理」截图，红框圈住「批量删除」左侧的空白，问「新增按钮被权限隐藏后这个间隔这么没有去掉呢？」

## 定位结论

不是「间隔（gap/margin）没去掉」，而是**按钮被隐藏了，包裹它的容器还在**。

链路（三方协作，逐层核实过源码）：

1. **按钮隐藏方式**：`views/system-manage/user/index.vue:280` 用 `<LButton auth="system:user:add" ...>`；`components/basic/LButton.vue:118-137` 在无权限时模板根 `v-if="visible"` 整段不渲染 ⇒ 组件自身只渲染出一个**注释节点** `<!---->`。
2. **父级包装**：页面把按钮组放在 naive 的 `NSpace` 里（`user/index.vue:279`）。naive `space/src/Space.mjs:100-144`：
   - `const children = flatten(getSlot(this), false)` —— 第二个参数为 `false`，注释 vnode **不会**被过滤掉；
   - `children.map(child => child.type === Comment ? child : h('div', { role: 'none', class: itemClass, ... }, child))` —— **只对「子 vnode 本身是 Comment」的情况跳过包装**。
   - 页面里 slot 的子 vnode 是 `LButton` **组件 vnode**（`type` 是组件对象，不是 `Comment`），注释是组件**内部**渲染出来的 ⇒ 判断不成立 ⇒ 仍然被套了一层 `<div role="none">`。且 `itemClass` 没传，这层壳**没有类名**。
3. **间隔来源**：空壳 div 仍然是 flex item，`NSpace` 的 `gap` 照常生效。naive `space/styles/_common.mjs`：`gapMedium: '8px 12px'` ⇒ 默认 medium 尺寸下**横向 gap = 12px** ⇒ 「批量删除」左侧多出 12px 空白（浏览器不支持 flex gap 时走 `marginRight` 兜底，结果同样是 12px）。

## 影响面（同一个根因的两种表现）

| 表现                                                         | 首次出现位置                    | DOM 残留                                      |
| ------------------------------------------------------------ | ------------------------------- | --------------------------------------------- |
| `LButton` 的 `auth` 无权限                                   | `user/index.vue:280`            | `<div role="none"><!----></div>`              |
| `v-auth` 移除了元素（`directives/auth.ts` 的 `el.remove()`） | `role/index.vue:292` 新增按钮等 | `<div role="none"></div>`（按钮被删，壳还在） |

两者都是「`NSpace` 包装壳 + 壳空掉 + gap 仍生效」。`v-auth` 情形下同样会残留 12px。

## 备选方案（待用户确认后再动代码）

- **方案 A（推荐）**：全局兜底 CSS，`src/styles/css/global.css` 新增
  ```css
  .n-space > div[role='none']:empty {
    display: none;
  }
  ```
  CSS 规范中 `:empty` **忽略注释节点**（只算元素节点与非零长度文本），因此 `<!---->` 空壳、`v-auth` 删空后的空壳都命中；`display: none` 后不再参与 flex 布局 ⇒ gap 消失。一处覆盖所有页面、零页面改动，与本仓库已有的 naive 全局补丁（`.n-base-select-option__content`、`.country-option-row`）风格一致。
- **方案 B（页面级）**：把 `auth` prop 换成 `v-if="hasAuth('system:user:add')"`（`hooks/business/auth.ts`）。`v-if` 为假时子节点**直接**是注释 vnode，`NSpace` 不包装 ⇒ 不产生壳。语义最干净，但每个用到的页面都要引入 `useAuth`，且放弃上轮刚统一起来的 `auth` prop 写法。
- **方案 C（结构级）**：按钮组不用 `NSpace`，改成普通 `<div class="flex items-center gap-8px flex-wrap">`。普通 flex 容器里注释节点不生成盒子 ⇒ 不占位、不产生额外 gap；缺点是要逐页改，且偏离「工具栏按钮组用 NSpace」的既有约定。

## 实施（用户确认：方案 A，全局兜底 CSS）

`src/styles/css/global.css` 末尾新增（沿用该文件已有的 naive 全局补丁写法，注释说明根因）：

```css
/* naive Space（NSpace）会给每个「非 Comment」子 vnode 套一层 <div role="none"> 包装（itemClass 未传 ⇒ 该层无类名）；
   子组件自身「不渲染」时（如 LButton 的 auth 无权限只渲染注释、v-auth 的 el.remove() 删掉按钮），
   这层壳会变成空壳，但它仍然是 flex item ⇒ Space 的 gap（medium 横向 12px）照常生效 ⇒ 按钮组左侧残留空白。
   :empty 按规范只算元素节点与非空文本、忽略注释节点 ⇒ 空壳命中后 display:none，不再参与 flex 布局，间隔随之消失。
   限定 [role='none'] 只命中 Space 自己生成的包装层，不误伤页面自己写的空 div */
.n-space > div[role='none']:empty {
  display: none;
}
```

要点：

- `:empty` 命中两种空壳：`LButton auth` 无权限时的 `<div role="none"><!----></div>`、`v-auth` 删掉按钮后的 `<div role="none"></div>`。
- `[role='none']` 限定只作用于 `NSpace` 自己生成的包装层，页面自己写的空 div（无该 role）不受影响，避免误伤。
- `display: none` 后该节点不再是 flex item，`NSpace` 的 `gap` 不再为它预留位置 ⇒ 首个可见按钮贴回容器左边。
