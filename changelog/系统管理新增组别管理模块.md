# 系统管理新增组别管理模块

## 需求

用户："新增组别管理模块"，并提供样例数据：

| 字段     | 样例值            |
| -------- | ----------------- |
| 组别名称 | 岳阳              |
| 组别备注 | 上海销售二组      |
| 创建     | 王恒 - 2026-07-15 |
| 所属站点 | 上海              |
| 最后更新 | 王恒 - 2026-07-15 |

与「站点管理」模块（同日新增）平级，同属系统管理。

## 需求澄清（已确认）

1. **所属站点**：下拉关联站点管理（表单里从站点数据中选站点，存 `siteId`、展示站点名称；站点改名后组别展示同步更新）；
2. **状态字段**：要（启用/禁用）——表格 status 列 + 搜索状态筛选 + 表单开关；
3. **组别名称**：做唯一性校验（mock 内查重，重复提示「组别名称已存在」）。

## 设计定稿

### 交互

- 顶部搜索栏：组别名称（模糊）+ 所属站点（下拉）+ 状态筛选；
- 表格：组别名称（detail 列，可复制/点击进详情）、组别备注、所属站点、「创建」列（`创建人 - 日期` 插槽）、「最后更新」列（同上）、状态列（fixed right）、操作列（编辑/删除）；
- 工具栏：新增 / 批量删除 | 列设置 / 刷新；
- 抽屉表单：组别名称、所属站点（下拉）、组别备注、状态开关；站点选项在抽屉每次打开时刷新（保证新建站点可即时选中）。

### 数据与接口

- 类型：`Api.SystemManage.Group / GroupList / GroupSearchParams / GroupCreateParams / GroupUpdateParams`；
- 接口：`fetchGetGroupList` / `fetchCreateGroup` / `fetchUpdateGroup` / `fetchDeleteGroup(ids)`；DEV 分支走 mock（裸数据），非 DEV 走 `/system/group/*`；
- mock：`groups` 内存数组预置若干条（首条为「岳阳 / 上海销售二组 / 站点=上海(id 4)」样例）；`mockGroupList` 按 `siteId` 实时解析 `siteName`；`mockCreateGroup` / `mockUpdateGroup` 查重（重复 `throw new Error('组别名称已存在')`）；`MENU_TREE` / `ALL_MENU_IDS` / `menus` 补「组别管理」菜单（id 26）。

### 设计取舍

- 与站点管理完全同构（`useVxeTable` + `Table` + `modules/` 抽屉），不抽公共组件；
- 组别只存 `siteId`，`siteName` 由数据层解析，避免站点改名后组别展示过期。

## 追加：菜单顺序按最新配置重建（同日）

用户自行把 `build/plugins/router.ts` 的 `routeOrders` 调成 `site=4 / group=5 / label-designer=6 / setting=7`（意图：站点管理、组别管理排在系统设置之前），但生成产物仍是旧值（`site=6 / group=7 / setting=4 / label=5`）——根因是 elegant-router 生成器**保留已存在条目的旧 meta**，配置改动对已有路由不生效。

处理：把 `routes.ts` 中这 4 个条目整段删除（原文件已备份到系统临时目录）→ 清 `node_modules/.vite-temp` → 重跑 dev → 4 个条目作为「新条目」按最新配置重建。

结果：`site=4 / group=5 / label-designer=6 / setting=7`（icon 与 label-designer 的 `hideInMenu` + `activeMenu` 均保留），其余路由与文件末尾的 `nonMenuRoutes` / `menuRoutes` 定制段不受影响；`pnpm typecheck` 通过。最终菜单顺序 = 用户管理(1) → 角色管理(2) → 菜单管理(3) → **站点管理(4) → 组别管理(5)** → 系统设置(7)。

**结论（可复用）**：想让配置里的 meta 改动对**已有路由**生效，步骤 = 从 `routes.ts` 删除目标条目 → 清 `.vite-temp` → 跑 dev 重新生成；**不要全量删除 `routes.ts`**（会丢掉文件里的定制段）。
