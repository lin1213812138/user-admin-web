# 标签设计器：拖拽预览看不清 → 自定义 drag image

日期：2026-09-14
范围：`modules/panels/field-panel.vue`、`modules/canvas/drag-ghost.ts`

## 现象与定位

用户反馈：「从左侧拖出来，为什么看不清」——拖动过程中跟随鼠标的预览是一块浅灰色、几乎看不清的框。

排查结论（已与用户逐条确认）：

1. 浏览器拖拽时默认用**源条目本身的快照**作 drag image —— 而字段条目是「白底 + 浅灰文字（`#999` / `#bbb`）+ 浅灰边框（`#e5e7eb`）」；
2. 浏览器还会给 drag image 叠一层**半透明**；
3. 浅灰 × 半透明，落到画布灰底（`#f5f5f5`）上 → 对比度极低，视觉上发「糊」。

同时确认、排除误诊：

- 那个浅色框是**拖动中跟随鼠标的预览**（松手即消失），不是拖拽幻影残留；
- 拖到纸张（白色区域）内松手，元素能正常创建 —— `onDrop` 的落点判定与创建链路无 bug。

## 方案（用户选定 A：自定义拖拽预览）

用 `dataTransfer.setDragImage()` 换成**自定义预览卡片**：

- `field-panel.vue` 模板里放一个**离屏常驻**的预览卡片（`Teleport` 到 `body` + `left/top: -9999px`）：
  - Teleport 的原因：`fixed` 若遇到带 `transform` 的祖先（页面过渡动画）会退化为相对祖先定位、露出视口；
  - 离屏放置不影响布局与滚动条（fixed 不参与文档流）；
- 样式与源条目解耦：白底 + **深色字**（`#1f1f1f`，暗黑 `#e0e0e0`）+ **主色描边 2px** + 阴影 + 圆角；
- `dragstart` 里**同步**写入文字（取源条目首个 `span` 的文本，即字段名 / 元素名）：
  - `setDragImage` 只在 dragstart 处理期间生效，Vue 响应式更新（nextTick）来不及，必须直接操作 DOM；
  - 强读一次 `offsetWidth` 触发同步重排，保证取到写入文字后的最新尺寸；
- 光标定位在卡片中心：`setDragImage(preview, offsetWidth / 2, offsetHeight / 2)`。

`drag-ghost.ts` 顶部注释同步更新（原注释写「不去动原生影子」，现已由 field-panel 接管预览，回位幻影逻辑不变）。

## 统一为「跟手预览」（同日，用户确认「做成一致的」）

用户二次反馈（两张对比截图）：**按住拖动时的预览发糊、松手后的幻影却清晰**，问「为什么鼠标松开就是正常的，鼠标按住是这样的」。

### 根因：两套机制观感不一致

| 时机       | 看到的是什么                                    | 为什么                                        |
| ---------- | ----------------------------------------------- | --------------------------------------------- |
| 按住拖动时 | **浏览器原生拖拽影子**（Chrome 用源项快照绘制） | 浏览器**强制叠一层半透明**，JS 拿不到也改不了 |
| 松手后     | 本模块的「回落幻影」（DOM 完整克隆源项）        | 完全不透明，所以清晰                          |

### 方案：统一成一套「跟手预览」

重构 `drag-ghost.ts`：

1. `dragstart`：
   - 用一张 **1×1 透明图** `setDragImage` 顶掉原生影子（图片在模块加载时预载，避免现取现用来不及解码）；
   - **克隆源项**作为跟手预览（`position: fixed` + `pointer-events: none` + `transformOrigin: top left`），
     初始位置与源项重合（抓取偏移与指针位置同源），从原生影子交接过来零跳变；
2. `dragover`（document capture，原逻辑内）同步更新预览 `left/top` 实现跟手；
3. `dragend`：**同一个元素原地转场**——已落纸快速淡出、未落纸直接补间回源项原位
   （原先「dragend 时再克隆一份幻影」的 `createGhost` 已删除，全程无切换）。

效果：按住与松开看到的是同一个不透明的条目克隆，观感完全一致。

验证：`pnpm typecheck` 0 error；`oxfmt` / `oxlint` 单文件 0 error。
