# 分组管理对接接口

> 日期：2026-09-17　|　状态：已实施完成

## 用户需求

用户贴出 tms-user 后端 `GroupSchema`（`lib/common/models/group.js`，组别 code 1003），要求前端分组管理页对接真实接口；并要求**接口按目录隔离生成模块文件夹，不要全部堆在一个文件里**。

## 确认结论（用户答复）

1. 拆分范围：**全部按模块拆成目录**（`service/api/<模块>/index.ts`），不是只拆分组一个文件。
2. status 字段：后端无此字段，**整体移除**（搜索项/状态列/抽屉开关/类型/i18n）。
3. 删除迁移：第一版**不做**「组内用户/客户迁移到指定组」交互，直接删除（后端 `deleteUpdateGroupId` 对空 newGroupId 容错置 `''`）。

## 现状定位

- 前端已有页面：`src/views/system-manage/group/index.vue` + `modules/group-operate-drawer.vue`，走 **本地 mock**（`mockGroupList` 等）。
- `src/service/api/system-manage.ts` 中 group 四个函数 PROD 分支指向 `/system/group/*`，是**错误 URL**。
- 真实后端（tms-user `lib/api-v1-web/group/` + `lib/services/group.js`）：

| 接口                 | 入参                                                      | 返回                                          | 说明                                                                                                 |
| -------------------- | --------------------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------- | --- | ----- |
| `POST /group/query`  | `{ where: { name?, siteId? }, keyword?, keywordFields? }` | `{ list }`（**无分页**，queryAllCommon 全量） | `siteService.fillName` 回填 `site`（站点名字符串）                                                   |
| `POST /group/create` | `{ siteId, name, desc? }`                                 | `{}`                                          | `siteId` 须为合法 MongoId、`name` 必填且全局唯一                                                     |
| `POST /group/update` | `{ _id, siteId?, name, desc? }`                           | `{}`                                          | name 唯一校验                                                                                        |
| `POST /group/delete` | `{ _id, newUserGroupId?, newCustomerGroupId? }`           | `{}`                                          | **单条删除**；组内用户/客户迁移到指定组，不传则 groupId 置空（`deleteUpdateGroupId` 容错 `newGroupId |     | ''`） |
| `POST /group/get`    | `{ _id }`                                                 | 文档 + `userCount`/`customerCount`            | 详情                                                                                                 |

- 后端字段与前端 mock 口径**不一致**：`_id:string / name / desc / siteId:string / site / creator / updateBy / createDate / updateDate`（毫秒时间戳），**无 status 字段**、无 `groupName/remark/siteName/createTime/updateTime`。

## 设计方案（待确认）

1. **类型**（`typings/api/system-manage.d.ts`）：重写 `Group / GroupList / GroupSearchParams / GroupCreateParams / GroupUpdateParams` 对齐后端字段；删除 status 相关类型。
2. **service**（`service/api/system-manage.ts`）：去掉 group 的 DEV mock 分支，URL 改为 `/group/query|create|update|delete`，与站点（`/site/*`）同款 flat `{ data, error }` 风格；`fetchDeleteGroup` 改为单条 `_id: string`（批量删除由页面循环调用）。
3. **列表页**（`index.vue`）：
   - 列改为：组别名称(name)、所属站点(site)、备注(desc)、创建人(creator)、创建时间(createDate)、编辑人(updateBy)、更新时间(updateDate)，时间戳 dayjs 格式化。
   - **移除 status** 搜索项/状态列/抽屉开关。
   - query 是全量接口：`useVxeTable` api 拉全量后**本地分页**。
   - 搜索：组名 → `where.name`（正则），站点 → `where.siteId`。
   - 批量删除：循环单条调 `/group/delete`。
4. **抽屉**（`group-operate-drawer.vue`）：字段 name(必填)/siteId(必填,字符串 \_id)/desc；编辑回填 `_id`。

## 实施结果

### 1. service/api 全量目录化拆分（本次主改造）

旧扁平文件全部删除（`auth.ts / route.ts / system-manage.ts / data-manage.ts / channel-quote.ts / print-format.ts / export-format.ts / mock-channel-quote.ts / mock-data-manage.ts`），改为 `src/service/api/<模块>/index.ts` 共 18 个模块目录：

`auth / route / user / role / menu / site / group / customer / init-data / trace-config / trace-transform / trace-keyword / operation-trace / op-log / data-manage / channel-quote / print-format / export-format`；`channel-quote`、`data-manage` 的 DEV mock 移入各自目录 `mock.ts`；共享 DEV mock 保留根级 `mock.ts`；barrel `index.ts` 改为逐模块 `export *`。视图层 22 处 import 路径同步更新（print-format / export-format / channel-quote / data-manage 因 `目录/index.ts` 解析规则 import 路径不变）。

### 2. 分组接口对接（service/api/group/index.ts，全部真实接口、无 mock 分支）

- `POST /group/query`：body `{ where: { siteId? }, keyword?, keywordFields: ['name'] }`（keyword 对 name 正则模糊）；**queryAllCommon 全量无分页** → `useVxeTable` api 拉全量后**本地分页**（slice + total=list.length）。
- `POST /group/create`：`{ name, siteId, desc? }`（siteId 须 MongoId、name 全局唯一，审计字段后端按登录用户填充）。
- `POST /group/update`：`{ _id, name, siteId, desc? }`。
- `POST /group/delete`：单条 `{ _id }`；批量删除前端 `Promise.all` 逐条调用。
- 另加 `POST /group/get`（`fetchGetGroup`，详情含 userCount/customerCount，暂无调用方）。

### 3. 类型（typings/api/system-manage.d.ts）

`Group` 重写为 `{ _id: string; name; desc?; siteId: string; site?; creator?; updateBy?; createDate/updateDate: number; userCount?/customerCount? }`；`GroupList = { list, total? }`；`GroupSearchParams` 改为 `{ where, keyword, keywordFields }`；status 相关全部移除。

### 4. 页面（views/system-manage/group）

- 列表列改为：组别名称(name, detail)/所属站点(site)/备注(desc)/创建人(creator)/创建(createDate)/编辑人(updateBy)/最后更新(updateDate)，时间戳 dayjs 格式化；移除 status 搜索项/状态列。
- 抽屉字段 name(必填)/siteId(必填，站点 `_id`)/desc；提交改 flat 解包 `{ error }`，错误提示交给拦截器。
- 列配置缓存 key 升级 `system-manage-group-v2`（避免旧列配置残留）。
- `user-operate-drawer.vue` 组别下拉同步改真实接口（`{ label: name, value: _id }`，flat 解包）。

### 5. i18n

zh-cn / en-us / `app.d.ts` Schema 三处同步：group 段加 `creator / updateBy`，删 `status / form.statusPlaceholder`。

`pnpm typecheck` 0 错误（fmt 后复跑通过）；`pnpm lint` 0 error（仅 link.vue 2 条既有无关 warning）；`pnpm fmt` 已执行。后端联调效果待用户在测试环境复核。
