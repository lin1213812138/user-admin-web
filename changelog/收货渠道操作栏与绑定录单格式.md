# 收货渠道操作栏（启用·停用 / 绑定录单格式）

> spec：`docs/superpowers/specs/2026-09-20-收货渠道操作栏与绑定录单格式-design.md`（✅ 已确认）

## 1. 需求（用户三张截图）

- 图 1（老系统详情页，红框 = 对齐项）：操作栏 = 新建渠道 / 编辑 / **停用** / 删除 / **绑定录单格式**（新建、编辑、删除本仓库已有）。
- 图 2：「绑定录单格式」弹窗 = 标题 + 必填下拉「录单格式:」（placeholder 请输入）+ 取消 / 确定。
- 图 3（本仓库列表页，红框 = 落点）：本仓库现有列表页的**操作列**，不改造主从结构。

## 2. 后端契约（已核 `tms-user`）

| 事项         | 事实                                                                                                                                                    | 处理                                                           |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 绑定关系位置 | 录单格式 `OrderTemplate.channelIds: string[]`（渠道表无此字段）                                                                                         | 绑定动作落在录单格式一侧                                       |
| 绑定接口     | 无专用接口，只能 `/order-template/update`；`uniqField:'name'`                                                                                           | 必须随行回传 `name`，只提交 `_id + name + channelIds` 部分更新 |
| 选项数据源   | `/order-template/query` 需传 `scene: 1`（否则被强制 `status=1` + 按角色 `orderTemplateIds` 过滤）；列表返回 `channelIds`（`omitFields` 仅 `fieldList`） | 一次查询同时得到下拉选项与「当前绑定」回显                     |
| 渠道启停     | `/channel/update` 走 `uniqField:['name','code']`                                                                                                        | 必须随行回传 `name + code`，仅补 `status`                      |

## 3. 决策（用户确认：回复「可以」，Q1–Q4 未另答 ⇒ 按推荐）

| #           | 结论                                                                               |
| ----------- | ---------------------------------------------------------------------------------- |
| Q1 绑定语义 | **一个渠道只属于一个录单格式**：确定时先从其它已含该渠道的格式解绑，再加入所选格式 |
| Q2 启停文案 | 沿用仓库统一口径 `common.disable` / `common.enable`（禁用 / 启用）                 |
| Q3 详情按钮 | 保留（本仓库既有能力）                                                             |
| Q4 落点     | 操作列（依图 3）                                                                   |

## 4. 实施

- **类型**：`Api.ChannelQuote.ReceiveChannelSaveParams` 增 `status?: Api.Common.EnableStatus`（启停部分更新）；`Api.InputFormat.BindChannelsParams`（`_id + name + channelIds`）。
- **服务**：`service/api/input-format/index.ts` 增 `fetchBindInputFormatChannels()`（复用 `/order-template/update`）。
- **弹窗**（新增 `modules/bind-order-template-modal.vue`，`NModal preset="card"` + `FormWrap` 单字段）：
  - 打开：`/order-template/query { scene: 1, page: 1, size: 9999 }` 取选项，并 `find(channelIds 含该渠道)` 回显当前所属格式；
  - 确定：必填校验 → 未变更直接关闭 → 否则「其它格式解绑 → 所选格式去重追加」→ 成功提示 + 关闭 + 刷新列表；任一中间步骤失败即中断并保留弹窗。
- **列表**（`index.vue`）：操作列 = 编辑 / 详情 / **禁用·启用** / **绑定录单格式** / 删除；`actionWidth` 180 → 280；启停带 `popconfirm` 并就地更新行状态，绑定按钮打开弹窗。
- **i18n**：新增 `page.channelQuote.receive.bindOrderTemplate` / `orderTemplate` / `orderTemplatePlaceholder`（zh-cn / en-us / `typings/app.d.ts` 三处同步）。

## 5. 边界

- 不改造成主从结构（右侧 7 个 tab 除「渠道备注」外未实现）；不改后端、不加专用绑定接口；不改录单格式（系统设置）页与其抽屉；不动工具栏「新增 / 批量删除」、搜索、列配置、发货渠道页；不加 `v-auth`（本页 buttons 为空，与新增 / 批量删除一致）。
