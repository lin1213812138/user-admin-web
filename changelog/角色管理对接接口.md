# 角色管理对接接口

## 背景

用户贴出 tms-user 后端 Role Schema（`lib/common/models/role.js`）要求对接角色真实接口。角色模块此前与用户/组别/站点模块一样仍是 mock 实现（`mockRoleList` 等，字段为 mock 结构 `id/roleName/roleCode/status`），与后端真实 Schema 完全对不上。

## 后端接口调研（tms-user `/api/v1/web/role/*`，全部 POST）

| 接口                | 行为                                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/role/query`       | `queryAllCommon` **全量查询无分页**，后端固定 `sort: { order: 1 }`；参数 `{ where?, keyword?, keywordFields? }`，返回 `{ list, total? }`          |
| `/role/get`         | 详情，body `{ _id }`                                                                                                                              |
| `/role/create`      | `name` 必填且全局唯一（`uniqField: 'name'`）；传 `refId` 时后端自动复制被套用角色的 `auths`；审计字段（creator/creatorId 等）由后端按登录用户填充 |
| `/role/update`      | body `{ _id, ... }`；`refId` 变更时后端做 auths 差集/并集合并（`difference` + `concat` + `uniq`）                                                 |
| `/role/updateAuths` | 单独更新权限 `{ _id, auths: string[] }`（本轮未接）                                                                                               |
| `/role/delete`      | `deleteCommon` **单条删除** `deleteOne({ _id: body._id })`，无批量接口                                                                            |

Role Schema 关键字段：`name`（唯一）/ `roleType`（0-客服 1-销售 2-操作 3-财务 4-经理 5-管理员）/ `desc` / `auths: [String]` / `refId` / `dataAuths: [Number]`（0-仅查看专属客户业务 1-仅查看所属组别客户业务）/ `orderTemplateIds` / `sendOrderCtrl` / `sendCtrl` / `orderColCtrl` / `editInfoCtrl`（四个 0/1 开关）/ `order` / 审计字段 / `createDate`·`updateDate`（毫秒时间戳）。**没有 status、roleCode 字段。**

## 范围决策

权限抽屉（`role-permission-drawer.vue`）现基于 mock 菜单树（`/role/menuTree` / `/role/assignMenu` 均为虚构接口），而后端真实权限模型是 `auths` 权限码 + `/role/updateAuths`，且后端未提供权限码查询接口。经确认：**本次只对接基础 CRUD，权限抽屉保持现状（仍走 mock），权限对接另起一次讨论设计。**

## 实施内容

1. **typings**（`src/typings/api/system-manage.d.ts`）：删除 mock Role 类型，重写为真实 Schema——新增 `RoleType` / `RoleDataAuth` / `RoleCtrl` 联合类型；`Role` 接口（`_id`/`name`/`roleType`/`desc`/`auths`/`refId`/`dataAuths`/`orderTemplateIds`/四个 Ctrl/`order`/审计字段/毫秒时间戳）；`RoleList = { list, total? }`；`RoleSearchParams`（`where.name|roleType` + `keyword`/`keywordFields`）；`RoleCreateParams` / `RoleUpdateParams`；原 `RoleQueryItem`/`RoleQueryList`（用户模块在用）保留为别名。`RoleAssignMenuParams.roleId` 由 `number` 改为 `string`。
2. **服务层**（`src/service/api/role/index.ts`）：重写为真实接口——`fetchGetRoleList`（/role/query）、`fetchGetRoleQueryList`（保留别名供用户模块选角色）、`fetchGetRole`（/role/get）、`fetchCreateRole`、`fetchUpdateRole`、`fetchDeleteRole(id: string)` 单条删除；`fetchGetRoleMenuTree` / `fetchAssignRoleMenu` 保留 DEV mock 分支（权限对接另起设计）。
3. **mock.ts**：删除角色 CRUD mock（`createRole`/`roles`/`mockRoleList`/`mockCreateRole`/`mockUpdateRole`/`mockDeleteRole`/`roleMenuMap`）；权限树 mock 简化为不依赖角色数字 id（任意 `_id` 返回全选演示树）。
4. **列表页**（`role/index.vue`）：对齐 group 页范式——`/role/query` 全量拉取后本地分页；搜索=名称 keyword 模糊 + 角色类型 where 精确；列=名称(detail)/角色类型 NTag/描述/排序/数据权限/创建人/创建时间/编辑人/更新时间（时间戳 dayjs 格式化）；删除改单条 `_id`、批量逐条调用；cacheKey 升 `system-manage-role-v2` 防旧列配置残留。
5. **编辑抽屉**（`role-operate-drawer.vue`）：表单字段改为 `name`（必填）/`roleType`（下拉 0-5）/`refId`（权限套用下拉，来自 /role/query、编辑时排除自身）/`order`/`dataAuths`（NCheckboxGroup 插槽多选）/四个 Ctrl 开关（switch checkedValue 1）/`desc`；提交 `_id` 用真实 MongoId。
6. **权限抽屉**最小适配：`row.roleName`→`row.name`、`row.id`→`row._id`（仅字段引用，逻辑不动）。
7. **i18n**（zh-cn/en-us/app.d.ts 三处同步）：role 段重写——删 `roleCode/remark/sort/status`，加 `roleType/desc/refId/dataAuths/order/creator/updateBy/updateTime`、`roleTypes.*`、`dataAuthOptions.*`、`ctrls.*` 及对应 placeholder。**教训：I18nKey 由 `app.d.ts` 的 `App.I18n.Schema` 派生，只改两个 lang 文件会 TS2561，必须三处同步。**

## 验证

`pnpm typecheck` 通过（0 错误）。lint/fmt 与浏览器联调待复核。

## 遗留

- 权限抽屉对接 `auths` + `/role/updateAuths`（需先确定权限码清单来源：后端无查询接口，需前端维护码表或后端补接口）。
- `orderTemplateIds`（可见录单格式）依赖录单格式接口，本轮未做表单项。
