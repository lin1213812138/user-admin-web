# 标签设计：点击元素后高度被压缩一点

> 日期：2026-09-12
> 关联：[标签设计点击元素跑到左上角](./标签设计点击元素跑到左上角.md)（同日连续排查的第二个按下/松手期症状）

## 现象

点击元素选中后，元素内容视觉上矮了 1~2px（内容贴着选中虚线框，像被压缩）；鼠标松开（pointerup）后立即恢复原高。按住期间反复出现、松开即恢复，不持久。

## 排查过程

静态走查了画布全部代码路径（`design-canvas.vue` / `element-renderer.vue` / `property-panel.vue` / `use-canvas-interaction.ts` / store）：

- syncing 防回写机制（selectedId watch / geo watch rAF / deep watch）逐时序推演无漏洞；
- `onPointerUp` 恢复写入的 height 公式与 `elementStyle` 一致；
- `is-selected` 的 outline 不占布局、resize-handle 为 absolute 不参与父高计算。

静态推理无法唯一确定压缩在 store 数据层还是 DOM 层，遂向用户求证两个观察：

1. 按住时面板「高」数值变小？——用户选「变小了」（存疑，可能误选）；
2. 松开后是否恢复？——用户明确补充「**鼠标按下去高度变低，鼠标松开又恢复原样**」。

「按下/松开」的瞬时性直接锁定渲染层：**按下的唯一 DOM 副作用是 `begin()` 里的 `dom.style.willChange = 'transform'`**。

## 根因

`will-change: transform` 在按下的瞬间把元素提升为独立合成层（GPU 单独栅格化）：

- 元素高度是 mm→px 换算的非整数（15mm = 56.69px），独立栅格化时层边界对齐整数设备像素，高度被舍入 → 内容视觉矮 1~2px；
- 同时选中虚线框（outline + offset 2px 向外扩）与压缩后的内容形成「内容贴框」的对比，压缩感更明显；
- 松手时 `onPointerUp` 清掉 `willChange` → 回主层渲染 → 恢复原高。

## 修复（方案 A，用户确认）

`use-canvas-interaction.ts` 删除两行：

- `begin()` 中 `if (dom) dom.style.willChange = 'transform';`（换成说明注释）；
- `onPointerUp` 中 `d.dom.style.willChange = '';`。

性能影响评估：`will-change` 的唯一收益是拖动前预热合成层；高频帧直写 `transform` 时浏览器会自动提升合成层，仅差第一帧，可忽略。拖动卡顿优化的核心收益（脱离响应式 + rAF 合帧）不受影响。

## 验证

- `pnpm typecheck` 通过；label-designer 目录 oxlint 0 警告 0 错误；
- 手测清单：
  - [ ] 按住元素不动 → 高度不再瞬时变矮；
  - [ ] 松开 → 与按住前完全一致；
  - [ ] 正常拖动流畅度与之前无差别。
