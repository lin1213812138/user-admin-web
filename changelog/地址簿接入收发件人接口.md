# 地址簿页面接入收发件人接口（设计待确认）

> 日期：2026-09-19
> 范围：前端 `data-manage/business/modules/address/Address.vue` 接入现有收发件人真实接口（ship-to / shipper）。
> 状态：**设计已提出，待用户确认后实施**（AGENTS.md 要求设计先于编码）。

## 一、问题定位

- `Address.vue` 当前走通用 `MasterDataArchive`（`archive: 'address'`），而 `src/service/api/data-manage-archive/index.ts` 的 `archiveApiMap.address` 指向 **本地 mock**（`mockList/mockCreate/mockUpdate/mockDelete`），数据工厂生成 `ADDRxxxx` 假数据 ⇒ 页面列表是假数据（用户截图 `ADD...` 即此）。
- 收发件人**真实接口已就绪**：`src/service/api/ship-address/index.ts` 提供 `fetchGetShipToList` / `fetchCreateShipTo` / `fetchUpdateShipTo` / `fetchDeleteShipTo` 与 shipper 同构四件套；返回结构 `{ list, total }`、主键 `_id`，调用方解包 `{ data, error }`。
- **已有正确参考实现**：`customer-manage/customer/modules/customer-detail/address-tab.vue` + `address-operate-drawer.vue` 已用上述接口（按 `type: 'ship-to'|'shipper'` 经 `apiByType` 切换），但客户由父级（`customer-detail`）传入，抽屉内「客户」字段为**只读灰底**（`customerName` 插槽 `<NInput disabled>`），`handleSubmit` 直接用 `props.customerId`。

## 二、用户已确认的决策

1. **接口范围**：收件 + 发件都接，页面内用 tab 切换（同 `address-tab.vue` 的 `apiByType`）。
2. **客户来源**：`customerId` 放在新增/编辑弹窗里选（不在页面顶部加客户选择框）⇒ 独立地址簿是**跨客户的全局视图**。

## 三、设计方案

### 3.1 `Address.vue` 重写为自带表格 + 顶部内 tab

- 顶部两个 tab：`收件地址`（ship-to）/ `发件地址`（shipper）。
- 每个 tab 一个 `useVxeTable<Api.SystemManage.CustomerAddressList, Api.SystemManage.CustomerAddress>`：
  - `api` 调 `fetchGetShipToList` / `fetchGetShipperList`，参数 `{ page: current, size, keyword, keywordFields: ['name','phone','zip'], where: {} }`。
  - **关键假设**：`where: {}`（不带 customerId）= 后端返回全部客户地址（全局地址簿）。`CustomerAddressSearchParams.where.customerId` 为可选，符合；但后端无 customerId 时是否返回全量需联调确认（见 §四待确认）。
  - `transform: r => ({ records: r.list, total: r.total })`。
  - 列定义复用 `address-tab.vue`（tag / country / name / company / phone / email / address / city / state / mobile / zip / taxNo），文案按 `isShipTo` 切；**额外加「客户」列**（`customer` 字段，后端 `fillName` 回填）以区分跨客户数据。
  - 操作：新增（打开抽屉、**不传 customerId** ⇒ 抽屉内选客户）、编辑、删除（调对应 `remove`）。
- 不再使用 `MasterDataArchive` / `ArchiveConfig` / `Api.DataManage.BusinessAddress`。

### 3.2 `AddressOperateDrawer` 支持弹窗内选客户

- 新增 prop 语义：`customerId` 为空 ⇒ 「客户」字段变为**可编辑客户下拉**（`fetchGetCustomerList` 取选项）；有值 ⇒ 维持只读灰底（兼容 customer-detail 现有用法，零回归）。
- `FormItemConfig` 的 `customerName` 项：空 customerId 时 `type: 'select'` + `options: customerOptions`、`required: true`；否则 `type: 'custom'`（只读插槽不变）。
- `handleSubmit` 的 `payload.customerId`：`props.customerId || model.customerId`（编辑场景沿用行内 customerId）。
- 客户选项加载：页面/抽屉内调用 `fetchGetCustomerList`（或新增 `useCustomerSelect` Hook 对齐 `useCountrySelect` 的单例缓存风格；**倾向复用现有 `fetchGetCustomerList` 即可，不强行新增 Hook**）。

### 3.3 清理 `data-manage-archive` 的 address mock

- `Address.vue` 不再消费 `archive: 'address'`，`archiveApiMap.address` 及其 `factories.address` 变为死代码 ⇒ 移除（避免与真实接口并存造成混淆）。
- 其余 11 个档案（currency/sales-terms/export-reason/customs-type 真实 + 其余 mock）保持不动。

### 3.4 i18n

- `src/locales/langs/zh-cn.ts` / `en-us.ts` 新增 tab 文案 `page.dataManage.business.address.shipTo` / `.shipper`（及必要列标题）；其余复用 `page.manage.customer.detail.*`（已存在）。
- 同步在 `src/typings/app.d.ts` 的 `App.I18n.Schema.page.dataManage.business.address` 补声明（因 `$t` 受 `I18nKey` 强约束）。

### 3.5 类型

- 列表/表单统一用 `Api.SystemManage.CustomerAddress` / `CustomerAddressList` / `CustomerAddressSearchParams` / `CustomerAddressSaveParams`（与参考实现一致）。
- `Api.DataManage.BusinessAddress` 暂留（其它处可能引用），不强行删除。

## 四、待确认点（实施前）

1. 列表查询 `where: {}`（无 customerId）后端是否返回**全量**地址？若后端强制 customerId，需改为「页面顶部客户选择框」或「默认当前登录客户」——但用户已选「弹窗里选」，故优先按全局视图实现，联调时验证。
2. 是否接受引入 `useCustomerSelect` Hook（与 `useCountrySelect` 风格一致、缓存客户列表），还是抽屉内直接 `fetchGetCustomerList` 即可。

## 五、验证

- `pnpm typecheck` + `pnpm lint` + `pnpm build`（本仓无单测）。
- 手动：`pnpm dev` 进入 业务资料 > 地址簿，切换收件/发件 tab；新增（弹窗选客户）、编辑、删除、关键字搜索、列设置/刷新。

## 六、实施（已交付 2026-09-19）

- 用户确认：**全局视图**（列表 `where: {}` 不带 customerId）+ 客户下拉在抽屉内 `fetchGetCustomerList` 直取（不新引 Hook）。
- **业务资料页拆 tab**：把原来 `data-manage_business > 地址簿` 一个 tab 拆成「收件地址 / 发件地址」两个独立子模块 tab，分别走 `/ship-to/*`、`/shipper/*` 两套接口，不再共用 `.vue` 文件。
- **新增**
  - `src/views/data-manage/business/modules/address/Address.vue`：地址簿容器页，顶部 tab 栏切换收件/发件，分别挂载下面两个模块。
  - `src/views/data-manage/business/modules/address/ship-to/ShipTo.vue`：收件地址列表模块（Table、搜索、删除）。
  - `src/views/data-manage/business/modules/address/ship-to/ShipToOperateDrawer.vue`：收件地址新增/编辑弹窗。
  - `src/views/data-manage/business/modules/address/shipper/Shipper.vue`：发件地址列表模块。
  - `src/views/data-manage/business/modules/address/shipper/ShipperOperateDrawer.vue`：发件地址新增/编辑弹窗。
- **删除** 共用的 `src/views/data-manage/business/modules/address/Address.vue`、`AddressTable.vue`，以及扁平化的 `ShipTo.vue`、`ShipToOperateDrawer.vue`、`Shipper.vue`、`ShipperOperateDrawer.vue`。
- **解耦新增/编辑弹窗**：每个模块的 `OperateDrawer` 各自包裹 `AddressOperateDrawer` 并固定 `type`，对外仅暴露命令式 `open(row?)`、emit `submitted`。列表不再持有弹窗显隐与行状态、不再直接耦合 `AddressOperateDrawer`，只通过 `operateRef.open()` 打开。
- **改** `src/views/data-manage/business/index.vue`：左侧恢复单个 `key: 'address'`（地址簿），内部通过 `Address.vue` 的 tab 栏切换收件/发件，不再把收件/发件拆成左侧两个 tab。
- **对齐现有界面** `system-manage/setting/modules/trace-capture/TraceCapture.vue`：`Address.vue` 改用 `NCard` + `NTabs type="line"` + `KeepAlive` + `component :is`；`ShipTo.vue`/`Shipper.vue` 搜索栏从 `operation-right` 移到 `Table` 的 `search-action` 插槽（搜索 + 搜索按钮 + 重置），操作栏左侧放「新增」、右侧放「刷新」。
- **改** `src/views/customer-manage/customer/modules/customer-detail/address-operate-drawer.vue`：`props.customerId` 为空时「客户」字段变可编辑 `select`（`fetchGetCustomerList` 选项，打开即加载）；有值时维持只读灰底（客户详情页零回归）；`payload.customerId = props.customerId || model.customerId || ''`。
- **清** `src/service/api/data-manage-archive/index.ts`：移除已无用的 `address` mock 工厂与 `archiveApiMap.address` 条目（Address.vue 不再消费）。
- **i18n**：`zh-cn`/`en-us` 的 `page.dataManage.business.address` 补 `shipTo`/`shipper`；`typings/app.d.ts` schema 同步补声明；列文案/占位复用 `page.manage.customer.detail.*`。
- **验证**：typecheck 0 / lint 0 error（link.vue 2 既有 warning 与本次无关）/ build:test 成功。
- **遗留**：列表 `where:{}` 后端无 customerId 是否返全量，需联调确认；若后端强制 customerId，则全局视图不成立，需退回页面顶部客户选择框。
