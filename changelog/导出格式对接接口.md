## 二、后端契约（读 tms-user 源码核实）

路由前缀 `/tms/api/v1/web`（与前端 `VITE_SERVICE_BASE_URL` 一致），控制器 `lib/api-v1-web/export-template/`：

| 接口                                  | 校验 / 行为                                                                                                                                                                                                                                   |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /export-template/upload?dest=4` | 中间件 `upload.file` 先存盘（`destMap[4] = export-template`，form-data 字段名 `file`）→ `parseFile` 解析 xlsx 标记后回传解析结果                                                                                                              |
| `POST /export-template/create`        | validate 必填 `name` / `templateType`（数字）/ `file` / `fileUrl`；`uniqField: 'name'` ⇒ 名称**全局唯一**（重复报 102401）                                                                                                                    |
| `POST /export-template/update`        | validate 必填 `_id`；`model.updateOne({_id}, body)` ⇒ **未提交的字段保持原值**                                                                                                                                                                |
| `POST /export-template/delete`        | validate 必填 `_id`；**仅单条**，无批量接口                                                                                                                                                                                                   |
| `POST /export-template/query`         | body `{ page, size, keyword, where }`，`keywordFields: ['name']`（名称模糊）；返回 `ret:{ list, total }`；模型 `omitFields=['infoList','fieldList','subList']` ⇒ 列表不含这三个大数组（含 file/fileUrl/thPos/tdPos/note/updateBy/updateDate） |
| `POST /export-template/get`           | 任意条件查单条完整文档（含解析结果），`check=1` 查不到抛 102400                                                                                                                                                                               |

**xlsx 标记规则**（`lib/services/export-template.js#parseFile`，上传即解析）：

| 标记                              | 含义                   | 解析结果                                                                                                 |
| --------------------------------- | ---------------------- | -------------------------------------------------------------------------------------------------------- |
| `@field` 或 `前缀<@field>`        | 信息字段               | `infoList[{row, column, fields, content, formats}]`                                                      |
| `#field`                          | 列表字段               | `fieldList[{column, fields, content}]` + 首个 `#` 行写入 `fieldRow`                                      |
| `##field`                         | 子列表字段             | `subFieldList[{column, fields, content}]`（存在时给 fieldList 补 `columnName`）                          |
| `$subField.field`                 | 子列表                 | `subList[{field, fieldList}]`                                                                            |
| `%field-A1[-类型[-前后缀]]`、`&…` | 条码（`&` = 显示文本） | `barcodeList[{pos, field, barcodeType, prefix, suffix, text}]`；出现在 `#` 单元格里则进 `subBarcodeList` |

上传返回体额外带 `file`（原始文件名）与 `fileUrl`（静态地址 `http://host/tms/upload/export-template/<uuid>.xlsx`）。

模板类别 9 类：`0 系统列表 / 1 发货清单 / 2 应收账单 / 3 应付账单 / 4 提单装箱单 / 5 提单发票 / 6 提单文件 / 7 清关资料 / 8 运单详情`（`lib/common/define/1024-export-template.js`）。前端原有 13 分类口径与本枚举无关，整体废弃。

### 数据流（关键设计点）

- **新增**：上传 → 组件回传 `file/fileUrl` + `parsed`（存到 `parsedFields`）→ 提交 `{...formModel, ...parsedFields}` 走 `/create`。
- **编辑**：以**列表行数据**回填 6 个字段（query 未 omit 它们，无需额外 `/get`）；`parsedFields` 保持 `null` ⇒ 提交体不含 `infoList/fieldList/subList` 等 ⇒ 后端 `updateOne` **不会覆盖**库中既有解析结果；一旦重新上传，则带新解析结果整体覆盖。
- 下载 = `window.open(fileUrl, '_blank')`（浏览器按下载处理，不新开空白页）；`fileUrl` 为空时 warning 提示。

## 五、坑与备忘

1. **上传组件不要设 `:max="1"`**：naive 在满额时会隐藏上传触发块，导致无法「选新文件替换旧文件」（基础配置 LOGO 场景才需要 `:max="1"`）。
2. **`type:'custom'` 项在 FormWrap 中照常参与校验**：`fieldItems` 只过滤带 `slot` 的项，custom 项仍生成 `NFormItem` + required 规则（按 `item.key` 校验 `model.file`），因此「Excel模板必填」零手写代码。
3. **图标可用性**：`icon-mdi-content-copy` 依赖本地 `@iconify/json`（pnpm store 内已存在），无需新增依赖；`icon-mdi-upload` / `icon-mdi-download` 项目已在用。
4. **测试期间观察到与本改动无关的现象**：导出格式页停留一段时间后 URL 会偶发被切到 `?tab=basic-config`（对 `history.pushState/replaceState` 打过补丁，未捕获到调用 ⇒ 非本页代码所为，疑似并行浏览器会话/多窗口共用 default 会话驱动）。规避方式 = 把操作压进单条指令内完成（`goto → 点击 → 填值 → 保存` 一次下发）。`setting/index.vue` 只**读** `route.query.tab`、无写回逻辑，故与本页无因果关系。
5. 列表 `query` 不返回 `infoList/fieldList/subList`（模型 omitFields），因此编辑回显只能用列表行数据；如后续要做「解析结果预览」，需补 `/get` 调用。
