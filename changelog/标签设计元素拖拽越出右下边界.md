# 标签设计元素拖拽越出右下边界

> **追代**：本文 move 的「每帧钳制贴边」曾被 [标签设计元素拖拽越界回到原位动画](./标签设计元素拖拽越界回到原位动画.md) 改成「自由出界 + 松手回弹」，但那次改动是**认错需求**（详见 [标签设计面板拖拽未落纸回到原位动画](./标签设计面板拖拽未落纸回到原位动画.md)）——用户要的「回到原位动画」指的是**左侧面板被拖项**，不是画布元素。**现已恢复本文的 move 纸界钳制**（元素不允许被拖出纸张，贴边停住），`resize` 的纸界钳制一直保留。

自研标签设计器（`label-designer`，非 hiprint 的 `print-design`）。

## 问题

用户反馈：手写标签设计界面上，元素「只有左和上有边界不能移出，下和右还是能移出」；同时从左侧面板拖入的元素如果没拖进纸张（标签）内，也不该被创建。

键盘方向键移动（`index.vue` 的 `moveSelected`）本来就是双端钳制，所以表现为「键盘移不出去、鼠标拖拽能移出去」的不一致。

## 根因

`src/views/system-manage/label-designer/modules/use-canvas-interaction.ts`：

1. `move` 只有下界 `Math.max(0, …)`（守左/上），没有 `paperW - width` / `paperH - height` 上界 → 右/下可拖出。
2. `resizeGeometry()` 只保证 `MIN_SIDE`，完全没有纸界约束：
   - `e` / `s` 手柄 → 右/下边越界；
   - `w` / `n` 手柄反而会把 `x` / `y` 推成负数（左/上也守不住）。
3. `design-canvas.vue` 的 `@drop` 绑在灰色视口（比纸张大）上，落点在纸张外也会创建元素，x/y 甚至为负。

## 设计（用户确认）

- 钳制**只动位置、不改尺寸**：元素本身比纸张大时上限退化为 0（贴左/上边），仍允许溢出。
- 修复面**仅限拖拽移动 + 8 向缩放**，外加「拖入落点必须在纸张内，否则不创建（拖拽项自动回原位）」。
- 钳制逻辑必须**预览（rAF 直写 DOM）与落库（写回 store）同源**，否则会出现拖动中越界、松手才回弹的跳变。

## 实现

`use-canvas-interaction.ts`：

- `DragState` 增 `paperW` / `paperH`（`paperPt()` 于 `begin` 缓存一次，拖拽期间纸张不变）。
- 新增纯函数 `clampInPaper(geo, paperW, paperH)`：`x ∈ [0, max(0, paperW - width)]`，`y` 同理，尺寸原样返回。
- `resizeGeometry()` 增加纸张参数与上限：
  - `e` → `width ≤ max(o.width, paperW - o.x)`；`w` → `width ≤ max(o.width, o.x + o.width)`（保证 `x ≥ 0`）
  - `s` / `n` 同理作用于高度与 `y`
  - 上限取 `max(原尺寸, 纸界余量)`：元素本来就超界时**不允许被强制缩小**，只禁止继续变大
  - `keepRatio`（Shift + 角手柄）：高度受纸界限制时先收敛高度再回推宽度，比例不破；补上 `w` 手柄的 `x` 回算
- `applyFrame()` 与 `onPointerUp()` 的 move / resize 全部改走同一套钳制。

`design-canvas.vue` · `onDrop()`：

- 取 `paperRef` 的 `getBoundingClientRect()`，落点不在矩形内直接 `return`（不创建元素，原生拖拽自动把列表项弹回原位）；
- `x` / `y` 随之改为 `const`，去掉了原来「拿不到 rect 就落在 (0,0)」的兜底。

## 遗留（未纳入本次范围）

- 拖入元素**落点在纸张内但靠近右/下边**时，元素仍可能按默认尺寸伸出纸张（落点即左上角，不做贴边钳制）——与「元素可以比纸张大」的约定一致，若需要收紧再单开。
- 复制/粘贴（`+4mm` 偏移）、属性面板手输 X/Y/宽/高、拖入后 `addElement` 均未加钳制。
