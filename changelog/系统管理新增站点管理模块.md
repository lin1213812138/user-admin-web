### 交互

- 顶部搜索栏（站点编号 / 站点名称 模糊 + 状态筛选）+ 表格（序号、勾选、操作列 fixed right）+ 分页；
- 工具栏：左侧「新增」「批量删除」，右侧「列设置」「刷新」；
- 行内操作：编辑 / 删除（NPopconfirm）；
- 新增 / 编辑走右侧抽屉（复用 `drawer.vue` + `FormWrap`）。

### 数据与接口

- 类型：`Api.SystemManage.Site / SiteList / SiteSearchParams / SiteCreateParams / SiteUpdateParams`（五件套）；
- 接口：`fetchGetSiteList` / `fetchCreateSite` / `fetchUpdateSite` / `fetchDeleteSite(ids)`；DEV 分支返回 mock 裸数据，非 DEV 走 `/system/site/list|create|update|delete`；
- mock：内存数组预置 6 条（首条为用户提供的「75501 深圳」样例），增删改真实生效；编号查重在 create/update 中校验（`throw new Error('站点编号已存在')`）；
- 错误提示口径：真实接口错误由 `request` 拦截器统一提示（`createFlatRequest` 永不 reject）；mock 同步抛错会 reject，由抽屉 `handleSubmit` 的 catch 兜底提示。

- 不采用 `src/components/MasterData/master-data-archive.vue` 通用归档组件：其接口层写死 `data-manage` 归档体系（`DataManageArchiveKey` + `fetchGetDataManageList`）且强制附加 status/createTime 列，与「挂在 system-manage 下、走独立接口」不符；
- 与 system-manage 现有模块（user/role/menu）保持同构：`useVxeTable` + `Table` + `modules/xxx-operate-drawer.vue`。

## 过程记录：elegant-router 生成踩坑（重要）

1. **vite 配置缓存**：修改 `build/plugins/router.ts` 后首次启动 dev，生成的路由 meta 仍是旧值（site 无 icon/order、setting order=4）——根因是 `node_modules/.vite-temp` 的配置 bundle 缓存未失效；**删掉 `.vite-temp` 后重新启动才按新配置生成**。结论：调完 `build/plugins/*` 配置后先清 `.vite-temp` 再跑 dev。
2. **生成器对已存在条目保留旧 meta**：`setting`(4) / `label-designer`(5) 的 order 不随配置更新（改了也不生效），只有新路由按配置写 meta ⇒ 想改已有路由的 order 得先删/还原该条目再生成；「配置=生成结果」原则下应反过来把配置对齐产物。
3. **order 去重顺移**：配置 `site: 5` 与 `label-designer: 5` 冲突时，生成结果为 `site: 6`；已把配置改为 6 保持一致。
4. **一次生成把 `routes.ts` 写坏**：文件末尾出现残片（重复了 `menuRoutes` 行的后半段 `route => !isNonMenuRoute(route));`），导致下次 dev 启动时 Babel 解析报 `MissingSemicolon (229:31)` 直接启动失败。修复：`git checkout -- src/router/elegant/routes.ts` 恢复 + 清 `.vite-temp` + 重跑 dev 生成（产物完好）。注：`routes.ts` 末尾的 `nonMenuRoutes` / `menuRoutes` 段是项目定制内容（HEAD 即存在），生成器会保留，非本次引入。
