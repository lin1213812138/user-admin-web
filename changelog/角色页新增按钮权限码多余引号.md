# 角色管理新增按钮不显示（权限码多余引号）

## 用户现象

用户反映有 `system:user:add` 权限但按钮不显示（实际根因定位到「角色管理」新增按钮 `system:role:add`）。

## 定位

- `src/views/system-manage/role/index.vue:292` 角色新增按钮写成 `<LButton auth="'system:role:add'" ...>`。
- `auth` 是 LButton 的**静态 prop**（无 `:`），Vue 把属性值当字面值，于是 `props.auth` 拿到的是**带单引号的字符串** `'system:role:add'`。
- `hasAuth`（`src/hooks/business/auth.ts`）检查 `userInfo.permissions.includes(code)`，而真实权限码是 `system:role:add`（无引号），故 `includes("'system:role:add'")` 永远 false → 按钮 `v-if="visible"` 恒为 false → 永不渲染。与角色配没配该权限无关。
- 关键区分：`v-auth="'x'"` 是**指令**，Vue 对指令值按 JS 表达式求值，内层引号被吃掉、`binding.value` 拿到 `x`（正确）；只有组件**静态 prop** `auth="'x'"` 才会原样保留引号（错误）。全仓 grep 确认仅此 1 处静态 prop 带引号，其余 8 处 `v-auth="'...'"` 均正确。

## 决策

单点修复：去掉 `role/index.vue:292` `auth` 静态 prop 多余的英文单引号（`auth="'system:role:add'"` → `auth="system:role:add"`）。零逻辑改动、零业务影响。

## 实施

`src/views/system-manage/role/index.vue:292` 一列改动（删掉值两侧单引号）。

## 验证

- `read_lints` 对 `src/views/system-manage/role/index.vue` 0 诊断；
- 浏览器复核：非超管账号、且角色 `auths` 含 `system:role:add` 时，角色管理页「新增」按钮正常显示；超管恒显示。

## 附带说明（用户页新增）

`src/views/system-manage/user/index.vue:282` 用户页新增 `auth="system:user:add"` 写法本身正确。若该按钮不显示，属权限配置问题：当前账号所属角色的 `auths` 不含 `system:user:add`（「角色管理→分配权限」里用户管理菜单下「新增」复选框未勾选保存，或改完权限后未重新登录刷新会话），非代码 bug。
