# 完善收货渠道界面（渠道报价 → 收货渠道）

## 背景

用户给出 `tms-user` 的 `ChannelSchema`（收货渠道，`lib/common/models/channel.js`）与旧系统「新建收货渠道」界面截图，要求「完善收货渠道界面」。

## 现状定位

- 目标页 `src/views/channel-quote/receive/index.vue` 是当初建模块时的**占位骨架**：只有 `code / name / status / remark` 四个字段、抽屉宽 520。
- 其调用的 `/channel-quote/receive/*` 在 `tms-user` **不存在**（`lib/api-v1-web` 下没有 `channel-quote` 目录），真实资源是 `/channel/*`；DEV 走 `channel-quote/mock.ts` 假数据，因此该页当时无法真正使用。
- 后端 `/channel/*`（query/get/create/update/delete）、以及全部选项数据源（`/carrier`、`/channel-group`、`/no-rule`、`/item-no-rule`、`/print-template`、`/weight-rule`、`/remote-group`、`/route-group`、`/site`、`/channel-out`）均已就绪。

## 后端契约要点（查 tms-user 得出）

1. `/channel/query` 传 `scene` 时后端 `fillName` 回填 `carrier / channelGroup / site / noRule / labelTemplate / weightRule / remoteGroup / routeGroup / itemNoRule` 名称，列表列可直接展示；同时 `setSite(params,'siteIds')` 按当前用户站点自动过滤。
2. `/channel/update` 走 `uniqField: ['name','code']` ⇒ 局部更新必须随行回传 `name` + `code`，否则写脏字段。
3. `/channel/delete` 仅支持单条 `_id` ⇒ 批量删除前端逐条调用。
4. `/channel/create` 只校验 `name`；`code` 为空时后端按序号自动生成。
5. `/no-rule/query` 的 `scene`：`1`=收货渠道转单号（前置「发货渠道获取」`_id='2'`）、`2`=收货渠道报关号（前置「号码池获取」`_id='1'`）、`3`=发货渠道。

## 设计结论（已确认并采纳推荐）

- 收货渠道页改用真实 `/channel/*`；新增/编辑/详情抽屉按截图分「基本信息（6 行 × 3 列）+ 渠道备注」两个区域；**本仓库没有 `LCard`/`components/basic/l-card` 组件**，改用 `FormWrap` 的 `type: 'section'` 表单项复刻截图的蓝色竖条分区标题；抽屉宽 520 → 1040。
- 选项全部取真实接口；`转单号规则 = 发货渠道获取` 时「绑定发货渠道」可选，否则禁用。
- 公共组件两处扩展：`FormItemConfig.labelTooltip`（承运网络 ⓘ）与 `FormItemConfig.suffix`（燃油费率 `%` / 报关费 `元`）。
- 边界：不动发货渠道页与 `channel-quote/mock.ts`、不动菜单/路由/权限码、不新增后端接口。

完整设计见 `docs/superpowers/specs/2026-09-20-收货渠道界面对接设计.md`。

### 空值口径（用户追加要求：「默认不要赋值空字符串」）

- 抽屉模型 `emptyModel()` 与回填 `fillModel()`：**空值统一落 `null`**（多选 `siteIds` 用空数组），不再使用 `''`；`openEdit/openDetail` 用 `row.xxx ?? null` 回填。
- 提交 `buildPayload()`：`null / undefined / ''` 一律不下发（避免把空字符串写进后端）；`code` 新建留空即不传（后端自动生成）、编辑必传；`siteIds` 例外——始终提交数组，以便清空站点。
- 列表搜索条件同样以 `null` 起步（`keyword: null` / `status: null`）。
