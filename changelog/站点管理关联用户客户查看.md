# 站点管理关联用户/客户查看

## 需求

用户："站点管理表格新增两个字段，关联用户、关联客户，显示查看两个字然后点击查询关联的用户和客户。"

## 用户确认的决策

1. **展示形式**：Modal 弹窗（项目此前无 NModal 先例，用户在「抽屉+Table / Modal / 跳转页面」三选项中拍板 Modal）。
2. **用户弹窗列**：用户姓名（name）、用户账号（account）、所属站点（site）、状态（status）。
3. **客户弹窗列**：客户编码（code）、客户名称（name）、所属站点（site）、状态（status）。
4. **弹层无搜索**：纯查看，不加关键词搜索。
5. **封装公共组件**：用户追问"能不能封装一个组件这样的？"→ 组件放公共目录 `src/components/common/`（非站点页私有），并进一步泛化——组件不感知 siteId，过滤条件由调用方 fetcher 闭包绑定。

## 定位（后端事实，零后端改动）

- **关联用户**：tms-user `User` 实体自带 `siteId`，`/user/query` 原生支持 `where.siteId` 精确过滤（`typings` 的 `UserSearchParams.where.siteId` 已有声明）；返回 `ret:{list,total}`，后端 `fillName` 回填 `site`（站点名称）。
- **关联客户**：tms-user `lib/common/models/customer.js` 有 `siteId`（所属站点）+ `site`（站点名称冗余字段）；管理端真实接口 `/customer/query`（`lib/api-v1-web/customer/customer.js` → `customerService.query` → `queryCommon`）支持 `{page,size,keyword,where}` 任意字段过滤。
- 前端现有 `service/api/customer/index.ts` 是模板遗留 mock（`/system/customer/*`），与真实客户接口无关，客户管理页面尚未接真实数据——本次不动它，在站点域 service 内新增真实查询函数。

## 关键细节

- **no-shadow**：页面内解构 `{ data: res, error }` 命名，避免与主表格 `useVxeTable` 返回的 `data` 重名（oxlint `no-shadow` 2 处，改后通过）。
- 组件内 `useVxeTable` 的 `columns: () => props.columns` 仅 setup 求值一次，故站点页挂两个实例各自固定列，而非单实例切换 fetcher/columns。
- 关联列 key（`relationUser/relationCustomer`）不是 `Site` 实体字段，与业务字段无冲突。
