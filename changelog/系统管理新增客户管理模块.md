# 系统管理新增客户管理模块

> 设计确认记录（2026-09-14）

## 背景

用户要求「系统管理新增客户管理模块」。当前 git status 中 `MasterData/archives/basic/customer/index.vue` 已被删，而 `changelog/基础资料子模块改造.md` 仍处于待确认状态（用户想把基础资料改造为 5 个子模块）。经澄清，客户管理**不回归** MasterData 通用归档体系，而是作为 `system-manage` 下的独立菜单页，与站点管理 / 组别管理完全同构。

## 关键决策

1. **落地形式**：`system-manage` 独立菜单页（新建 `views/system-manage/customer/index.vue` + `modules/customer-operate-drawer.vue`），独立 CRUD、独立路由（icon/order）、DEV mock 先行。不采用 `MasterData` 通用归档组件（其接口写死 data-manage 归档体系，与系统管理模块解耦）。
2. **字段范围**：基础客户档案（用户确认）。
3. **客户等级 / 客户来源**：先用静态中文选项，避免跨模块耦合（后续可改为关联 `data-manage` 的 `customer-level` / `customer-source` 档案）。

## 数据模型（Api.SystemManage.Customer）

| 字段                                                  | 含义     | 说明                                                     |
| ----------------------------------------------------- | -------- | -------------------------------------------------------- |
| id                                                    | 主键     |                                                          |
| customerCode                                          | 客户编号 | 必填，**唯一查重**（mock 抛「客户编号已存在」）          |
| customerName                                          | 客户名称 | 必填                                                     |
| customerLevel                                         | 客户等级 | `'normal' \| 'important' \| 'vip'` → 普通 / 重要 / VIP   |
| customerSource                                        | 客户来源 | `'website' \| 'referral' \| 'ad'` → 官网 / 转介绍 / 广告 |
| contactName                                           | 联系人   |                                                          |
| contactPhone                                          | 联系电话 |                                                          |
| email                                                 | 邮箱     |                                                          |
| address                                               | 地址     |                                                          |
| status                                                | 状态     | `0 \| 1` 启用 / 禁用                                     |
| remark                                                | 备注     |                                                          |
| createByName / createTime / updateByName / updateTime | 审计字段 |                                                          |

- `CustomerSearchParams`：`customerCode?` `customerName?` `customerLevel?` `status?`
- `CustomerCreateParams` / `CustomerUpdateParams`：业务字段（不含 id / 审计字段）

## 静态选项（避免跨模块耦合）

- `customerLevelOptions`：`普通/重要/VIP` → `normal/important/vip`
- `customerSourceOptions`：官网 / 转介绍 / 广告 → `website/referral/ad`

## 实现要点

- 列表 / 搜索 / 抽屉照 `site`/`group` 范式（`useVxeTable` + `Table` + `TableColumnConfig`，抽屉用 `FormWrap` 三区块 + 详情态 `mode='view'` 文本展示）。
- 搜索栏：客户编号(input) / 客户名称(input) / 客户等级(select) / 状态(select) + actions。
- 表格列（可见）：客户编号(detail,120) / 客户名称(140) / 客户等级(100,插槽反查中文) / 客户来源(100,插槽) / 联系人(100) / 联系电话(140) / 状态(100, fixed right, `type:'status'`) / 更新时间(180,「更新人 - 时间」插槽)；邮箱、地址默认隐藏。
- 路由 key：`system-manage_customer`；icon `ic:round-business`；**order 6**（group 之后、setting 之前；`label-designer` 隐藏占 6 无展示冲突）。
- mock `customerCodeExists` 查重抛错；状态 0 为有效筛选值用 `=== 0 || === 1` 判断。
- 菜单树：`MENU_TREE` 加 `{ id: 27, title: '客户管理' }`；`menus` 加 `createMenu(27, 2, 'customer', ...)`；`ALL_MENU_IDS` 加 27。
- 按钮权限：`permission: 'system:customer:list'`、`routePath: '/system-manage/customer'`，buttons = query / reset / add / edit / delete。
- **路由生成前先删 `node_modules/.vite-temp`**，再 `pnpm dev` 触发 elegant-router 重新生成（禁止手改 `router/elegant/**`、`typings/components.d.ts`、`typings/elegant-router.d.ts`）。
