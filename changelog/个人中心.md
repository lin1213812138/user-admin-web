# 个人中心（修改个人信息 + 修改密码）

## 需求

用户："再加个个人中心界面链接在这里，用来修改个人信息和修改密码的"（"在这里" = 侧栏底部用户区下拉菜单）。

## 后端事实（tms-user 源码核实 + 数值验证）

1. **改自己密码会被后端拒绝**：`lib/services/user.js` 的 `update` 中 `if (!user.editPwdCtrl && body.password) throw EDIT_PWD_ERROR`（100107「不允许修改密码」）；而 `editPwdCtrl` 全库仅此一处引用、**没有任何赋值来源**（`fillAuthMap` 只合并 `editInfoCtrl`；`Role` Schema 里也没有 editPwdCtrl）→ 恒为 `undefined` → 必然拒绝。管理员可改**他人**密码（用户管理页），改不了自己的。
2. **改自己信息需要 `editInfoCtrl`**（角色字段「用户修改个人信息」0/1）；admin（accountType=1）后端自动置 1，故管理员可改自己的信息，普通用户由角色控制。
3. **改自己密码会销毁会话**：`update` 返回 `logout=true` → ctrl 调 `userService.logout(ctx)`。
4. **密码格式 = `md5(md5(明文)+明文)`**（数值验证：`md5(md5('admin@12345')+'admin@12345') = e6b74644a7667245c0298e795506479a` = 后端常量 `ADMIN_PASSWORD`）。
5. 没有独立的改密码接口，只有 `/user/update`。

## 决策（用户确认）

- 改密码阻塞 → **前端先做界面、整体置灰**，提示「后端未开放」，待后端支持后启用。
- 入口形态 → **独立页面 + 两个 tab**（VerticalTabLayout：基本信息 / 修改密码），不进左侧菜单。
- 可改字段 → **全量**（与用户管理抽屉一致）。

关键设计点：

- 保存只提交可编辑字段（后端 `assign(dbUser, body)` 只覆盖传入字段），成功后 `$message` + `authStore.getUserInfo()` 刷新侧栏。

- 修改密码页**不做旧密码字段**（后端无旧密码校验机制）；启用步骤：去掉 disabled → 提交 `{ _id, password: md5(md5(新密码)+新密码) }` → 成功后提示重新登录并 `resetStore()`。

## 踩坑

1. **NDropdown 菜单项不能用 DOM `click()` 点击**：`option.click()` 不触发 naive 的选中逻辑（菜单不关、不跳转）；必须用真实鼠标事件序列（`mousemove` + `mousedown` + `mouseup`）。playwright 复测时注意。
2. 页面模板顶层禁止 HTML 注释（否则组件变 Fragment，布局层 `Transition` 收不了尾 → 之后所有页面内容区永久空白，见 `changelog/系统设置tab切换后跳转空白页.md`）；`personal-center/index.vue` 已按规则把注释放在根组件内部。
3. `FormWrap` 对同一 key 的自定义 rules 会**覆盖**自动生成的必填规则 → required 星号与空值校验要在自定义规则对象里一并手写（`{ required: true, message, trigger, validator }`）。
4. i18n 的 `route` 段类型是 `Record<I18nRouteKey, string>`：新路由生成后 zh-cn / en-us **必须同步补 key**，否则 typecheck 报缺键。
