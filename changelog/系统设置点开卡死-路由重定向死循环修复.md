# 系统设置点开卡死 —— 路由重定向死循环修复

## 问题现象

点击左侧菜单「系统设置」后页面卡死（白屏 / 无响应），浏览器控制台报 vue-router 重定向循环。

## 根因

`src/router/elegant/transform.ts` 在路由转换时，会给**任何拥有 `children` 的路由**自动追加 `redirect` 指向第一个子路由（见自动生成的 `transformElegantRouteToVueRoute` 中 `if (children?.length && !vueRoute.redirect)` 分支）。

而「系统设置」的 7 个 tab 子页原本放在 `views/system-manage/setting/<子页>/index.vue` 下，被 elegant-router 自动生成为 `system-manage_setting` 的 7 个子路由，于是父路由被自动加上 `redirect: { name: 'system-manage_setting_export-format' }`。

同时 `src/router/guard/route.ts` 旧有规则：所有 `system-manage_setting_*` 子路由一律 `replace` 回父路由 `system-manage_setting`（设计意图是「子页不独立可访问，由页内 tab 接管」）。

两者叠加形成死循环：

```
点系统设置 → /setting 自动重定向到 export-format 子路由
→ 守卫拦截重定向回 /setting
→ /setting 又自动重定向到子路由 → ……无限循环
```

## 修复方案

将 7 个 tab 子页从自动路由目录移出到 `setting/modules/`（纯组件，elegant-router 默认忽略 `modules/` 目录，不再生成子路由），`system-manage_setting` 退化为叶子路由（无 children → 无自动 redirect），从而彻底消除循环。

### 改动清单

1. 移动 7 个子页（保留内容为纯组件，仅改所在目录）：
   - `setting/input-format/index.vue` → `setting/modules/InputFormat.vue`
   - `setting/print-format/index.vue` → `setting/modules/PrintFormat.vue`
   - `setting/export-format/index.vue` → `setting/modules/ExportFormat.vue`
   - `setting/waybill-rule/index.vue` → `setting/modules/WaybillRule.vue`
   - `setting/notification-config/index.vue` → `setting/modules/NotificationConfig.vue`
   - `setting/init-data/index.vue` → `setting/modules/InitData.vue`
   - `setting/station-scan/index.vue` → `setting/modules/StationScan.vue`
   - 子页内部仅引用 `../components/MasterDetail.vue` 与 `../components/FieldMapping.vue`，移动到 `modules/` 后 `../components/` 仍指向 `setting/components/`，**无需改子页内部 import**。
2. `setting/index.vue`：7 处 import 由 `'./input-format/index.vue'` 改为 `'./modules/InputFormat.vue'` 等（componentMap 的 key 不变）。
3. `src/router/guard/route.ts`：删除已失效的 `system-manage_setting_*` 重定向规则（子路由已不存在）。
4. 路由重新生成（`pnpm dev` 触发 elegant-router 插件）：`routes.ts` / `imports.ts` / `transform.ts` / `elegant-router.d.ts` 不再含 7 个子路由（`components.d.ts` 由 unplugin 生成、本就不含这些子页，无需改）。
5. `build/plugins/router.ts`：删除 `hiddenRoutes` 数组及其 `hideInMenu` 应用（子路由键已不存在，否则 typecheck 报错）。
6. `src/locales/langs/en-us.ts`、`zh-cn.ts`：删除 7 个已失效的 `route.system-manage_setting_*` i18n 键。

## 验证

- `pnpm typecheck` 通过。
- 点击「系统设置」应正常进入 tab 页，7 个子模块可切换；刷新后默认停在录单格式（页内 tab 默认值）。
- 外部直接访问 `/system-manage/setting/xxx` 的 URL 将因路由不存在而落到 404（符合「子页不独立可访问」设计）。
