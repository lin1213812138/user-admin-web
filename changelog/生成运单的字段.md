# 运单字段清单生成（fields-config.js）

日期：2026-09-17
范围：`src/views/system-manage/setting/modules/input-format/fields-config.js`（单文件）

## 背景

`fields-config.js` 是新建的录单字段清单文件（尚无任何引用），结构为平铺数组 + 注释分区（运单 / 收件人 / 发件人 / 子单号 / 物品信息），每条 `{ type, key, label, required, show }`。本轮先把「运单字段」分区补全：用户给出 52 个中文字段清单（客户 → 备注5）。

## 设计决策（已与用户确认）

1. **key 对齐后端运单模型**（`tms-user/lib/common/models/order.js`），下拉类存 id 字段：`customerId` / `channelId` / `countryId` / `billModeId` / `customTypeId` / `customsClearId` / `exportReasonId` / `salesTermsId`（不用名称字段 `channel` / `customType` 等）。
2. **「类型」= `packType`**（0-包裹 / 1-袋子 / 2-文件；后端导入字段表 `uploadField` 里中文就叫「类型」）。
3. **`required` / `show` 默认全 `false`**（沿用已有 `customerId` 条目：默认不显示、非必填，由配置方后续启用）。
4. **`type` 沿用 Form 组件 `FormItemType` 命名子集**：`select` / `input` / `number` / `switch` / `textarea`。

## 续：收件人字段（16 条，同日追加）

用户给出收件人字段清单（FBA仓库代码 → 证照2）。

### 决策（已与用户确认）

1. **key 用短名**（`name` / `phone` / `fbaCode`…）——分域改由 `fieldType` 承担。背景：用户在本文件首次生成后自行给全部运单字段补了 `fieldType: 'order'`，并给 `packType` 增加 `component: 'packTypeSelect'` 对接组件。
2. **`fieldType: 'shipTo'`**（对齐后端 `shipTo` 子文档名；后续发件人 / 子单 / 物品同规则用 `shipper` / `item` / `product`）。
3. **证照1 / 证照2 = `image`**（对应后端 `shipTo.imgUrl1` / `shipTo.imgUrl2`，FormItemType 自带的图片上传类型）。
4. **国家 = `select`**（选项来自国家档案、存名称；省州仍 `input`）。注意与运单层「目的地」`countryId`（select、存 id）区分；「税号」`taxNo` 也不同于运单层 `vat`。
5. 顺手补上用户漏写的 `customsNo`（报关号）的 `fieldType: 'order'`（该条是全部运单字段中唯一缺失）。

## 续：发件人 / 子单号 / 物品信息字段（48 条，同日追加）

用户一次给出三组清单（发件人 15 / 物品信息 20 / 子单号 13）。

### 决策（已与用户确认）

1. **fieldType 沿用域标识约定**：发件人 `shipper`、子单号 `item`、物品信息 `product`（分别对齐后端 `shipper` 子文档、`order-item` 模型、`productList` 数组项）。
2. **发件人与收件人同构**：`country` = `select`（国家档案存名称）、证照1/2 = `image`、其余 `input`。
3. **物品信息**：币种 `currency` = `select`（财务资料币种档案，后端默认 USD）、单位 `unit` = `select`（后端固定枚举 PCS/SET/MTR/KG/ROLL/BOX/PRS/DOZ/PKGS/EA/M2/M3/CM/CM3）、产地 `producer` = `input`（用户定，自由输入）；产品图片 `imgUrl` = `image`。
4. **子单号**：8 个计算类字段（单件实重 weight、长/宽/高 length/width/height、三边和 totalLen、围长 wrapLen、单件材重 volumeWeight、计费重 priceWeight）= `number`；5 个单号/备注（子内单号 no、子转单号 channelNo、子派送号 trackNo、客户子单号 customerNo、物品备注 note）= `input`。
5. **短名重复说明**：域内短名导致 key 跨域重复 24 个（如 `shipTo`/`shipper` 的 name/country/imgUrl1、`order`/`item` 的 weight/note、`shipTo`/`product` 的 imgUrl 等），唯一性由 `fieldType.key` 组合保证。
