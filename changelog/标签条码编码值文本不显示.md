# 标签设计：条码「编码值」下方文本不显示（displayValue 旧数据缺失）

> 日期：2026-09-12

## 现象

用户在属性面板填了「编码值 11111111」，画布条码图形按新值重绘，但下方人读文本不显示。

## 排查过程（系统性验证）

1. 画布渲染链：`resolveDisplayText`（value → placeholder → 空）→ `renderBarcode({ displayValue: o.displayValue, ... })` → bwip-js `includetext`。参数链路静态看是对的。
2. 查 bwip-js Options Reference：`includetext: true` 即渲染下方文本；`alttext` 仅改显示内容；`textsize`/`textxalign` 只在 includetext 开启时生效。
3. **node 实测**（项目同款 bwip-js，`toBuffer` 渲染 PNG 对比）：`includetext: true` → 237×**109**（含 23px 文本带）；`false` → 237×**86**。参数与渲染核心无问题。
4. 用户截图条码比例接近 86px 无文本版本 → 运行时 `o.displayValue` 为 falsy。
5. 而新建条码 `defaultOptionsFor` 硬编码 `displayValue: true`，不可能缺失 → **元素来自 `loadFromJson` 还原的旧 designJson**（`loadFromJson` 原样还原 elements，不补默认字段；旧数据 barcode options 没有 `displayValue` 键）→ `includetext: undefined` → 不画文本。

## 修复（渲染层单点兜底 + 面板同步，向后兼容旧数据）

- `barcode.ts` `renderBarcode`：`displayValue?: boolean` 放宽为可选，`showValue = opts.displayValue !== false`——**未配置视为显示，仅显式 false 才隐藏**；`textsize` 三元同步。画布 `element-renderer.vue` 与打印 `render-element-html.ts` 共用此函数，一处修复两端生效。
- `property-panel.vue` `buildModel`：barcode 且 options 无 `displayValue` 键时补 `displayValue: true`——「显示值」开关对旧元素正确显示为开（避免 UI 关/实际开的错位），选中回写后 options 自动补全。

## 备注

- agent-browser 在本环境不可用（Volta shim 损坏），浏览器端未单独实测；bwip-js browser/node 共享同一 bwipp 渲染核心，node 实测已覆盖渲染正确性。
- 临时验证文件（node 脚本 / PNG / html）已清理。

## 验证

- `pnpm typecheck` 通过；label-designer 目录 lint 0 错误。

## 追查：修复后「还是空的」

- 用 playwright-cli 启真实 Chromium + 项目同款 `dist/bwip-js.js`（UMD）实测：`includetext: true` 清晰渲染出 `321321321` 文本，`false` 无文本——**浏览器渲染管线 100% 正常**（agent-browser 在本机 Volta 环境不可用，playwright-cli 可用但禁 file://，用临时 node 静态服务绕过）。
- 结论：`displayValue !== false` 兜底只救「缺字段」，**该元素 options 里是显式 `false`**（旧保存数据/误触），显式关闭仍隐藏是开关的设计内行为。
- 体验修复：「显示编码值」开关从样式卡**挪到数据预览卡「编码值」正下方**（barcode 专属；qrcode 无下方文本概念不加），状态一目了然，拨开即显示。

## 追加：fontSize 缺失 → textsize NaN → bwip-js 抛错（第三轮实锤）

- node 复现：`textsize: Math.max(4, Math.round(undefined))` = NaN → bwip-js **抛 `bwipp.invalidOptionType: textsize: not a realtype: NaN`** → `draw()` catch 落 ERR 占位图。旧数据 barcode 缺 `fontSize` 时，拨开「显示编码值」就会从「无文本」变成「ERR 图」。
- 修复：`fontSize = Math.max(4, Math.round(opts.fontSize || 10))`（缺省 10）。
- 多轮「还是空的」的最大嫌疑：**dev server 未重启/热更失效，用户一直跑旧代码**（用户侧需确认数据预览卡是否出现「显示编码值」开关；没有=代码未加载）。

## 追加：真正的同步 bug——空 text 键遮蔽编码值（第四轮，实锤修复）

用户持续反馈「改字号/编码值画布变空、不同步」。playwright 复现页（项目同款 bwip-js + 与 renderBarcode/resolveDisplayText 完全一致的逻辑）逐步模拟「改字号 → 清空编码值 → 重输」，对照用户截图锁定根因：

- `buildModel` 的受控空值兜底**不分元素类型**给所有 options 回写 `text: ''`（为修「输入框残留旧值」而加）；
- `resolveDisplayText` 按**键存在与否**取值（`'text' in opts` 优先）→ 条码 options 被污染出空 `text` 键后，**`value`（编码值）永远被遮蔽** → 画布渲染空格、改编码值不更新；
- 基础元素 `123456` 条码「有文本」只是因为它从未被点选、未被污染——两码显示逻辑其实一致。

修复（双保险）：

1. `resolveDisplayText`：回退链改为 **text → value → src 依次取第一个「非空」值**（空串不再遮蔽后续键），已污染的存量 designJson 自动恢复；
2. `buildModel` 兜底**按元素类型限定内容键**（text/longText→text，barcode/qrcode→value，image→src；title/field 公共），条码 options 不再被写进 text 键。contentKeyMap 用 `Partial<Record<ElementType, string>>`（首次用 as const 字面量对象索引 ElementType 报 TS7053，rect/line 无对应键）。

playwright 复现验证：污染 options（text:''+value）与正常 options 均渲染文本，改编码值画布同步。`pnpm typecheck` 通过。

## 终局：截图对比定位——不是 bug，是数据不同（后被第四轮推翻部分结论）

用户对比图：基础元素「条形码」拖入的条码下方有 `123456`，业务字段 orderNoCode 拖入的没有，问「为什么不一样」。

- 两条路径走**同一个** `defaultOptionsFor` barcode 分支（`displayValue: true`、`fontSize: 10` 硬编码都在），渲染代码完全一致；
- 唯一差异：基础元素自带示例值 `defaultOptions: { sample: '123456' }` → 编码值/人读文本 = 123456；orderNoCode 是用户自定义字段，**没配 `sample`**（空串）→ `value: ''` → `resolveDisplayText` 返回空 → `renderBarcode` 的 `text: opts.text || ' '`（空格）→ 条码编码空格、人读文本显示空格 = 看起来空；
- 结论：显示逻辑正常，**在「编码值」里填内容即显示**；想让 orderNoCode 拖入自带值，在 `BUSINESS_FIELDS` 给它配 `sample`。前几轮修的 displayValue 缺字段兜底、fontSize NaN 兜底是独立真实问题，仍然有效。
