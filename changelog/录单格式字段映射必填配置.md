# 录单格式字段映射：新增「必填」配置

日期：2026-09-14
范围：`src/views/system-manage/setting/`（`components/FieldMapping.vue`、`components/field-mapping-config.ts`、`modules/input-format/InputFormat.vue`）

## 背景

系统设置 → 录单格式的字段映射，原先只能配置每个字段是否显示：

```ts
// FieldMapping.vue 的 modelValue / InputFormatItem.fields
Record<string, string[]>; // 分组 key → 已勾选（显示）的字段 key 列表
```

实际业务中不同录单格式对字段的必填要求不同，需要把每个字段的配置从「一个布尔」升级成「显示 + 必填」两个维度。

## 设计决策（已与用户确认）

### 1. 数据结构：`string[]` → `{ show, required }`

```ts
/** 某个分组下的字段映射，显示 / 必填两个维度各自独立 */
interface FieldMappingValue {
  show: string[]; // 显示该字段的 key 列表（原 string[] 原样迁入）
  required: string[]; // 设为必填的字段 key 列表（新增）
}

// 例
fields: {
  waybill: { show: ['bizRemark', 'innerRemark'], required: ['bizRemark'] },
  receiver: { show: [], required: [] }
}
```

备选方案「每个字段一条 `{ show, required }` 对象」因稀疏数据变密集、40 条 mock 全重写而放弃，当前只有两个维度不值得。

### 2. 「显示」与「必填」数据层独立，UI 层不许新增矛盾配置

- 数据层：两个数组独立存储，**不自动联动**（取消显示不清除已设必填），天然支持 4 种状态组合；
- UI 层：**未勾「显示」时「必填」置灰禁用**，不允许新配置「必填但不显示」；已勾选状态保留可见，重新勾选显示后恢复可编辑。
  即「必填但不显示」只可能来自历史 / 后端数据，UI 展示为「置灰 + 已勾选」。

### 3. 分组「一键全选」按钮完全不变

仍只统计 / 操作 `show` 数组，按钮文案「分组名 n/m」含义不变（n 为显示数）。

### 4. 布局

字段格子内两个 checkbox 并排（显示 / 必填，gap 8px），字段名弹性占满、必填定宽不压缩。
`receiver` 的「地址 / 公司」原先 span 4（1/6 宽）放不下两个框，调为 8（其余字段 span 不动）。

### 5. 不做的事

- 分组按钮文案 / 行为不变，不做必填数量统计；
- 本页其它硬编码中文（分组标题、mock 名称等）不在本次范围。

## 二次调整：展示方式重做（用户截图反馈「太丑」）

### 丑的根因

1. 「必填」二字在每个字段旁重复 20+ 次，文字噪音盖过字段名；
2. 未勾「显示」的字段也渲染置灰的「必填」框（如整组「发件人信息」），一半控件是无意义占位；
3. 两个等权重复选框并排（`☐业务备注 ☐必填 ☐内部备注 ☐必填`），分不清「必填」归属、一行仅放 3 个字段。

### 新方案（用户选定「复选框 + 星标」）

- 每个字段只保留一个文字标签：`☑ 业务备注 ★`
  - 勾选框管「显示」（行为不变）；
  - 紧跟的星标管「必填」：`★` 主题红 `text-error` = 必填、`☆` 灰 `#c0c4cc` = 非必填， hover 变红提示可点，点击切换 + `NTooltip`「必填」；
- **未勾「显示」时星标不渲染**（数据保留，重新勾选显示后自动恢复原必填状态）；
- 星标 `inline-block w-14px text-center` 固定宽（避免 ★/☆ 切换时布局抖动）+ `select-none`；只读态仍渲染但不可点（保证非编辑态能看到必填信息）；
- 默认栅格 `span 8 → 6`（一行 4 个），`senderAddress` 的 `span: 12` 不受影响；
- 星标颜色走主题色板（`text-error` = `rgb(var(--error-color))`），随主题 / 暗黑自动适配，不硬编码色值。

### 二次验证

- `pnpm typecheck`：0 error。

## 三次调整：星标可点性 + 勾显示默认必填（2026-09-14）

用户反馈：「星号太小不方便勾选，而且勾选显示，必填默认勾选上」。

### 1. 星标放大

- 字号 `14px → 16px`，点击热区固定 `24×24`（`inline-flex h-24px w-24px rd-4px`，约等于一个 checkbox 的可点范围）；
- hover 出现浅灰底（`hover:bg-#f3f4f6`，暗黑 `dark:hover:bg-#ffffff1a`）并变红（`hover:text-error`），未必填时也能一眼看出可点；
- 只读态（`disabled`）仍渲染星标但无 hover 反馈、不可点。

### 2. 勾选显示 → 默认必填

- `toggleField(checked = true)` 时同时把字段并入 `required`（判重追加），即新勾选的字段默认「显示 + 必填」；
- 取消显示**不清除**已设必填（保持数据不破坏，与「两维度独立存储」原则一致）；
- 交互闭环：想要「显示但选填」需手动点一次星标取消。

### 三次验证

- `npx oxfmt` / `npx oxlint --fix` / `npx eslint --fix` 单文件：0 error。
- `pnpm typecheck`：0 error。

## 四次微调：显示复选框补 tooltip（2026-09-14）

用户反馈：「这个（字段的显示复选框）能不能也加个 tooltip」——与星标的「必填」tooltip 对称。

- `NCheckbox`（显示）外包 `NTooltip`，文案复用现有 i18n 键 `common.show`（显示 / Show），无需新增键；
- 只读态（`disabled`）下原生复选框不触发 mouseenter，tooltip 自然不显示，无需额外处理；
- 至此两个控件都有悬停说明：勾选框 =「显示」、星标 =「必填」。

## 五次修正：分组一键全选未设必填（2026-09-14）

用户反馈：「一键全选没有勾选必填」——分组全选此前只操作 `show` 数组，与字段级「勾选显示 → 默认必填」的行为不一致。

- `toggleGroup` 改为：全选时 `show = 全部字段` 且 `required` 合并全部字段（判重），与字段级勾选行为对齐；
- 取消全选仍只清空 `show`，**不清除**已设必填（与字段级「取消显示不清除」一致）；
- 分组按钮的 `7/7` 计数仍只统计显示维度（不变）。
