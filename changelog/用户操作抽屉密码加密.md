# 用户操作抽屉密码加密

> 2026-09-17 ｜ `system-manage/user/modules/user-operate-drawer.vue`

## 需求

用户管理「新增 / 编辑用户」抽屉提交时，密码字段原来以**明文**传给后端，需要按登录的加密方式加密后再提交。

## 现状定位

- 登录约定：`src/service/api/auth/index.ts` 的 `fetchLogin` 使用 `password = md5(md5(plain) + plain)`；工具函数 `md5()` 位于 `src/utils/crypto.ts`（crypto-js `MD5`，输出小写 hex）。
- 抽屉提交：`user-operate-drawer.vue` 的 `handleSubmit` 中
  - 新增：`fetchCreateUser({ ...buildSubmitParams(), password: model.password })` —— 明文；
  - 编辑：`model.password` 非空时以明文携带，留空表示不修改密码 —— 明文。

## 方案对比

| 方案      | 说明                                                   | 结论                                     |
| --------- | ------------------------------------------------------ | ---------------------------------------- |
| A（采纳） | 页面提交处加密，与登录、个人中心既有约定一致           | 改动最小，仅 1 文件 2 处                 |
| B         | 在 `crypto.ts` 抽公共 `encryptPassword()` 并让登录复用 | 更 DRY，但要动登录代码，超出本次范围     |
| C         | 在 `service/api/user.ts` 层加密                        | 与项目惯例不符（登录也是页面层算好再传） |

方案 A 经用户确认采纳。

## 实施

仅改 `src/views/system-manage/user/modules/user-operate-drawer.vue`：

1. 引入 `import { md5 } from '@/utils/crypto';`
2. `handleSubmit` 中密码统一套用登录同格式 `md5(md5(p) + p)`：
   - 新增：`password: md5(md5(model.password) + model.password)`；
   - 编辑：仅当 `model.password` 非空时携带加密后的密码，留空仍表示不修改（原逻辑不变）。

## 验证

- `pnpm typecheck` 通过；
- 无 UI / 交互变化，编辑留空仍表示不改密码。
