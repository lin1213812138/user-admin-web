# 硬闸门口令补充「开始」

> 日期：2026-09-20 ｜ 状态：已实施（hooks 改动需**新开会话**生效）

## 背景

> 用户原话：「你把开始加到口令里面去」

起因：本任务的 spec 确认环节，用户两次用「开始吧」「开始」催开工，但两词都不在原口令清单里（原清单：`确认 spec` / `spec 已确认` / `设计通过` / `按这个实现` / `开始实现`），`gate-user-prompt.mjs` 的 `prompt.includes(phrase)` 未命中 ⇒ 闸门不开，只能由 Agent 按「实质确认」处理，体验割裂。用户要求直接把「开始」纳入口令。

## 改动（4 个文件）

1. `.codebuddy/hooks/gate-user-prompt.mjs`
   - `PHRASES` 追加 `'开始'`，并**置于数组末尾**：`find` 命中即记录，顺序保证「开始实现」等更精确的口令优先匹配，记录到的 phrase 更准确；
   - 补注释说明该口令宽泛；
   - stdout 的闸门提醒文案补全口令清单。
2. `.codebuddy/hooks/gate-pre-write.mjs`
   - 拦截提示第 3 条的口令清单补全（含 `开始`）。
3. `.codebuddy/rules/workflow-gate/RULE.mdc`
   - 「自动放行口令」行补 `开始`，并加一句宽泛说明（该文件是工作区规则的正文来源，与 `AGENTS.md` 同源）。
4. `AGENTS.md`
   - 顶部「**自动放行口令**」行同步补 `开始` + 宽泛说明。

## 副作用（已向用户说明）

`开始` 只有两个字，`includes` 匹配下**消息中只要出现「开始」二字即开闸**（如「开始吧」✓，以及「先别开始」「还没开始做」也会命中）。这是用户明确要求的取舍；如需收紧，可改为只在消息以此词结尾 / 或退回原 5 条口令。

## 边界（未动）

- 闸门判定逻辑本身未改：仍是「`.codebuddy/gate/approved.json` 存在且 mtime ≥ 最新 spec」；**新写一份 spec 仍会自动关门**，每个新任务依旧要重新等确认。
- 历史 `changelog/` 与 `AGENTS_CHANGELOG.md` 中的既有记录不回改（历史记录不做改写）。
- hooks 改动**需新开会话生效**。

## 验证

- `node --check` 两个 hook 脚本：通过（无语法错误）。
- 以 node 直接投递 payload 实测（避开 PowerShell 管道编码干扰，且 `CODEBUDDY_PROJECT_DIR` 置空、`cwd` 指向临时目录，不污染项目 gate 状态）：
  - 消息 `开始吧` → `gate-user-prompt.mjs` 写出生效文件 `approved.json`，`A_APPROVED=true` ✓
  - 未开闸状态下 `write_to_file` 目标 `src/a.vue` → `gate-pre-write.mjs` 输出 `⛔ 硬闸门拦截：禁止写入 src/a.vue` 且 `exit=2` ✓（闸门拦截能力未因新增宽泛口令而削弱）
