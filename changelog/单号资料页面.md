# 单号资料页面（运单号规则归位）

## 用户需求

「运单号规则加到资料管理-单号资料-单号规则这里」

## 讨论与确认（六项）

1. **位置** = 「资料管理」下新建「单号资料」页面（二级菜单第 4 页，基础/业务/财务之外），页内 tab 叫「单号规则」（不含替代方案：改造业务资料的「单号资料管理」tab / 把业务资料页改名）。
2. **旧入口** = 系统设置里的「运单号规则」移除（信息架构归位，不并存）。
3. **数据源** = 接后端真实接口 `/no-rule/*`（用户贴 tms-user `NoRuleSchema`），DEV 也直连、无 mock。
4. **sysType** = 表单可选（自定义默认 / 1-运单号 / 2-客户编号）；sysType 有值的记录前端同步禁删（对齐后端 `BUILD_IN_ERROR`）。
5. **业务资料的「单号资料管理」tab** = 删除（单号规则独立成页后多余）。
6. **路由/目录命名** = `/data-manage/no-rule`、`src/views/data-manage/no-rule/`（对齐后端模块名，避免与业务资料里 waybill 档案混淆）。

设计文档：`docs/superpowers/specs/2026-09-17-单号资料页面对接后端设计.md`

## 后端事实（tms-user 源码核实）

- 模型 `lib/common/models/no-rule.js`：`name/start/end/len/current/prefix/suffix/checkType(0-无验证位 1-加权验证 2-模7验证)/buildIn/sysType(1-运单号 2-客户编号)/note` + 创建人/更新人/毫秒时间戳；**无 code、无 status**。
- 接口 `lib/api-v1-web/no-rule/index.js`：`/no-rule/{create,update,delete,query,get}`。
  - create 必填 name/start/end/current/len、name 唯一、prefix/suffix 自动转大写；
  - update 时 buildIn=1 忽略 name（不可改）、改 current 同步 redis；
  - delete 时 sysType 有值抛 BUILD_IN_ERROR（不可删）；
  - query 未配 keywordFields（keyword 无效）、不传 scene 无过滤。
