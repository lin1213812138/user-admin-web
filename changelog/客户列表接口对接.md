# 客户列表接口对接

- 用户："客户列表的接口帮我对接上"，随后贴老系统「新增客户」表单截图："新增客户按这个"

## 后端事实（tms-user 源码，零改动）

- 前端客户模块（`customer-manage/customer` + `service/api/customer`）此前为纯 mock：假端点 `/system/customer/*`、`id: number`、字段名（customerCode/contactName…）与后端完全不符
- 真实接口在 `/api/v1/web/customer/*`：
  - `/customer/query`：`{ page, size, where, keyword, scene }` → `{ list, total }`；`scene=1` 为管理列表（否则后端强制 `where.status=1`）；`keyword` 固定匹配 code/name/account（服务端 keywordFields）
  - `/customer/create`：name/account 必填且唯一（uniqField code+account），code 不传走 `fillCode` 按单号规则自动生成
  - `/customer/update`：需 `_id`，改 account 时后端校验唯一并同步 upperAccount
  - `/customer/get`：`{ _id }`，fillNames 回填 billMode/level/source/group 名称
  - ⚠️ **没有 delete 接口** → 删除/批量删除按钮直接移除（用户未反对默认方案）
- 字典：`/customer-level/query`、`/customer-source/query`、`/bill-mode/query`（billPeriod 0-每天 1-每周 2-每月、billDay、billGenStatus 0-已预报 1-已收货 2-已出库 3-转运中 4-已送达）
- 字段映射：customerCode→code、customerName→name、contactName→contact、contactPhone→mobile、remark→note、id→_id、updateTime→updateDate（毫秒时间戳）、customerLevel→level/levelId、customerSource→source/sourceId（fillNames 回填名称）

## 坑

- **i18n key 必须同步 `app.d.ts` 的 `App.I18n.Schema`**（本仓 I18nKey 是静态 Schema 声明而非从 zh-cn.ts 推导），否则 vue-tsc 全量 TS2345/TS2353（同「用户管理关联客户」既有结论）
- `selectedBillMode` computed 引用 `model` 需声明在其后（eslint no-use-before-define）
- NDatePicker daterange 用时间戳 v-model 时不可传 `value-format`（会按字符串解析）
- 派生展示字段（billPeriodText 等）提交前必须剔除，否则后端 strict/原样写入产生脏字段
