# 附加费/加收「删除」报「请求数据出错了」排查

> 日期：2026-09-21 ｜ 状态：**已修复（用户授权：可以；删除口径补充：同步删除渠道副本）**

## 用户反馈

用户原话：

> 「删除附加费报错了」

附图：「附加费 - EMS」抽屉（勾选列已是 vxe 内置 checkbox），点行内「删除」后右上角报 **请求数据出错了**。

## 根因（前后端契约不符）

后端 `tms-user`：

```js
// lib/api-v1-web/channel-fee-ext/index.js
'/channel-fee-ext/delete': {
  post: {
    opLog,
    ctrl: ctrl.delete,
    validate: {
      ids: validate.requireStrArr // 必填、minItems: 1 的字符串数组
    }
  }
}
```

```js
// lib/services/channel-fee-ext.js
async delete(body) {
  const { ids, sync } = body;
  await Promise.all([
    this.model.deleteMany({ _id: ids }),
    sync && this.model.deleteMany({ syncId: ids })
  ]);
}
```

```js
// lib/common/utils/validate.js
requireStrArr: { type: 'array', items: '', minItems: 1 }
```

前端 `user-admin-web`：

```ts
// src/service/api/channel-fee-ext/index.ts
/** 删除加收（/channel-fee-ext/delete；后端仅支持单条 _id） */
export function fetchDeleteChannelFeeExt(_id: string) {
  return request<null>({
    url: '/channel-fee-ext/delete',
    method: 'post',
    data: { _id } // ← 与后端 { ids: string[] } 不符，ids 缺失 ⇒ 校验不通过
  });
}
```

**结论**：载荷缺 `ids` 字段，后端 `requireStrArr` 校验直接不通过 → 前端统一报「请求数据出错了」。

**属既有缺陷，与本次「勾选列改内置 checkbox」改动无关**：`handleDelete` 与 `fetchDeleteChannelFeeExt` 均未在本次改动中触碰（service 注释「后端仅支持单条 \_id」与实际路由的 `ids` 数组契约不一致，是遗留的错误认知）。

## 修复（已实施）

### 1. 契约对齐（`src/service/api/channel-fee-ext/index.ts`）

```ts
export function fetchDeleteChannelFeeExt(_id: string, sync = false) {
  return request<null>({
    url: '/channel-fee-ext/delete',
    method: 'post',
    data: { ids: [_id], sync }
  });
}
```

函数注释一并订正（原「后端仅支持单条 \_id」是错误认知），并补上 `sync` 的语义说明。

### 2. 同步删除渠道副本（用户 2026-09-21 补充口径）

用户原话：

> 「我的意思是要同步删除」

- `CarrierFeeExtDrawer.vue#handleDelete` 改为 `fetchDeleteChannelFeeExt(row._id, true)` —— 承运网络侧删除的是**源**，后端据此 `deleteMany({ syncId: ids })` 连带清掉此前同步到各渠道的副本；
- 渠道加收面板（`fee-ext/index.vue#handleDelete`）**保持不传** `sync`：那里删的是渠道自身记录，其 `_id` 不会是任何记录的 `syncId`，传了也匹配不到（避免无意义行为）。

> ⚠️ 这是**破坏性**操作 —— 删除源附加费会同时抹掉所有渠道里由它同步出的副本，且不可恢复（当前删除按钮只有 popconfirm 默认文案，未特别提示"会连带删渠道副本"）。
