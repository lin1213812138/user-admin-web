# 附加费「同步到渠道」抽屉的渠道列表字段（7 列）

> 日期：2026-09-21 ｜ 状态：**已实施，待手动冒烟**
> spec：`docs/superpowers/specs/2026-09-21-附加费同步渠道列表字段-design.md`

## 用户原话与需求确认

- 「那你先修复一下附加费同步渠道界面的字段，跟收货渠道的字段要一样」
- 追问三点后回「是的」（= 8 列全要、发货渠道 tab 也换、保留创建时间）
- 追问列取舍后：**「那就去掉创建时间」** ⇒ 最终列定为 **7 列**
- 「先开始改这个，我再看看会不会消失」⇒ 授权实施；**对齐问题暂缓**（另一份 spec 保持待确认）

## 字段核实（已核代码 + `tms-user` 模型）

- **收货渠道列表页** `channel-quote/receive/index.vue` 共 8 列：`code / name / carrier / channelGroup / site / weightRuleName / status / createDate`；其中 `carrier / channelGroup / site / weightRuleName` 由 `scene=1` 回填（`fetchGetChannelList` 内部固定带）。
- **发货渠道列表页** `channel-quote/ship/index.vue` **仍是 mock 骨架**（列里的 `remark` / `createTime` 是占位名，后端真实字段为 `note` / `createDate`）；后端 `tms-user/lib/common/models/channel-out.js` 的字段与收货渠道**对称**，且 `scene=1` 回填的字段名两边**同名** ⇒ 收货 / 发货两个 tab 可以共用同一套列。
- 故最终列 = 收货渠道 8 列**去掉 `createDate`** = `code / name / carrier / channelGroup / site / weightRuleName / status`。

## 实施（`src/views/data-manage/ship/modules/carrier/CarrierFeeExtSyncDrawer.vue`）

| #   | 改动                                                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------ |
| 1   | `columns` 由 1 列（渠道名称）扩为 **7 列常量数组**（两个 tab 共用，无需按 `channelType` 切换）               |
| 2   | 发货渠道查询补 **`scene: 1`** —— 原先未传，`carrier / channelGroup / site / weightRuleName` 四列会全空       |
| 3   | `SyncChannelRow` 由 `{ _id, name }` 扩展为携带上述 7 列所需字段的可选形状                                    |
| 4   | `rows` 直接引用接口返回行（原先被裁剪成 `_id + name` 两项）                                                  |
| 5   | 模板补 5 个插槽做空值兜底 `--`（与项目其他列表口径一致）；`status` 走内置 `type: 'status'` 渲染启用/禁用标签 |

**未改动**：勾选 / 保存逻辑（`checkedRows` → `refIds`）、保存前二次确认、`tms-user` 后端、其他页面、i18n（列标题全部复用既有键 `page.channelQuote.receive.*` / `common.status`）。
