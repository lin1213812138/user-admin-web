# 菜单排序（number 字段）有值却必填校验不通过

> 日期：2026-09-01
> 模块：`src/components/Form/index.vue`（FormWrap）+ 菜单编辑抽屉 `sort` 字段

## 现象

编辑菜单抽屉里 `sort` 已填入数字（如 `21`），点击「确认」提交时，`NForm.validate()`
仍报「排序必填」，校验不通过。

## 根因

`FormWrap` 的 `mergedRules` 在 `item.required` 为真时，自动生成的必填规则只有
`{ required: true, message, trigger: ['change','blur'] }`，**没有 `type` 字段**。

Naive UI 调用 `async-validator` 做校验时，规则里带有 `trigger` 数组，而数字值（21、0 等）
会被 `async-validator` 误判为「空」，从而 `required` 校验失败——即使实际值是一个合法数字。
（字符串值则正常通过，因此只有 `number` 类型字段受影响。）

### 实证验证（隔离复现 + 纯 Node 复测）

- 规则 `{ required: true, trigger: [...] }` + 值 `21`（number） → **FAIL**
- 规则 `{ required: true, trigger: [...] }` + 值 `"21"`（string） → PASS
- 规则 `{ required: true, type: 'number' }` + 值 `21`（number） → **PASS**
- 规则 `{ required: true, type: 'number' }` + 值 `null` → FAIL（符合预期）

浏览器端复现（`v-model:value="model[item.key] as number"` + 动态 key + 自动必填规则）也确认：
加载 `sort:21` 后直接 `validate()` 返回 FAIL（`fieldValue:21` 仍判必填），补上 `type:'number'`
后返回 PASS。

## 修复

`src/components/Form/index.vue` 的 `mergedRules`：当 `item.type === 'number'` 时，给自动生成的
必填规则补上 `type: 'number'`：

```ts
const rule: FormItemRule = {
  required: true,
  message: item.requiredMsg || `${item.label}必填`,
  trigger: ['change', 'blur']
};
if (item.type === 'number') {
  rule.type = 'number';
}
base[item.key] = [rule];
```

这样数字值（含合法的 `0`）能正确通过必填校验，且清空为 `null` 时仍正常报必填。

## 影响面

- 仅影响 `FormWrap` 中 `type: 'number'` 且 `required: true` 的字段（当前为菜单 `sort`）。
- `select` / `input` / `switch` 等类型无需改动（`switch` 为布尔、`select` 多为字符串值）。
- 抽屉 `loadDetail` 中 `sort: row.sort ?? 1` 保证编辑时 `sort` 一定是数字，配合本次修复彻底解决。
