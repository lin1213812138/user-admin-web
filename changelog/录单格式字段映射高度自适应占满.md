# 录单格式「字段映射」高度自适应占满

日期：2026-09-04

## 1. 现象

系统设置 → 录单格式：右侧「字段映射」卡片高度由内容决定，字段少时下方大片留白；字段多时是右侧整页滚动，而不是卡片自己滚。

## 2. 定位

渲染链路：

```
views/system-manage/setting/index.vue（NTabs + <component>）
  └─ modules/InputFormat.vue
       └─ components/MasterDetail.vue（左列表 + 右卡片；右侧内容走 default slot）
            └─ components/FieldMapping.vue
```

根因在 `MasterDetail.vue` 右侧结构：

```
NCard（content: flex column, min-height: 0）
  └─ NScrollbar（class="min-h-0 flex-1"）
       └─ div（class="min-w-full px-16px py-16px"）
            └─ <slot />
```

`NScrollbar` 的 content 没有 `min-height`，slot 里的元素只能自然高度排列，剩余空间表现为留白；溢出时由这一层滚动，于是「整页滚」。

`FieldMapping.vue` 只是个普通 `NCard`（`class="mt-16px"`），无法吃掉剩余高度。

补充事实（用户确认）：**右侧内容是每个界面独有的，不是共用组件**，所以不能把「谁去占满」写死在壳里，只能由各页面自己的卡片决定。

## 3. 决策

方案对比：

| 方案      | 做法                                                                                                                                                                                                       | 结论                                                     |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| A（选定） | 壳只负责「让 slot 有可用高度」：`NScrollbar` content 加 `min-h-full flex-col`，内部 slot 容器加 `flex-1 flex-col`，**不加 prop、不加分支**；「谁占满」交给页面自己的卡片（`FieldMapping` 新增可选 `fill`） | 采纳                                                     |
| B         | `MasterDetail` 新增 `contentFill` prop，`true` 时移除外层 `NScrollbar`                                                                                                                                     | 壳里多开关多分支，且 fill 页面内容超高要自己兜滚动，否决 |
| C         | `InputFormat` 不用 `MasterDetail` 的右侧 slot，自己复制一套右侧布局                                                                                                                                        | 破坏复用，否决                                           |

设计文档：`docs/superpowers/specs/2026-09-04-field-mapping-fill-height-design.md`。

## 4. 改动

### 4.1 `components/MasterDetail.vue`

```vue
<!-- content 撑满：高度不足时 slot 容器被拉伸，卡片可 flex:1 吃掉剩余空间；内容超高时仍由本层滚动 -->
<NScrollbar class="min-h-0 flex-1" content-class="min-h-full flex-col">
  <div class="min-w-full flex-1 flex-col px-16px py-16px">
    <slot />
  </div>
</NScrollbar>
```

- `min-h-full`（`min-height: 100%`）：内容不足时撑满容器，超出时自然增高 —— 用 `min-height` 而不是 `height`，避免内容被截断、滚动条失效。
- 内部 div 用 `flex-1` 吃掉这份高度并作为 flex column 容器。
- 其它页面（打印/导出格式、通知配置、初始数据、站点扫描、WaybillRule）的子元素没有 `flex-1`，仍是自然高度顶部排列，**视觉零变化**。

### 4.2 `components/FieldMapping.vue`

新增可选 prop `fill?: boolean`（默认 `false`）：

- `class` 追加 `{ 'flex-1 min-h-0 flex-col': fill }`；
- `content-style` 为 `fill` 时改为 `{ display: 'flex', flexDirection: 'column', minHeight: 0, flex: 1 }`，让内容区吃掉卡片除标题外的剩余高度；
- 分组勾选区包一层 `NScrollbar`（`min-h-0`，`fill` 时追加 `flex-1`），溢出时在卡片内部滚动；
- 不传 `fill` 时不追加 class、不覆盖 `content-style`，渲染与改动前一致。

### 4.3 `modules/InputFormat.vue`

- `<FieldMapping ... fill />` 开启占满；
- `<NFormWrap ... class="shrink-0" />`，防止空间不足时表单被压缩变形。

## 6. 遗留 / 后续

1. `PrintFormat.vue` 的 6 个 eslint 误报会让 `pnpm lint` 与 pre-commit 失败，建议单独排查（怀疑 eslint 对该文件模板变量收集异常，同样结构的 `StationScan.vue` 不报错）。
2. 其它 5 个页面（打印/导出格式、通知配置、初始数据、站点扫描）的 `FieldMapping` 是模板复制的占位数据，业务上字段映射只在录单格式存在；本轮按要求未动，需要清理时再单独处理。
3. 将来任何页面想让卡片占满右侧剩余高度，只需给自己的卡片加 `fill`（或参照同样的 `flex-1 min-h-0 flex-col` + content flex 写法）。
