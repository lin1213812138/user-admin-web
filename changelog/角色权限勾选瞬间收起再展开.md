# 权限抽屉勾选表头「导航菜单」后树瞬间收起再展开

> 日期：2026-09-17
> 来源：用户贴「分配权限」抽屉截图（红框圈出「导航菜单」表头复选框）："这个勾选了为什么要瞬间收起再瞬间展开为什么会这样？"
> 状态：**已定位并实施（用户确认方案 A2）**

## 现象

角色管理 →「分配权限」抽屉里，勾选「导航菜单」列的表头全选复选框后，整棵权限树先瞬间收起、再瞬间展开（约 70ms 的视觉抖动）。

## 根因（实测，未改代码）

四环链条：

1. **数据被整体重建**：表头复选框走 `toggleCheckAll()` → `checkedIds` 更新 → `applyView()` → `buildView()` 用 `withChecked()` **为每个节点新建行对象**，`viewRows` 被整份替换（勾选态靠行上的 `checked` 字段 + `checkbox-config.checkField` 回填，因此必须重建行对象）。
2. **rowid 不稳定**：表格启用了 `tree-config.expandRowKeys`，但**没有配置 `row-config.keyField`** ⇒ vxe 的 rowid 取内部 `_X_ROW_KEY`（首次渲染时逐行生成 `row_N` 并写进行对象）。整份重建后新对象上没有该字段 ⇒ vxe 为每行发一批**全新 rowid**。
3. **展开态按 rowid 索引回收**：vxe 数据加载后会执行 `getRecoverRowMaps(treeExpandedMaps)`，按 rowid 过滤保留仍存在的展开行；rowid 全变 ⇒ `treeExpandedMaps` 被清空 ⇒ 表格瞬间收起。
4. **抽屉再把树展开**：`syncTreeExpand()`（`applyView()` 末尾 `nextTick` 里的 `setTreeExpand(rows, true)`）把可展开行重新展开 ⇒ 形成「收起 → 展开」两帧。

## 证据（dev 9111 实测）

| 证据                    | 内容                                                                                                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| vxe 官方警告（console） | `[vxe ui v4.17.19 table v4.21.2] [table] 缺少必要的 "row-config.keyField" 参数，这可能会导致出现错误`（每次打开抽屉各出现一次）                                                |
| vxe 源码                | `es/table/src/table.js:14456`：只要用到 `tree-config.expandRowKeys` / checkbox `reserve` 等按 rowid 索引的状态，就要求 `props.rowId \|\| rowOpts.keyField`，否则只 warn 不兜底 |
| DOM rowid               | 点击前 `row_51`~`row_70`（20 行）；点击后 `row_71`~`row_90` —— 整批换新，证明发生了全量重建                                                                                    |
| MutationObserver 采样   | 点击 305ms → 318ms 可见行数 20 → **6**（收起态）→ 390ms 回到 20（重新展开），抖动约 72ms                                                                                       |

- rowid 公式：`props.rowId || row-config.keyField || '_X_ROW_KEY'`（`es/table/src/util.js:575`）；`updateFastRowKey` 会把生成的 `row_N` 写回新行对象。
- 同样能触发该抖动的不止表头复选框：搜索关键字、勾选任意行、勾选行内按钮/子模块权限（勾到未选菜单时）都会走 `applyView()` 全量重建。

## 附带问题

同一机制下，用户**手动折叠**的节点也会被 `syncTreeExpand()` 强行重新展开（每次 `applyView()` 都执行）。

## 决策与实施（用户确认方案 A2）

- **方案 A2（采用）**：`components/Table` 恢复被注释掉的 `rowConfig` prop（interface + 模板 `:row-config` 绑定），抽屉传 `:row-config="{ keyField: 'id' }"`；同时把 `syncTreeExpand()` 从 `applyView()` 挪到 `loadData()`（仅在打开抽屉时展开一次），勾选/搜索触发的行重建不再强制展开。
- 未采纳：A1（只加 keyField、保留每次重建的强制展开，会覆盖用户手动折叠）、B（抽屉侧不重建数据，改动面大且解决不了搜索抖动）、C（仅解释）。

改动清单：

| 文件                                                              | 改动                                                                                                                                                                 |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/components/Table/table.vue`                                  | 恢复 `rowConfig?: VxeTablePropTypes.RowConfig` prop（原被注释）；模板加 `:row-config="rowConfig"`                                                                    |
| `src/views/system-manage/role/modules/role-permission-drawer.vue` | 新增 `const rowConfig: VxeTablePropTypes.RowConfig = { keyField: 'id' }` + 模板绑定；`applyView()` 去掉 `syncTreeExpand()`；`loadData()` 末尾调用 `syncTreeExpand()` |

## 验证

- typecheck 0 / oxlint 0 / oxfmt 无改动 / eslint 0。
- playwright 实测（dev 9111，真实后端，超级管理员行「分配权限」）：
  - 行 rowid 由内部 `row_51` 变为业务 id（`100/200/201/300…`）。
  - 打开抽屉 20 行全展开；点击表头「导航菜单」复选框：MutationObserver 仅 1 次行数变更（保持 20）、rowid 完全不变，**无「20→6→20」抖动**（改前实测 305ms → 318ms 20→6 → 390ms 回 20）。
  - 手动折叠「客户管理」→ 再点表头复选框 → 仍 19 行、`201`（客户列表）保持隐藏 = 手动折叠不再被覆盖。
  - 关闭再打开抽屉仍默认全展开（20 行）。
  - console 不再出现 `缺少必要的 "row-config.keyField"` 警告；用户管理页回归正常（表格渲染 6 行、0 error）。
