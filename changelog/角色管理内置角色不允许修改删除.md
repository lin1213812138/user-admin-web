# 角色管理：内置角色（buildIn=1）不允许修改和删除

用户需求："角色管理，buildIn=1为内置角色不允许修改和删除"。

## 现状定位

- 后端 `tms-user` Role 模型（`lib/common/models/role.js`）已有 `buildIn` 字段（`Number, default 0`，注释"内置"），`/role/query` 全字段返回。
- 后端 `lib/services/role.js`：
  - `update` 无 buildIn 校验，内置角色可被任意修改；
  - `delete` 仅拦截 `roleType == ADMIN`（错误码 100203"内置角色不可删除"已存在但只用于 ADMIN）。
- 前端 `views/system-manage/role/index.vue` 编辑/删除按钮无条件可用，批量删除未过滤；`Api.SystemManage.Role` 类型缺 `buildIn`。
- 同类先例：no-rule / bill-mode / fee-type 后端均按 buildIn 限制更新/删除，前端 no-rule 用 `editRow?.buildIn === 1` 做禁用。

## 设计决策（用户确认）

1. 后端 `update`、`delete` 均拦截 buildIn=1，抛 `ApiError`（修改用新错误码 100204，删除复用 100203）。
2. 权限分配 `/role/auths/update` **不拦截**（内置角色仍可调权限）。
3. 前端禁用编辑/删除按钮 + tooltip 提示（与"超级管理员不允许分配权限"的 NTooltip + span 包裹写法一致），批量删除自动跳过内置角色。
4. 角色名列保留 Link 点击详情，追加「内置」NTag 标识（name 列由 `type: 'detail'` 改为自定义插槽，放弃 copy 图标——Table 插槽优先级高于 type，且 detail 模板的 copy 内部状态无法在插槽复用）。

## 实施

### 后端 tms-user

- `lib/common/define/1002-role.js`：新增 `EDIT_ERROR: { code: 100204, msg: '内置角色不可修改' }`。
- `lib/services/role.js`：
  - `update`：`findCheckById` 后追加 `if (dbRole.buildIn) throw new ApiError(ROLE_ERROR_CODE.EDIT_ERROR);`
  - `delete`：投影补 `buildIn`（原来只有 `'roleType'`，漏投会影响判断），buildIn 校验置于 ADMIN 校验之前。

### 前端 user-admin-web

- `src/typings/api/system-manage.d.ts`：`Role` 新增 `buildIn?: Api.SystemManage.RoleCtrl`（复用 0|1 类型）。
- `src/views/system-manage/role/index.vue`：
  - name 列去 `type: 'detail'`，新增 `#name` 插槽：`Link`（点击 handleDetail）+ `buildIn === 1` 时「内置」`NTag`（type info）；补 `Link` 显式 import。
  - 操作列「编辑」「删除」按钮 `:disabled="row.buildIn === 1"`，外包 `NTooltip :disabled="row.buildIn !== 1"`（删除按钮在 NPopconfirm 外再包 tooltip，禁用按钮不派发事件需 span 桥接）。
  - `handleDelete` 改收 `Role[]`：过滤 `buildIn === 1`，有跳过时 `window.$message?.warning(builtInBatchDeleteTip)`，全被跳过则不请求；单删传 `[row]`，批量传 `checkedRows`。
- i18n 三处（zh-cn / en-us / `app.d.ts` Schema）新增 `page.manage.role.builtIn`、`builtInEditTip`、`builtInDeleteTip`、`builtInBatchDeleteTip`。
  - 坑（先例）：i18n key 必须同步 `app.d.ts` Schema，否则 vue-tsc TS2353。
