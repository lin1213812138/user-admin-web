# 运单号码池改为「导入」（含内联类型统一到类型文件）

> 日期：2026-09-20 ｜ 状态：已实施（待手动冒烟）
> 页面：资料管理 / 单号资料 / 运单号码池（`src/views/data-manage/no-rule/modules/no-pool`）

## 1. 背景与用户诉求

- **诉求一**：运单号码池入口应是「导入」而非「新增」——运单号码由批量粘贴录入，不存在单条新建。
- **诉求二（追加）**：组件内的内联类型（如 `ref<{ refType: number; channel: string; noText: string }>`、`ref<{ label: string; value: string }[]>`）不允许就地书写，必须统一收敛到**类型文件**（`src/typings/`），与 `service/api/channel/index.ts` 的「service 仅引用 `Api.*`、零内联」范式对齐。

## 2. 定位（实现前调研）

- 目标页 `NoPool.vue` 工具栏为「新增」（`drawerRef.openCreate()`），抽屉 `NoPoolOperateDrawer.vue` 为单条录入（关联类型 + 渠道 + 号码 + 备注）。
- 后端 `tms-user` 运单号码池仅提供 `/no-pool/query`、`/no-pool/batch/create`、`/no-pool/delete`（按 `_id`），**无** `/no-pool/create`、`/no-pool/update` 单条能力。
- 渠道数据源：`refType=0` 取收货渠道 `/channel/query`；`refType=1/2` 取发货 / 派送渠道 `/channel-out/query`（`where.channelType`）。

## 3. 决策（用户确认）

| 问题     | 结论                                              |
| -------- | ------------------------------------------------- |
| 改动范围 | **只加导入**（`/no-pool/batch/create`）           |
| 去重规则 | 按行拆分 → 去空白 → 去空行 → 按 `no` 去重后再提交 |
| 入口     | 「导入」+ `icon-ic-round-file-upload`             |
| 文案     | 接入 zh-cn / en-us 国际化                         |
| 追加     | 内联类型统一收敛到类型文件                        |

> 因原「编辑」走单条 `_id` 更新而后端无此能力，**一并移除「编辑」入口**与 `fetchUpdateNoPool`（否则 `openEdit` 不存在会直接报错）；「删除」按用户口径保留不动。

## 4. 实施

### 4.1 接口层

- `service/api/data-manage-no-rule/index.ts`：
  - 新增 `fetchImportNoPool(list: Api.NoPool.ImportItem[])` → `POST /no-pool/batch/create`（body `{ list }`）。
  - 删除无引用的 `fetchCreateNoPool` / `fetchUpdateNoPool`，移除内联 `NoPool` 接口。
  - `fetchGetNoPoolList` 返回改用 `Api.NoPool.List`。
- `service/api/channel-out/index.ts`：`fetchGetChannelOutList` 增加可选 `channelType`（0-发货 / 1-派送），`where.channelType = params.channelType ?? 0`。

### 4.2 类型层（统一收敛，禁止内联）

- `typings/api/data-manage/no-rule.d.ts` 新增 `Api.NoPool`：`RefType` / `Item`（对齐列表列：号码 · 渠道名称 · 渠道类型 · 状态 · 提取者 · 提取时间 · 录入者 · 录入时间）/ `List` / `ImportForm` / `ImportItem`。
- 复用既有通用类型：`Api.Common.EnableStatus`、`Api.Common.CommonSearchParams`、naive-ui `SelectOption`。
- `constants/options.ts` 注册全局选项 `noPoolRefType`（0-收货渠道 / 1-发货渠道 / 2-派送渠道）；`composables/use-options.ts` 新增 `useNoPoolRefTypeOptions()`，消除列表与抽屉重复声明同一组选项。

### 4.3 视图层

- `NoPoolOperateDrawer.vue` 重写为「运单号码导入」：关联类型（`optionsKey: 'noPoolRefType'`）→ 具体渠道（随关联类型联动拉取）→ 单号多行文本（去重后提交）。类型全部走 `Api.NoPool.ImportForm` / `Api.NoPool.ImportItem`。
- `NoPool.vue` 工具栏「新增」→「导入」（`openImport`），移除「编辑」入口；列 / 泛型改用 `Api.NoPool.List` / `Api.NoPool.Item`。
- `NoPoolSearchForm.vue` 状态模型改用 `Api.Common.EnableStatus | null`。

## 8. 追加修正（用户指出列表字段未按截图对齐）

用户指出此前只做了「导入」而**漏改列表列**。按用户参考列表 + `tms-user` 源码（`lib/common/models/no-pool.js`、`lib/services/no-pool.js`、`lib/common/services/common.js`、`lib/api-v1-web/no-pool/index.js`）核对后修正：

### 8.1 列表列对齐（`NoPool.vue`）

| 列       | 字段                                                 | 渲染                          |
| -------- | ---------------------------------------------------- | ----------------------------- |
| 运单号码 | `no`                                                 | detail（可点击复制）          |
| 渠道名称 | `refName`（后端 `fillRet` 回填；refType=2 暂不回填） | 文本                          |
| 渠道类型 | `refType`                                            | `optLabel(refTypeOptions, …)` |
| 状态     | `status`                                             | 已提取 / 未提取（`NTag`）     |
| 提取者   | `pickBy`                                             | 文本                          |
| 提取时间 | `pickDate`                                           | `formatDateTime`              |
| 录入者   | `creator`                                            | 文本                          |
| 录入时间 | `createDate`                                         | `formatDateTime`              |

原「号码 / 收发货渠道(`refId`) / 关联类型 / 状态(启用-禁用) / 创建时间」已替换。

### 8.2 类型修正（`Api.NoPool.Item`）

按后端 schema 真实字段修正：补 `refName` / `pickId` / `pickBy` / `pickDate` / `creatorId` / `updateDate` / `shipOrder`，移除臆造的 `channelName` / `picker` / `pickTime` / `note`。

### 8.3 删除契约修正（发现即修）

`/no-pool/delete` 后端路由校验 `body.ids`（`validate.requireStrArr`），`batchDeleteCommon` 走 `{ _id: { $in: body.ids } }`；原前端传 `{ _id }` 必然校验失败。`fetchDeleteNoPool(ids: string[])` 改为提交 `{ ids }`：单条传 `[row._id]`、批量一次传全部 id。

### 8.4 去掉操作栏（`NoPool.vue`）

按用户参考截图，列表**无操作栏**：移除 `Table` 的 `show-action` / `:action-width` 与 `#action` 插槽（行内删除入口）及随之无用的 `confirmDelete`；删除仅保留工具栏的批量删除（`confirmBatchDelete` → `fetchDeleteNoPool(ids)`）。

### 8.5 号码搜索修复（`NoPool.vue` / `NoPoolSearchForm.vue`）

用户反馈「搜索没生效」。根因：`no-pool` 的 `query` 未定义 `keywordFields`，`queryCommon` 中 `if (keyword && !isEmpty(keywordFields))` 分支不成立 ⇒ 前端传的 `keyword` 被丢弃；且 `formatWhere` 仅把数组转 `$in`，不处理字符串。修复：把号码写入 `where.no = { $regex: <转义后的关键词>, $options: 'i' }`（模糊、不区分大小写）。

**对齐用户手改**：搜索框只保留号码输入（移除状态下拉），模型由 `keyword` 统一为 `no`；批量删除改用 `LButton popconfirm @positive-click="confirmBatchDelete"`（补上缺失的事件绑定，否则点击无效），并把误用的上传图标改为 `icon-ic-round-delete`。

> 更彻底的做法是后端给 `no-pool` 的 `query` 加 `keywordFields: ['no']`，前端即可直接传 `keyword`；因本仓库为纯前端，暂用 `where` 兜底。

### 8.6 移除无效的列设置（`TableColumnConfig`）

用户质疑「组件引入为什么放在 `#operation-right`、这两个页面没有列配置按钮却不清掉」。核查结论：

- `TableColumnConfig`（`src/components/Table/table-column-config.vue`）本体只有一个 `NModal`，**不含触发按钮**；`NModal` 默认 teleport 到 `body`，放在 `#operation-right` 里或 `</Table>` 之后渲染结果一致——**位置本身无意义**。
- 本仓库既有约定是：页面持有 `visible` 状态 + 一个齿轮按钮 `@click="configVisible = true"` 触发（如 `system-manage/user`、`data-manage/finance/*`）。
- `data-manage/no-rule` 三个子页（`no-pool` / `item-no-rule` / `long-no-rule`）只声明 `columnConfigVisible = ref(false)`、从未置 `true` ⇒ 弹窗永远打不开，属死代码。

处理：三页移除 `<TableColumnConfig>` 及其绑定，并清理因此不再使用的导入/解构（`TableColumnConfig`、`columnConfigs`、`persistColumns`、`resetColumns`、`columnConfigVisible`）。

> - 仓库内还有一批页面（`data-manage/ship/*`、`data-manage/bl/*`、`system-manage/setting/*` 等）同样是「有 `TableColumnConfig` 无触发按钮」，需要的话可统一排查/清理。
> - `useVxeTable` 的 `cacheKey` 暂予保留：现无写入入口，仅在初始化时读取本地缓存。
