# 打印格式「设计」跳转自研标签设计器（并隐藏菜单入口）

- 日期：2026-09-14
- 范围：`src/views/system-manage/setting/modules/print-format/PrintFormat.vue`、`src/views/system-manage/label-designer/index.vue`、`build/plugins/router.ts`、`src/router/elegant/routes.ts`（生成）

## 需求

1. 打印格式列表的「设计」原跳旧 hiprint 页（`system-manage_print-design`），改为跳**自研标签设计器**（`system-manage_label-designer`）并打开被点击的那条模板。
2. 标签设计器**不再出现在左侧菜单**（改为只能从「系统设置 → 打印格式 → 设计」进入）。
3. 进入设计器时**保留左侧菜单「系统设置」高亮**（用户补充）。
4. 澄清：只隐藏菜单项，**不是**进入设计器时收起整条侧边栏。

## 设计确认（brainstorming）

- **隐藏菜单项的做法**：
  - 方案 A（**采用**）改 `build/plugins/router.ts` 的 `hideInMenuRoutes`，再 `pnpm dev` 触发重新生成。
  - 方案 B（否）用 `src/router/routes/index.ts` 的 `customRoutes` 覆盖 meta —— 源码核对：`@elegant-router/vue` 0.3.8 的 `customRoutes` 插件选项只生成路由**类型声明**，本仓库 `createStaticRoutes()` 也只是把 `customRoutes` 与 `generatedRoutes` **拼接**（没有按 name 合并）→ 同名会重复注册路由，不可靠。
- **菜单高亮链路**（`layouts/modules/global-menu/context/index.ts`）：`selectedKey = hideInMenu ? activeMenu : name` → 隐藏后必须在 meta 上**同时给 `activeMenu`** 才能点亮「系统设置」。
- **query 收敛为 `{ id, name }`**：`categoryId` / `paperSize` 不再传 —— 设计器按 `id` 拉详情，纸张取详情 `paperSize`（单一来源），`name` 仅用于详情返回前的标题展示。

## 改动

1. `PrintFormat.vue` `openDesign()`：路由 key 改 `system-manage_label-designer`，query 改 `{ id, name }`。
2. `label-designer/index.vue`：
   - 读 `route.query.id` → `currentId` 预置、`onMounted` 直接 `loadTemplate(id)`（不再无条件加载分类 1 的第一个模板）；
   - 无 `id`（手输地址 / 调试）保留原兜底 `loadTemplates()`；
   - 工具栏标题由 computed 改为 `currentName` ref，`loadTemplate` 拿到详情后回填 `detail.name`（详情缺名称时保留 query 值），`computed` import 随之移除。
3. `build/plugins/router.ts`：
   - `hideInMenuRoutes` 加 `'system-manage_label-designer'`；
   - 新增 `menuActiveKeys` 映射并写入 `meta.activeMenu = 'system-manage_setting'`；
   - `routeOrders` 的 `system-manage_role` / `system-manage_user` 由 1 / 2 调整为 **2 / 1**（见「注意」）。
4. 路由重新生成（`pnpm dev` 触发，**不手改** `src/router/elegant/**`）：label-designer 的 meta 新增 `hideInMenu: true` + `activeMenu: 'system-manage_setting'`。

## 注意（生成覆盖风险）

- 工作区 `src/router/elegant/routes.ts` 原本存在**未提交改动**：菜单里把「用户」排在「角色」之前，而 `build/plugins/router.ts` 的 `routeOrders` 仍是 `role=1 / user=2` —— 直接重新生成会把该改动冲掉。故本次把配置对齐为 `role: 2 / user: 1`，生成后菜单顺序与生成前一致。
- 生成器对**配置里没有的 meta 键会保留旧值**：`icon` / `order` 曾在配置中删过，生成结果仍保留 → 最终把这两个键保留在配置里，保持「配置 = 生成结果」一致（`hideInMenu` 后无展示效果，留作日后重新开放菜单入口）。

## 追加（同日）：设计器「返回」跳回「打印格式」分页

用户："点返回要自动跳转到打印格式的 tab"。

- **根因（两条叠加）**：① 设计器「返回」是 `router.back()`，而设置页其实早已支持 `?tab=` 定位分页（`setting/index.vue` 的 `syncTabFromQuery()`，注释写的就是"来自标签设计页「返回上一页」"）——返回时从未带上该 query；② `system-manage_setting` 路由**没有 `keepAlive`** → 返回时页面重新挂载、`activeKey` 落回默认第一页「录单格式」。
- **方案（用户选 A）**：`panels/tool-bar.vue` 的返回按钮由 `router.back()` 改为 `routerPushByKey('system-manage_setting', { query: { tab: 'print-format' } })`（新增 `goBack()`），改用 `useRouterPush`、移除不再使用的 `useRouter`；消费端 `syncTabFromQuery()` 已存在，**设置页零改动**。
- 备选 B（未采用）：设置页切分页时把 `?tab=` 写进 URL（`router.replace`）、返回按钮保持 `router.back()` —— 「分页状态 URL 化」更彻底（可刷新/可分享），但改动更大、每次切分页都会改 URL。
- 验证：`pnpm typecheck` 0；`tool-bar.vue` oxfmt + oxlint（0/0）+ eslint（0 error）。
