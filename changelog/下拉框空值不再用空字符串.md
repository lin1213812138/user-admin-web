# 下拉框空值不再用空字符串（FormWrap 统一归一化）

> 日期：2026-09-20 ｜ 状态：已实施（待手动冒烟）
> 页面：资料管理 / 单号资料 / 运单号码池（`src/views/data-manage/no-rule/modules/no-pool/NoPoolOperateDrawer.vue`）｜ 组件：`src/components/Form/index.vue`
> spec：`docs/superpowers/specs/2026-09-20-下拉框空值统一-design.md`

## 1. 背景与用户诉求

用户贴「运单号码导入」抽屉截图（红框标出「具体渠道」）：

> 这种的能不能不要赋空空字符串，这种下拉框给空字符串就会变成空的也看不到 placeholder

## 2. 定位（根因）

`NSelect` 只在值为 `null` / `undefined`（多选为 `[]`）时才渲染 `placeholder`；值为 `''` 时被视作「已选」，渲染成**空白选中态** —— 框是空的、placeholder 也看不到。

| 现象                           | 位置                                                                                                 | 原因                                                                                                                    |
| ------------------------------ | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 「具体渠道」空白无 placeholder | 抽屉 `formModel = { refType: 0, channel: '', noText: '' }`、`loadChannelOptions()` 里 `channel = ''` | 初值 / 重置 / 切换关联类型都写 `''`                                                                                     |
| 「关联类型」空白无 placeholder | `Form/index.vue` select 默认 `clearable: true`，该 item 未配 placeholder                             | 被清空后变 `null` 又无 placeholder ⇒ 无提示空白框；且 `watch(refType)` 会走 else 分支去拉「发货渠道」列表，渠道选项错乱 |

仓库既有约定本就是**下拉空值用 `null` / `undefined`**（搜索区 `statusFilter = null`、客户抽屉 `sourceId/siteId = undefined`），此前同类要求也提过（`changelog/完善收货渠道界面.md`「默认不要赋值空字符串」），只有本抽屉写成了 `''`。

## 3. 决策（用户确认）

| 问题       | 结论                                                                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 修复范围   | **组件层 + 页面层**（用户选推荐项）：组件层治本、覆盖全部 FormWrap 下拉；页面层把 model/类型改 `null` 并收紧联动下拉                     |
| 归一化方向 | 只做**读取侧**（交给 `NSelect` 前把 `''` → `null`、多选非数组 → `[]`）；写回保持 `NSelect` 原生语义（清空 → `null`），与仓库既有口径一致 |
| 误伤防护   | 选项里本身存在 `value: ''` 的合法选项时**不收敛**                                                                                        |
| 关联类型   | `clearable: false`（必填 + 联动渠道数据源，不允许清空）                                                                                  |

## 4. 实施

### 4.1 组件层（`components/Form/index.vue`）

- 新增 `selectValue(item)`：单选时 `''` / `null` / `undefined` → `null`；多选时非数组 → `[]`；`hasEmptyOption()` 命中时不收敛。
- 新增 `handleSelectChange(item, value, option)`：按字段写回 model（`Object.assign`，与既有 `handleDateChange` 同口径）并透传 `item.onUpdate`。
- 模板：`NSelect` 由 `v-model:value` 改为 `:value="selectValue(item)"` + `@update:value="…handleSelectChange(item, value, option)"`，其余 props（`clearable` / `filterable` / `multiple` / `render-label`）不变。

### 4.2 页面层 / 类型层

- `typings/api/data-manage/no-rule.d.ts`：`Api.NoPool.ImportForm.channel` 由 `string` 改 `string | null`。
- `NoPoolOperateDrawer.vue`：`formModel` 初值、`openImport()` 重置、`loadChannelOptions()` 切换关联类型时的渠道清空统一改 `null`；「关联类型」补 `clearable: false`；提交时对 `channel` 加类型收窄守卫后再作为 `refId`。

## 5. 边界

- 不逐个改其它页面 select 的空串初值（组件层已兜住，后续新页面按 `null` 写即可）。
- 不改 `NSelect` 的 `clearable` 默认行为（其它下拉仍需可清空）、不改接口 / 后端 / 菜单 / 路由 / i18n。
