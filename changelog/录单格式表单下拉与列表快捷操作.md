# 录单格式：表单开关改下拉 + 列表快捷操作（停用/启用、设为默认）

> 状态：已实施（2026-09-19）

## 用户诉求

1. 贴「编辑录单格式」抽屉截图，要求「switch 改成下拉的，然后改成一行三个」。
2. 贴「录单格式」列表截图，指出「少了两个功能，一个停用启用，一个设置默认」。
3. 确认栅格范围选「6 项排成 2 行 × 3 列（备注也缩为 1/3 宽）」，并要求两部分一起改。

## 定位

- 抽屉表单：`views/system-manage/setting/modules/input-format/input-format-drawer.vue` 的 `formItems`，`status / customerEnable / isDefault` 三个 `type: 'switch'`，栅格 `name:12 + status:12 / customerEnable:8 + isDefault:8 + order:8 / note:24`。
- 列表：`views/system-manage/setting/modules/input-format/InputFormat.vue` 操作列只有「编辑 / 删除」，状态与默认只能进抽屉改。
- 后端 `services/order-template.js` 的 `create/update` 都做 `if (params.body.isDefault) updateMany({isDefault:1},{isDefault:0})`，**「设为默认」无需新接口**，走 `/order-template/update` 即可自动清掉其它默认。
- **关键坑**：`/order-template/update` 走 `commonService.updateCommon({ uniqField: 'name' })`，当 `body.name` 与库中值不等时会进 `checkUniqField`；该方法取 `filter.name = $in([body.name])`，而 `$in(list)` 在 `list.length === 1` 时**直接返回 `list[0]`**（`lib/common/utils/index.js:145`），`body.name === undefined` 时等价于 `findOne({})` ⇒ 命中任意文档 ⇒ 抛「已存在」。所以快捷操作**不能照抄 user 列表「只传 `_id + status`」的写法**，必须回传 `name`（等值即跳过校验）。
- 另注：`/order-template/update` 路由**未配 `opLog`**，中间件不会把 body 裁成差量；`updateBy` 由 `api-v1-web/middlewares.js:209-227` 补、`updateDate` 由 mongoose `updateOne` 前置钩子补，快捷操作后「最后操作 / 最后更新时间」会正常刷新。
- `components/Form/index.vue` 里 select/input/number 的 `:clearable="item.clearable || true"` 是短路 bug：显式传 `false` 也会被吃掉，导致「禁止清空」无法表达。

## 决策

1. **三态字段改下拉**（用户确认）：`status` = 启用(1)/禁用(0)，`customerEnable`、`isDefault` = 是(1)/否(0)；`filterable: false`（两个选项不需要搜索框）、`clearable: false`（布尔语义不允许清空成 `null` 提交后端）。
2. **栅格 2 行 × 3 列**（用户确认）：6 项 span 统一 8，`name/status/customerEnable` 一行、`isDefault/order/note` 一行，备注一并缩为 1/3 宽。
3. **配套修 `clearable` 短路**：`|| true` → `?? true`（3 处）。默认行为不变（不传仍是 true），只是让显式 `false` 生效；副作用是 `ShipperOperateDrawer.vue` / `ShipToOperateDrawer.vue` 的 `clearable: !props.customerId` 开始按预期工作（属修复）。
4. **快捷操作走部分更新**：新增 `fetchPatchInputFormat` + `Api.InputFormat.PatchParams`（`_id + name + 目标字段`），与全量的 `fetchUpdateInputFormat` 区分语义，避免调用处 `as` 断言。
5. **交互对齐现有页面**：停用/启用沿用 `user/index.vue` 的模式（`NPopconfirm` 二次确认 + 文案 `common.confirmDisable/confirmEnable`，按钮色 `warning/success`）；设为默认沿用 `PrintFormat.vue` 的模式（`isDefault === 1` 时 disabled、不加二次确认，点了即切）。按钮统一 `NButton text size="small"`，与本文件已有的编辑/删除按钮同风格（该文件尚未纳入全仓 LButton 重构，不在本轮扩大范围）。
6. **内置格式不设限**：`buildIn === 1` 仍可停用 / 设为默认，仅「删除」维持原有排除（与现状一致）。
