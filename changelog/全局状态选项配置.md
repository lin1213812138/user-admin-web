# 全局状态选项配置（启用/禁用）

> 日期：2026-09-19 ｜ 状态：已实施 ｜ 范围：通用表单/筛选「状态下拉」

## 背景

用户要求「状态的下拉选择能不能添加一个全局的配置，所有这种的直接取，不要每个界面都配置」。

代码中大量界面重复定义同一段状态选项：

```ts
const statusOptions = computed(() => [
  { label: $t('common.enable'), value: 1 },
  { label: $t('common.disable'), value: 0 }
]);
```

## 实施

### 1. 全局选项注册表 `src/constants/options.ts`

- `registerGlobalOptions(key, factory)` / `getGlobalOptions(key)`。
- 工厂在解析时调用，可安全使用 `$t`，语言切换后文案随调用方重建更新。
- 预置 `status`：`[{ label: $t('common.enable'), value: 1 }, { label: $t('common.disable'), value: 0 }]`。

### 2. 组合式 `src/composables/use-options.ts`

- `useStatusOptions()`：返回 `computed<SelectOption[]>`，语言切换自动更新；供非 `NFormWrap` 的筛选/下拉直接取。

### 3. `NFormWrap` 支持全局 optionsKey

- `FormItemConfig` 新增 `optionsKey?: string`（`src/components/Form/form-config.ts`）。
- `src/components/Form/index.vue` 新增 `itemOptions(item)`：优先取 `getGlobalOptions(item.optionsKey)`，否则用 `item.options`；`NSelect` / `NCheckboxGroup` / 只读 `viewText` 均走此解析。
- 抽屉里状态项只需写 `{ key:'status', type:'select', optionsKey:'status' }`，零选项配置。

### 4. 迁移重复定义（统一取全局）

- 抽屉状态项：`provider/ProviderOperateDrawer.vue` 状态改为 `optionsKey:'status'`。
- 列表/筛选重复 computed：`system-manage/user/index.vue`、`personal-center/.../ProfileInfo.vue`、`provider/Provider.vue`、`no-rule/.../ItemNoRule.vue`、`LongNoRule.vue`、`NoPool.vue` 的 `statusOptions` 改为 `useStatusOptions()`；`setting/.../input-format/config.ts` 的 `statusOptions()` 改为返回 `getGlobalOptions('status')`。
- 4 个 SearchForm（`ProviderSearchForm`/`NoPoolSearchForm`/`ItemNoRuleSearchForm`/`LongNoRuleSearchForm`）的 `statusOptions` prop 类型由 `{ label: string; value: number }[]` 放宽为 `SelectOption[]`（配合全局选项类型）。

## 收益

- 单一数据源：状态文案/值（启用=1、禁用=0）只维护一处（如需加「停用」等，改 `constants/options.ts` 即可全站生效）。
- 新增界面状态下拉：抽屉写 `optionsKey:'status'`，列表筛选写 `const statusOptions = useStatusOptions()`，不再重复配置。
