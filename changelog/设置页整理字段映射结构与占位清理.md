# 设置页整理：字段映射结构改造 + 占位页清空

日期：2026-09-04
范围：`src/views/system-manage/setting/`

## 一、字段映射项结构改造（key / label / span）

### 背景

`FieldMapping` 组件里「一行几个字段」是写死在 `:cols="3"` 上的，没有暴露任何列数 prop；
字段列表 `navGroups` 是各页面内写死的常量，数据来自本地 `ref`，未接后端，所以「一行几个」后端也配不了。
另外 `modelValue`（已选字段）存的是 label 文案本身（如 `{ waybill: ['业务备注'] }`），文案一改已保存配置就失配。

### 决策

1. **span 用 24 栅格**（与 `FormItemConfig.span` 同语义，span=8 占 1/3、span=12 占 1/2），缺省 8。
2. **modelValue 存 key 不存 label**（`Record<string, string[]>` 存 `['bizRemark']`），文案可随时改不影响已保存配置。
3. **label 本轮继续硬编码中文**，不引入 i18n（历史遗留，等接真接口时一并处理）。

### 组件改造要点

`FieldMapping.vue`：

- `:cols="3"` → `:cols="24"`，`f.span` 直接透传 `NGridItem`，绕开 `span/24*cols` 的非整数换算坑。
- **关键坑**：`NGrid` 的 `x-gap` 是 CSS `column-gap`，`cols=24` 会产生 **23 个** 间距（12px×23≈276px）把内容挤没
  → 改 `:x-gap="0"`，列间距改由 `NGridItem` 内容的 `pr-12px` 提供，视觉不变且与列数无关。
- `y-gap` 保持 8（行数不随列数膨胀）。
- 类型本体放同目录 `field-mapping-config.ts`，组件用 `export type { ... }` 重导出（对齐 `Form/index.vue` 既有模式），页面导入路径不变。

### 迁移清单

仅 `InputFormat.vue` 一个使用方（其余 5 页已清空，见下）：

- `navGroups`：5 组 21 个字段改为 `{ key, label, span }`，其中收件人/发件人的「地址」标 `span: 12`（半行）。
- mock 的 `fields`：10 条手写 + 30 条生成的共 40 条，全部从中文文案改写为 key。

## 二、占位页清空（除录单格式外 5 个页面）

### 背景

`PrintFormat` / `ExportFormat` / `NotificationConfig` / `InitData` / `StationScan` 五个页面的右侧
「基本信息表单 + 字段映射卡片」全是从同一模板复制的占位假数据，继续展示会让人误以为功能已完成。

### 决策

- 右侧表单 + 字段映射**全删**，改为空状态。
- 左侧列表**保留**（可看、可搜索、可点击切换选中）。
- 列表三按钮（新建/编辑/删除）**全部隐藏**（`:show-actions="false"`）。
- 空状态**复用现有 `LookForward` 组件**（`components/custom/look-forward.vue`，自动按需引入，
  自带 `size-full min-h-520px flex-col-center` 居中，i18n `common.lookForward` 三处齐全），
  **不新增组件、不新增 i18n key、不写布局代码**。

### 为什么列表三按钮必须隐藏（死结）

`MasterDetail` 顶部三按钮都挂在 `v-if="editable"` 上，而各页面传 `:editable="!isEditing"`：

```
点「新建/编辑」→ isEditing = true → editable = false → 三按钮隐藏 + 列表不可点选
                                                    ↓
                                   出口是右侧 #operation-extra 的「保存/取消」
```

右侧清空后「保存/取消」随之删除，**点一次新建就把列表永久锁死**（不能退出、也不能再选其它项）。
因此三按钮一并隐藏，不保留按钮改行为；后续这些页面正式开发时把 `:show-actions` 改回 `true` 即可。

### 连带影响

- `FieldMapping` 使用方由 6 个降为 1 个（仅 `InputFormat.vue`），因此原计划的「迁移其余 4 页 navGroups」
  「迁移 PrintFormat 常量」两个任务作废——这些 navGroups 被整体删除，无需迁移。
- `PrintFormat.vue` 的 6 个 `@typescript-eslint/no-unused-vars` 误报随未使用变量（`formModel` / `fieldModel` /
  `navGroups` 等）删除**自然消失**，全库 `pnpm lint` 首次 0 error。
- `WaybillRule.vue` 是 Table 页面，无主从结构，不在范围。
