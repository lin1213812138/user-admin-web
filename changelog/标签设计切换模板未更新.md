# 标签设计「点设计进来还是旧模板」（keep-alive 缓存未重载，已实施）

- 日期：2026-09-19
- 范围：`src/views/system-manage/label-designer/index.vue`、`.../modules/panels/tool-bar.vue`、`src/store/modules/label-design/index.ts`、`src/locales/langs/zh-cn.ts`、`src/locales/langs/en-us.ts`、`src/typings/app.d.ts`

## 现象

用户（贴打印格式列表截图）：点另一条模板的「设计」，标签设计界面的信息还是之前那条模板的内容，「没有更新信息」。

澄清后的期望（两轮确认）：

1. 保持一个「标签设计」页签，点哪条模板就显示哪条模板的内容（不做多页签多开）。
2. 切换模板前若有未保存修改，弹确认框；用户补充：点「返回」也要判断未保存修改并提示。

## 根因

三条链路叠加，导致「再次点设计」不会重新加载模板：

1. **路由进了 keep-alive 缓存**：`build/plugins/router.ts` 的 `onRouteMetaGen` 对所有非 constant 业务路由写 `meta.keepAlive = true`；`@elegant-router/vue` 的 `inject-name` 插件在 transform 时为页面组件注入 `defineOptions({ name: '<routeName>' })`，因此 `global-content` 的 `<KeepAlive :include="routeStore.cacheRoutes">` 确实命中 label-designer 页面（组件 name 与 route name 一致）。
2. **query 不参与缓存身份**：`store/modules/tab/shared.ts` 的 `getTabIdByRoute` 只在 `meta.multiTab` 为真时才把 query 拼进 tab id；label-designer 没有 `multiTab`，所以 tab id / `<component :key>` 恒为 `/system-manage/label-designer`，`?id=xxx` 变化不产生新 key。
3. **页面自身不感知 id 变化**：`index.vue` 只在 setup 读一次 `route.query.id`、只在 `onMounted` 调 `loadTemplate`，没有 query 监听 / `onActivated` 兜底。

结果：`列表 → 点 A 的设计（首次挂载，加载 A）→ 返回列表 → 点 B 的设计` 这条路径下路由 path 与组件 key 都没变，复用 A 的缓存实例，`onMounted` 不再执行，`loadTemplate(B)` 永远不调用 → 画布与标题都停留在 A。

## 方案对比（brainstorming）

| 方案                                                           | 结论                                                                        |
| -------------------------------------------------------------- | --------------------------------------------------------------------------- |
| **A. watch `route.query.id` 重载 + 未保存确认**（采用）        | 保持单页签、改动局部、可精确控制「同 id 保留编辑」；缓存收益保留            |
| B. `meta.multiTab = true`（每模板一个页签）                    | 用户选「保持一个页签」；且页签 label 是 i18n 固定文案，无法区分模板，体验差 |
| C. 路由改 `/system-manage/label-designer/:id`（path 参与 key） | 等价多开且改动大（文件改 `[id].vue` + 重新生成路由），地址栏语义也变        |
| D. label-designer 关闭 `keepAlive`                             | 每次进入重新挂载，看似简单，但切去别的页签再切回来会丢编辑状态，代价最高    |

确定 A 后追加一条约束：**返回确认放弃修改后，要把设计器恢复成「已保存版本」** —— 否则缓存里的未保存修改还在，用户返回后再点同一条模板的「设计」（id 未变不重载）会看到与刚才「放弃」相矛盾的内容。

## 实施

### 1. store（`store/modules/label-design/index.ts`）

- 新增 `dirty`（相对上次加载/保存是否有修改）与 `savedJson`（上次加载/保存时的序列化快照）。
- 标脏：`commit()`、`updateElement()`、`updateElementOptions()`（后两者是拖动/属性面板的静默修改，不经 commit）、`undo()`、`redo()`、`setPaper()`；`setZoom`/`showGrid`/`selectElement` 属视图状态，不标脏。
- 清脏：`loadFromJson()`（解析后即写 `savedJson`）、`markSaved()`（保存成功/详情加载完成后刷新快照）、`reset()`。
- 新增 `revert()`：从 `savedJson` 还原并清脏（无快照时不动作）。

### 2. 页面（`views/system-manage/label-designer/index.vue`）

- 抽 `applyTemplate(id, name)`：同步 `currentId/currentName` 后 `loadTemplate`，首次进入与切换模板共用。
- `loadTemplate` 增加竞态保护：`await` 后校验 `currentId.value === id`，不匹配则丢弃过期响应（连点 A→B 时旧响应不覆盖新模板）；加载完成调 `store.markSaved()` 确立基线（`setPaper` 会标脏）。
- 新增 `watch(() => route.query.id)`：
  - 守卫：`route.name !== 'system-manage_label-designer'`（离开本页时 id 变 undefined）、id 为空、id 与当前相同 → 直接返回；
  - 无未保存修改 → 直接 `applyTemplate`；
  - 有未保存修改 → `window.$dialog.warning` 确认：**确认**按「确认时刻的 route id」加载（弹窗期间路由可能又变）；**取消**用 `router.replace` 把 URL 的 `id/name` 回滚成仍在编辑的模板，保持地址与画布一致（回滚触发的 watch 因 id 相同直接返回，无死循环）；
  - `switchConfirming` 防重入：连点多条「设计」只处理一次；用 `onAfterLeave`（弹窗真正关闭后）解除。
- 新增 `handleBack()`：无修改直接跳「系统设置 → 打印格式」；有修改先确认，确认后 `store.revert()`（还原为已保存版本）再跳转。
- 共用 `confirmUnsaved(onConfirm, onCancel?, onAfterLeave?)` 封装确认弹窗。

### 3. tool-bar（`modules/panels/tool-bar.vue`）

- 返回按钮由组件内 `goBack()`（`routerPushByKey`）改为 `emit('back')`，导航/确认/还原逻辑上收页面，组件保持纯 UI。

### 4. i18n

- `page.manage.labelDesign.unsavedTitle` / `unsavedContent`：zh-cn「有未保存的修改」/「当前模板有未保存的修改，继续将丢失这些修改，是否继续？」；en-us 同步；`typings/app.d.ts` 的 I18n schema 补两个键。

## 边界与已知行为

- **同一条模板重复点「设计」不重载**：同 URL 的 router push 被 vue-router 视为重复导航，页面拿不到「用户又点了一次」的信号；且保留编辑中草稿更符合继续编辑的语义。若用户从列表改了模板基础信息后再点同一条「设计」，仍显示缓存内容（跨模板切换不受影响）。
- **顶部页签切换 / 浏览器后退不拦截未保存修改**：本次只按需求拦「返回按钮」与「切换模板」两条路径。
- Naive UI 的 `onClose` 是「点击右上角关闭按钮」语义（返回 `false` 可阻止关闭），不是关闭后回调，防重入解除必须用 `onAfterLeave`。
- 取消切换模板时 `router.replace` 会触发一次同路由导航（NProgress 可能一闪，页签不新增）。
