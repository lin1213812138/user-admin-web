# 列设置「重置」不生效修复

## 需求

用户附列设置弹窗截图（点「重置」后无任何变化）："列设置点重置，为什么没有更新为当前界面的表格最新配置？"

## 定位（根因链）

「重置」链路三处断点，最终表现为**空操作**：

1. **弹窗自己把重置写成了无意义的自我同步**——`src/components/Table/table-column-config.vue` 的 `handleReset()` 只做「`localColumns = jsonClone(props.columns)` + `emit('reset')`」。`props.columns` 正是表格当前在用的那份配置，值完全一样，所以弹窗与背后表格都不会有任何变化。
2. **`emit('reset')` 无人监听**——9 个调用点（`system-manage/{user,site,group,role,menu}` + `setting/modules/{waybill-rule,print-format,export-format}` + `MasterData/master-data-archive.vue`）全部只写了 `@confirm="persistColumns"`，事件发出即被丢弃。
3. **真正干事的函数是死代码**——`use-vxe-table.ts` 的 `resetColumns()`（恢复 `options.columns()` 里定义的默认列配置 + 清 `localStorage['vxe-table-column:<cacheKey>']`）**全项目零调用**。

结论：点「重置」既没恢复页面里定义的默认列配置，也没清本地缓存，刷新后旧配置照旧回来。

## 设计（用户确认）

- **重置语义 = A：点击即生效**——立即恢复页面代码里定义的默认列配置 + 清除 localStorage 缓存；弹窗内列表与背后表格同步更新，关掉弹窗不回滚，刷新页面也是默认。
- **接线方式 = 显式接线**——各调用点解构 `resetColumns` 并补 `@reset="resetColumns"`，与既有 `@confirm="persistColumns"` 对称；不使用 provide/inject 隐式接管（同页多表格会取最后一个，存在歧义）。

## 改动文件

- `src/components/Table/table-column-config.vue`：
  - `handleReset()` 收敛为「清 `pendingDrag` + `emit('reset')`」，重置动作交给父级（页面）执行；
  - 新增 `watch(() => props.columns)`：弹窗打开期间父级列配置变化（重置恢复默认 / 确认写回）时，重新 `jsonClone` 到本地副本并清 `pendingDrag`，让弹窗内列表跟随刷新（**弹窗关闭后不处理**，打开时会重新拷贝）。
- 9 个调用点：`const { ..., persistColumns }` → `const { ..., persistColumns, resetColumns }`，`<TableColumnConfig>` 补 `@reset="resetColumns"`：
  - `views/system-manage/user/index.vue`、`site/index.vue`、`group/index.vue`、`role/index.vue`、`menu/index.vue`；
  - `views/system-manage/setting/modules/waybill-rule/WaybillRule.vue`、`print-format/PrintFormat.vue`、`export-format/ExportFormat.vue`；
  - `components/MasterData/master-data-archive.vue`（MasterData 档案页共用壳，一处生效覆盖全部归档页）。
- `use-vxe-table.ts` **零改动**：`resetColumns()` 语义本就正确，本次只是把它接上。

## 生效链路

点重置 → 弹窗 `emit('reset')` → 页面 `resetColumns()` → `columnConfigs = jsonClone(默认配置)` + 清 `localStorage['vxe-table-column:<cacheKey>']` → `<Table :columns>` 立刻回到默认列配置；弹窗经 `watch(props.columns)` 同步为默认值，可继续调整后点「确认」。

## 已知取舍

- 重置后再点「确认」会把**当前（即默认）配置写回缓存**（等价于默认，无功能差异）；此时缓存由"不存在"变为"存在且等于默认"，属 `persistColumns` 既有行为，本次不引入额外分支。
- 无 `cacheKey` 的表格（不持久化配置）同样支持重置，效果 = 回到页面默认列配置。
