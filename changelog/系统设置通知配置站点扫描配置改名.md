# 系统设置：通知配置 / 站点扫描配置 改名为 轨迹抓取配置 / 操作轨迹配置

## 需求

用户附截图，要求把系统设置里的两个页内子模块改名：

- 「通知配置」→「轨迹抓取配置」
- 「站点扫描配置」→「操作轨迹配置」

## 设计确认

经澄清，用户确认**同步修改**：不仅改前端显示名称，连目录名、组件名、变量名、i18n key 也一起同步改掉。英文命名采用推荐方案：

- 通知配置 → `trace-capture` / `TraceCapture` / `traceCapture`
- 站点扫描配置 → `operation-trace` / `OperationTrace` / `operationTrace`

## 改动清单

1. 移动并重命名目录（Windows 下 `git mv` 报 ENOENT，改用 `Move-Item` + `git add -A`，git 识别为 R 重命名保留历史）：
   - `modules/notification-config/` → `modules/trace-capture/`，`NotificationConfig.vue` → `TraceCapture.vue`
   - `modules/station-scan/` → `modules/operation-trace/`，`StationScan.vue` → `OperationTrace.vue`
2. `src/views/system-manage/setting/index.vue`：改 import 路径与组件名、tabs 的 key+label、componentMap 的 key+组件引用（每模块 3 处，共 6 处）
3. `src/views/system-manage/setting/modules/trace-capture/TraceCapture.vue`：`list-title="通知配置列表"` → `"轨迹抓取配置列表"`
4. `src/views/system-manage/setting/modules/operation-trace/OperationTrace.vue`：`list-title="站点扫描配置列表"` → `"操作轨迹配置列表"`
5. `src/locales/langs/zh-cn.ts`：`notificationConfig:'通知配置'`→`traceCapture:'轨迹抓取配置'`；`stationScan:'站点扫描配置'`→`operationTrace:'操作轨迹配置'`
6. `src/locales/langs/en-us.ts`：同步 `traceCapture:'Trace Capture Config'`、`operationTrace:'Operation Trace Config'`
7. `src/typings/app.d.ts`：i18n 类型声明 `notificationConfig`→`traceCapture`、`stationScan`→`operationTrace`

## 不改

- 其余 5 个 tab（input-format / print-format / export-format / waybill-rule / init-data）不动
- `docs/superpowers/*`、`changelog/*` 历史文档不改动

## 验证

- `read_lints` 针对 6 个改动文件：0 错误、0 警告

## 备注

- 这两个子模块是 setting 页内的 `NTabs` 切换组件（非独立路由），移动/重命名目录不会影响 elegant-router 自动生成的路由文件。
