# 权限管理独立顶级菜单重组

> 日期：2026-09-14
> 触发语：「把用户管理、角色管理单独提到权限管理文件夹下面，新建一个文件夹」

## 1. 背景与需求

用户希望把「用户管理 / 角色管理」从 `系统管理` 下抽离，归到一个新建的「权限管理」文件夹，并明确这是一个**新的顶级菜单分组**。

经澄清确认三件事：

1. **位置**：在 `views/` 下新建 `permission-manage/`，作为与 `系统管理` 同级的顶级菜单（不是挂在系统管理下的子目录）。
2. **菜单形态**：「权限管理」做成带父级菜单的分组，用户管理 / 角色管理作为其子菜单，层级更清晰。
3. **范围**：除用户 / 角色外，把「菜单管理」也一并归入（权限三件套：用户 / 角色 / 菜单），更符合权限管理语义。

## 2. 关键约束（来自 AGENTS.md）

- 路由由 `src/views/` 目录结构自动生成，**禁止手改 `src/router/elegant/**`**（`routes.ts`/`imports.ts`/`transform.ts`/`elegant-router.d.ts`/`components.d.ts`）。
- 路由 meta（icon / order / hideInMenu 等）**不写在自动生成文件里**，而是在 `build/plugins/router.ts` 的 `onRouteMetaGen()` 集中维护（`routeIcons` / `routeOrders` / `hideInMenuRoutes` / `menuActiveKeys` / `constantRoutes`）。
- i18n 文案 zh-cn / en-us 必须同步，否则另一语言缺失且 TS 报错（`route: Record<I18nRouteKey, string>`，`I18nRouteKey` 由 `RouteKey` 派生，重新生成后自动同步）。
- Windows 环境下 `git mv` 在本仓库报 `ENOENT`（疑似路径映射问题），改用 `Move-Item` + `git add -A`，git 自动识别为 `R`（重命名）并保留历史。

## 3. 实施方案

### 3.1 目录移动

- `src/views/system-manage/user/` → `src/views/permission-manage/user/`
- `src/views/system-manage/role/` → `src/views/permission-manage/role/`
- `src/views/system-manage/menu/` → `src/views/permission-manage/menu/`

每个目录含 `index.vue` + `modules/`，整体移动；三个页面彼此无跨目录引用，移动安全。git 状态为 `R`（重命名），历史保留。

`permission-manage/` 无 `index.vue`，elegant-router 会像 `data-manage` / `system-manage` 一样自动生成父级路由分组。

### 3.2 路由 meta（`build/plugins/router.ts`）

`routeIcons`：

- 移除 `system-manage_role` / `system-manage_user` / `system-manage_menu`
- 新增 `permission-manage`(`ic:round-lock`)、`permission-manage_user`(`ic:round-person`)、`permission-manage_role`(`ic:round-supervisor-account`)、`permission-manage_menu`(`ic:baseline-menu`)

`routeOrders`：

- 移除 system-manage 下 user/role/menu 三项
- 新增 `permission-manage: 3`，子项 `permission-manage_user: 1` / `permission-manage_role: 2` / `permission-manage_menu: 3`（保持原相对顺序）

顶级菜单顺序：`首页 0` / `资料管理 1` / `系统管理 2` / **`权限管理 3`**。

### 3.3 国际化（zh-cn.ts / en-us.ts 的 `route` 段）

- 删除：`system-manage_user` / `system-manage_role` / `system-manage_menu`
- 新增：`permission-manage`(权限管理 / Permission Management)、`permission-manage_user`、`permission-manage_role`、`permission-manage_menu`
- `system-manage` 自身保留。

### 3.4 业务代码

- `src/views/permission-manage/user/index.vue`：两处 `$t('route.system-manage_user')`（导出文件名）→ `$t('route.permission-manage_user')`。
- `src/service/api/mock.ts` 第 274 行的 mock 菜单树 `'system-manage'` 目录节点属演示数据，与真实路由解耦，**未改动**（如需视觉一致可顺手改，但不强制）。

### 3.5 自动生成文件（由 `pnpm dev` 重新生成，禁止手改）

`pnpm dev` 启动后 elegant-router 重新扫描 `views/`，自动：

- `routes.ts`：加入 `permission-manage` 父路由及三子路由（父级带 icon `ic:round-lock`、order `3`），移除 system-manage 下三项。
- `imports.ts` / `transform.ts` / `elegant-router.d.ts` / `components.d.ts`：同步更新 `RouteKey` / 路由映射 / 视图组件映射。

实测 `pnpm dev` 启动后 `routes.ts` 已含正确父级与子项 meta，`git status` 显示 `R` 重命名；dev 服务启动后已关闭。

## 4. 验证

- `pnpm dev` 路由重新生成成功：`permission-manage` 父级带 icon / order，三子项齐全。
- 定向 `eslint src/views/permission-manage`：0 error。
- `pnpm typecheck`：本次改动**零新增错误**；仓库中残留的 `page.dataManage.basic.*` / `countryRegion` 类型错误来自并行的「资料管理基础资料」重构，与本次权限管理移动无关，未处理。
- 侧边栏预期：新增顶级「权限管理」分组，下挂 用户 / 角色 / 菜单管理；原系统管理下三项消失。
