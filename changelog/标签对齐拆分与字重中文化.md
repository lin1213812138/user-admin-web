# 标签设计：对齐拆分水平/垂直 + 字重中文化

> 日期：2026-09-14　模块：`src/views/system-manage/label-designer`

## 背景

用户截图反馈属性面板「样式」区两处：

1. 「对齐」要拆分为**水平对齐**与**垂直对齐**两个下拉；
2. 对齐、字重的选项文案要**中文**（现状 `left/center/right`、`normal/bold` 全英文）。

现状核查：`align` 只有水平语义（CSS `text-align`，仅 text/longText 有该项），垂直方向能力完全缺失——导出格式 `style.verticalAlign` 长期写死 `'top'`，内部无对应字段。

## 方案（已与用户确认）

### 一、数据模型（`core/types.ts`）

- `TextOptions.align` 保留，语义明确为**水平对齐** `left | center | right`；
- 新增 `TextOptions.verticalAlign?: 'top' | 'middle' | 'bottom'`，缺省按 `top`（旧数据无此字段 → 视觉与现状完全一致，无需迁移）；
- 取值用 `top/middle/bottom`：与导出格式 `style.verticalAlign` 的 CSS 语义一致，导出直传不映射。

### 二、渲染（画布 + 打印两处同步）

- 文本容器改为 `display:flex; flex-direction:column; justify-content:flex-start|center|flex-end`；
- 内容包一层宽 100% 的内层 div —— 保证「关联标题行内前缀 + 内容」仍在同一文本流（不被 flex 拆成两个块、不破坏折行行首顶格）；
- `verticalAlign` → justify 值的映射收敛在 `render/render-utils.ts`（画布与打印共用）；
- `canvas/element-renderer.vue` 与 `render/render-element-html.ts` 两端同步，缺省 `?? 'top'`。

### 三、属性面板「样式」区（仅文本 / 长文本，布局重排）

| 行  | 内容                                        |
| --- | ------------------------------------------- |
| 1   | 字号 \| 颜色                                |
| 2   | 字重 \| 行高                                |
| 3   | 水平对齐 \| 垂直对齐                        |
| 4   | 显示边框（开启后追加 边框宽度 \| 边框颜色） |

选项全部中文（走 i18n，zh/en/typings 三处同步）：

- 水平对齐：左对齐 / 居中对齐 / 右对齐；
- 垂直对齐：顶部对齐 / 居中对齐 / 底部对齐；
- 字重（含标题字重）：正常 / 加粗（存储值仍是 `normal/bold`，仅显示中文）。

i18n 键：新增 `propAlignH` / `propAlignV` 与值文案键（`alignLeft` / `alignCenter` / `alignRight` / `valignTop` / `valignMiddle` / `valignBottom` / `weightNormal` / `weightBold`），删除旧 `propAlign`（全仓仅属性面板一处引用）。

### 四、导出 / 回读（`core/export-format.ts`）

- 导出：`verticalAlign` 由写死 `'top'` 改为读真实值（`str(o.verticalAlign) || 'top'`）；
- 回读：新增 `pickVAlign(style.verticalAlign)` 反推，缺省 `top`。

### 五、默认值（store `defaultOptionsFor`）

文本 / 长文本补 `verticalAlign: 'top'`。

### 六、范围

条码 / 二维码 / 图片 / 矩形 / 线条不动（它们目前没有对齐项；条码编码值行保持现有居中）。

## 实施记录（2026-09-14，已完成）

按上表全部落地，无偏离。要点备注：

- `buildModel()` 对 text/longText 兜底 `base.verticalAlign ??= 'top'`（放对象展开之后、其余兜底同段），旧元素上下拉不空且不残留上一元素选中项；回写时会把 `'top'` 落进旧 options，语义即缺省值，无害；
- 旧数据渲染兜底走 `vAlignToJustify(undefined) → flex-start`，与改动前视觉一致；
- `textLike`（text/barcode/qrcode 共用的导出块）里 `verticalAlign: str(o.verticalAlign) || 'top'`：条码/二维码无该字段，依旧输出 `top`，与改造前一致。

## 验证（实测）

- `pnpm typecheck` 通过；IDE 诊断 0 错误；全仓 `propAlign`（旧键）0 残留；
- tsx 直调 `renderTemplateHtml()`：`top/middle/bottom` 分别输出 `justify-content:flex-start/center/flex-end`，且「标题:内容」仍在内层 div 的同一文本流（`<span>…</span>100` 连续）；
- tsx 直调导出/回读：`toExportTemplate` 输出真实值 `bottom`；删除 options 的纯目标格式回读 `bottom`；删除 `style.verticalAlign` 后导出与回读均兜底 `top`（旧数据兼容）；
- 画布端与打印端结构同构（外层 flex column + 内层 100% 宽 div），逻辑复核一致；画布实际观感建议在 dev 页面目检一次。
