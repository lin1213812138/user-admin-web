## 用户诉求（两张截图）

1. **第一张图**：角色编辑抽屉底部红框圈出两个复选框「仅查看专属客户业务」「仅查看所属组别客户业务」→ **改成下拉**；用户追问后明确为 **多选**。

## 现状定位

### 第一张图对应：`src/views/system-manage/role/modules/role-operate-drawer.vue`

- 红框两个复选框 = `dataAuths`，用 `#dataAuths` 具名插槽裸写 `NCheckboxGroup + NCheckbox`（0=仅查看专属客户业务、1=仅查看所属组别客户业务），**没走 FormWrap 的控件体系**。
- 同一抽屉里已有 4 个 `type: 'switch'` 项：`sendOrderCtrl` / `sendCtrl` / `orderColCtrl` / `editInfoCtrl`（span 12，两列排布）。
- `model` 为 `Api.SystemManage.RoleCreateParams`，`fillFormByRow` / `resetForm` 各自逐字段赋值/重置。

### 第二张图对应：前端目前**不存在**该弹窗

全仓搜索「限制性权限设置 / 用户修改密码 / 运单列表禁止设置」零命中（`setting/modules/basic-config/BasicConfig.vue` 的「系统操作控制定义」是公司级配置，字段完全不同）。第二张图是老系统/参考系统的界面，其 5 个字段与**后端 Role 模型**一一对应。

### 后端事实（`tms-user/lib/common/models/role.js`，零改动）

```js
sendOrderCtrl: Number, // 出库后禁止修改 0-不允许 1-允许
sendCtrl:      Number, // 出库必须称重 0-不启用 1-启用
orderColCtrl:  Number, // 运单列禁止设置列表字段 0-不允许 1-允许
editPwdCtrl:   Number, // 用户修改密码 0-不允许 1-允许
editInfoCtrl:  Number, // 用户修改个人信息 0-不允许 1-允许
```

- **结论**：第二张图的 5 项 = 后端已有 5 个字段，语义与现有 4 个 switch 完全同源（只是文案口径相反，现有前端用正向描述「出库后允许修改运单」，后端注释是「出库后禁止修改」）。
- **唯一缺口**：`editPwdCtrl`（用户修改密码）前端 `Role` / `RoleCreateParams` 类型、model、回填、重置**全都缺失**，需要补齐。
- `lib/services/role.js:72-92` 用户侧取 `max(map(roleList, 'editPwdCtrl'))`，且 `roleType == 100` 强制 `editPwdCtrl = editInfoCtrl = 1`（后端 ADMIN=100，与前端 roleType=5 不一致，本轮不处理）。

### 组件能力确认（`src/components/Form/index.vue`）

- `FormItemConfig` 已有 `multiple?: boolean`（`NSelect` 透传 `:multiple`），多选时 `model[key]` 为 `Array<string | number>` → **dataAuths 改多选下拉不需要改公共组件**。
- `FormItemConfig.type` 已有 `'section'`（占整行、左侧蓝色竖条 + 15px 粗体标题，不包 `NFormItem`）→ **「限制性权限设置」区块标题可直接用 section**，无需手写 NCard。
- `viewText()` 的 `select` 分支已处理数组值（`value.map(...).join('、')`）→ 详情只读态多选下拉自动正确展示。

## 最终设计方案（已确认）

**核心判断**：第二张图的 5 项不是「新增一套新功能」，而是**把角色编辑抽屉里已有 4 个 switch 换成下拉 + 补齐缺失的第 5 项 editPwdCtrl**，与 `dataAuths`、角色名称、角色类型等字段**合并为一个连续表单**，不再单独分「限制性权限设置」section 区块（2026-09-18 用户截图确认「去掉合成一个表单」）。

1. `dataAuths` → `type: 'select'` + `multiple: true`，删 `#dataAuths` 插槽与 `NCheckboxGroup`，选项沿用现有 `dataAuthOptions`（0/1），`filterable: false`。
2. 5 个限制性权限字段全部改 `type: 'select'`（原 switch → 下拉），span 12 两列，直接排在 `dataAuths` 之后、`desc` 之前：
   - `sendOrderCtrl` 出库后禁止修改（0 不允许 / 1 允许）
   - `sendCtrl` 出库必须称重（0 不启用 / 1 启用）
   - `orderColCtrl` 运单列表禁止设置列表字段（0 不允许 / 1 允许）
   - `editInfoCtrl` 用户修改个人信息（0 不允许 / 1 允许）
   - `editPwdCtrl` 用户修改密码（0 不允许 / 1 允许）← **新增**
3. 默认值：`sendOrderCtrl=1` / `sendCtrl=0` / `orderColCtrl=1` / `editInfoCtrl=1`（沿用现状），新增 `editPwdCtrl=1`。
4. 类型：`Api.SystemManage.Role` 与 `RoleCreateParams` 补 `editPwdCtrl?: RoleCtrl`。
5. i18n：`page.manage.role.ctrls.*` 文案按第二张图口径调整 + 新增 `editPwd`、新增「允许/不允许」选项文案；`restrictSection` 因已去掉 section 标题**不再使用**（保留在字典中无害，未删除）；zh-cn / en-us / `app.d.ts` Schema 三处同步。
6. 列表页 `role/index.vue` 的 `dataAuths` 列已是 `map` 转文案，**不需要改**。

**不改**：后端（零改动）、公共 `Form` 组件、路由/菜单、角色列表其它列。
