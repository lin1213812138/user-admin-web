# 追踪网络「轨迹信息改造」

日期：2026-09-18
设计文档：[docs/superpowers/specs/2026-09-18-track-network-replace-design.md](../docs/superpowers/specs/2026-09-18-track-network-replace-design.md)

## 问题定位

用户附两张原型截图：

1. 「系统设置 → 轨迹抓取配置 → 追踪网络」列表操作列，从现状「编辑 / 删除」变为平铺三个按钮 **编辑 / 轨迹信息改造 / 删除**。
2. 点击「轨迹信息改造」弹出**弹窗**（非抽屉），标题「追踪网络」，顶部只读展示当前网络名称，下方「改造规则」表格（**原始字符串 / 替换字符串**），带「+ 添加一行」与行内「删除」，底部「取消 / 保存」。

现状：前端仅有 `track-config` 的 CRUD，完全**未对接** `track-replace`（字符串替换规则）；「轨迹改造」tab 实为异常状态定义表，与此功能重名但无关联。

## 后端事实（零改动，已存在于 tms-user）

- `lib/api-v1-web/track-replace/`：`/track-replace/batch/save`（`{ configId, list:[{_id?, oriStr, replaceStr}] }`，控制器补 creatorId/creator 后走 `batchSaveCommon` 按 `_id` 差集增删改）、`/track-replace/query`、`/track-replace/get`。
- 模型 `track-replace`：`configId / oriStr / replaceStr / creatorId / creator / createDate / updateDate`。
- `batchSaveCommon`：传 `refValue=configId` 时对全量记录与入参 `list` 求 `_id` 差集 → 删除差集、新增无 `_id`、更新带 `_id`，即"整表提交、本地删除即移除"语义。
- `query` 走 `queryCommon`，入参 `{ where:{configId}, page, size, sort }`。

## 澄清 4 问结论

① 入口平铺三按钮（编辑 / 轨迹信息改造 / 删除），不用下拉；② 规则单元格始终可编辑、「添加一行」直接追加空行、最后统一保存；③ 弹窗内增删改仅本地，点「保存」一次性提交 batch/save；④ 原始/替换字符串都可空，保存时过滤两者皆空的行。

## 方案（待实施）

- **类型**：`typings/api/system-manage.d.ts` 新增 `TraceReplaceItem { _id?; oriStr?; replaceStr?; creator? }` + `TraceReplaceList` + `TraceReplaceBatchSaveParams`。
- **接口**：新增 `service/api/track-replace/index.ts`，`fetchGetTrackReplaceList`（/track-replace/query，size 拉满）+ `fetchBatchSaveTrackReplace`（/track-replace/batch/save），真实请求无 DEV mock，flat 解包 `{data,error}`。
- **入口**：`TrackNetworkTable.vue` 操作列三按钮平铺，`轨迹信息改造` 打开弹窗传 `row._id`/`row.name`。
- **弹窗**：新增 `track-network/TrackReplaceModal.vue`（`NModal`，只读网络名 + naive `NDataTable` 改造规则表，行内 NInput 始终可编辑、行内删除、+ 添加一行、取消/保存；watch(show) 拉规则，保存过滤空行后整表提交）。
- **i18n**：zh-cn / en-us / `app.d.ts` 三处同步新增 `traceInfoTransform` `transformRules` `col.oriStr` `col.replaceStr` `addRuleRow`（`save` 复用 `common.save` 若存在）。

不做：其余 4 个 tab 任何改动、后端改动、路由/菜单/elegant 变动。
