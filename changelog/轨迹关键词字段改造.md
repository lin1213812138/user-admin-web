# 轨迹关键词：字段改造（匹配规则表）

日期：2026-09-15
设计文档：[docs/superpowers/specs/2026-09-15-trace-keyword-fields-design.md](../docs/superpowers/specs/2026-09-15-trace-keyword-fields-design.md)

## 问题定位

用户附原型截图（"这是轨迹关键词的字段"）：「系统设置 → 轨迹抓取配置 → 轨迹关键词」的字段应为
**规则名称 / 使用范围 / 关键词组 / 运单状态 / 启用状态 / 最后编辑 / 编辑时间** + 操作（编辑 / 省略号），
示例 2 条（安达配送完成 / 规则）；第二张截图给出「运单状态」下拉选项（转运中 / 已送达 / 异常件 / 已退件，必填）。

现状：「轨迹关键词」仍与追踪网络 / 抓取时间同构，共用 `TraceConfigTable` + `TraceConfigDrawer`
（名称 / 服务器地址 / 系统类型 / 最后编辑 / 编辑时间），与截图不符。

## 方案（已确认）

- **范围**：只改「轨迹关键词」，其余 4 个 tab 不变。
- **枚举**：使用范围 = 全局通用 / 指定站点 / 指定客户（按初版，本版只存枚举值不联动）；运单状态 = 转运中 / 已送达 /
  异常件 / 已退件（按用户截图）；两者均存枚举 key、展示走 i18n。
- **关键词组**：自由文本、多个关键词用中文逗号分隔。
- **操作列**：编辑 + 删除（`NPopconfirm` 二次确认），截图省略号按原型示意处理。
- **类型**：`typings/api/system-manage.d.ts` 新增 `TraceKeywordScope` / `TraceKeywordWaybillStatus` /
  `TraceKeywordItem / List / SearchParams / CreateParams / UpdateParams`（create 不含审计字段；
  `enabled` 用 `Api.Common.EnableStatus`，新增默认 1）。
- **组件**：新增 `trace-capture/TraceKeywordTable.vue`（列=序号/规则名称/使用范围/关键词组/运单状态/
  启用状态 NTag/最后编辑/编辑时间/操作，cacheKey `trace-keyword`）与 `TraceKeywordDrawer.vue`
  （NFormWrap：规则名称必填 / 使用范围 select 默认全局通用 / 关键词组必填 / 运单状态 select 默认转运中 /
  启用状态 switch）→ `TraceCapture.vue` 的 `configTabs` 循环加 `track-keyword` 分支。
- **数据**：`mock.ts` 增 `traceKeywordItems` 2 条截图数据（含审计字段）+ 4 个 mock 函数（create/update 自动填
  `lastEditor` / `editTime`）；`system-manage.ts` 增 4 个 `fetch*TraceKeyword`（DEV mock，PROD
  `/system/trace-keyword/*`，删除 `ids: number[]`）。
- **i18n**：`traceCapture` 段增 `col.ruleName/scope/keywordGroup/waybillStatus/enabled`、`form` 同名字段与占位、
  `scopeOption`、`waybillStatusOption`，zh-cn / en-us / `typings/app.d.ts` 三处同步。

不做：勾选列 / 批量删除；其余 4 个 tab 的任何改动。
