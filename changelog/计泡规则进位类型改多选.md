# 计泡规则进位类型改为多选

> 日期：2026-09-20 ｜ 状态：已实施，待手动冒烟

## 背景

用户对「计泡规则」新增/编辑抽屉（`WeightRuleOperateDrawer.vue`）的**进位规则**区块提出调整：

1. 把每个规则组内的「进位类型」下拉**提到区块顶部**，改为**多选**。
2. **选中一个进位类型 = 新增一个对应进位规则组**。
3. 去掉「加进位规则组」按钮与每组的「删除该组」按钮。
4. **取消勾选某个进位类型 = 删除对应的进位规则组**。

原实现（2026-09-19 重绘）是「空状态 + 加进位规则组」自由增删：每组内含一个单选的「进位类型」`NSelect`，因此理论上可以存在**多个 carry 值相同的重复组**。

## 决策

- 顶部「进位类型」用 `NSelect multiple` 承载；**选项即规则组**，勾选集合与 `carryList` 双向绑定，天然去除重复 carry 组。
- 组内不再放「进位类型」下拉，改为**组标题**（主题色竖条 + 进位类型文案），保持区块可读性。
- 取消勾选即 `splice` 掉该组（含已填区间）——按用户要求直接删除，不加二次确认；二次勾回时该组区间为空（数据丢失属预期语义）。
- 组的展示顺序按**选项枚举顺序**（进位类型 0→3）排列，而非用户的点选顺序，避免视觉顺序抖动。

## 实施

`src/views/data-manage/ship/modules/weight-rule/WeightRuleOperateDrawer.vue`：

- 新增 `selectedCarryTypes` 计算属性（`get/set` 双向）：
  - `get`：`carryList.map(i => i.carry)` 过滤 `undefined`，回显已勾选项。
  - `set`：按 `carryOptions` 顺序，对选中值复用 `carryList` 中已存在的组（**保留已填区间**），缺失的补 `{ carry, ruleList: [] }`，未选中的自然被丢弃 → 即「取消即删除」。
- 新增 `carryLabel(carry)`，用于各组标题文案。
- 删除 `addCarryGroup()` / `removeCarryGroup()` 两个函数。
- 模板：顶部改为带标签的 `NSelect multiple`；`NEmpty` 空状态、每组「进位类型」下拉与「删除该组」按钮、底部「加进位规则组」按钮全部移除；每组改为主体色竖条 + 进位类型标题。
- `addRule` / `removeRule`（区间增删）、`FormWrap` 基础字段、提交与校验逻辑**零改动**。

i18n（zh-cn / en-us）与 `src/typings/app.d.ts` 同步：

- 新增 `weightRule.carryTypePlaceholder`（「请选择进位类型，选中后自动生成对应进位规则」）。
- 删除已无引用的 `weightRule.carryEmpty` / `weightRule.addCarryGroup` / `weightRule.removeCarryGroup`。
- 保留 `weightRule.carryType`（标签）、`ruleEmpty`、`addRule`、`removeRule`。

## 边界（未动）

- 数据契约不变：提交仍是 `carryList: [{ carry, ruleList: [{ start, end, unit }] }]`，后端无需改动。
- 列表页 `WeightRule.vue`、`service/api/data-manage-ship`、`typings/api/data-manage/ship.d.ts` 均未动。
- 抽屉宽度、`FormWrap` 分区（基础信息 / 进位规则）、其它字段未动。
