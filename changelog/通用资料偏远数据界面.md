## 3. 探查结论（只读）

### 3.1 后端已就绪，本任务为纯前端落地

| 能力                 | 路由                                                                  |
| -------------------- | --------------------------------------------------------------------- |
| 类别 查/增/删        | `/remote-group/query`、`/remote-group/create`、`/remote-group/delete` |
| 类别条数统计（未用） | `/remote-group/remote/count`                                          |
| 明细 查/批量重建     | `/remote/query`、`/remote/batch/create`                               |
| Excel 解析           | `POST /file/parse?fileType=1`（`serviceMap[1] = remoteService`）      |

### 3.2 两个决定实现的契约

1. **`/file/parse?fileType=1`**：表头必须逐字等于 `uploadField`（`国家代码*` / `城市` / `起始邮编` / `结束邮编`）；行级校验在服务端做、**非法行被直接丢弃**，返回的 list 只含合法行，并已回填 `countryId`、`parseMsg='通过'`。
2. **`/remote/batch/create`**：先 `deleteMany({ remoteGroupId })` 再插入 ⇒ **导入 = 全量覆盖**，同时回写类别的 `remoteCount`；只校验 `list[0].remoteGroupId` ⇒ 前端须为每行补齐 `remoteGroupId`。

### 3.3 页面判定

截图表格列（`偏远类别` / `偏远数据条数` / `更新人` / `数据更新时间` / `创建时间`）与 `RemoteGroup` 字段逐一对应，工具栏为「新增类别 / 批量删除」⇒ **主表 = 偏远类别列表**；操作列仅 `导入 / 删除`（**无编辑**，故本期不实现 `/remote-group/update`）；「新增类别」只有「类别名称」一个必填项。

## 10. 追加修复二（2026-09-21，**解析接口报 100030「上传目录不能为空」**）

**现象**：用户贴出接口 Preview `{errcode: 100030, errmsg: "上传目录不能为空"}`。

**根因（源码定位）**：`/file/parse` 与 `/upload` 共用同一个上传中间件 ——

```96:98:tms-user/lib/common/services/file.js
  async file(ctx, next) {
    if (!+ctx.request.query.dest) throw new ApiError(ERROR_CODE.UPLOAD_DEST_ERR);
    await upload.single('file')(ctx, next);
  },
```

`UPLOAD_DEST_ERR` = `100030「上传目录不能为空」`（`lib/common/define/error-code.js:123-126`），即 **`dest` 是必填 query 参数**（`storage.destination` 用 `destMap[destType]` 决定落盘目录，见 `file.js:27-38,77-87`）。而我的 `fetchParseRemoteFile` 只传了 `fileType=1`，**漏传 `dest`** ⇒ 中间件直接抛错，请求根本没进到解析逻辑。

**修复**：`src/service/api/remote/index.ts` 的 `fetchParseRemoteFile` 请求参数改为 `{ dest: 10, fileType: 1 }`。
选 `10`（`destMap[10] = 'temp'` 临时目录）的依据：解析完成后后端会 `fs.unlink(file)` 删掉文件（`services/file-parse.js:91`），不落正式目录，也符合「临时文件」语义。同时补了注释说明 `dest` 必传的原因。

**验证**：`oxfmt` / `oxlint` 0-0 / `eslint`（无匹配配置，仅提示忽略）/ `pnpm typecheck` 本文件 0 错误；`git status` 确认未触碰无关文件。
**待冒烟**：选择文件后 Network 里应为 `POST /file/parse?dest=10&fileType=1`，返回 `{list:[...]}` 且预览表格出现数据。
