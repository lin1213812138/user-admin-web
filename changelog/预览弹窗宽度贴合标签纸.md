# 预览弹窗宽度贴合标签纸

## 问题

点击预览时，弹窗内的预览区域（灰色背景 + 白色纸张）比实际标签纸大很多，预览的宽度比标签纸宽，看起来「不贴合」。

## 定位

`src/views/system-manage/print-design/modules/preview-modal.vue` 中：

1. 容器 `<div class="min-w-400px w-full bg-#f5f5f5">` 强制了 `min-w-400px`：
   iframe 由 JS 读内部 `.hiprint-printPaper` 的实际尺寸设置为约 280px，
   但 `min-w-400px` 让容器宽度至少 400px，导致两侧出现明显的灰色背景留白。
2. 弹窗本身 `NModal preset="card"` 内部用 `NCard` 渲染，
   `NCard` 默认 `content` 有 `padding-left/right`（由 `--n-padding-left/right` 控制，约 16–20px），
   即使容器宽度 = 纸张宽度，弹窗整体宽度仍会比纸张宽一圈。

## 方案

两处一起改，使弹窗宽度 = 纸张宽度：

1. 容器由 `min-w-400px w-full` 改为 `w-fit`，
   `width: fit-content` 让容器收缩到 iframe（= 纸张）的实际宽度。
2. `NModal` 透传 `content-style="{ paddingLeft: 0, paddingRight: 0 }"`：
   Naive UI `NModal preset="card"` 内部通过 `Object.assign({}, this.$attrs, ...)` 把 `$attrs` 透传给 `NCard`，
   `NCard` 有 `contentStyle` prop，可直接覆盖 `.n-card-content` 的 inline style，
   从而去掉 NCard 自身的左右内边距（上下保留，避免内容贴 title/footer）。

`max-width: 95vw` 与 `auto` 宽度保留，避免纸张尺寸异常时超出屏幕。

## 影响

- 预览弹窗宽度严格贴合当前标签纸尺寸，左右不再有 NCard 内边距留白。
- 上下仍有 NCard content padding（让预览纸张不贴紧标题/底部按钮），视觉合理。
- 打印尺寸不受影响（仍由 `iframe.contentWindow.print()` 触发，仅弹窗尺寸变化）。
