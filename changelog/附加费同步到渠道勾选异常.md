### 一级「附加费 - <承运网络>」`CarrierFeeExtDrawer.vue`

1. **默认全勾**：取数时每行强制注入 `checked: true`：


2. **每次取数都重置为全勾**：`transform` 无条件写 `checked: true`，而 `reload()`（= `getData()`）会在

3. **提交按勾选过滤**（逻辑本身正确）：

```ts
function handleSyncToChannel() {
  const ids = data.value.filter(row => row.checked).map(row => row._id);
  if (ids.length === 0) {
    /* warning needFeeExt，不发请求 */
  }
  syncFeeExtIds.value = ids;
  syncDrawerVisible.value = true;
}
```

### 顺带核对的契约（`tms-user`，零改动）

- `lib/services/channel-fee-ext.js#syncList`：`find({ _id: ids })` → 仅勾选源加收；`deleteMany({ refId: refIds, syncId: ids })` + `insertMany` ⇒ 目标渠道也严格来自 `refIds`，**后端不会自作主张扩大到全量**。

## 修复方向（**待确认根因后出 spec，先不动代码**）

1. **默认不勾**（`checked: false`）：最贴合"勾选即选择"的直觉，用户操作不再反转；代价是要同步多条时需逐条勾选（或点表头全选）。
2. **保留用户勾选**：`reload()` 时按 `_id` 保留已勾状态（新行默认不勾），避免取数静默重置；可与方案 1 组合。

## 补充讨论：这两个界面为什么自绘勾选列？是否该改用内置 checkbox 列？

用户追问：

> 「新增附加费和附加费同步到渠道界面为什么要自定义多选框？」

### 当时的自绘理由（引自 [承运网络附加费.md](./承运网络附加费.md) 关键决策表第 6 项）

1. spec 原定用 `Table` 暴露的 `setAllCheckboxRow` 实现"默认全勾"，但该 expose 全仓**尚无调用先例**；
2. 认为可"**避免 vxe 内部勾选态与数据刷新耦合**"；
3. 与既有的 `CarrierSyncDrawer` 勾选列**同款**，保持一致。

### 复核后：这三条对「附加费」这两个界面均不成立

1. **"无先例"不成立**：`role-permission-drawer.vue` 早已用内置 checkbox 走"默认勾选"路径 ——

```ts
// src/views/system-manage/role/modules/role-permission-drawer.vue
const rowConfig: VxeTablePropTypes.RowConfig = { keyField: 'id' };
const checkboxConfig = computed<VxeTablePropTypes.CheckboxConfig>(() => ({
  checkStrictly: false,
  checkField: 'checked', // 用行上的 checked 字段回填初始勾选
  checkMethod: ...
}));
```

```vue
<Table :row-config="rowConfig" :show-checkbox="true" :checkbox-config="checkboxConfig" ... />
```

—— `checkField: 'checked'` 正是"由数据决定初始勾选态"的能力，等价于附加费要的"默认全勾"，无需命令式 `setAllCheckboxRow`。

2. **"避免耦合"方向恰好相反**：自绘把勾选态存进 `data` 的行对象，而取数逻辑（`transform`）每次都会**重建**整个 `data` ⇒ 勾选被无条件重置（即本次 bug 的候选根因 B）。内置 checkbox 由 vxe 按 `keyField` 的 rowid 维护勾选态，配了 `checkField` 时再同步回行字段，**更不容易被取数冲掉**。

3. **"与 CarrierSyncDrawer 同款"不构成理由**：那边自绘是**必需**的 —— 其行框需要"部分勾选 → 半选"三态（vxe 内置行框不支持行级半选，见其文件注释）；而附加费列表只有"勾 / 不勾"两态，没有该约束，属于照搬形态。

### 结论（待用户确认后才出 spec）

- 一级「附加费」列表与二级「同步到渠道」渠道列表，**改用 `Table` 内置 checkbox 列更合适**：`:show-checkbox="true"` + `:row-config="{ keyField: '_id' }"` + `:checkbox-config="{ checkField: 'checked' }"`，可省掉整块自绘联动（`headerCheckState` / `toggleAll` / 手写 `rowCheck` 列）。
- 但需明确：**"默认是否全勾"是业务口径，与组件选型无关** —— 内置方案同样要在取数时写 `checked: true` 才能默认全勾，因此该口径需与上一节的修复方案（默认不勾 / 保留勾选 / 二次确认）**一并决定**。
- 取出勾选的写法：配了 `checkField` 后仍可直接 `filter(row => row.checked)`，或改用 `@selection-change` 拿 `getCheckboxRecords()`。
- 内置方案下 vxe 自带表头全选与半选，无需自算。

## 追加：表头与勾选框「没对齐」排查（2026-09-21，待用户确认方案）

**逐像素测量（截图放大 6~8 倍）**：

| 截图                                       | 固定列数 | 表头 vs 数据偏差      | 非固定列                           |
| ------------------------------------------ | -------- | --------------------- | ---------------------------------- |
| ① 仅勾选列（本次改内置 checkbox 后）       | 1        | ≈1px                  | 「渠道名称」对齐                   |

### 实测数据（用户在 Console 量测，勾选列宽 50）

| 层级                  | 表头                       | 行内                     | 差异                               |
| --------------------- | -------------------------- | ------------------------ | ---------------------------------- |
| 列单元格              | `[280, 92, 50, 41.2]`      | `[280, 133, 50, 40]`     | 一致                               |

| `.vxe-cell--wrapper`  | `[288, 101.6, **34**, 22]` | `[288, 142, **32**, 22]` | **行内少 2px**                     |
| `.vxe-cell--checkbox` | `[**296.5**, …]`           | `[**295.5**, …]`         | **差 1px（左右，与用户描述一致）** |

### 根因

`Table` 的表格级 `show-overflow: 'tooltip'` 会给 **body 的 `.vxe-cell` 预留 2px**（50 → 48），表头不受影响（仍 50）；两侧内容区（wrapper）因此为 34 / 32，勾选框（17.1px 宽）在各自区域内居中 ⇒ 左边缘差 **`(34 − 32) / 2 = 1px`**。

### 修复（已实施）

`src/components/Table/table.vue` 的两个内置列加 `:show-overflow="false"`：

```vue
<vxe-column v-if="showSeq" type="seq" title="#" :width="50" fixed="left" align="center" :show-overflow="false" />
<vxe-column v-if="showCheckbox" type="checkbox" :width="50" fixed="left" align="center" :show-overflow="false" />
```

- 只影响序号列 / 勾选列（这两列内容天然不溢出）；其他列的省略号 + tooltip 行为完全不变；
- **全仓生效**：所有带序号 / 勾选列的表格一并修好（不再局限于附加费这两个抽屉）；
- **树形表格零影响**：唯一树表 `role-permission-drawer.vue` 的表格级本就是 `false`，列级再设 `false` 属 no-op；树形由 `tree-config` + 业务列 `treeNode` 驱动，与内置列无关（详见 spec §7）。

## 追加：打开抽屉 / 重新取数时清空勾选态（修「勾着却提示没勾」，2026-09-21）

用户原话：

> 「打开附加费界面和同步到渠道界面多选需要清空，因为选择的值已经清空了，这时候虽然勾选了但是还是会提示请勾选」

### 根因

两个抽屉改用内置勾选列时传了 `:row-config="{ keyField: '_id' }"` —— vxe 会**按 `_id` 记忆勾选态**：数据重新取数后，只要行 `_id` 相同，**勾选会被自动恢复**；而业务代码只清空了 JS 侧的 `checkedRows`（`@selection-change` 回传值）⇒ **视觉勾选态与 `checkedRows` 不一致** ⇒ 校验读 `checkedRows` 判空 ⇒ 误报「请先勾选」。

### 修复（复用 `Table` 既有 `setAllCheckboxRow` expose，未改公共组件）

- `CarrierFeeExtDrawer.vue`：新增 `const tableRef = ref<InstanceType<typeof Table> | null>(null)` + 模板 `ref="tableRef"`；`reload()` 改为 **先 `checkedRows = []` → `await tableRef.value?.setAllCheckboxRow(false)` → `await getData()`**；
- `CarrierFeeExtSyncDrawer.vue`：同样新增 `tableRef`；`loadChannels()` 开头**先 `await tableRef.value?.setAllCheckboxRow(false)`** 再做 `rows = []` / `checkedRows = []` 与取数。

> **顺序关键**：必须先清 vxe 勾选、再取数；顺序颠倒的话取数后 vxe 又会按 `_id` 把旧勾选恢复回来。
> `setAllCheckboxRow(false)` 会触发 `checkbox-all` ⇒ `Table` emit `selectionChange` ⇒ `handleSelectionChange` 把 `checkedRows` 置空 ⇒ 视觉与数据天然同步。
