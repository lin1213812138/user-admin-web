# 基础配置接入公司接口（详情 + 修改）

> 日期：2026-09-17
> 触发语：用户贴 tms-user `CompanySchema` ——「这是基础配置的字段，这个只要接一个详情和修改的接口就可以」

## 1. 需求与澄清

**原始需求**：基础配置页面对接后端公司接口（详情 + 修改）。

**澄清确认**：

| 问题                 | 用户选择                                                                                                       |
| -------------------- | -------------------------------------------------------------------------------------------------------------- |
| 表单字段范围         | **补齐全字段**：现有 9 项 + Schema 里 8 个业务规则项                                                           |
| 员工登录 / 客户登录  | **文本输入**（Schema 为 String，语义 = 登录地址 / 入口，不再用开关）                                           |
| LOGO 上传            | **页面内自定义上传**（FormWrap `type: 'custom'` 插槽 + `/upload?dest=2`），公共 FormWrap 组件零改动            |
| 布局（用户补充截图） | 两张卡片：上「基本信息」、下业务规则卡片（三列，标题后由用户改为「系统控制」）；底部按钮居中、文案「提交修改」 |

## 2. 后端契约（读 tms-user 源码核对）

| 用途 | 接口                  | 说明                                                                                                                                                                                                                            |
| ---- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 详情 | `POST /company/get`   | 无参，返回整份 Company 文档（`ret` 即文档）；老文档字段可能缺省                                                                                                                                                                 |
| 保存 | `POST /company/save`  | ajv 校验必填 `name/sysName/address/web/logoUrl`（string 类型）；剔除 `status/expireDate/sysVersion/authModules/authApis`（属 `/admin/update` 授权管理），其余字段原样透传 `commonSave`（单文档 `findOne({})` 更新，无需 `_id`） |
| 上传 | `POST /upload?dest=2` | form-data 字段名 `file`，返回 `{ name, size, url }`（静态资源地址，写入 `logoUrl`）                                                                                                                                             |

## 3. 字段映射（model 直接用后端字段名）

| 界面                                      | 后端字段                                         | 控件                                                        |
| ----------------------------------------- | ------------------------------------------------ | ----------------------------------------------------------- |
| 公司名称 / 公司地址 / 公司网址 / 系统名称 | `name` / `address` / `web` / `sysName`           | input / textarea，必填（与后端 ajv 一致）                   |
| 联系电话 / 默认出发地                     | `phone` / `startPlace`                           | input                                                       |
| 员工登录 / 客户登录                       | `userWeb` / `customerWeb`                        | input（字符串语义）                                         |
| 公司LOGO                                  | `logoUrl`                                        | NUpload `image-card`（内置缩略图 + hover 预览/删除，必填）  |
| 应收总费用取整规则                        | `feeTotalStrategy`                               | select：0 不取整(2位小数) / 1 取整(抹零) / 2 取整(四舍五入) |
| 运费允许为负数 / 重量允许为零             | `feeTotalCtrl` / `weightCtrl`                    | select：1 允许 / 0 不允许                                   |
| 内单号允许重复 / 转单号允许重复           | `noCtrl` / `channelNoCtrl`                       | select：1 允许 / 0 不允许                                   |
| 出库重小于入库重量不提示                  | `outInWeightDiffNotify`                          | select：1 提示 / 0 不提示                                   |
| 出库重量差提示阈值 / 退件重量差提示阈值   | `outWeightDiffNotify` / `returnWeightDiffNotify` | 数字输入（KG，空值提交 0）                                  |

不展示 `status/expireDate/authVersion/authModules/authApis`（后端 save 会剔除）。

## 4. 实施内容

- **类型**：新增 `typings/api/company.d.ts`（`Api.Company`：`FeeTotalStrategy` / `SaveParams` / `Info`（extends Partial<SaveParams>，兼容老文档缺省）/ `UploadResult`）。
- **service**：新增 `service/api/company/index.ts`（`fetchGetCompany` / `fetchSaveCompany` / `fetchUploadCompanyLogo`），barrel `service/api/index.ts` 追加 `export * from './company'`；无 DEV mock（与 input-format 一致，直连真实接口）。
- **页面**：重写 `BasicConfig.vue`
  - 两张 `NCard`（卡片头复用 Form section 同款竖条样式）+ 两个 `NFormWrap` 实例共用同一 model，提交时两个都 `validate`；
  - `mode="edit"`、`:disabled="loading || saving"`；底部按钮居中「提交修改」，操作条 `py-8px` + `-mb-16px` 抵消 VerticalTabLayout 内容区 `p-16px` 实现贴底（改前为 `p-12px`，被用户反馈「高度太高」）；
  - 上传：`type: 'custom'` 项（key=`logoUrl`）+ `#logoUrl` 插槽放 `NUpload`（`list-type="image-card"` + `:max="1"` + `custom-request` 调 `/upload?dest=2`；缩略图、预览、删除全部用 naive 内置交互，`max=1` 时已有图片会**自动隐藏「+」上传块**（替换 = 先删再传）；`@update:file-list` 收敛列表并同步 `logoUrl`，`onFinish` 无参故把地址写在 `file.url` 上再结束）；
  - 回填：`onMounted` → `fetchGetCompany()` 逐字段 `??` 兜底；保存成功 `$message.success` + 重新拉取回填；
  - 数字阈值字段允许 `null`（NInputNumber 清空），提交时统一 `?? 0`。
- **i18n** 三处同步（zh-cn / en-us / app.d.ts）：`common.submitModify`、`basicConfig.infoCard` / `ruleCard` / `rule.*`（8 项）/ `option.*`（7 项）；`ruleCard` 文案 = 「系统控制」。

**踩坑（FormWrap 的 `slot` 语义）**：`FormItemConfig.slot` 表示「操作区按钮项」，带 `slot` 的项会被 `fieldItems` 过滤掉（不渲染进表单网格、不生成必填规则、不参与校验）。自定义单元格只能写 `type: 'custom'`，插槽名自动取 `item.key`。首版误传 `slot: 'logoUrl'`，导致 LOGO 项跑到表单底部操作区且无 label / 星号 / 校验；删除该字段后恢复正常。

## 5. 验证

- `pnpm typecheck` exit 0；`pnpm lint` 0 error（仅 `link.vue` 既有 2 warning）；`pnpm fmt` 已跑。
- playwright 连 dev（9111）+ 真实后端（192.168.2.105:15001）实测：
  - 渲染：两张卡片（基本信息 / 系统控制）、基本信息 9 项含必填星号、业务规则 8 项三列布局、6 个下拉文案正确、底部「提交修改」居中；
  - 必填校验：空表单提交 → 公司名称 / 公司地址 / 公司网址 / 系统名称 提示「必填」；LOGO 删除后提交 → 提示「公司LOGO必填」；
  - 详情回填：`/company/get` 数据回来后 17 个字段全部正确回显（含 LOGO、6 个下拉文案、2 个数字）；
  - LOGO 上传：上传 `public/logo.png` → 返回 `http://192.168.2.105:15001/upload/company/<uuid>.png` 并在缩略图即时回显；hover 缩略图出现预览/删除图标，点删除后列表清空、上传按钮保留；
  - 保存：UI 点击「提交修改」→ 库中 `updateDate` 更新；改写「默认出发地」→ 提交 → 库中 `startPlace` 随之变化（验证后已改回原值）；
  - console 0 errors（仅既有 1 条 Vue `injection "Symbol(router)" not found` warning）。
- **测试数据**：测试环境原无 company 记录；实测过程写入 1 条（牛迈物流 / 牛迈物流专线系统 / 测试值 / logo 指向测试上传的图片）。后端无删除接口，如需清理可在页面上覆盖为真实信息或直接在库中删除该文档。
