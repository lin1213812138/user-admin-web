## 后端契约（已核实 tms-user 最新代码，本次零改动）

- **模型** `lib/common/models/channel-fee-ext.js`：`refId` 注释扩为「收发派渠道、**承运网络**」；新增 `syncId`（同步承运网络的附加费：记录来源加收 `_id`）。
  ⇒ 承运网络附加费与渠道加收**同一张表**：承运网络侧 `refId = 承运网络 _id`（无 `syncId`），渠道侧副本 `refId = 渠道 _id` + `syncId = 来源加收 _id`。
- **路由** `lib/api-v1-web/channel-fee-ext/index.js`：
  - `POST /channel-fee-ext/create`（validate `refId` 36 位 + `name`，同 `refId` 内重名 103401）；
  - `POST /channel-fee-ext/query`（`{ page, size, keyword, where }`，`where.refId` 过滤归属）；
  - **`POST /channel-fee-ext/sync`**（validate `ids: requireStrArr` + `refIds: requireStrArr`）；
  - `POST /channel-fee-ext/delete` 已改 `{ ids: string[], sync?: boolean }`（`sync` 为真时连带删除 `syncId ∈ ids` 的渠道副本；本轮未用）。
- **同步服务** `lib/services/channel-fee-ext.js#syncList`：

```js
const { ids, refIds } = body; // ids = 源加收；refIds = 目标渠道
let feeExtList = await this.model.find({ _id: ids });
feeExtList = map(feeExtList, item => item.toJSON());
const refFeeExtList = concat(
  ...map(refIds, refId =>
    map(feeExtList, item =>
      omit(
        assign({}, item, {
          refId, // 副本归属渠道
          syncId: item._id, // 记录来源加收
          creator: user.name,
          creatorId: user._id
        }),
        ['_id', 'createDate', 'updateDate']
      )
    )
  )
);

await this.model.deleteMany({ refId: refIds, syncId: ids }); // 幂等：覆盖同来源旧副本
await this.model.insertMany(refFeeExtList);
```

- **自动带出**：`lib/services/channel.js` / `channel-out.js` 的 `create` / `batchCreate` / `update`（`carrierId` 变更时）会调 `carrierService.batchSaveFeeExtList`，把该承运网络的附加费自动复制给渠道（带 `syncId`）。
- **关联渠道查询**：`/channel/query`、`/channel-out/query` 均走 `queryCommon` 透传 `where` ⇒ `where.carrierId` 过滤有效（后端 `setSite` 会额外追加当前用户站点 `where.siteIds`，属页面既有行为）。
