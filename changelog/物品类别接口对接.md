# 物品类别接口对接

日期：2026-09-19

## 背景

用户提供 `ProductGroupSchema`（name 类别名称必填 / sensitive 敏感货 / charged 带电 / danger 危险品 / note 说明 / isDefault 是否默认 / status，均为 0-否1-是）+ 老系统截图（列：序号/类别名称/说明/是否敏感货/是否带电/是否危险品/是否默认/状态，搜索仅「输入类别名称搜索」），要求接入真实接口。

## 定位

- 后端 `tms-user/lib/api-v1-web/product-group` 已有 `/product-group/query|get|create|update|delete` 路由，契约同 problem-group：
  - `query` → `queryCommon`，service 固定 `keywordFields: ['name']`；读 `page`；status 过滤放 `where`
  - `delete` → `batchDeleteCommon`，校验 `ids: string[]`
  - `create/update` 校验 `name`；service `uniqField: 'name'`；`setDefault`（isDefault=1 时后端自动清其他默认）
- 前端 `GoodsCategory.vue` 原走 `MasterDataArchive` mock（code/name/remark），与 Schema 不符（无 code）。

## 方案（沿用 problem-category 同款范式）

1. `data-manage-archive`：新增 `fetchGetProductGroupList / fetchCreateProductGroup / fetchUpdateProductGroup / fetchDeleteProductGroup`（list 显式 `current→page` + status 拼 `where`）；`archiveApiMap['goodsCategory']` 切真实；删 goodsCategory mock 工厂；注释真实 5→6、mock 7→6。
2. `GoodsCategory.vue` 按截图对齐：列 = 类别名称(detail) + 说明 + 是否敏感货 + 是否带电 + 是否危险品 + 是否默认（布尔列经 slot 渲染 是/否，用 `common.yesOrNo`；status/createTime 自动追加）；搜索仅关键字；表单 = 类别名称(必填) + 敏感货/带电/危险品/默认 4 个 switch(默认 0) + 说明(textarea)；`status` 不进表单默认 1；`createDefault` 含全部 Schema 字段。
3. 类型 `BusinessGoodsCategory` → `{ name; sensitive?; charged?; danger?; note?; isDefault? }`（0|1，去 code）。
4. i18n `business.goodsCategory` 补 `name/note/sensitive/charged/danger/isDefault/namePlaceholder`（zh/en），`App.I18n` 同步。

## 结果与备注

- typecheck 0 / lint 0 error（link.vue 2 既有 warning）/ fmt / build:test 通过。中途修掉模板引用 `Api` 命名空间触发的 vue/no-undef-properties warning。
- 表单 switch 未加 checkedText/uncheckedText（沿用 NSwitch 默认样式）；「是否默认」置 1 时由后端 `setDefault` 清其他默认，前端无需额外处理。
