# 标签设计切换元素后输入框残留旧值

## 现象

属性面板选中元素 A（文本，标题名称=「批次」、绑定字段=`batch`）后，再切换到另一个未配置过标题/字段的新建基础元素：

- 「标题名称」仍显示「批次」、「绑定字段」仍显示 `batch`；
- 而底部绑定信息条正确显示「字段: 未绑定」；
- 「文本」框则正常显示为空（placeholder「请输入」）。

显示值与元素真实数据不一致。

## 根因

三步叠加：

1. **model 中键值为 `undefined`**：`property-panel.vue` 的 `buildModel()` 用 `...el.options` 浅展开构建 model。新建基础元素时 `defaultOptionsFor` 写入的是 `field: seed.field`、`title: seed.title`，而基础元素的 seed 没有这两个字段 → 值为 `undefined`（JSON 序列化往返后键甚至直接消失）。于是 `model.title` / `model.field` 为 `undefined`。

2. **naive-ui 对 `undefined` 走非受控分支**：`NInput` 内部用 `useMergedState(controlled, uncontrolled)` 合并值——`value === undefined` 被视为「未受控」，回落到组件实例内部的 uncontrolled 值（即上一个元素时用户输入的内容）。`''` / `null` 都是合法受控值，只有 `undefined` 会触发回落。

3. **组件实例被 Vue 复用**：切换元素前后 `dataItems` 结构相同、`NGi :key="item.key"` 不变，`FormWrap` / `NCollapseItem` / `NInput` 实例整体复用，内部 uncontrolled 状态自然残留。

对照组印证：

- 「文本」框正常清空 → `text` 键恒有值（`seed.sample ?? ''` → `''`），始终受控；
- X/Y/宽/高正常 → 恒为数字，始终受控。

## 隐患

残留输入框并非只读：此时在其中输入任意字符，`v-model` 会把值写进 `model.title` / `model.field`，深度 watch 再经 `updateElementOptions` 全量写回新元素 options——上一个元素的数据会污染新元素。

## 修复实施（方案 A，2026-09-12 用户确认）

`buildModel()` 预置面板绑定键的受控空值（`title/field/text/value/src` → `''`），保证任何元素下这些键都非 `undefined`、始终受控。

**二次修正（同日）**：第一版把空串预置放在 `...el.options` **之前**，被 `defaultOptionsFor` 显式写入的 `title: seed.title`（值为 `undefined` 的键）在展开时覆盖回 `undefined`（`{ title: '', ...{ title: undefined } }` → `{ title: undefined }`），用户实测仍残留。修正：展开 options **之后**再对绑定键执行 `base[key] ??= ''` 补空。方案 B（`:key="selectedId"` 强制重建）未采用，保持切换零重挂载。

教训：**JS 对象展开会拷贝显式为 `undefined` 的属性**，「前置默认值 + 后置展开」的惯用法对含 undefined 键的对象会失效；默认值兜底必须放在展开之后（`??=`）。
