# 报价设置页「渠道上下文」去 URL 明文化

> 日期：2026-09-20 ｜ 状态：已实施，待手动冒烟 ｜ spec：`docs/superpowers/specs/2026-09-20-报价设置渠道上下文去明文化-design.md`

## 背景

> 用户原话：「这个不要明文啊，太危险了」（截图：地址栏 `/quote-setting?channelId=b1b7f9ac-…&name=测试收货渠道&tab=zone`，红框圈住整段 query）

即：渠道 id 与渠道名称不应明文挂在 URL 上（会留在浏览器历史、截图与分享链接中）。

## 方案确认（用户口径）

- 采用 **方案 B：sessionStorage 传递**（URL 彻底不含渠道信息）；
- **保留 `tab=zone`**（纯展示态、无业务信息，tab↔URL 同步逻辑不动）；
- 接受方案 B 的代价：浏览器「后退」到上一渠道的报价设置页时，展示**最后进入的**渠道（F5 刷新不受影响）。

## 实施

1. `src/typings/storage.d.ts` — `StorageType.Session` 新增 `quoteSettingContext: { channelId, channelName } | null`，走项目既有 `sessionStg`（`src/utils/storage.ts` 的 `createStorage` 封装），不裸写 `window.sessionStorage`。
2. `src/views/channel-quote/receive/index.vue` — 列表页 `handleQuoteSetting(row)`：跳转前 `sessionStg.set('quoteSettingContext', { channelId: row._id, channelName: row.name })`，随后 `routerPushByKey(...)` **不再带 query**。
3. `src/views/channel-quote/receive/modules/quote-setting/index.vue` —
   - `channelId` / `channelName` 由 `computed(route.query)` 改为 `ref('')` + `loadChannelContext()`；
   - `loadChannelContext()` 在 setup 首调一次，并挂 `onActivated`（页签 keep-alive 复用实例：从列表再次点入其它渠道时重读，保证展示当前渠道）；
   - 无上下文（新标签页直开 / 书签 / 分享链接）→ 沿用既有引导空态 `quoteSetting.noChannel`；
   - tab↔URL 双向同步、keep-alive 命名、5 个分页面板零改动。

## 行为变化对照

| 场景                 | 改造前                  | 改造后                                |
| -------------------- | ----------------------- | ------------------------------------- |
| 地址栏               | 含 `channelId` + `name` | 仅 `?tab=xxx`（或空）                 |
| F5 刷新              | 上下文来自 URL          | 上下文来自 sessionStorage，**仍可用** |
| 新标签页直开 URL     | 显示 URL 里那个渠道     | 引导空态                              |
| 分享链接给别人       | 对方点开即见渠道信息    | 对方点开是引导空态                    |
| 浏览器后退到上一渠道 | 显示对应渠道            | 显示最后进入的渠道（已知取舍）        |

## 验证

- `pnpm typecheck` exit 0（`sessionStg` 键值类型对齐）。
- `npx oxlint` / `npx eslint`（列表页 + 报价设置页）：0 warnings 0 errors。
- `npx oxfmt --check`（含 `storage.d.ts`）：通过。
- 待用户冒烟：从列表点「报价设置」→ 地址栏无 `channelId`/`name`、渠道名正常展示；F5 后仍正常；新标签页直开 → 空态提示。
