## 字段映射项结构改造：fields 改 { key, label, span }

- 起因：用户问「一行占几个是需要配置的吗」——答案是**否**，`FieldMapping.vue` 里 `NGrid :cols="3"` 硬编码，`navGroups.fields` 是 `string[]`，`modelValue` 存的是 label 文案本身。
- 用户确认的三项决策：**span 用 24 栅格**（与 `FormItemConfig.span` 同语义，缺省 8）、**modelValue 存 key 不存 label**、**label 本轮继续硬编码中文不 i18n**；`navGroups` **6 个页面各自保留**不抽共享。
- 类型放同目录 `setting/components/field-mapping-config.ts`，`FieldMapping.vue` 用 `export type { ... } from './field-mapping-config';` 重导出 —— 这是 `Form/index.vue:8` 的既有模式（`<script setup>` 里 `export type` 合法，编译期剥离），页面导入路径不变。
- **关键坑：NGrid 改 `:cols="24"` 后，`x-gap` 会变成 23 个 column-gap（12px×23≈276px）把内容挤没** → 必须 `:x-gap="0"`，列间距改由 `NGridItem` 内容的 `pr-12px` 提供。`y-gap` 不受影响（行数不随列数膨胀）。
- 用 cols=24 而非「cols=3 + span/24\*cols 换算」，是为了绕开非整除的精度丢失。
- 迁移范围：`InputFormat.vue`（5 组 21 字段，10 条 mock + 30 条生成 mock 的 fields 改 key）、`ExportFormat`/`StationScan`/`InitData`/`NotificationConfig`（各 2 组 7 字段占位数据）、`PrintFormat.vue`（FieldMapping 已注释但常量同步改，防解注释时类型不匹配）。
