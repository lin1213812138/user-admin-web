## 解释：为什么 `pnpm dev` 一启动 `src/router/elegant/routes.ts` 就被"格式化/重排"

- 根因不是格式化工具（oxfmt/prettier 只会调空白，不会重排对象/数组顺序），而是 **elegant-router 的 Vite 插件在每次 dev/build 启动时全量重新生成并重写这 4 个文件**：`routes.ts`、`imports.ts`、`transform.ts`、`typings/elegant-router.d.ts`。
- 插件注册点：`build/plugins/router.ts` 的 `setupElegantRouter()`（`ElegantVueRouter`，来自 `@elegant-router/vue/vite`，本质是 unplugin）。源码（node_modules/@elegant-router/vue/dist/shared/vue.adf39a67.mjs）可见它扫描 `src/views` → magicast 解析既有 `generatedRoutes` 合并 meta → 用 **prettier**（printWidth120/tabWidth2/单引号/无尾随逗号）格式化后 writeFile 覆盖写盘；dev 还 watch views 目录，新增页面也会触发。
- 输出顺序以"本次扫描到的页面顺序"为准（不保留手工排的顺序）→ 所以昨天手工/旧版把 data-manage 放后面，今天启动 dev 后被写回生成器的规范顺序（data-manage 提前）。`nonMenuRoutes`/`menuRoutes`/helper 等附加导出由 AST 保留，不会丢。
- 时间证据：routes.ts 最后提交 2026-09-02 20:15，磁盘 LastWriteTime 2026-09-03 09:23 —— 即今早用户/环境起了一次 dev，生成器重写产生 uncommitted diff（git status 可见仅 routes.ts modified，imports.ts/transform.ts 无 diff）。
- 结论：`src/router/elegant/**` 手改无意义，每次启动都会被覆盖；想控制菜单顺序/图标/标题用 `build/plugins/router.ts` 的 `onRouteMetaGen`（routeIcons/routeOrders）或 `customRoutes` meta。

## 表格 loading 流畅化（spinner 硬切 / 高度跳动 → fade 遮罩）

## 修复：系统设置点开卡死（路由重定向死循环）

- 现象：点左侧「系统设置」页面卡死（白屏/无响应），vue-router 报重定向循环。
- 根因（踩坑，重要）：elegant-router 的 `transform.ts`（自动生成）会给**任何有 children 的路由**自动加 `redirect` 指向第一个子路由。此前系统设置的 7 个 tab 子页放在 `setting/<name>/index.vue`，被自动生成为 `system-manage_setting` 的 7 个子路由，父路由因此被加 `redirect` 到 `export-format` 子路由；而当时 `guard/route.ts` 又有「`system-manage_setting_*` 一律 replace 回父路由」的规则 → 父子互指，无限循环。
- 修复（用户确认方案「重构目录」）：把 7 个子页从自动路由目录移出到 `setting/modules/`（纯组件，elegant-router 默认忽略 `modules/`，不再生成子路由），`system-manage_setting` 变叶子路由、无自动 redirect，彻底消除循环。同步删除 `guard/route.ts` 里已失效的 `system-manage_setting_*` 重定向规则，并清理 `build/plugins/router.ts` 的 `hiddenRoutes` 与两份 locale 里 7 个失效的 `route.system-manage_setting_*` i18n 键（否则 typecheck 报 `RouteKey` 不存在）。
- 关键经验：**`sa gen-route` 是交互式「新建路由」脚手架，不是全量重新生成**；全量重生成由 `pnpm dev`/`build` 的 `@elegant-router/vue/vite` 插件完成。本机 WebStorm `coding-copilot` 插件的 `node-safe-delete-shim` 会拦截 vite 的 `rm`（`--file parameter is required`）导致 dev 启动失败——但插件在配置阶段已经写了 `routes.ts` 等生成文件（本次它把子路由删到只剩 input-format 一节点，属部分写盘，需手动把 `routes.ts` 残留 `children` 块删干净）。手动改 `src/router/elegant/**` 是允许的临时同步手段（下次 dev 会被覆盖，属于预期）。
- 验证：`pnpm typecheck` 0 error。文档 `changelog/系统设置点开卡死-路由重定向死循环修复.md` + AGENTS_CHANGELOG.md 索引已更新。
