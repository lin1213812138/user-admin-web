## 解释：为什么 `pnpm dev` 一启动 `src/router/elegant/routes.ts` 就被"格式化/重排"

- 根因不是格式化工具（oxfmt/prettier 只会调空白，不会重排对象/数组顺序），而是 **elegant-router 的 Vite 插件在每次 dev/build 启动时全量重新生成并重写这 4 个文件**：`routes.ts`、`imports.ts`、`transform.ts`、`typings/elegant-router.d.ts`。
- 插件注册点：`build/plugins/router.ts` 的 `setupElegantRouter()`（`ElegantVueRouter`，来自 `@elegant-router/vue/vite`，本质是 unplugin）。源码（node_modules/@elegant-router/vue/dist/shared/vue.adf39a67.mjs）可见它扫描 `src/views` → magicast 解析既有 `generatedRoutes` 合并 meta → 用 **prettier**（printWidth120/tabWidth2/单引号/无尾随逗号）格式化后 writeFile 覆盖写盘；dev 还 watch views 目录，新增页面也会触发。
- 输出顺序以"本次扫描到的页面顺序"为准（不保留手工排的顺序）→ 所以昨天手工/旧版把 data-manage 放后面，今天启动 dev 后被写回生成器的规范顺序（data-manage 提前）。`nonMenuRoutes`/`menuRoutes`/helper 等附加导出由 AST 保留，不会丢。
- 时间证据：routes.ts 最后提交 2026-09-02 20:15，磁盘 LastWriteTime 2026-09-03 09:23 —— 即今早用户/环境起了一次 dev，生成器重写产生 uncommitted diff（git status 可见仅 routes.ts modified，imports.ts/transform.ts 无 diff）。
- 结论：`src/router/elegant/**` 手改无意义，每次启动都会被覆盖；想控制菜单顺序/图标/标题用 `build/plugins/router.ts` 的 `onRouteMetaGen`（routeIcons/routeOrders）或 `customRoutes` meta。

## 续：用户诉求 = 启动可加 order 但不得打乱已配置的路由块顺序（结论）

- 已翻插件选项类型（vue.9d9f94c9.d.ts）与合并源码（vue.adf39a67.mjs 的 N/F）：elegant-router **没有"保留旧块顺序"开关**；启动全量重写，块顺序 = 生成器按路由名逐层字典序；meta 合并只"填空缺、不覆盖已有 key"。

- 用户偏好：不允许把 routes.ts 的路由块顺序改乱；禁止手改/手排 elegant/\*\*；生成器规范版本提交一次后幂等无 diff。

## archive-switch 两个回归 bug 修复（库位加载不出来 + 横向滚动条）

## 表格 loading 流畅化（spinner 硬切 / 高度跳动 → fade 遮罩）

- 原实现：`src/components/Table/table.vue` 用 `<NSpin :show="loading" class="h-full w-full" :content-style="{height:'100%'}">` 直接包裹 `vxe-table`。问题：naive-ui NSpin 的 `show` 切换是**硬显隐 spinner（无淡入淡出）**，且 loading 期间 vxe-table 被包在 NSpin 内、高度易跳动 → 用户反馈「出现/消失生硬」。
- 新实现：让 `vxe-table` **始终渲染**（高度固定不跳），外层 div 加 `relative`；loading 显隐改用独立遮罩层 `<Transition name="fade"><div v-if="loading" class="absolute inset-0 z-10 flex items-center justify-center bg-white/60"><NSpin size="large" /></div></Transition>`。复用全局 `styles/css/transition.css` 的 `.fade-*`（`opacity 0.3s ease-in-out`）做平滑淡入淡出。spinner 居中、表格高度稳定、切换顺滑。
- 涉及全项目所有 Table（通用组件），影响面大但纯样式/结构改动。`pnpm typecheck` 0 error（仅 vxe-table 第三方 slot 类型提示 `#trigger/#empty` 的预存 warning，无害）。

## 表格 loading 最终决策（回退到 vxe-table 自带）

- 用户最终拍板：**表格 loading 直接用 vxe-table 自带的 `:loading`**，撤销前面用 NSpin + fade 遮罩的方案。理由：vxe-table 原生 loading 遮罩自带平滑淡入淡出、与表格高度/滚动条协同更好，比自己包 NSpin 更顺。
- 落地（src/components/Table/table.vue）：`vxe-table` 加 `:loading="loading"`，去掉外层 `relative` 与结尾的 `<Transition name="fade">` 独立遮罩层；`loading` 仍由 `useVxeTable` 的 `startLoading/endLoading` 控制（mock 异步化 400ms 让其真实可见）。`NSpin` 在 Table 内不再使用（全局注册，无显式 import，删 usage 即可）。`pnpm typecheck` 0 error。
- 结论性约定：本项目通用 Table 的 loading 统一走 vxe-table `:loading`，不要另包 NSpin/自定义遮罩。

## 搜索栏展开/收起卡顿修复

- 现象：搜索栏点图标展开/收起时卡顿。
- 根因：`search-bar.vue` 初版用 `<Transition>` + JS 钩子逐帧设 `node.style.height = scrollHeight`，动画 `height` 每帧触发整张 `NFormWrap`（含多个 input/select）的布局重排 → 字段多时掉帧。
- 修复：改为 `grid-template-rows: 1fr ↔ 0fr` + `overflow:hidden` 裁剪（`display:grid` 外层，单 grid 子 `.search-bar__clip` 包 `NCard`）。只改变网格行高、内部表单不再被反复重排，过渡平滑无卡顿。`NCard` 始终挂载、收起时仅被裁剪（无空盒、无 v-if 卸载）。`typecheck` 0 error、`lint` 0 error。
- 注意：`grid-template-rows` 的 fr 动画需现代浏览器（Chromium 107+），本项目目标浏览器满足。

## 搜索栏卡顿二次修复（grid 仍卡 → fade）

- 反馈：换 grid-template-rows 后仍"有点卡"。根因：`grid-template-rows` 0fr↔1fr 虽不逐帧设 height，但每帧仍触发整张 `NFormWrap`（NGrid 响应式 + Naive input/select）重新布局 → 字段多掉帧。
- 修复：彻底不动画布局属性，只动画 `opacity` + `transform: translateY(-8px)`（合成器属性，GPU，不重排）；`display` 切换由 `v-show` 在点击瞬间完成一次，`Transition name="search-fade"` 0.2s 仅做淡入淡出+轻位移。`NCard` 经 `v-show` 常驻、收起 `display:none`。`typecheck`/`lint` 0 error。
- 结论性约定：本项目任何"展开/收起"类动画，凡含表单/表格等重内容的面板，**只用 opacity/transform 做淡入淡出，禁止动画 height 或 grid-rows**（两者都会逐帧重排、必卡）。

## 修复：`pnpm release` 提交被 pre-commit 钩子拦截（git diff --exit-code 失败）

- 根因：`sa release` 用 bumpp，`execute`（`pnpm sa changelog`）重生成 `CHANGELOG.md` 时 `@soybeanjs/changelog` 在贡献者段加了空行，`oxfmt` 会删它；`git commit -A` 触发的 `pre-commit` 钩子里 `pnpm fmt` 删空行后，`git diff --exit-code` 检测到未暂存改动 → `git commit` 退出 1 → bumpp 抛错（日志里那段 CHANGELOG.md diff 即现场）。不是 commit-msg 校验问题（正则能匹配 `chore(projects): release v%s`）。先 `pnpm fmt` 再 release 没用，因为 release 会重新生成 changelog。
- 修复：把 `packages/scripts/src/commands/release.ts` 的 bumpp `execute` 由字符串改为函数，先跑 `pnpm sa changelog` 再补一句 `pnpm fmt`，让 changelog 在 bumpp 暂存前就 fmt 干净，钩子里的 fmt 变空操作。bumpp `execute` 字符串含 `&&` 会被 tokenizeArgs 误拆，必须用函数式 execute 分两次 execCommand。`sa` 由 tsx 直跑 scripts，改完即时生效。
