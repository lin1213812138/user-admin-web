## 标签设计器（label-designer）属性面板表单溢出 NCard — 诊断结论

- 现象：`property-panel.vue` 的「位置与尺寸」等卡片内，X/Y 等输入框超出 NCard 边界。
- 根因（已用 naive-ui 源码 + 纯 CSS 复现页验证）：`FormWrap`（src/components/Form/index.vue）渲染 `NGrid :cols="24" :x-gap="16"`，naive NGrid 是真 CSS Grid（`repeat(24, minmax(0,1fr))` + `column-gap:16px`），24 条轨道之间产生 **23 个 gap = 368px 固定开销**。属性面板 300px、卡片内容区仅 ~250px < 368px → 轨道全部被压成 0 宽，但每个 `span=12` 的 NGi 仍跨越 11 个内部 gap ≈ 176px，按 176px 一格画出卡片 → 溢出。
- 关键事实：
  - NGi（GridItem.mjs）渲染出的 div **没有 class**，`:deep(.n-grid-item)` 是无效死代码；要选中它需用 `:deep(.n-grid > div)`。
  - 溢出与控件宽度无关（控件已 w-full/min-width:0），任何控件级 max-width 都治不了；把字段改 span=24 也没用（gap 开销与 span 无关）；面板需 ≥~430px 才不塌缩。
  - 不改布局结构的唯一解：调小 `grid-x-gap`（8 → 开销 184px < 250px，格子 ≈121px 正常两列）。
- naive NGrid `responsive="self"` + `item-responsive` 已由 FormWrap 传入，span 支持容器级断点串，但对 cols=24 的 gap 塌缩无帮助。
- 用户反馈：「不要改布局，跟这个没有关系」——用户不认可从布局/gap 方向修，方案待与用户对齐后实施。
- 临时复现页：`.codebuddy/tmp/grid-overflow-repro.html`（已删除）。

## 标签设计器拖动卡顿 — 根因定位与方案（待确认）

- **naive Modal 结构事实（源码 modal/src/styles/index.cssr.mjs 实证）**：`.n-modal-container` fixed h0 w0 flex；`.n-modal-body-wrapper` fixed inset0 **overflow:visible（默认不可滚！超高内容直接溢出视口）**；`.n-modal-scroll-content` min-height:100%+flex；卡片 `.n-modal` `align-self:center; margin:auto`——margin auto 天然「矮时居中、超高时顶对齐」。给该弹窗做整体滚动必须覆盖 wrapper overflow 并隐藏滚动条视觉；间隔 padding 要放 scroll-content（滚动内容内）而非 wrapper。
- CSS 教训链：naive 类名横/双下混用必须查源码；`flex:1 1 0` 在高度自适应容器压扁内容须 `1 1 auto`；`justify-center + overflow-auto` 溢出左裁剪 → `w-fit mx-auto`。**用户偏好定论：无底色块、无可见滚动条、弹窗永不限宽限高**。
- **重大教训（本次布局崩坏根因）**：naive 类名横线/双下划线混用——`n-card-header`（横）、`n-card__footer`/`n-card__action`（双下划线）、**`n-card-content`（横，不是 n-card\_\_content）**。凭感觉写 `.n-card__content` 未命中 → flex/overflow 全落空 → footer 被顶出卡片漂在 mask 上。**覆盖 naive 内部类名前必须 Select-String 查 node_modules 源码确认**。header/footer 加 `flex-shrink:0` 防压缩。
- **二次修复教训**：内容区 `flex: 1 1 0` 把纸张压成一条——**容器高度 auto（仅 max-height 上限）时，basis 0 使子项贡献 0 高**；自适应容器里的弹性子项必须 `flex: 1 1 auto + min-height:0`（正常随内容撑开、触顶才收缩滚动）。`flex:1` 只适用于容器高度确定的场景（h-full）。
