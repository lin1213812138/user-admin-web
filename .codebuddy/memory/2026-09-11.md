## 打印设计属性面板：根因调查（原「自定义 Naive 面板」方案不成立）

- 现象：选中元素后右侧面板始终显示「未选中元素」空态（用户截图）。
- 根因1（事件名用错）：hiprint 元素点击选中时触发的是 `hinnn.event.trigger(template.getPrintElementSelectEventKey(), { printElement })`，事件名 = `PrintElementSelectEventKey_<id>`；而 `BuildCustomOptionSettingEventKey_<id>` 只用于纸张/页码等全局设置。`use-hiprint.ts` 的 `onElementSelect` 误监听后者 → 永远收不到选中事件。（附注：元素 click 有 500ms 去抖；`clearSettingContainer` 仅在删除元素时 trigger，点空白不会清空。）
- 根因2（方案硬障碍）：hiprint 属性字段（option item）是**自渲染对象**——`PrintElementOptionItemManager.getItem(name)` 返回的 item 实例**只有 `this.name`**（如 `function Qe(){this.name="maxRows"}`），控件类型/标题/下拉项全部封装在其 `createTarget()/setValue()/getValue()` 方法内部；config 中 option 定义也只有 `{name, hidden}`，无 type/title。因此**无法自动把字段映射为 Naive 控件**，原「用 Naive 组件重建属性面板」方案技术上不成立。
- 有用事实：`element.updateOption(name, value, silent?)` 存在且可用（仅当 name 在元素支持列表内才写回并重绘）；`element.getPrintElementOptionTabs()` 不依赖 settingContainer，返回 `[{name:"基础"|"样式", list:[item,...]}]`（item 仅 name + 方法）。
- 待用户选型：①回退 hiprint 原生面板 + CSS 美化（最稳、字段零遗漏）；②Naive 折叠分组壳 + hiprint 原生控件；③手写 name→Naive 控件映射表（工作量大、可能漏字段）。

## 打印设计属性面板：最终方案 D（混合）已选定

- 用户决策：「基本元素用 Naive 控件就行，复杂字段原生兜底即可」。经进一步确认 `getConfigOptions()` 返回的是元素类型的**原始字段配置**（含 `name/type/title/options`），简单字段（text/textarea/number/select/checkbox/color/image）的 `type` 与下拉项完全可得，可 Naive 重建；复杂字段（coordinate 坐标 / widthHeight 尺寸 / border 边框 / table 列配置 / 未知 type）用 hiprint 原生 `item.createTarget()` 兜底。
- **修正根因2 的不完整结论**：`getPrintElementOptionTabs()` 返回的 item 单例确实只有 `name`（无法映射），但 **`getConfigOptions()` 提供 `type/options`** —— 纯 Naive 重建对简单字段可行，不必完全放弃。初判"方案硬障碍"仅针对 item 单例路径，需区分两条 API。
- 关键 API 事实（源码验证）：`template.getPrintElementSelectEventKey()` 才是元素选中事件（修 bug 用，非 `BuildCustomOptionSettingEventKey`）；`element.getConfigOptions()` = 原始字段配置；`element.getPrintElementOptionTabs()` = 仅 item 单例（按 name 匹配复杂字段原生渲染）；`element.updateOption(name,value)` 单元素精准写回（**不调 `submitOption`**，其会批量改同类型其它选中元素）；`item.createTarget(el,el.options,el.printElementType)`/`setValue`/`getValue`。
- 当前实际状态：`index.vue` 已 `import PropertyPanel` 并使用，但 `modules/property-panel.vue` 文件**实际缺失**（git 无记录、search 找不到）→ 项目当前 broken；方案 D 需**新建**该文件修复引用。
