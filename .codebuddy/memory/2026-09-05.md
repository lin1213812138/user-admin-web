## 分配权限表格化 —— 已实现（同日，待手测）

- 抽屉实现要点（易忘）：
  - **勾选权威集合是 `checkedIds`**（不是 vxe 内部状态）。`@selection-change` 做**增量同步**：只更新当前可见行的勾选，被关键字过滤掉的行原样保留 → 否则「搜索后提交丢权限」。
  - `applyView()` 只在加载完成 / keyword 变化时调用，勾选时不重建（避免重置展开态与滚动位置）；行每次重建都是递归浅拷贝 `withChecked`，不污染 `allRows`。
  - 合并时 `children: []` → `undefined`（mock 有空数组），否则 vxe 给叶子渲染多余展开箭头。
  - 菜单名优先 `menuName`（/system/menu/list），回退权限树 `title`。
  - 取数 `Promise.allSettled`：权限树 rejected → 提示并关抽屉；菜单详情 rejected → 静默降级显示 `-`。
- **UnoCSS 坑（通用）**：`h-[calc(100vh_-_160px)]`，calc 减号两侧空格在 Uno arbitrary value 里必须写成 `_`，写 `calc(100vh-160px)` 是非法 CSS、高度直接失效。
- **eslint 坑（通用）**：同一个 `<Table>` 上多个插槽都解构 `{ row }` 会报 `vue/no-template-shadow`（"row is already declared in the upper scope"）→ 改名 `{ row: menuRow }` 消除。
- 校验：typecheck ✅ lint ✅（仅剩既有 link.vue 2 个 no-undef-properties warning）fmt ✅ build ✅（build 前先 `Remove-Item -Recurse -Force dist`）。
- 手测重点：`checkStrictly:false` + `checkField:'checked'` 的父子联动与半选是否生效；不生效则走设计里的回退（自维护 Set + setCheckboxRow + 自算半选态）。

- 定位：`en-us.ts` / `zh-cn.ts` 末尾 `export default local;` 完好，`pnpm typecheck` 与 `pnpm build` 均通过 → **源码没问题**，是 dev server 在文件被外部改写（编辑 + oxfmt 重排）时的 HMR/模块缓存竞态，Vite 缓存了写入中途的转换结果。
- 解法：先硬刷新；无效则重启 dev server，并**用 PowerShell 手动删 `node_modules\.vite`**（`Remove-Item -Recurse -Force node_modules\.vite`）再 `pnpm dev`——本机 vite 自己 rm 缓存会被 WebStorm `node-safe-delete-shim` 拦。
- 教训：改语言包/大文件时若用户 dev 正在跑，提醒其重启 dev；判断这类报错先用 typecheck/build 排除源码问题，别去改 export。

## 分配权限树「展开自动收起」修复（同日）

- 现象：展开节点后，搜索或勾选未勾菜单下的按钮（触发 `applyView` 重建 `viewRows`）时，树会自动收起；打开抽屉时也不默认展开。
- 根因：vxe 树表展开状态在 `:data` 引用整体替换时丢失；`tree-config.expandAll` / `expandRowKeys` 仅初次 mount 读取，后续 data 重建不重新应用。
- 修复：改走 **vxe 实例方法 `setTreeExpand`**。`Table` 暴露 `setTreeExpand(rows, expanded)`；抽屉 `applyView()` 后 `nextTick` 调用 `tableRef.setTreeExpand(collectExpandableRows(viewRows), true)`，把有子节点的行全部强制展开。`@toggle-tree-expand` 继续透传，用于后续记忆用户手动收起（当前每次 applyView 仍恢复全展开，可接受）。

## 操作权限列按钮过多被截断修复（同日）

- 现象：用户管理已配置 11 个按钮，但抽屉里只显示前 4 个。
- 根因：`Table` 组件默认 `:row-config="{ isHover: true, height: 40 }"` 固定行高 40px，超出内容被 `show-overflow="tooltip"` 裁掉。
- 修复：`Table` 新增 `rowConfig` prop，允许父组件覆盖；抽屉传 `:row-config="{ height: 'auto' }"`，让行高随按钮数量自适应撑高，按钮自动换行显示完整。

## 勾选菜单默认全选按钮权限（同日）

- 需求：勾选某个菜单时，该菜单下的按钮权限默认全选；取消勾选则清空。
- 实现：抽屉新增 `getButtonsByMenuId(id)`（从 `allRows` 取该菜单的 `buttons`）。在 `handleSelectionChange` 中，对「新勾选」的菜单把 `rowButtonChecks[id]` 设为该菜单全部按钮 code；对「取消勾选」的菜单删除其 `rowButtonChecks[id]`（保留搜索过滤掉的行）。`toggleCheckAll` 全选时同样给所有有按钮的菜单默认全选，取消全选则清空。用户仍可手动取消单个按钮且不被动重置（仅新勾选那一刻才默认全选）。

## 首页菜单必选不可取消勾选（同日）

- 需求：首页（`/home`，title「首页」）默认必须勾选，用户无需也不能取消。
- 识别：在 `mergeRows` 给行打 `home` 标记（`detail.routePath === '/home' || node.title === '首页'`）。
- 实现：① `checkboxConfig` 加 `checkMethod: (params) => !params.row?.home`，首页行复选框禁用；② 加载时 `findHomeIds` 收集首页 id 存入 `HOME_IDS`，把其 id 强制加入 checked set（mergeRows 初始即 checked）；③ 新增 `withHome(ids)` 在所有设置 `checkedIds` 处（loadData / handleSelectionChange / toggleCheckAll / handleButtonCheckChange）保证首页 id 始终在集合内，即使用「取消全选」也不会被移除。
- 影响：提交 `menuIds` 始终含首页；首页无按钮配置，按钮列保持为空。

## drawer 类型报错修复（同日）

- 报错：`role-permission-drawer.vue(469): error TS2322: Type 'string' is not assignable to type 'number'`，源自 `:row-config="{ height: 'auto' }"`。vxe `RowConfig.height` **类型只声明 `number`**，但运行时 `'auto'` 合法。
- 坑：`read_lints` 只跑 ESLint/oxlint，**不查 `vue-tsc` 类型**，所以此前没暴露；必须用 `pnpm typecheck` 验证。
- 修复：新增 `const autoRowConfig = { height: 'auto' } as any;`，模板改用 `:row-config="autoRowConfig"`。修复后 `pnpm typecheck` 通过（无 error TS）。

- 触发审查（drawer / table.vue / 新增 button-permissions.ts 未提交改动）。reviewer 结论：6 项需求整体对齐，无 Critical；2 个 Important 必须修，2 个 Important 属后端契约事项。
