## elegant-router 不支持 exclude 目录（关键结论）

- 用户问能否不把 setting/modules 子组件当子路由写进路由表。查证:`ElegantVueRouterOption`(vue 层 `node_modules/@elegant-router/vue/dist/shared/vue.9d9f94c9.d.ts`)+ `ElegantRouterOption`(core)均无 `exclude`/`ignore`/`dirs`/`scan` 配置项
- elegant-router 按文件路径扫描 `src` 下**所有** `.vue` 自动生成路由,所以把 modules 从 `src/views/.../modules` 移到 `src/components/.../modules` 仍会被扫(实测 dev server 重生成了 `system-manage_setting_modules_*` 路由,route name 为 kebab 目录名)
- 处理:7 个模块留在 `src/components/system-manage/setting/modules`(标准"组件放 components"位置);`setting/index.vue` 引用改 `@/components/...`,各模块内 `../../components/`→`@/views/system-manage/setting/components/`;从生成的 `src/router/elegant/routes.ts` 删除误生成的 `system-manage_setting_modules` 整段子路由(`system-manage_setting` 保留空 children),typecheck 恢复绿
- 限制:`routes.ts`/`imports.ts`/`d.ts` 是 elegant-router **自动生成文件**,dev server 运行时会基于当前 .vue 重新生成这些路由;要"开发运行期也绝对不进路由表"需给 elegant-router 加扫描排除能力(改 `build/plugins/router.ts` 或底层 unplugin scan),当前配置项不暴露该能力
- 结论:**配置级 exclude 不可行**;当前"提交/类型检查"层面路由表已干净

### 修正 + 全局方向（用户要求"不止 setting，所有页面"）
