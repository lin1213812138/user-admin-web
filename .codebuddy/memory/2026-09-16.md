## vxe 表格「不需要横向滚动也显示横向滚动条」定位 + 修复

- 用户截图（财务资料 → 结算方式）底部恒有横向滚动条，滑块约 98% 长；用户要求**必须保留 hover 浮现**交互，并选定 `--x-scrollbar-size` 用运行时测量（方案 A）。
- 根因（vxe-table 4.5.9 源码级）：`x: { visible: true }` 是布尔、vxe 只识别 `'visible'/'hidden'/false` → 走自动判定且本页 `overflowX=false`（列宽由 `autoCellWidth()` 按主区宽度分配、总宽=容器宽），vxe 内联写 `visibility: hidden`；项目 `scrollbar.css` 的 `:hover ... visible !important` 把它显示回来；**滑块必然出现的真因**是 handle 恒有 16px 伪溢出（JS 内联轨道宽扣了 8px 纵向滚动条宽，但本项目纵向滚动条已浮动不占布局 + handle 自身 thin 滚动条占位 8px），而 `--scroll-x-space` 宽 = `scrollXWidth` = 容器满宽。另：浮动化后 `.vxe-table--scroll-x-virtual`（absolute 无 width）宽度塌成 0。
- 修复（2 文件增量，无新文件）：`src/plugins/vxe-table.ts` 加 `measureScrollbarSize()`（离屏探针实测 thin 占位 → `:root --x-scrollbar-size`，先于 `injectScrollbarStyle()` 调用）；`src/styles/css/scrollbar.css` 加 3 条：x-virtual `width:100%!important`、x-wrapper `width:100%!important`、x-handle `width: calc(100% + var(--x-scrollbar-size, 8px))!important`。
- 验证：oxlint 0 error / read_lints 0 / `pnpm typecheck` exit 0；dev server 当时未运行（9527 无监听），浏览器效果待用户复核（hover 无滑块；缩窄窗口令列总宽超容器时滑块出现且可拖）。
- 记录：`changelog/不需要横向滚动也显示横向滚动条修复.md` + `AGENTS_CHANGELOG.md` 2026-09-16 分组。

## 后续：无滚动条时隐藏滚动条端点（同一问题第二处）

- 用户新截图（角色管理页）红框标出 hover 时滚动条浮层两端的小色块，问"没有滚动条的时候这个能不能也不显示"。
- 定位（用户实测配合）：① 鼠标移出表格色块消失 → 属滚动条浮层；② 用户右键检查元素 = `.vxe-table--scroll-x-handle > .vxe-table--scroll-x-space{width:1720px}`，1720 与表格实际宽度一致 → **列宽总和==容器宽、无横向溢出**（据此排除四角补块 corner：vxe 与项目 CSS 均已 `display:none`）；③ 真因 = vxe 给两条 handle 设 `overflow-x/y: scroll`（`vxe-table/es/table/style.css:2540-2557`），scroll = 不论是否溢出都渲染滚动条，无滑块时轨道端点仍被画出。
- 修复：`scrollbar.css` 新增 0.4 节 `.vxe-table .vxe-table--scroll-x-handle { overflow-x: auto !important }` + `.vxe-table .vxe-table--scroll-y-handle { overflow-y: auto !important }`（auto = 溢出才渲染；对 vxe 的 overflowX/overflowY 判定无影响）。
- 记录：`changelog/无横向滚动时隐藏滚动条端点.md`；视觉效果待用户复核。

## 角色权限抽屉树表行高自适应

- 问题：「操作权限」列复选框换行被 40px 固定行高裁切；`{ height: 'auto' } as any` 传 `cell-config` 无效。
- vxe-table 4.17 源码结论（对将来的树表自适应有复用价值）：① `cell-config.height` 只接受 number，`'auto'` 被 `toNumber` 吞掉；② vxe **默认不做行高实测**，`calcCellHeight` 的条件是 `!isAllOverflow && (scrollYLoad || scrollXLoad || (treeConfig && treeOpts.showLine))`——树表必须开 `tree-config.showLine` 才逐行实测，写入 `rowRest.height`；③ `isAllOverflow = !!showOverflow`（`table.ts:1754/1791`）——**这是最容易被忽略的一层**：`Table.vue` 写死 `show-overflow="tooltip"` 导致 `isAllOverflow=true`，`calcCellHeight` 直接跳过；④ 行高取值链 `getCellRestHeight`：`cellOpts.height → rowOpts.height → rowRest.height → defaultRowHeight`，要让位给实测值须 `cell-config.height=0`（falsy）；⑤ 单行内容行高 = `Math.max(defaultRowHeight, 实测值)`，不会变矮；⑥ 数据更新/树展开后 vxe 自动 recalculate（reHeight=true → calcCellHeight），业务侧无需手动触发；⑦ 超过 `virtualScrollRowThreshold`（默认 200）启用虚拟滚动后实测停止。
- 方案（用户确认：不用 row-config、只用 cell-config、showLine 连接线用 CSS 隐藏）：
  - `Table.vue` 新增 `showOverflow` prop，默认 `'tooltip'`，模板绑定 `:show-overflow="showOverflow"`（默认行为不变，其他页面无影响）；
  - `role-permission-drawer.vue` 传 `:show-overflow="false"` 让 `isAllOverflow=false`；
  - `autoRowConfig` 改 `{ height: 0 }`（去 as any）；
  - `treeConfig` 加 `showLine: true`；
  - 文件尾 scoped `:deep(.vxe-tree--line-wrapper){display:none}`。
- 设计文档：`docs/superpowers/specs/2026-09-16-role-permission-tree-table-auto-row-height-design.md`。

- 验证：read_lints 0 / `pnpm typecheck` 0 错误；浏览器效果待用户复核（按钮多的行撑高、搜索/展开后自适应、无树连接线）。
