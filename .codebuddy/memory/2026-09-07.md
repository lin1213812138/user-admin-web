## 阿里巴巴普惠体 Web 化方案讨论（未落地，待用户确认后开发）

- 需求：全站使用阿里巴巴普惠体（官方 fonts.alibabagroup.com，免费商用，3.0 系）。
- 用户痛点演进：先问"如何自动提取文字"，再强调"字太大/加载慢"。
- 已澄清关键技术结论：
  1. 中文字体不引入不会加载；一旦全局挂全量字库，每页首访强制下载 9~16MB 全字库 → 加载慢根因。
  2. unicode-range 全量分片（cn-font-split 默认/vite-plugin-font 默认）产物=全字库大小，只有产物/存储优势在"传输按需"；真子集产物才小。
  3. 本项目**后端动态文案多**（菜单/表格/表单/字典来自 wms-user），纯扫源码子集覆盖不了动态数据字。
- 我方推荐档位：**静态文案自动提取（扫 src/views、src/components、src/locales 含 naive 文案）+ 3500 常用字兜底 + 子集化 woff2（几百KB~1.5MB）+ @font-face font-display:swap + 非阻塞 class 切换 + 系统字体 fallback**。数据字缺字回退雅黑/苹方可接受。
- 可选替代：服务端 dynfont 动态子集（Koa 后端可做，但改动大，不推荐现在做）。
- 候选工具：vite-plugin-font（vite 集成，?subsets+scanFiles 扫源码）、cn-font-split（CLI/API）、fontmin。
- 项目接入点备忘：字体放 `src/assets/fonts/`（目录尚不存在）；vite 插件在 `build/plugins/index.ts` 集中注册；全局 font-family 现定义在 `src/styles/css/reset.css` 的 `html{}`。
- 状态：用户尚未拍板覆盖范围与是否落地。待确认后按 AGENTS 规则先出设计/brainstorming，落地补 changelog。

- **左侧字段面板样式重构（2026-09-07 晚）**：用户反馈左侧样式不明显、基础元素未收进折叠、折叠时出现空白白条（NCollapse 折叠态残留白块，加 `display-directive="if"` 和清样式 `!important` 仍未消除）。最终方案：把 `field-panel.vue` 从 `NCollapse` 改为原生 `<details>/<summary>` 自实现类菜单折叠面板，彻底规避白条；分组项上下相连、无间距、无圆角，标题 40px 高度居中，自定义三角箭头；字段项白底小卡片带缩进；用户确认**默认全部折叠**（初始 `expandedNames=[]`）。拖拽注册靠 `use-hiprint.ts` 的 `MutationObserver`，`<details>` 内容始终在 DOM（仅 display:none），挂载即可注册，故默认折叠不影响拖拽。
- **设计器画布溢出滚动条（2026-09-07 晚）**：用户反馈把元素拖到画布外会出现整页滚动条。根因是 `AdminLayout` 布局主滚动元素（id=`__SCROLL_EL_ID__`，来自 `@sa/materials` 的 `LAYOUT_SCROLL_EL_ID`）默认 `overflow: auto`。修复：页面挂载时给 `body` 加 `print-design-no-scroll` 类，CSS 中仅对 `#__SCROLL_EL_ID__` 设置 `overflow: hidden !important`；组件卸载时移除 body 类。之前同时隐藏 `html/body` 会干扰 hiprint 坐标计算，已去掉。
- **切换纸张后页码未跟随（2026-09-07 晚）**：用户切到 100×150mm 后，页码「1-1」仍停留在旧纸张位置。根因是 hiprint 的 `setPaper` 内部 `designPaper.resize` 只在页码超出边界时才钳制，且使用的是 `designPaper` 自己保存的 `paperNumberLeft/Top`；在 `setPaper` 之后再改 `editingPanel` 上的值无法影响 resize 的结果。修复：① `use-hiprint.ts` 的 `resetPaperNumberPosition(template)` 在 `setPaper` 之前把 `editingPanel.designPaper.paperNumberLeft/Top` 与 `editingPanel.paperNumberLeft/Top` 设成极大值；② `index.vue` 的 `applyPaper(true)` 先调用 reset 再调用 `setPaper`，让 hiprint 自动钳制回新纸张右下角默认值（width-30pt, height-22pt）。初始加载时不重置，避免覆盖用户手动调整过的页码位置。
- **基础元素默认尺寸过大 / 拖动位置乱跳（2026-09-07 晚）**：用户拖动基础元素（尤其「长文本」）时元素铺满甚至盖住左右面板，轻微拖动就"跳"到另一侧。根因：hiprint 自带默认元素尺寸过大（长文本 `default:{height:42,width:550}`，在 100mm 标签纸约 283pt 宽时远超纸张），叠加上画布 `overflow:visible`，元素远超纸张、盖住面板，拖动时看起来像位置乱跳。修复：`use-hiprint.ts` 新增 `applyDefaultElementSizes(api)`，在 `initHiprint` 的 `init` 之后调用，用 hiprint 顶层导出 `hiprint.updateElementType(tid, updater)`（实现是 `a.instance.updateElementType`）按 tid 把 longText(160x42)/text(80x20)/image(60x60)/barcode(100x30)/qrcode(60x60)/rect(80x60)/hline(80x10)/vline(10x80) 默认宽高收敛到合理范围。⚠️ `updateElementType` 是 **hiprint 顶层函数**，不是 `PrintElementTypeManager.updateElementType`（前者不存在该实例方法，曾误用报错 `manager.updateElementType is not a function`）。只影响后续新拖入的元素，已存在的旧元素需删除重拖。
- **hiprint 对齐吸附（2026-09-07 晚）**：用户问“拖进来超出边界的，然后稍微拖一下，就直接全部强制拖进来了，这个是规定吗？”。确认是 hiprint 自带的**对齐吸附**（adsorption）设计辅助行为：元素边缘靠近纸张边缘或其它元素时，在 `HIPRINT_CONFIG.adsorbLineMin` 阈值内自动贴边对齐。如用户需要关闭，可在加载 hiprint 前设置全局 `window.HIPRINT_CONFIG = { adsorbLineMin: 0 }`。
- **右侧面板横向滚动条（2026-09-07 晚）**：用户截图右侧属性面板出现横向滚动条。根因：hiprint 属性面板内某些表单项（如「字体」「纸张方向（仅自定义纸质有效）」）宽度超出固定 300px 的右侧面板，原 `overflow-auto` 同时显示横向滚动条。修复：`index.vue` 右侧面板改为 `overflow-x-hidden overflow-y-auto`，保留纵向滚动、隐藏横向滚动条。
