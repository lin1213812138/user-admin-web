- 搜索栏收展卡顿（用户："搜索栏展开后收起很卡顿"）三轮尝试的教训与结论：
  - **第一版/第二版均被否（"更卡了" / "改的都不对：比原来更差"），已回退**。两版都错在"凭源码推理改复杂逻辑"：① 把 `:auto-resize` 做成响应式动态切换（冻结→手动 recalculate→恢复）；② 关掉 vxe autoResize + 自管理 ResizeObserver 接管重算。
  - **核心教训**：本项目 vxe-table 的插槽是内联的，`Table` 组件任何一次渲染都会带着 vxe-table 一起 patch → **不要在交互过程中动态切换 vxe 的 props**，也不要贸然"接管" vxe 的尺寸/重算逻辑，净增渲染次数就是净增卡顿。另外用户偏好**简单动画**（"收起动画简单一点"），不要在收展上堆过渡 / 合成层优化。
  - **第三/四版迭代（用户反馈驱动）**：先做成"150ms 双向纯 opacity 淡入淡出" → 用户："还是没啥过渡动画"（只改透明度、高度瞬跳，观感上没有"收/展"过程）→ 最终定为 **纯 CSS 的 grid 行高过渡**。
  - **最终实现（定稿，仅 2 文件）**：`SearchBar` 模板包成 `div.search-collapse`（`display:grid; grid-template-rows: 1fr`）→ `div.search-collapse-inner`（`min-height:0; overflow:hidden`）→ `NCard`（`card-wrapper shrink-0 mb-12px`）；收起时根节点加 `.is-collapsed { grid-template-rows: 0fr }`，过渡 `transition: grid-template-rows 0.2s ease` —— **高度本身被平滑动画**，表格随之被推开/收回；间距在卡片上，收起后随行高 0 一起被裁掉。全程无 JS 测量、无 `will-change`、无位移，vxe 配置一行未动；`table.vue` 仅删掉外层 div 的 `:class="{ 'mb-12px': !searchCollapsed }"`。验证 typecheck 0 / oxlint 0 / build 成功。
  - 用户 UI 偏好补充（2026-09-15）：**"简单"≠ 没动画** —— 要的是"一眼能看出收/展过程的过渡"（高度/位置随动），而不是透明度渐变；同时不要花哨元素（位移、合成层、JS 接管）。
  - 高度动画的必然副作用与修法（用户："展开的时候我不希望出现整体的滚动条"）：动画 200ms 内 vxe 表格**内部高度仍是旧值**（vxe 的 resize 处理有节流：连续 resize 只跳过，等尺寸稳定后才重算），表格比被压缩后的容器高 → 溢出到页面 → 顶出 layout 的整体滚动条。`table.vue` 给表格区容器补 `overflow-hidden`（表格自身滚动由 vxe 内部负责，不依赖溢出可见）即可裁掉；这是"要高度过渡"与"vxe 尺寸跟不上"之间的必要折中 —— 动画期间表格底部会被短暂裁切，尺寸稳定后重算恢复。
  - 若仍需优化：**先拿 Performance 火焰图/长任务数据定位，不要再凭推理改**；可考虑"搜索栏改成弹出层"绕开高度变化。用户已明确不喜欢复杂的接管方案与新增文档。
