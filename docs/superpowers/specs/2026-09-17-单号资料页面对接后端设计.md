# 单号资料页面（运单号规则归位）设计

> 日期：2026-09-17
> 需求原话：「运单号规则加到资料管理-单号资料-单号规则这里」

## 一、背景与目标结构

原「运单号规则」位于「系统设置」第 5 个 tab，纯前端 mock（编号/名称/前缀/后缀/起始值/结束值/当前值/数字位数/验证位 open|close），与后端 tms-user 的 `no-rule`（单号规则）模型脱节；且从信息架构看，单号规则属于主数据（资料），不应留在系统设置。

本次做三件事：

| #   | 动作                    | 位置                                                                                                                        |
| --- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1   | 新增「单号资料」页面    | 「资料管理」二级菜单第 4 位（基础资料/业务资料/财务资料/**单号资料**），路由 `/data-manage/no-rule`，页内左 tab「单号规则」 |
| 2   | 移除「运单号规则」tab   | 「系统设置」7 → 6 个 tab（旧 module 目录一并删除）                                                                          |
| 3   | 删除「单号资料管理」tab | 「业务资料」9 → 8 个 tab（`archives/business/waybill/` 删除）                                                               |

## 二、已确认的设计决策

1. **页面形态**：「资料管理」下新建独立二级页面（沿用基础/业务/财务三页同款 `VerticalTabLayout` 壳），页内 tab 名为「单号规则」（当前仅一个 tab，后续扩展直接往 items 数组加）。
2. **旧入口处理**：系统设置里的「运单号规则」移除（信息架构归位，不并存）。
3. **数据源**：接后端真实接口 `/no-rule/*`（DEV 也直连，无 mock，与录单格式/打印格式/导出格式一致）。
4. **系统类型 sysType**：表单可选（自定义默认 / 1-运单号 / 2-客户编号）；sysType 有值的记录前端同步禁删（对齐后端 `BUILD_IN_ERROR`）。
5. **业务资料里的「单号资料管理」**：删除该 tab（单号规则独立成页后多余）。
6. **路由/目录命名**：`/data-manage/no-rule`，目录 `src/views/data-manage/no-rule/`，service/typings 同名（对齐后端模块名，避免与业务资料里 waybill 档案混淆）。
7. **实施路径**：新建重写，不迁移旧文件（旧 mock 形状与后端差异大：`_id`/`checkType` 3 态/`sysType`/`buildIn`/无 code 无 status）。

## 三、后端事实（tms-user，已读源码核实）

模型 `lib/common/models/no-rule.js`（`NoRuleSchema`）：

```
name      String  名称，必填
start     String  起始值，必填
end       String  结束值，必填
len       Number  数字位数，必填
current   String  当前值
prefix    String  前缀
suffix    String  后缀
checkType Number  验证位 0-无验证位 1-加权验证 2-模7验证
buildIn   Number  系统内置 0-否 1-是
sysType   Number  系统类型 1-运单号 2-客户编号
note      String  备注
creatorId/creator/updateId/updateBy  创建/修改人（后端自动写）
createDate/updateDate                毫秒时间戳
```

接口 `lib/api-v1-web/no-rule/index.js` + `lib/services/no-rule.js`：

| 接口                   | 行为                                                                                                                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /no-rule/query`  | `queryCommon`，body `{page,size,where?}` → `ret:{list,total}`；未配 keywordFields ⇒ keyword 无效；不传 scene 时无 sysType 过滤、无头部插入；sort `{order:1}`（模型无 order 字段，等同自然序） |
| `POST /no-rule/get`    | `{_id}` → 单条                                                                                                                                                                                |
| `POST /no-rule/create` | ajv 必填 `name/start/end/current/len`；`name` 唯一（重名报错）；prefix/suffix 自动 trim + 转大写；创建后同步 redis 当前值                                                                     |
| `POST /no-rule/update` | `{_id}` + 字段；**buildIn=1 时 name 被忽略（不可改）**；改 current 会同步 redis；sysType=2 时更新客户编号起始                                                                                 |
| `POST /no-rule/delete` | `{_id}`；**sysType 有值的记录抛 BUILD_IN_ERROR（不可删）**                                                                                                                                    |

`validate.num = { type: ['number','string'] }` ⇒ start/end/current 可提交数字串；len 提交 number。

### 4.2 列表 `views/data-manage/modules/no-rule/NoRule.vue`

- `Table` + `useVxeTable`，cacheKey `data-manage-no-rule`，默认分页 50（全局默认）。
- 列（默认 12 列 + 操作列）：

| key        | 标题         | 备注                                                |
| ---------- | ------------ | --------------------------------------------------- |
| name       | 名称         | `type:'detail'`                                     |
| prefix     | 前缀         | 宽 80                                               |
| suffix     | 后缀         | 宽 80                                               |
| start      | 起始值       | 宽 90                                               |
| end        | 结束值       | 宽 90                                               |
| current    | 当前值       | 宽 90                                               |
| len        | 数字位数     | 宽 90                                               |
| checkType  | 验证位       | 插槽渲染文案（无验证位/加权验证/模7验证）           |
| sysType    | 系统类型     | 插槽渲染标签（运单号/客户编号，无值 `--`）          |
| note       | 备注         | —                                                   |
| updateBy   | 最后操作     | `fixed:'right'`                                     |
| updateDate | 最后更新时间 | `fixed:'right'`，毫秒时间戳 → `YYYY-MM-DD HH:mm:ss` |
| （操作列） | 编辑 / 删除  | 删除 NPopconfirm；`sysType` 有值 → 禁用 + tooltip   |

- 搜索栏：`#search-action` 插槽，系统类型筛选（全部/运单号/客户编号 → `where.sysType`）+ 查询/重置。
- 操作列右侧工具：列设置（TableColumnConfig）+ 刷新。
- 抽屉打开时新建传 null / 编辑传行数据；`@submitted` → `getData()`。

### 4.3 表单 `views/data-manage/modules/no-rule/NoRuleForm.vue`（抽屉 720）

| 字段                                       | 类型     | 规则                                             |
| ------------------------------------------ | -------- | ------------------------------------------------ |
| name 名称                                  | input    | 必填；`buildIn=1` 时 disabled                    |
| prefix 前缀 / suffix 后缀                  | input    | 提交后后端自动转大写                             |
| start 起始值 / end 结束值 / current 当前值 | input    | 必填，正整数（自定义校验）                       |
| len 数字位数                               | input    | 必填，正整数（提交 number）                      |
| checkType 验证位                           | select   | 0-无验证位 / 1-加权验证 / 2-模7验证，默认 0      |
| sysType 系统类型                           | select   | 空-自定义（默认，不提交）/ 1-运单号 / 2-客户编号 |
| note 备注                                  | textarea | span 24                                          |

- 新建提交体：`{name,prefix,suffix,start,end,current,len,checkType,note,sysType?}`；编辑加 `_id`。
- 成功 → `emit('submitted')` → 父级刷新。
